6. **Saiful raised a sharp methodology question: "I wonder if the chunking is correct."**
   Investigated and found a real, confirmed bug in `i18n_verify_lesson_translation.py`'s
   chunking (used for any small-context endpoint — allam, JAIS, and now Falcon):
   - Old `_rechunk_oversized` re-grouped each language's oversized heading-section into
     character-budget batches **independently per language**. Since translated text runs
     a different length than the source, the two languages' cutoffs land at different
     paragraph indices — same-index chunks can silently stop corresponding to the same
     content. This was only *detectable* when final chunk counts differed (46/342
     lessons forced a whole-body fallback); when counts *coincidentally* matched
     (263/342 lessons!), the misalignment was invisible and the mismatched pair still got
     sent to the verifier as if aligned.
   - **Confirmed concretely** on `071_how_to_verify_before_you_wire_money`: EN's cutoff
     fell after its 4th numbered point, AR's after its 5th — "chunk 2" compared an EN
     worked example against an unrelated AR list item. Verified via direct paragraph
     inspection that paragraph *counts* matched exactly (8=8) with perfect 1:1 content
     correspondence — the bug was purely the independent character-budget regrouping,
     not a genuine translation-structure divergence.
   - **Fixed** (commit `b85de55`): split any oversized section into paragraphs, pair by
     INDEX first (translation preserves 1:1 paragraph correspondence — structurally
     guaranteed, not a coincidence), then batch adjacent *already-correctly-paired*
     paragraphs up to the character budget via a new `_batch_pairs` helper — a pair can
     never be separated from its partner. Falls back to a character slice only when
     paragraph counts genuinely diverge for a given section, and that fallback is now
     **scoped to just the offending section**, not the whole lesson body (the old
     whole-body-fallback blast radius was needlessly large).
   - **Measured improvement**: of 683 (lesson, locale) pairs corpus-wide, **675 are now
     fully paragraph-index-aligned with zero fallback anywhere** (up from the old
     algorithm's 263 "coincidentally matching count, no structural guarantee" cases).
     Only 8 pairs still need the (now safely localized) section-scoped fallback:
     `133_on_balance_volume_obv[ms]`, `135_money_flow_index_vs_rsi[ms]`,
     `137_bollinger_squeeze_and_breakout[ms]`, `138_bollinger_band_walk[ms]`,
     `139_stochastic_k_d_crosses[ms]`, `140_stochastic_fast_vs_slow_divergence[ms]`,
     `147_false_confluence_indicator_redundancy[ar]`,
     `147_false_confluence_indicator_redundancy[ms]`.
   - Live smoke-tested end-to-end against JAIS post-fix (see point 5) — confirms the fix
     itself works correctly; it just doesn't rescue a weak-judge model's output quality.
   - Module docstring in `i18n_verify_lesson_translation.py` updated to describe the new
     approach (was previously describing the old, buggy one).

## Active constraints / gotchas — do not forget

- **Sequential-only per vLLM instance** — never two concurrent requests to the *same*
  port. Different ports (e.g. ami-llm :8000 + allam :8040, or now + Falcon :8044) can run
  concurrently — proven safe earlier this session (the pilot), though it roughly doubles
  `ami-llm`'s per-request latency under concurrent load. allam's port (:8040) went **down**
  (connection refused) partway through this session — presumably swapped out for JAIS/Falcon
  work; don't assume it's still there without checking.
- **`i18n_coverage_report.py` syncs `locale_versions` from file existence alone** — it has
  no concept of translation quality. A hand-edited `locale_versions` field WILL get
  silently clobbered next time the report runs (this bit me once with 355 — coverage
  report re-enabled its flawed MS translation because the file still physically existed).
  **To actually exclude a bad translation from serving, relocate the file** —
  established pattern: `content/i18n/_excluded_staging/<filename>.needs_fix`. Currently
  holds: `355_how_amis_halal_flag_maps_to_real_screening.ms.mdx.needs_fix`.
- **355's MS translation is intentionally quarantined, not broken/forgotten.** Two
  independent verification passes + a retry all confirmed the same mechanism-inverting
  errors in this Sharia four-state-screen lesson: "SCREENED OUT" (blocking) → "DISELIT"
  (hidden/concealed), "PAUSES" (temporary) → "BERHENTI" (permanent stop). Don't re-enable
  without either a human Malay check or a demonstrably-better model actually fixing those
  two specific terms. AR is fine and live.
- **`360_steelmanning_the_other_side`'s AR prose** (not quiz/title, those are fine) stays
  English-fallback — a reproducible model quirk (drops the entire "## Quiz" heading +
  bare-placeholder subsection when it has zero non-placeholder content to translate)
  survived 4 retry attempts (bumped from the original 2). Documented, not worth chasing
  further; title + both quizzes translate correctly for this lesson.
- **Shared checkout, multiple concurrent tracks** (architect, auditor, a new Support
  track S1, etc.) are committing throughout this session. Before assuming exclusive
  ownership of any content/docs area, check `git log --oneline <known-good-sha>..HEAD --
  <path>` for surprises — this caught DEF102 and DEF097's staleness. Always explicit
  pathspec commits (`git commit -m "…" -- <files>`), never bare/`-am`/`-A`.
- **Ground truth for "is a lesson actually broken" is the real backend gate**, not any
  LLM's opinion: `backend/app/services/lessons_service.py`'s `parse_mdx` +
  `_locale_quiz_servable`, run from `backend/` with `.venv/bin/python`. This caught real
  bugs AND caught `ami-llm` hallucinating "broken tag" citations that didn't match actual
  file content (confirmed false-positive pattern earlier this session) — never trust an
  LLM verifier's prose claim about corruption without checking the file directly.
- **Two separate translation scripts, two separate purposes**: `scripts/translate_lessons_lan.py`
  (the translator — always `ami-llm`, sequential-only, has its own `--ids`/`--locales`/
  `--overwrite` flags) vs. `scripts/i18n_verify_lesson_translation.py` (the verifier —
  `primary` model = `ami-llm` whole-body single-shot, `allam` = AR-only chunked; `ENDPOINTS`
  dict at the top of the file is where a model would get formally registered, not done yet
  for JAIS or Falcon).
