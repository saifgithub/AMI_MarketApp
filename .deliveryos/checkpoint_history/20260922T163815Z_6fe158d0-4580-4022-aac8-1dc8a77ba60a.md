## What was decided this session

- **CR224 scope**: Saiful clarified "Alpaca has several servers" means Alpaca does NOT
  give every user the same paper-trading host (some resolve to a different endpoint than
  `https://paper-api.alpaca.markets`) — not paper-vs-live, not data-feed tiers. He gave
  the concrete example `https://paper-api.alpaca.markets/v2` as "what Alpaca set."
- **Storage**: device-local only, per CR202's existing custody model (Alpaca credentials
  never reach the AMI backend — confirmed via research that no `UserSettings`/
  `UserPreference` table exists, and the backend's `alpaca_paper_base_url` setting is
  unrelated — it only serves the dead/unreachable OAuth token exchange, not per-user data
  access).
- **UI placement**: added directly to the existing Alpaca Connect screen's API Key tab,
  next to key ID/secret — not a separate advanced/settings field. Saiful's explicit choice
  when asked.
- **Release flags**: `--internal-only` on both `build_testflight.sh` and
  `publish_playstore.sh --no-bump --internal-only` — games tab (CR109) stays in, team-only
  distribution, matches recent standard releases. First `publish_playstore.sh --no-bump`
  attempt (no `--internal-only`) failed the RevenueCat Test Store key gate — had to add
  the flag on retry; that is now the known-correct invocation for this repo's Android
  publish path.
- Saiful chose "ship now, verify via TestFlight build" over a local on-device check first
  — the CR224 manual verification (default endpoint links, bad endpoint fails cleanly,
  corrected endpoint links) was deliberately deferred to him on his phone, not done in
  this session.
