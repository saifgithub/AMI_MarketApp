## 4. ACTIVE CONSTRAINTS — several learned/re-confirmed THIS session

- **melehost's bare `python3` has NEITHER `pydantic` NOR `pydantic_settings`.** Any script
  importing `app.core.config` or anything that transitively pulls in the FastAPI app MUST run via
  `docker exec ami_api_alpha python -m scripts.<name>`, never as a host-side cron job directly —
  confirmed live 2026-07-30. `backend/scripts/` is NOT baked into the image and was NOT mounted
  into the container before this session (fixed — see `docker-compose.yml`'s new
  `./backend/scripts:/app/scripts:ro` line) — but that mount isn't LIVE on melehost yet (needs
  promotion).
- **No passwordless sudo on melehost from this session** (`sudo -n true` → "interactive
  authentication is required"). Can't read root's crontab, can't touch
  `/var/lib/docker/volumes/*/​_data` directly (root-owned). Anything touching Docker-volume data
  must go through `docker exec`, not the host filesystem path, even though the path is
  discoverable via `docker volume inspect`.
- **The CR084-ALPHA dirty tree is STILL dirty** (`backend/app/api/webhooks.py` +
  `test_cr084_revenuecat_webhook.py` + the CR084 doc + all 3 build scripts) — checked freshly at
  the top of this memo. It now blocks THREE things: DEF157, DEF195, and DEF201's janitor
  promotion. Not mine to touch; another track's in-flight work.
- **Tests share `tmp_path` with the sqlite test-DB tempfile.** Any new disk-scanning code
  (`_current_total_bytes`-shaped) MUST filter to its own expected file types, or it will count
  the DB file as data. `test_bug_attachments.py`'s own comments already flagged this for a
  different test; I re-learned it the hard way building the volume-cap check.
- **`FastAPI` threadpools a plain `def` dependency automatically** — `get_current_user` (a sync
  `def`, not `async def`, in `dependencies.py`) does NOT block the loop despite being called from
  `async def` handlers, because FastAPI runs sync dependencies (and sync path operations) in a
  threadpool by its own framework behavior. Do not flag `Depends(get_current_user)` as a DEF200
  site — checked this specifically before trusting the census's scope.
