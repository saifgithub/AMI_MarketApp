# What was decided this session, in order

## 1. DEF335 root cause — the row's own prescribed fix was refuted by measurement

The row said twice, in the present tense, that the proper fix was: re-backfill
`price_history_daily` with `auto_adjust=False` so `close` would carry an as-traded quote
and `adj_close` the adjusted one. **That is false.** Measured against yfinance 1.3.0:
`auto_adjust` toggles the DIVIDEND adjustment only; the OHLC series stays split-adjusted
in BOTH modes. Raw `Close` across each split:

    BKNG  2026-04-06  25:1   167.77 -> 176.19   ratio 0.952  (25 if truly unadjusted)
    NFLX  2025-11-17  10:1   111.22 -> 110.29   ratio 1.008  (10 if truly unadjusted)
    NOW   2025-12-18   5:1   156.48 -> 153.38   ratio 1.020  ( 5 if truly unadjusted)

Executing the prescribed fix would have rewritten 119,311 live rows across 201 tickers,
moved `close` by the ~0.7% dividend factor, left the 25x market-cap error exactly in
place, and printed a success summary. Filed as a second surface of **P24** (a mutation/
mechanism claim written from reading, not running) in
`docs/initial_specs/08_tech/failure_patterns.md` — a new instance block was added there,
plus the existing P24 entry's enforcing-checks list got a line about measuring the
replacement before believing it.

## 2. The actual fix — restate the SHARE basis, not the price basis

New `ticker_splits` table (migration `def335a0b0c0d2`, additive, revises
`cr210a0b0c0d1`) + `backend/app/services/ticker_splits.py`. `edgar_pit.fetch_pit_
fundamentals` restates the filed dei share count by the product of split ratios with
`share_fact.period_end < ex_date <= bars.fetched_at` — **not** `as_of`, **not**
`date.today()`, each of which produces a plausible wrong market cap rather than an error
(mutation-tested, see below). The correction lands ONCE on `shares`, so `market_cap`,
`shares_outstanding`, `trailing_eps`, `revenue_per_share`, `pe`, `price_to_sales` all read
one basis and the sheet still divides into itself (DEF302's rule). Declared in
`shares_basis` (`dei_cover_page+split_adj_25`) so the correction isn't silent.

`backend/scripts/backfill_price_history.py` gained `fetch_splits()` (whole split history,
`None` on provider failure vs `[]` on genuinely none — different facts) and persists every
split via `upsert_splits`; `splits_in_window()` now delegates to it. An empty
`ticker_splits` table yields factor 1.0 — i.e. today's numbers exactly — so the code
change alone cannot move any figure until the backfill runs.

**P15 caught a real bug in the new code before a human did.** `upsert_splits` originally
SELECTed-then-INSERTed against `uq_ticker_splits_ticker_ex_date` with no `IntegrityError`
handler — the exact check-then-INSERT race the P15 ratchet exists to catch. Fixed with a
nested SAVEPOINT converging to an update, same pattern as
`price_history.upsert_daily_bars`. Exercised deterministically (one call, two pairs
sharing an ex-date) rather than by racing two processes.

`backend/tests/unit/test_def335_share_basis_restatement.py`: **20 tests, 10 mutations,
10 killed.** `backend/tests/unit/test_def335_split_basis_exclusion.py`'s
`test_splits_outside_the_window_do_not_exclude` was rewritten off a docstring-content
assertion (`assert "hand-listed" in __doc__`) onto a behavioral one — the old form was a
test of prose, passing on any refactor that kept the sentence.

Read-only dry run over the real 150-ticker universe (before touching Alpha): **0 provider
failures**, 142 clean, exactly the 8 named tickers with splits — BKNG 25.0, NFLX 10.0,
NOW 5.0, FDX 1.241, CMCSA 1.067, SPGI 1.057, HON 1.0117 (compounds 1.061 x 0.9535 — proves
the compounding matters, last-split-alone would err the other way), LCID 0.1.
