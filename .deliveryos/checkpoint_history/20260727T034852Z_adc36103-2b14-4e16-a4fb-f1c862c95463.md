### The problem, precisely
Auditor (track U, a self-respawning watcher Saiful runs) writes its verdict to
`orchestration/audit/cr/<ITEM>.auditor.md` as `VERDICT: COMPLETE | AWAITING_FIXES`. The
Architect is supposed to notice `AUDIT_PASSED` (verdict COMPLETE + `DISPATCH` not yet
ACCEPTED) and integrate. **The Architect isn't checking**, so COMPLETE verdicts sit
un-integrated for sessions (saw exactly this earlier: CR090-BE/CR026-BE verdicts I had to
find by hand via git, not by any signal).

### KEY INSIGHT for the suggestions — the machinery already exists; this is a *trigger* gap
`orchestration/dispatch/dispatch.sh` already derives `AUDIT_PASSED` and has:
- `dispatch.sh state` — prints the whole board once (every lane's derived state).
- `dispatch.sh architect [-i N]` — blocks until ≥1 lane needs the Architect
  (`UNASSIGNED|BLOCKED|NEEDS-INFO|IN_REVIEW|AUDIT_PASSED`).
So the fix is NOT new tooling — it's making the Architect *run* the check reliably. Also
`DISPATCH_PROTOCOL.md` §8 guardrail 7 ALREADY says "re-derive the board at the start of
every session and clear anything in UNGATED/AWAITING_AUDIT before taking new work" — but
nothing makes it happen (it's prose, not a step). CLAUDE.md rule applies: *prompt
instructions are not controls* — a rule with no trigger gets skipped.

### Candidate LIGHT suggestions to present (pick 1–2, keep it cheap)
1. **Session-start "audit inbox" check in CLAUDE.md** — add a numbered session-start step
   (like the CR085 daily-review step 2) that runs `dispatch.sh state` (or a new one-shot
   `dispatch.sh inbox`) and surfaces any `AUDIT_PASSED` lane BEFORE taking new work. Makes
   §8.7 an actual step instead of buried prose. Cheapest, highest-leverage. RECOMMEND.
2. **A tiny `dispatch.sh inbox` (or `architect --once`) one-shot** that prints only the
   lanes owing the Architect (AUDIT_PASSED / AWAITING integration), exit code non-zero if
   any — so it can gate "start new work" and be eyeballed in one line. Small add to an
   existing script.
3. **Auditor drops a durable "verdict ready" breadcrumb the Architect greps** — e.g. the
   auditor, on COMPLETE, also appends to a single `orchestration/audit/INBOX.md` the
   Architect checks at session start. (Careful: single shared file = the same
   shared-mutable-flag write-race we just killed in CR097 — prefer per-item files +
   read-time grep: `grep -l "VERDICT: COMPLETE" orchestration/audit/cr/*.auditor.md` then
   cross-check each item's assign lane isn't `DISPATCH: ACCEPTED`.)
4. **Live doorbell (weak, don't lead with it)** — auditor SendMessages the architect's
   live_handle on verdict. Unreliable across independent sessions (file is truth); at most
   a nudge on top of #1.
Lean: #1 + a read-time grep (#3's safe variant) is the light, race-free combo. Don't build
a daemon; don't add a shared mutable flag.
