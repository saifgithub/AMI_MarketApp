## THE FINDING — already confirmed real, not verifier over-strictness

Sampled actual `critical_issues` text from 8 random flagged entries (`ami-llm` model, primary verifier). **Confirmed genuine, substantive defects**, two distinct root causes:

**Root cause 1 — mechanical, cheap, unambiguous fix.** `scripts/translate_lessons_lan.py`'s `COMPONENT_RE = re.compile(r"<(Quiz|Term|ChatWith|Animation)\b.*?/>", re.DOTALL)` (around line 62) does **not** include `Lesson` as a protected component. **142/342 EN lessons contain `<Lesson id="..."/>` cross-reference tags** that are therefore sent unprotected into the prose-translation LLM call and come back corrupted/truncated (e.g. `<Lesson id="/>` — id value stripped). 55 flagged entries explicitly cite this. Fix: add `Lesson` to the regex alternation, matching the existing pattern for `Term`/`ChatWith`/`Animation` (id-only, no translation) — a one-line, well-justified surgical fix, not a rewrite.

**Root cause 2 — real translation-quality issues, harder to fix mechanically.** Examples pulled from the actual log:
- `070_pressure_tactics...` (MS): "high-pressure sales" → "jualan beransur tinggi" (**gradual** sales) — meaning inversion.
- `020_candlesticks...` (MS): stray untranslated Chinese characters "解码" appearing in candidate output — generation artifact/corruption.
- `064_market_breadth` (AR): **"mandate"** (a core, load-bearing app term — the user's investment-constraints contract with the PM) mistranslated as "ولاية" (**province/governorate**) in several places. This is the most severe single example — a fundamental app-concept mistranslation, not a stylistic nitpick.
- `161_capex_intensity...` (AR): "Capex" translated two *different* ways in the same lesson — main text vs. Quiz section, because prose and Quiz are translated in **separate, uncoordinated LLM calls** with no shared-terminology constraint between them. Also: "Accounts Receivable" and "Payables" both translated to the same Arabic word (المستحقات), creating ambiguity.
- `347_the_four_prohibitions` (MS) — **inside the strict_review Islamic-finance cluster**: lender/borrower semantic inversion, "gharar" mistyped as "ghar" (a specific Islamic-finance term of art, corrupted), financier/developer role confusion.

**Numbers:** 589/673 primary (`ami-llm`) checks flagged ≥1 critical issue (AR 294/339 = 87%, MS 295/334 = 88% — evenly split, not locale-specific). Confidence score distribution skews OK-ish: `{2: 51, 3: 168, 4: 444, 5: 10}` — most lessons score 4/5 confidence, but the `_is_verified()` rule requires **zero** critical issues regardless of score, so even one broken tag disqualifies an otherwise-good lesson. Net read: **not** "590 lessons are garbage" — more like "590 have ≥1 real flaw when scrutinized this hard, ranging from one corrupted cross-reference tag to a genuine core-term mistranslation."
