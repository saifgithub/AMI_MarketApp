2. **Stuck spinner after a failed quote** (`0754159f`): `_ConfirmCard` opened
   `if (t.quoting || t.quote == null) → spinner`, so a FAILED quote fell into
   the loading branch forever. Root cause: real Cloudflare tunnel outage

   backend 5xx, 12/12 hand-curled quotes 200 OK). Fix: RETRY button on error,
   mutation-checked.
3. **Second order always failed** (`91ec5af1`): placing an order invalidates
   `gamesRunDetailProvider`; during refetch `.asData?.value` is NULL even
   mid-refresh (Riverpod AsyncLoading semantics), so `?? 0` sized the next
   quote against zero cash → 422 → unhelpful error copy. Fixed both sides:
   screen reads `.valueOrNull`, notifier's `fetchQuote` now takes nullable
   cash and refuses non-positive requests structurally.
4. **The "no cash" spinner I introduced with fix #3** (`5326cd16`, shipped
   LATE/uncommitted-then-fixed — see Active constraints): `cashAvailable:
   null` (still loading) and `cashAvailable: 0.0` (genuinely none left) both
   fell into the "stay in quoting" branch. Split them: null → wait, `<=0` →
   end in a drawable state. Ticket now shows a dedicated "Nothing left to
   deploy" panel (heading, amount committed, order count, button back to the
   list) instead of ticker/size/confirm steps.
5. **Queue-drain fairness — Saiful's direct question** (`bee79a44` +
   `2d864493` fixture pin): "we've committed more than the 10K stake — what
   happens at the real open? Adjust? Decline? Which one?" Code answer before

   red-bordered section with NO cancel action.
