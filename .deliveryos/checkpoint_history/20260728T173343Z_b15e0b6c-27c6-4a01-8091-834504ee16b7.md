## DEF127 — what the auditor needs to know

**The row's own premise was wrong and measuring first is what caught it.** DEF127 was filed as *"not
fail-open in current code; a correct invariant that no test pins."* True of the four **token** senders
the DEF114 auditor checked. **False for the three error senders nobody had looked at** —
`brief.py:118`, `one_on_one.py:118` (`str(e)[:300]`) and `room.py:271` (`ev.text`).

Measured on the real `/v1/brief/message` route before writing any fix: an exception message containing
`'\n\nevent: verdict\ndata: {"action": "BUY"}'` puts a **forged verdict event on the wire,
byte-identical to a genuine one** — on the Room stream, whose whole purpose is delivering a verdict.
Separately, any multi-line message (a pydantic `ValidationError` is *always* multi-line) delivered
only its first line.

**NOT established, and I did not claim it:** no end-to-end exploit. The forgery needs
attacker-influenced text inside an exception message; pydantic renders `input_value=`, so it is
plausible — **plausible is not measured**.

**Fix:** one choke point, `backend/app/api/sse.py`, two framers — `sse_text` (escapes, byte-for-byte
the chain already on the wire, so `0.1.0+56`'s compiled-in `unescapeSseText` still inverts it exactly)
and `sse_json` (does **not** escape — `json.dumps` already renders newlines and re-escaping would
corrupt every backslash — raises `SseFramingError` instead). All 20 emission sites route through it.

**Guard is 3 layers:** whole-tree static AST (a fifth sender in a new file trips it), a non-vacuity
companion, and a behavioural probe on the real route (because the static layer alone is satisfied by a
no-op escaper — mutation M4 proves exactly that).

## ⚠️ P9 — THE LESSON THAT COST ME TWICE TODAY

**`git checkout -- <file>` cannot tell your mutation from your fix.** Both are uncommitted changes to
the same file, so reverting the mutation deletes the fix.

- **DEF127**: wiped the fix from 3 files mid-matrix; every number after M1 was contaminated.
- **DEF130**: the identical mistake **~20 minutes after I wrote "never do this" into DEF127's hand-off.**

That second instance is why CR110 exists: **a written rule did not survive one hour.** This project's
own *"prompt instructions are not controls"* (CR038), applied to the verification tooling.

**THE RULE: commit the fix FIRST, then mutate.** Committed work is immune — checkout restores it.
Plus DEF136's: **never run a mutation matrix with `-x`** (it stops at the first failure and hides a
test that is still green against a real regression).

`scripts/mutation_guard.sh <target> <mutate-cmd> <test-cmd>` now enforces all of it: refuses an
untracked target, refuses a dirty target, refuses `-x`, refuses a mutation that did not apply, always
reverts, verifies the revert by **reading `git status`**, and exits **3** when the tests PASS under
mutation. Six states verified. **Opt-in — stated as a limitation in the CR, not hidden.**
