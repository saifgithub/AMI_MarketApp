## Active constraints / gotchas hit this session

- **Alembic vs `create_all()` race on a non-fresh DB.** New tables get
  created by `init_schema()`'s unconditional `Base.metadata.create_all()` on
  every boot, but the self-stamp-to-head step only fires when
  `alembic_version` doesn't exist yet. On melehost's already-populated DB,
  CR128's migration hit `DuplicateTable` on `alembic upgrade head` — fixed
  with `alembic stamp head` (verified schema was already structurally
  identical to the migration first). Will recur for any future migration
  that adds a brand-new table to a non-fresh environment.
