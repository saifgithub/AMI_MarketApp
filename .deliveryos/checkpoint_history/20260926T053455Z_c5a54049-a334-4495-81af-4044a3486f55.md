## What was decided this session

1. **Kimi reasoning/thinking must be disabled for Room benchmark runs**
   (Saiful: "Turn off reasoning for Kimi") — fixed via `_force_kimi_gateway()`
   replacing the gateway's `kimi` provider entry with a manually-constructed
   `OpenAICompatibleProvider(extra_body={"thinking": {"type": "disabled"}})`.
   Confirmed live: reasoning-enabled Kimi ran ~18min/ticker (9-12h projected
   for 30 tickers); thinking-disabled runs ~5-6min/ticker. This is now baked
   into the reusable toolkit's default (see below).
2. **A single Room draw is not reliable evidence of anything** — repeatedly
   demonstrated: BAC risk_score=2 alone showed 4 APPROVE / 2 PASS across 6
   draws; my first-pass conclusion ("the fork is at the `trader` agent") was
   WRONG and got corrected in RES009 07 after checking all 6 draws instead of
   the original 2, and diffing `trader`'s INPUT not just its output.
3. **Corrected root cause for the BAC risk_score=2 instability** (RES009 07,
   `docs/Research/RES009_room_llm_consistency/07_cr228_bac_risk_score_instability.md`):
   instability compounds through the WHOLE sequential ~8-agent pipeline
   starting at the very first LLM call (`fundamentals_analyst` already frames
   identical numbers differently between draws), not a single fork point.
   `trader`'s Side/Size is a 6/6 perfect predictor of the final action, but
   `room_agent_replay.py`-style direct replay (5x each) of the two PASS runs'
   EXACT captured `trader` prompts came back perfectly stable (5/5 WAIT, 5/5
   BUY) — proving `trader` itself is NOT noisy; it faithfully resolves
   whatever upstream input it receives.
4. **Traced the actual upstream cause for THAT specific instance**: the two
   PASS draws' `news_context.py`-sourced live news feed (yfinance-backed,
   ~5min cache TTL) had genuinely rolled over in the ~29min gap between the
   two draws — a real Citigroup/Banamex IPO headline appeared in one draw's
   prompt and not the other's, displacing an older story. This is a REAL,
   non-LLM, non-bug root cause (the feed working as designed) for that one
   pair of draws — NOT yet proven to be the general explanation for
   risk_score=2's instability as a whole; only demonstrated for this one pair.
5. **Numeric facts vs. narrative scaffolding in `_profile_for_ticker`**
   (`backend/app/services/room_runner.py:1299`): numeric facts (price, P/E,
   RSI, technicals) are LIVE/ABSENT only (CR104, no rng fallback since
   DEF123). Narrative scaffolding (`sentiment_tone`, `bull_evidence`, etc.) IS
   seeded by `random.Random(zlib.crc32(ticker.upper().encode()))` — but this
   is TICKER-ONLY seeded, so it's IDENTICAL across all draws of the same
   ticker regardless of when they ran. Ruled out as a variance source for the
   BAC instability specifically.
6. **Only the `portfolio_manager` stage votes** — 5 independent samples per
   run (CR197 self-consistency), majority decides, threshold graded by
   risk_score (`_approve_vote_threshold`, `room_runner.py:7945`: 4/5 needed at
   risk_score≤2, 3/5 at risk_score=3, 2/5 at risk_score≥4). Every other agent
   (4 analysts, bull/bear researchers, research_manager, trader, 3 debators)
   is a SINGLE sequential pass with no self-consistency sampling — instability
   at any of those stages has no averaging-out mechanism before it reaches the
   PM.
7. **Built and committed a reusable investigation toolkit**
   (`docs/tools/room_investigation/`, commit `878e049a`) per Saiful's explicit
   instruction ("these capabilities will 100% be used again... rerun the room
   or one agent multiple times... on vLLM or Kimi"). Five scripts:
   `room_kimi_gateway.py` (shared core, `force_gateway("kimi"|"vllm")`),
