## THE ACTIVE BLOCKER — reasoning-token budget

Calibration replay (5 real recent Room verdicts pulled from melehost's
`room_runs`/`mandates` tables — user `8f1e288a…`, mandate_version 1: BAC, NVDA,
NFLX, TDG, DIS, all under one mandate for a clean same-mandate replay) against
the corrected `kimi-for-coding` endpoint: **4/5 tickers still failed** — not
with an error, but by landing on the Portfolio Manager's DEF059 safety fallback
("AMI's analyst room lost its model connection... reconvene the room").

**Root cause, fully isolated (container logs + direct curl, not guessed):**
Kimi's Coding Plan models are genuine reasoning models. Streaming/non-streaming
responses carry chain-of-thought in a separate `reasoning_content` field, and
**that reasoning consumes the SAME `max_tokens` budget as the final answer.**
`room_runner.py` hardcodes per-agent-role token budgets tuned for local vLLM
inference (600 debators, 800 bull/bear researchers, 900 research_manager/
trader/portfolio_manager) — these are far too small for a reasoning model:

| max_tokens tested (same realistic PM prompt, 374 prompt tokens) | result |
|---|---|
| 900 (today's actual Room budget) | 100% reasoning, ZERO content, `finish_reason=length` |
| 4000 | ~1,200 reasoning tokens + a clean, complete JSON verdict, `finish_reason=stop` |

`reasoning_effort: "low"` was tested as a possible lever (Kimi's docs mention
k3 "supports reasoning_effort") — **did not help at all**, reasoning length was
unchanged. The only thing that worked was raising `max_tokens` outright.
