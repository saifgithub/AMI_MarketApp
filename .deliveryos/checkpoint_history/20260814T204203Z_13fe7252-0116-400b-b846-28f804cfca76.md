## Active constraints

- **Pathspec-only commits** — never bare `git commit`, `-am`, `git add -A`.
- **Registers are GENERATED** — write the row file, then
  `python3 scripts/registers/gen_registers.py gen [cr|def|all]`. `python` is
  not on PATH; use `python3` or `backend/.venv/bin/python`.
- **A row file's status can be WRONG even when "just filed"** — this session's
  biggest process finding. A commit that fixes something can file the row
  `open` in the same breath. When picking work off the register, cross-check
  `git log --oneline --grep=DEF###` before trusting a row's `open` status,
  not just `gen_registers.py verify` (which only checks the table matches the
  row files, not that the row files are TRUE).
- **A test that executes a real release script must disarm every side effect
  of that script, not rely on early exits landing before them** — a mutation
  run is precisely the case where early exits don't fire. Learned by
  producing a real spurious commit (`f11da9c4`, reverted) mid-session. Any
  future test/guard that shells out to `build_testflight.sh`,
  `build_playstore.sh`, or `publish_playstore.sh` needs
  `--no-bump --no-commit --no-upload` plus a snapshot assertion, not just a
  scrubbed `PATH`.
