# The design decision that is still owed (the actual next task)

**DEF231's own row specified the right design and I built something more
general.** The row says the fix is buildable *because* "the referenced level is
already a structured number the verdict carries… so a comparison is available
without parsing free text". I built a general prose parser that extracts ANY
`$` figure after a directional verb. That extra generality is 100% of the
defect surface:

- `$52.30` in "we'd pay $52.30" — not a structured level → r1 MAJOR impossible.
- second-level attribution — can't reach a level the run doesn't hold → r2 impossible.
- `$1.00` from a truncated `$1,073.46` — not a level on any run → DEF234 impossible.

**Narrow design (to build):** stage 1 deterministic — the run's own levels
(`support`, `breakout`, `last_close`, 52w `low`/`high`, and `entry`/`stop`/
`target` on an APPROVE, all in scope at the call site
`room_runner.py` ~line 2916). Stage 2 — does the reason name one of them, and
in which direction. Stage 3 deterministic — compare to `last_close`, annotate.

**Measured cost: ~26% coverage.** Of 121 corpus extractions, 90 (74%) are
precise to the cent (quoted off the fact sheet → will match a structured
level); 31 are round numbers the PM invented (`$100`, `$130`, `$400`).

# The regex-vs-LLM bake-off — RESULT, do not re-run

Saiful asked why not use an LLM for stage 2. Measured it against our own vLLM
(`ami-llm` at `http://192.168.20.74:8000/v1/chat/completions`, temp 0,
constrained closed-set prompt, script at
`<scratchpad>/bakeoff.py`):

- **Part A (10 constructed cases incl. all findings): regex 10/10, LLM 8/10.**
  The two the LLM failed are **the two audit MAJORs** — it answered
  `$52.30 / up` on both.
- **Part B (40 real verdicts): agree 14/40, disagree 26.** The LLM fires where
  the regex is silent and mostly fabricates: picks `$199.05 / up` from a
  sentence with no instruction at all; `$51.68 / down` for "trading below the
  $58.43 breakout" (wrong level AND wrong direction).
- **One genuine LLM win:** *"WAIT for a daily close above $548.2"* — a real
  wait-for instruction the verb set misses (`close above` is not a verb).

**Conclusion: better recall, far worse precision → disqualifying at runtime on
a precision-biased check. Use the LLM OFFLINE as a discovery tool** to find the
verb shapes the regex misses, then encode them deterministically. That is todo
item 7.
