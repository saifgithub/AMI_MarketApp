**DEF281 — found, root-caused, fixed, tested, mutation-verified. NOT YET
COMMITTED.**

- **Root cause, confirmed directly against Alpha's Postgres**: the weekly
  field `starts_on 2026-08-10` had `state = 'entry_open'` — **3 days after
  its own `locks_at`** — with **4 active entries** and `ends_on = 2026-08-14`.
  `ensure_field` only refreshes the state of the field it is currently
  TARGETING (mid-period that's next week's row); nothing else advances a
  calendar field's `state` column. This is a documented, known property
  (`ensure_field`'s own docstring warns about it) that a SIBLING fix
  (`games_desks.fields_in_lock_window`) already worked around — and the
  workaround was never applied to the two places that actually needed it.
- **Two consequences, one cause:**
  1. **What Saiful saw**: `games_arc.phase_for` derived the beat from the
     stale `state` column, so a run 3 days into its week rendered the ENTRY
     COUNTDOWN.
  2. **What Saiful did NOT see, and is the more serious one**: `run_scoring_
     pass` selects candidates `WHERE state == 'live' AND ends_on < today`.
     That field is `entry_open`, not `live` — so it would NEVER be selected,
     on 08-15 or ever after. **4 runs on live Alpha would never score, never
     close, silently** — no error, no log.
- **Fix** (uncommitted, in the working tree right now):
  - `backend/app/services/games_scoring_pass.py` — both the candidate query
    (`due_live_ids`) and `_close_field`'s guard now key off
    `ends_on < today AND state NOT IN (closed, archived, abandoned,
    settling)` instead of `state == 'live'`. `abandoned` stays excluded
    (§12 — a lobby that never filled has no result); `closed`/`archived`
    stay excluded (no re-scoring a shown result).
  - `backend/app/services/games_arc.py` — `phase_for()` gained optional
    `now`/`locks_at`/`starts_on` kwargs; when given, the PRE-CLOSE beats
    (`entry_open`/`bell`/`live`/`final_stretch`) are derived from the clock,
    and the column stays authoritative ONLY for the terminal beats the
    scoring pass actually writes (`settling`/`closed`/`archived`/
    `abandoned`). Falls back to the old column-only logic if the timestamps
    aren't passed (so any other caller degrades rather than breaks).
  - `backend/app/services/games_service.py` — `list_live_runs`'s call site
    updated to pass the new kwargs.
  - New test file
    `backend/tests/unit/test_def281_stale_field_state_still_closes.py` — 8
    tests. Two are the exact live reproduction (field stuck at
    `entry_open`/`locked` still closes); one guards `abandoned` stays
    excluded; one guards a closed field isn't re-scored; one guards a field
    whose period genuinely hasn't ended is left alone (the widening must not
    over-reach); the last three are `phase_for`'s clock-vs-column boundary
    (Saiful's exact case; a genuinely-open window still reads open;
    locked-but-not-started reads as the bell).
  - **Mutation-verified**: reverted the query back to `state == "live"`,
    confirmed 2 tests go red, restored, confirmed green again.
