## What was decided this session

- **Framework governing principle** (still correct per the review): mean
  returns are not estimable at any retail horizon; only second-moment metrics
  ship (volatility, beta+R², DR², risk contribution, weight concentration).
  Sharpe/Sortino/Treynor/alpha/information-ratio permanently excluded.
- **Product architecture**: CR136 = deterministic metrics engine only. CR137
  (reserved by number, **no row file, no doc — not filed**) = future
  multi-agent "Portfolio Room" where agents narrate/debate but never compute.
  Saiful, verbatim: *"Full portfolio scoped room, phase B. We go all in. This
  is an agentic app. But all math must be deterministic."*
- **Uncertainty contract**: `sufficient: false` ⇒ `value` AND `standard_error`
  both `null` (never `0.0`) — structural, not prompt-based, enforcement that
  an insufficient metric cannot reach the LLM narration layer at all.
- **History**: backfill AND persist going forward, not either/or (daily
  snapshot job is needed regardless of backfill).
- **The Finding** (user-facing report): 5 sections (F1 Headlines … F5
  Recommendations) under a hostile-reader standard — Saiful, verbatim: *"the
  next person to read the report will be the user and their human portfolio
  manager. They will be extremely critical, to the point of being rude."* This
  is exactly what `EXTERNAL_PM_REVIEW.md` is — Saiful asked for the review the
  methodology doc itself said it was written to invite, and it found real
  blockers. The instrument worked as designed.
- **Screen designs**: signature visual = solid bar (risk share) + outlined bar
  (money share), same scale/origin. Card accent `hexBlue` not `hexAmber`
  (amber already means mandate-violation app-wide). Insufficient-data state =
  neutral slate (an absence, not a warning); mock-data refusal = amber (system
  unavailable) — I drew refusal red first and self-corrected per
  `sharia_verdict_banner.dart:9-23`'s actual semantics.
  **Per F9, this bar chart itself has a defect**: "substantially a cash
  artefact" — not yet fixed in `SCREEN_DESIGNS.md`.
