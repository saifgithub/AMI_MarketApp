### CR171-BE — the halal ruling, DECIDED by Saiful this session

**This overrides what `CR171_short_selling.md` §6 currently says.** The CR doc
(`docs/forward_planning/CR171_short_selling/CR171_short_selling.md:271-274`)
proposes *"A halal mandate must refuse sell-to-open outright, independent of
`long_only`"* and explicitly escalates the ruling. **Saiful's ruling,
verbatim from this savepoint's own arguments:** *"for CR171-BE, halal ruling.
Our job is only to inform. The user can continue with whatever trade they
want to do. So we will put a flag and notice to inform the user, but we let
the trade through."*

Concretely, when building CR171-BE:
- **Do NOT add a hard refusal** for sell-to-open under a halal mandate. The
  CR doc's proposed §6 halal refusal is SUPERSEDED — the doc itself needs a
  correction note recording this, not a silent contradiction.
- **DO add a flag + notice.** A halal-mandate user attempting a sell-to-open
  sees an informational disclosure (short selling / borrow is widely held
  impermissible — cite the same posture as the existing sourced Sharia
  classification work, CR069) and the trade PROCEEDS if they continue.
- This is a narrower carve-out than `long_only`, which DOES still hard-refuse
  per §6's other bullet (`safety_floor.py:273-278`'s bare `pass` → real
  refusal — that part of §6 is UNCHANGED and still correct, closes DEF262).
  Only the HALAL leg becomes inform-not-block.
- Exact placement TBD when building: likely a `ComplianceResult`-shaped
  advisory that doesn't set `blocked_by`, surfaced in the trade ticket as a
  dismissible notice rather than a refusal banner. Design this against how
  the existing Sharia disclosure pattern already renders elsewhere in the app
  (halal-flag chips, classification verdicts) — check `sharia_universe.py`
  and `ShariaVerdict` schema for the existing informational shape before
  inventing a new one.
