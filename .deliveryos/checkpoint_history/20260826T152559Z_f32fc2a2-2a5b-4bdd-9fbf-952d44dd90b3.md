## What was decided this session (in order, with reasoning)

1. **Fixed run 2's OOM** (was dying non-deterministically at step 185 then 375 on cutoff_len=5120)
   by dropping cutoff to 4096 + dropping the ~32 rows (0.16%) that needed more — root cause was
   peak-memory set by the single longest sequence in a batch_size=1 run, not a gradual leak.
   Committed. Also fixed a *second* bug found via this: the length-filter itself was a silent
   no-op (`len(BatchEncoding)` = key count, not token count) — fixed, committed.

2. **Found decontamination failure**: 37% of the 456-prompt eval set (S4/S7/S8, 167 prompts) was
   verbatim training data — the eval-prompt generators for those 3 surfaces hardcoded
   `load_train_universe()` instead of `eval_tickers.txt`. This is why the original "0%→93%
   refusal breakthrough" was fake — real number is 45%→50% (CIs overlap, no real gain). Fixed,
   rebuilt those 3 surfaces on held-out tickers, added `_assert_held_out()` guard that fails the
   build on any future verbatim overlap. Logged as **P28** in
   `docs/initial_specs/08_tech/failure_patterns.md`.

3. **Found a 2nd scoring bug**: `stage_score` joined prompts↔completions on `(surface, ticker)`
   which isn't unique (S7 has 4 cases/ticker, S8 uses ticker="-" for all 60) — 116/468 prompts
   scored against the WRONG completion. Fixed by joining on `pid` (sha1 of prompt text), added to
   both `run_local_surfaces.py` and `eval_surfaces.py`. Committed.

4. **Found a 3rd bug**: N/A (inapplicable check, e.g. S8's `gave_code` when `lesson_code=None`)
   was being read as a literal 0, so `compare_arms.py` reported "S8 gave_code: 0% — NO GAIN" when
   the check never ran on a single row. Also inverted `rr_correct`: true reading is vanilla 44%
   (8/18, applicable rows only) vs tuned 34% (23/68) — tuned is actually WORSE at R:R arithmetic,
   not better as first (wrongly) reported. Fixed `compare_arms.py::rate()` to exclude `_NA` rows
   from the denominator and render NOT MEASURED when either arm's denominator is 0. Committed,
   logged in failure_patterns.md.

5. **Built the constrained-decoding control arm** (`run_constrained.py`, new file) using
   `lm-format-enforcer` (pure Python, drives transformers' `prefix_allowed_tokens_fn` directly —
   NOT vLLM, which isn't installed on alpha-spark and has unproven nemotron_h support). Two API
   quirks fixed along the way: `TokenEnforcer.get_allowed_tokens()` returns a `TokenList` object
   that is neither `len()`-able nor iterable — the actual list is `.allowed_tokens` (valid only
   because tokenizer data was built with `use_bitmask=False`). JSON schema for S4 (PM verdict) and
   S6 (size ladder, enum built per-prompt from the mandate's own sizes); regex for S5 (Trader money
   block, not JSON — validated with `re.fullmatch` against a real tuned completion before trusting
   it).

6. **Found and fixed a schema-hang bug**: unbounded string fields (no `maxLength`) let the model
   write prose inside a JSON string field forever without ever closing it — 3/11 first-batch rows
   ran to a 2400-token cap mid-sentence. Raising the cap made it WORSE (2x cost per failure).
   Fix: `maxLength` on every free-text field (400 for narrative fields, 60 for short
   numeric-reference fields, 1200 for PM `narration`). This is now the single most important
   operational finding for CR210 and is written into `CR210.md` under "Bound every free-text
   field, or generation hangs" (commit `3885a9f0`) — **I initially told the user this was in the
   CR when it wasn't yet; caught and fixed same-turn.**

7. **Final numbers** (all n confirmed at full scale, not probes):
   - S6 one_per_size: vanilla 57% | vanilla+grammar **69/69 (100%)** | tuned **69/69 (100%)** — exact match
   - S4 parses: vanilla 100% | vanilla+grammar 59/60 (98%) | tuned 60/60 (100%)
   - S5 has_side/side_legal/has_stop/size_within_cap: vanilla 26% | vanilla+grammar **68/68 (100%)** | tuned **68/68 (100%)** — exact match, same 68 prompts both arms
   - Primary-objective checks: S1 l1_plus 43/44 both arms (HOLDS vs control, not vs a wrong
