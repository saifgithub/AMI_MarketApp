## DEF110 — everything you need, so RESTORE can start writing code

### What it is (one sentence)

`SimEngine.evaluate_outcomes` flips a stop/target-hit trade to `won`/`lost` and stamps
`realised_pnl`, but — unlike `manual_close` two functions below it — **never reduces the
holding or credits cash**, so closed positions stay on the user's books as phantom shares.

### The fix — exact code

**(a) Core.** `backend/app/services/sim_engine.py:805-835` `evaluate_outcomes`. Mirror
`manual_close` (`:837-859`), which does it correctly:

```python
p_row = self._load_portfolio_row(s, user_id)          # ← ONCE, outside the loop
...
    t.realised_pnl = round((price - float(t.entry_price)) * float(t.quantity), 2)
    if p_row is not None:                              # ← the missing three lines
        self._apply_sell_row(s, p_row, t.ticker, float(t.quantity), price)
```

`_apply_sell_row` (`:788-801`) reduces the holding and credits `current_cash += fill*qty`,
deleting the row when `remaining <= 1e-6`. Load `p_row` **once before the loop** — per-trade
loading inside the loop would be N queries and risks stale row state across iterations.

**Only `Side.BUY` is evaluated today** (`:820-824`) — a SELL/short has no branch. Do not
silently start liquidating shorts; keep the scope BUY-only unless deliberately widened.

**(b) Alpaca.** For Alpaca-linked users the close should propagate. `alpaca_service.py` is
**link/read-only today** — its whole public surface is `exchange_code`, `validate_api_key`,
`get_account`, `get_positions`, `snapshot_text`. There is **no** submit/close function, so
(b) needs a new `alpaca_service.close_position` and is a **separate sub-lane**. Saiful's
original ruling: *"it should be closed. we also have alpaca API that we should close it"*.

**(c) BACKFILL — the part the code fix does NOT solve.** The bad rows are already written.
Three accounts above need their phantom holdings removed **and cash credited at
`closed_price`** — the sell never credited proceeds, so cash is understated by exactly
`closed_price × qty` per phantom. `realised_pnl` was already stamped, so **do not
re-realise P&L**; only move shares and cash. Write it as a one-shot script, not by hand.
