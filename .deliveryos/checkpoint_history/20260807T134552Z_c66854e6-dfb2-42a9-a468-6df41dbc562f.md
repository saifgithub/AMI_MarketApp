# CR095 — audited, 3 MAJOR, NOT YET FIXED

Auditor (`88d3c979`) found it can genuinely double-send, twice, both proven
as real pytest cases:
1. **Same-day timezone change → second reminder.** Dedupe key is recomputed
   from the user's CURRENT timezone every tick with no memory of what
   timezone produced a prior `source_ref`. One Settings change reproduces it.
2. **Concurrent ticks → double-send.** `NotificationRow` has no unique
   constraint on `(user_id, type, source_ref)`. Two real threads both pass
   the check-then-write race.
3. `PUT /v1/daily_challenge/reminder` with only `{"timezone": ...}` (omitting
   `daily_reminder_hour`) silently zeroes the hour — Pydantic can't
   distinguish omitted from explicit null; only `timezone` has
   leave-unchanged handling.

3 auditor pins already added + registered in `MIGRATED_PINS`:
`test_cr095_timezone_change_double_send_pin.py`,

  report**, but had done correct, complete work. Always verify via `git
  status` + your own test run before concluding an agent failed.

  reasoning on the cohort-marker seam; a second pass ran the actual
  adversarial test and bounced it. **Auditors that attack beat auditors that
  agree** — worth specifically asking for adversarial verification in future

  verifications repeatedly didn't reach the surface they claimed to cover**

  citation, CR131's marker coupling, three separate `_code_only()` comment-
  matching self-failures). Treat "I mutation-tested it" as suggestive, not
  conclusive — an independent adversarial pass keeps finding real gaps.
