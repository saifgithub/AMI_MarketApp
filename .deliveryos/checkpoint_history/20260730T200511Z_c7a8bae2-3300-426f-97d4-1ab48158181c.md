## Active constraints / gotchas (carried + new this session)

**Prototype is GENERATED — never hand-edit `nav.html`.** Edit `template.html`, then
`python3 docs/forward_planning/CR133_bottom_nav_restructure/prototype/build.py` (python3, not
python — `python` is not on PATH here). Inlines subsetted Inter+JetBrains Mono as base64 woff2
(Artifact CSP blocks font CDNs), cached in `prototype/.fonts/` (gitignored via the generic
`docs/forward_planning/*/prototype/.fonts/` pattern from CR120's session).

**Nav icons are inline SVG, not glyphs.** Geometric codepoints (U+25xx) aren't in
`build.py`'s `UNICODES` subset and Inter doesn't carry them either — a glyph icon silently
vanishes. This bit the CR120 prototype (caret→full stop) and is why CR133's icons are hand-drawn
SVG paths mirroring the actual Material icons `home_shell.dart` passes to `HexNavItem`.

**Verify agent/colour facts against `models/agent.dart`, not memory.** First insights-card draft
invented a "Risk Manager" agent (doesn't exist) and gave 4 analysts 4 different colours — broke
"family colour is sacred" (cyan=Analyst, purple=Researcher/Manager, amber=Risk, green=
Execution/PM... wait PM is purple/Manager family, TRADE is green/Execution). Corrected against
the real `kAllAgents` list before shipping.

**CSS traps hit and fixed in `template.html` this session:**
- `.row .gr`/`.t1`/`.t2` needs `display:block` — inline spans swallowed the `<br>`-equivalent
  line break between title and subtitle.
- `.bar .fl` (progress-bar fill) needs `display:block` — an inline span ignores `height`, so
  fills silently collapsed to nothing.
- `.q` (query code blocks in the build reference) needs `white-space:pre-wrap` — authored
  newlines in template literals collapse to one run without it.
- Active-hex icon: icon `<svg>` needs `z-index:1` relative to the `::before` hex background at
  `z-index:0` — a negative z-index on the hex paints it behind `.navbar`'s own background,
  hiding it entirely.
- `glassChrome` (`rgba(15,23,42,0.85)`) tokenised as `--chrome` custom property, redefined in
  both light-media-query AND `:root[data-theme]` blocks — a bare selector like
  `:root[data-theme="light"] .hdr` doesn't compose with an `@media` block cleanly.

**Headless-Chrome verification recipe** (used all session):
```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --no-sandbox --hide-scrollbars --window-size=1240,<tall-enough> --screenshot=out.png \
  --virtual-time-budget=3000 "file:///…/nav.html"
```
Then crop with PIL to the region of interest — full-page screenshots need `--window-size` height
≥ the measured `document.documentElement.scrollHeight` (get that via a `--dump-dom` probe first
with a small marker script appended, since `requestAnimationFrame` measurement races
`--dump-dom`). Force a specific state (e.g. `state.seg="insights"`) by appending
`<script>state.seg="X";render();</script>` to a scratchpad copy, never to `template.html`.

**Registers are GENERATED (CR081).** Never hand-edit `cr_list.md`. Write
`docs/forward_planning/_registry/CR###.row.md`, then `python3 scripts/registers/gen_registers.py
gen cr`. Diff was exactly +1 line each of the 4 times I regenerated this session — verified clean
every time before committing. **Always pathspec-commit**: `git commit -m "…" -- <files>`.
