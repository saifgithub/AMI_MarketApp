| DEF364 | 2026-08-24 | claude | backend | **A game run whose only position is a short is scored on a mock price, because the NAV day is labelled `cash` instead of `mock`.** Found while wiring CR172 §11's option marks through the same function. `portfolio_nav_daily._price_source_for_snapshot(raw, holding_count=...)` overrides the price source to `cash` whenever `holding_count == 0`, and both call sites pass `holding_count=len(portfolio.holdings)` — **holdings only**. But `_marked_tickers` (sim_engine.py:553) has included `p.shorts` since CR171, so the aggregate source genuinely reflects the short's quote, and a short is genuinely mark-dependent: `Portfolio.total_value`'s short term moves with `marks.get(s.ticker, s.entry_price)`. So a book with zero holdings and one open short has a NAV that moves with a price, and that price is reported as no price at all. `games_scoring_pass.py:510-511` voids a run on `price_source == "mock"` and nothing else — so the run is **scored on a fabricated price** rather than voided. Proven, not argued: `_price_source_for_snapshot("mock_walk", holding_count=0)` returns `"cash"`, while `holding_count=1` returns `"mock"`. The `cash` override is itself correct and was itself a fix (an empty book needs no price, and labelling it `mock` VOIDed nearly every queue-first run) — the bug is that its guard condition counts one kind of priced position when three now exist. **Fix:** the override asks "did any price affect this NAV?", so it must count every priced position — holdings + shorts + options — derived from the same `_marked_tickers`-shaped set rather than a hand-listed one, so the next position type cannot inherit the same blindness.
