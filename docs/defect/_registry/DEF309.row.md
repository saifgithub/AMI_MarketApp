| DEF309 | 2026-08-15 | prompt | backend | **A resting order's refusal is hidden from the user precisely when it matters most — the recent-history window was keyed on the wrong column.** `SimEngine.list_resting_orders` includes terminal rows from the last 24h so a rejected or expired order "never silently vanishes overnight" — the games lane's own `list_queued_orders` docstring records the cost of the alternative as *"from the player's side the order simply VANISHED."* It measured that window with `(o.filled_at or o.placed_at) >= terminal_since`. **`filled_at` is set on exactly one of the four exits from the book.** Cancelled, expired and rejected orders have no `filled_at`, so the expression fell through to `placed_at` — *when the order was created*. A GTD-90 buy limit placed four days ago and refused at fill this morning was therefore filtered out of its own 24h window and never rendered at all. **The failure is worst on the case the window exists for.** The longer an order rests, the more mandate changes accumulate under it, so long-lived orders are exactly the ones that get refused at fill — and exactly the ones certain to be hidden. The user sees an order disappear with no explanation, and the compliance sentence naming the violation (`cancel_reason`) is written to a row nothing will ever display. Nothing errors and nothing logs. **Found by reading the CR170 journey end to end** at Saiful's request (*"how are we showing it to the user while the user waits for it to be fulfilled"*), not from a report — the window has **no test at all**: `grep -rn terminal_since backend/tests/` returned nothing, which is why three versions of this code shipped with the fallback in it. **Fix — a column, because there was nothing to derive from.** `sim_resting_orders` carried `placed_at`, `triggered_at`, `claimed_at`, `filled_at` and `last_checked_at` — no timestamp for *left the book*.
