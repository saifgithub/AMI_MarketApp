| DEF262 | 2026-08-11 | prompt | sim | **Turning `long_only` off in Settings unlocks nothing, and the app actively tells the user to do it.** `Compliance.long_only` (`schemas/mandate.py:119`, default `True`) is a **live user-facing switch** — `settings_screen.dart:513` renders it as a toggle row with an `onChanged` handler, so any user can flip it today. Flipping it changes three things and none of them is the one that matters. (1) **The safety floor's own check is a no-op.** `safety_floor.py:273-278`: `if c.long_only and proposed.is_sell:` followed by a bare `pass  # delegated to trade service`, with a comment claiming *"the actual short detection happens in the trade-validation service that calls this function with full portfolio context."* (2) **The trade service refuses the short unconditionally, and never reads the flag.** `_execute_fill`'s SELL branch (`sim_engine.py:789-797`, twinned at `:1127`) rejects any sell beyond the held quantity — *"cannot sell {quantity} {ticker}: not enough held"* — stamped `blocked_by="long_only"`, **the very flag the user just turned off**. `grep -rn "long_only" backend/app/services/sim_engine.py` shows the string appears only as that literal; the mandate field is never consulted on the fill path. (3) **The agents start discussing what the engine cannot execute.** `overlay_generator.py:139/394/409/442` branch on `m.compliance.long_only` to build the prompts, so with it off the Room can propose a short that is then refused at submit. The sharpest edge: `brief_engine.py:158-162` refuses a shorting proposal with *"Toggle long_only off in your Mandate first if you want to allow shorts."* — an explicit instruction to take an action that grants nothing. A user who follows it gets agent commentary about shorts, a Brief engine that stops objecting, and a trade ticket that still refuses, citing a constraint they have disabled. This is CR040 inverted: instead of a feature failing silently for want of config, a config promises a feature that was never built. **Not a decision to reverse silently** — shorting is **not** in `rejected_features_register.md` (only options/derivatives are, and that entry's rationale leans on *"Long-only mandate flag blocks most users at Alpha"*), so the flag reads as anticipated-but-unbuilt rather than declined. **Two possible fixes, and the choice is a product decision, not a bug call:** (a) build short selling — a substantial CR, because a short credits cash while creating an obligation (`current_cash` stops meaning "money not in positions", corrupting `total_value` / `total_drawdown_pct` / `portfolio_nav_daily` / TWR), drives `SimHoldingRow.quantity` negative (which `backend/scripts/def110_backfill.py::expected()` cannot survive — it subtracts Σ quantity over open SELL rows to detect phantom shares), and introduces unbounded loss with no margin or forced-buy-in model; or (b) make the flag honest — hide or lock the toggle, make `blocked_by` cite long-only-is-not-supported rather than the user's own setting, and drop the brief-engine suggestion. **Until one lands, (b)'s copy fix alone stops the app instructing users toward a dead end.** Found while scoping CR170 (resting orders), from Saiful's question *"can we do on sell as well? and can we 'charge' a fee for 'borrowing' a ticker?"*.
