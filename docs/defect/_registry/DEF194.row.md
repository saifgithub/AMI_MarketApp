| DEF194 | 2026-07-30 | audit | mobile | **A failed retro-tightening breach check is swallowed by a bare `catch (_)`, so "no warning" and "we could not check" look identical to the user.** CR101-MOBILE auditor m1, non-blocking and shipped in `0.1.0+61` as-is. After a successful mandate PATCH the screen calls `GET /v1/mandate/{id}/audit` to find out whether the tightened limit puts current holdings in breach, and shows a flag-and-block dialog if so. That call is wrapped in a bare `catch (_)` (`settings_screen.dart:126-132`), deliberately, so a failed audit read can never make a genuinely-succeeded save *look* failed — the right priority, and the reason this is a MINOR. **The residual gap:** absence of the dialog is how the user learns "nothing is in breach." If the audit read throws, they get the same silence and draw the same conclusion, having just tightened a limit specifically to find out whether it bites. That is the **CR040** question answered badly — *if this fires silently, what does the user end up believing?* They believe they are compliant, and the app never checked. **Why it is small:** the call is a local request immediately after a PATCH that just succeeded, so the failure window is narrow; the save itself is honestly confirmed; and breach flags still surface on the next audit read from the Portfolio screen, so the state is recoverable rather than lost. **Fix:** keep the swallow, add the disclosure — a quiet "couldn't check your holdings against the new limit — open Portfolio to verify" snackbar on the catch path. Explicitly NOT an error dialog: the save DID succeed and presenting it as a failure would be the opposite misrepresentation. This is the same shape as **DEF158** (a dialog whose text asserted something the mechanism did not do) and the same family as **DEF059** (a null rendered as a neutral, reassuring result). Deferred rather than fixed inline because the screen was mid-release and a copy-plus-branch change to an audited surface warrants its own verification pass, not a last-minute edit after the COMPLETE.
