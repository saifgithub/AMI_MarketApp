| DEF180 | 2026-07-30 | prompt | security | **Magic-link verify is an unthrottled, cross-user 6-digit-code oracle; `/start` is an open email relay (security review H5 + M5).** `/v1/auth/magic_link/verify` has NO rate limiter — only `/start` is limited (3/min/IP, `auth.py:125-128`, verified). `verify_magic_link` looks up the active challenge by email only (`auth_service.py:373-380`), not bound to a caller. There is a 5-attempt-per-challenge cap (`MAX_MAGIC_LINK_ATTEMPTS`, `:55`), but an attacker loops `/start` (each mints a fresh challenge, attempts=0) then fires 5 guesses per challenge: ≈21,600 guesses/day/IP against a targeted account, and each wrong burst force-consumes the victim's legitimate challenge → continuous login-DoS. Adjacent: `/start` is an unauthenticated email relay — attacker-triggered AMI-branded mail to any address, a deliverability/reputation risk that could take down all logins. Fix: rate-limit `/verify` per-IP AND per-target-email; bind verification to the challenge's `user_id`; throttle `/start` per-email (not just per-IP). Also consider HMAC (not unsalted SHA-256) for the stored code (`auth_service.py:144-145`, Low/Info item). Under CR123. | open | — | AT:SEC1 |
