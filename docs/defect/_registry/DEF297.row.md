| DEF297 | 2026-08-14 | ux | mobile | **The Floor's omnibox raises the keyboard and gives the user no way to put it back down.** Reported by Saiful from `0.1.0+90`: *"the new 'floor' screen will bring up the keyboard when focus is on the ticker entry edit control, but there was no way to get rid of the keyboard because there is no other place the user can focus on."* `widgets/floor/floor_omnibox.dart:112`'s `TextField` sets no `onTapOutside`, and Flutter's default `EditableText._defaultOnTapOutside` **does nothing on iOS/Android** — it unfocuses on desktop platforms only. The Floor's scroll view sets no `keyboardDismissBehavior` either, so dragging does not dismiss it. That leaves exactly one exit: `textInputAction: TextInputAction.go` → `onSubmitted` → `_go()`, which always *navigates somewhere* (convene, Concierge, or the picker, per `routeOmnibox`). So the only way to lower the keyboard is to leave the screen — the user cannot simply stop typing and look at the Floor they were reading. Worse on the empty box, which is CR173 §5's deliberate "tap-first" state: an empty field routes to `picker`, so a user who focused the box by accident and wants out gets the ticker picker modal instead. **This is the second time the Floor's one-box redesign has traded a shipped affordance for a simpler surface** (see DEF298, same screen, same commit `3aa81c71`) — the omnibox replaced two controls that each had their own dismissal path with one that has none. Fix is `onTapOutside` on the field plus `ScrollViewKeyboardDismissBehavior.onDrag` on the Floor's scroll view, so both the tap and the natural mobile drag work. Found on device, not in the widget harness — the harness has no soft keyboard, so no existing test could have caught it, and the fix therefore needs a test that asserts the *focus* is dropped rather than that a keyboard disappeared. | open | — | AT:R69 |
