| DEF273 | 2026-08-12 | prompt | games | **The game's order queue accepted orders the run could never pay for, and only said so hours later by cancelling them.** `games_service.submit_trade`'s out-of-hours branch wrote a `GameQueuedOrderRow` with **no affordability check of any kind** — it stored whatever it was handed. A player could commit several times their book overnight; the FIFO drain then filled what fit and cancelled the rest with `rejected at fill time`, at the next open, on a screen nobody was looking at. Saiful had already hit the shape of this on build 78 (*"I have 10,003.29 committed to 8 queued orders, 0.00 available"*), and the fixes it produced — `cash_available` on the ticket, and the drain's explicit FIFO `ORDER BY` — each addressed a different half: the ticket stopped *offering* the whole stake twice, and the drain stopped letting undefined row order decide which orders survived. **Neither told the player at the moment they placed the order**, which is the only moment they could act on it. **Fix:** `_refuse_overcommitted_queue` runs before the row is written, prices the order at read time, and refuses when `estimate > current_cash − already_committed`, naming BOTH numbers plus what is already committed. The estimate includes the fee, because quoting the bare notional understates what the order needs — that is how a player retries at a size that is still one fee too big. **Two exemptions, each a worse defect if got wrong.** A **SELL** is never refused: it returns cash and is precisely the order a player most needs from an empty balance — the one-way book DEF259 had to fix. A **COVER** is never refused either (a buy on a name with a standing short), because Amendment G ruling 5 makes it structural: the cash to buy back was posted at open, and a cover blocked for want of cash traps a player in the one position whose loss is unbounded. The cover case is decided from the same standing-short fact the fill path uses, so the two cannot disagree about what the order is. **The market-hours fence is not breached:** that fence exists so an order never FILLS at a stale price, and this is an estimate used to REFUSE, never to fill — nothing is stored, and the fill still happens at the next open's price. Because an estimate can be wrong by a weekend's drift, the drain keeps its own check; this makes the common case honest, it does not replace the authority at fill time. **With no usable price (`price <= 0`) the check stands down and logs** rather than guessing — a refusal built on a fabricated number is the CR040 class, and it is the same "no usable price" condition `quote_trade` already refuses on. **Verification:** `backend/tests/unit/test_def273_queue_overcommitment.py`, 8 tests incl. the two-orders-each-affordable-alone sequence that is Saiful's actual case, an assertion that the refusal names both numbers *with the fee included*, and the sell/cover exemptions. Mutation-checked: removing the sell/cover exemption turns the sell test red.
