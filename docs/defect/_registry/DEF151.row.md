| DEF151 | 2026-07-29 | bug:589e7607 | mobile | **The ticker chart is dark for every ticker on every period — the client sends uppercase period tokens to a server that accepts only lowercase, and 100% of requests 422.** Reported by Platinum Anchor on `0.1.0+57` as half of a two-part report: *"why are we missing the chart?"* over a screenshot reading `Chart unavailable. Tap to retry.` **Root cause, exact.** [`ticker_chart.dart:29`](../../../mobile/lib/widgets/ticker_chart.dart#L29) declares `const List<String> _kPeriods = ['1D', '1W', '1M', '3M', '1Y', '5Y']` and passes the selected label verbatim through `tickerHistoryProvider` → `api.simHistory(ticker, period)` → `GET /v1/sim/history/{ticker}?period=1M`. The backend answers `{"detail":"invalid period; must be one of 1d,1w,1m,3m,1y,5y"}` — **lowercase only**. **Measured against live Alpha, not inferred:** all 6 periods × 3 tickers (TDG, NVDA, AAPL) = **18/18 HTTP 422**. Omit the parameter entirely and the same endpoint returns a full candle series (`"period":"1m","source":"yfinance"`, real OHLCV) — so market data, yfinance, the cache and the serialiser are all healthy. **The only fault is letter case, and it takes out the entire feature.** **Why nobody caught it, which is the more important half.** The failure degrades to `Chart unavailable. Tap to retry.` — copy that describes a *transient* fault. A user reads it as a network blip and taps retry, which re-issues the identical malformed request and fails identically, forever. There is no state in which that button can succeed. So the feature has been 100% dark on Alpha with **zero bug reports** until Saiful happened to ask why the chart was missing — a silent total outage wearing the costume of a flaky network, which is precisely the question CR040 tells us to ask (*if this fires constantly and silently, what does the user end up believing?*) and the answer here is: that their connection is bad. **Fix shape:** normalise the case (client-side `.toLowerCase()` at the call site is the one-line version; normalising server-side additionally repairs the **already-shipped `+56`/`+57` builds in testers' hands without an app update**, which is worth weighing since TestFlight users cannot be fixed by a client-only change until the next build). **The guard is the part that matters** and must ship with it: a test asserting every entry in `_kPeriods` is accepted by the server's allow-list, so the two lists cannot drift again — this is a contract between two files in two languages with nothing tying them together, which is `failure_patterns.md`'s recurring shape. A second, cheaper guard worth considering: make the retry surface distinguish "request rejected" (4xx — never retryable) from "network failed" (retryable), so a permanently-broken call can never again present as a transient one. **RULED (Saiful, 2026-07-29 0900 check-in): "File it and lane it"** — offered a fix-in-session given the one-line diff and the total outage; he chose standard track-R handling.
