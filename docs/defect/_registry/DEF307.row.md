| DEF307 | 2026-08-15 | ux | mobile | **Every large CTA in the app announces its label twice to a screen reader — third occurrence of the DEF249 pattern, and this time in the shared widget rather than one call site.** `HexButton` wrapped its subtree in `Semantics(label: label, …)` while its child is a `Text` rendering that same string. Semantics merges a node's own label with its merged descendants', so the node carries the label twice. Measured on the Android rig device (`R5CY91AY99Y`) with the app on Floor, the Convene CTA's `content-desc` came back as `'CONVENE THE ROOM\nCONVENE THE ROOM'`. **The a11y cost is the defect** — VoiceOver and TalkBack read the button out in full, twice, and `HexButton` is the one widget every large call-to-action in the app goes through, so this was every CTA, not one screen. **The second cost is what made it expensive to find:** an exact-text locator can never match a doubled label, so three Appium tests (`test_floor_renders_convene_cta`, `test_convene_sheet_navbar`, `test_convene_sheet_scroll_overflow`) failed as though the button were absent from the screen, and a debugging session went into *"why is CONVENE THE ROOM not rendering"* when it was rendering correctly and had been all along. **Same pattern as DEF249** (the bottom nav produced `"FLOOR\nFLOOR"`, the Concierge chips the same), **same resolution**: drop the redundant `label:` and let the visible `Text` supply it — the `button:`/`enabled:` flags stay, since assistive tech and iOS automation both key off them. **Third occurrence, so it gets a guard at the widget rather than the call site**, per `failure_patterns.md`'s second-occurrence rule: `mobile/test/widgets/hex_button_semantics_test.dart`, 5 cases — label announced exactly once, button+enabled flags survive the change, a disabled CTA stays readable rather than disappearing, the wrapper does not swallow the tap, and the visible `Text` renders once. **Mutation-verified**: reintroducing `label: label` fails the guard with the diagnostic naming the count. **The general rule, now three times proven: never set `Semantics(label:)` over a subtree that already renders the string.** Invisible on Android to a tap test and invisible in code review — only a label assertion catches it.
