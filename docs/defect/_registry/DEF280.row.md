The first postflight run reported `POSTFLIGHT PASSED`, all five checks green. The second run, minutes later against an unchanged deploy, reported `[x] tree FAILED — 3 path(s) differ between this worktree and melehost:~/ami_trade/ — the box is not running what this worktree holds`, naming `backend/app/`, `backend/app/core/` and `backend/tests/unit/`. **All three entries are `.d..t....`** in rsync's itemize format: `d` = directory, `t` = timestamp differs, and every content flag is empty. Re-running the same rsync `--dry-run --itemize-changes` and filtering directory entries (`grep -v '^\.d'`) returns **nothing at all** — zero files differ. **Cause:** the api-alpha container writes `__pycache__` into the source tree it bind-mounts, `__pycache__` is (correctly) rsync-excluded, so the *containing directory's* mtime diverges the moment the new container starts executing Python. The check is therefore guaranteed to start failing a minute or two after every successful promotion, permanently, on a deploy that is byte-identical. That also explains the run-to-run flip: run 1 beat the container to it; run 2 did not. **Why this is worth a defect rather than a shrug:** it is the exact failure CR175 was written to eliminate, reproduced by CR175's own code. The script's docstring argues that a check ending in operator judgement is a check nobody performs, and its exit codes are split three ways specifically so *"the promotion is broken"* and *"I could not tell"* never look the same. A `tree FAILED` that means "a directory mtime moved" teaches the operator that FAILED does not mean stop — the same habit the hold gate, the audit gate (DEF277) and step 7's `/v1/llm/status` 403 each had to be repaired for. It is also self-defeating in the one case it exists for: a real partial rsync would now arrive inside noise the operator has been trained to skip. **Fix:** the tree check must compare CONTENT, not directory metadata. Either pass `--no-times` semantics for directories, filter itemized lines matching `^\.d` before counting, or compare with `--omit-dir-times`.
