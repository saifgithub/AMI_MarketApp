| DEF135 | 2026-07-28 | process | orchestration | **A background audit watcher can exit without a verdict, a timeout, or a trace, and nothing downstream can tell "nothing is waiting" from "nobody is looking" — so the audit queue silently stops being served while every board reads healthy.** Observed on 2026-07-28 and established by the auditor from their own run-76 report and the reflog, while auditing DEF131: their background `watcher.sh` process **died at 00:11** during a process teardown. Its output file stops at the startup line — **no lane, no exit-3 timeout, no error, no non-zero status anyone saw**. Two lanes (`DEF120` round 4 at 02:07, `CR098-MOBILE-LIVE` round 1 at 02:11) then sat unaudited until **09:52**, when the auditor happened to read `git log` by hand and found them. This is the true cause of that stall: DEF131 originally recorded the delay as a consequence of unpushed commits, but the auditor began work four minutes *before* the backlog push and from the same checkout, so the delivery gap DEF131 fixes was not what held the queue — **this was**, and it remains unguarded. `watcher.sh state` reported both lanes correctly the entire time; nothing was polling it. The failure is the **silent-fallback** class this project degrades loudly against (CR040): a dead watcher and an empty queue are byte-identical from the outside, so the auditor's checkpoint memo recorded "queue is EMPTY" — true at 00:11, wrong by 02:07 — and every subsequent report inherited it. It is also the orchestration-layer twin of DEF038/DEF063: a capability that appears configured, is dark in practice, and shows nothing to say so. Aggravating: the watcher's own `-t N` timeout path was designed for exactly this concern (exit 3 rather than block forever) but only fires while the process is *alive*, so it cannot cover the case where the process is gone; and the architect-side inbox gate (CR099) polls local files, so it too reads green. Fix shape: give the watcher a **liveness stamp with an age** — a heartbeat file it rewrites each poll — and make the queue-check treat a stamp older than a small multiple of the poll interval as a **loud** state distinct from an empty queue, so "nobody is looking" is reportable rather than invisible; pin it with a check that kills a watcher mid-run and asserts the board says so, because the whole point is that a dead watcher currently produces no signal to assert on. Do **not** fix it by making the watcher more robust alone — that reduces the frequency without restoring the signal, and this project's rule is that anything gated on a process being alive must fail visibly, never silently. Note the sibling constraint from **DEF132**: `watcher.sh state` currently exits **1** on a successful read, so any liveness check that gates on its exit code inherits an inverted signal and must be built after (or alongside) that fix.
