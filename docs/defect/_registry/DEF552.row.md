| DEF552 | 2026-11-26 | device lab AMI-DL-34 (Android) / build 137, deploy #36 (AT:B1) | backend + mobile / Portfolio history (both books) | **The HISTORY tab marks a position that was bought and sold in full as OPEN, and its header reads "0 CLOSED, WON 0, LOST 0".** Android, lab account, Bursa book: two 6888.KL round trips (buy 100, sell 100 from the position), positions 0, history 6 rows, every badge OPEN. **Root cause:** not Bursa-specific. Since CR188 a sell order is the only manual exit, and the BUY row it consumes keeps `status='open'` by design (DEF316: writing `closed` would double-subtract the exit) while the SELL row is `open` forever (DEF319). History (`_HistoryTab`) badges and counts from `status`/`realised_pnl` on the row (`settled = !isOpen`), so a hand-closed buy could never be settled. Alpha rows for the lab round trip: buy 100 @ 1.58 `open`/pnl 0, sell 100 @ 1.58 `open`/pnl 0; the US training book has the same shape (253 buy rows `open` against 86 sell rows, only bracket/self-closed buys ever `won`/`lost`/`closed`). The Journal paired the close correctly because it reads the FIFO lot walk (`sell_close_effect`), not the row. **Fix:** `GET /v1/sim/trades` adds an additive `lot_close` object (closed_at, closed_price = qty-weighted exit, realised_pnl NET of fees per DEF542, fees) to exactly those buy rows whose every share a sell has taken, from the same FIFO walk as the lot cards and the Journal (`cost_basis_lots.hand_closed_lots`; reads each ticker's whole ledger, so pagination cannot hide an earlier buy). The ledger's stored `status`/`realised_pnl` are untouched. Mobile `SimTrade.fromJson` folds `lot_close` into a `closed` trade at the net P&L, so badge, WON/LOST and net all follow. A still-held buy and every other row keep their exact shape; the US book gets the same correction for its hand-closed round trips (it had the same defect).
