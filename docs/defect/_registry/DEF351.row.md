| DEF351 | 2026-08-21 | claude | mobile | **CR122's new `google_mobile_ads` dependency broke every iOS release build — and the whole test suite stayed green through it.** Adding `google_mobile_ads: ^9.1.0` (CR122 MOBILE-C, commit fb3c0523) made `flutter build ios --release` fail at compile: `Include of non-modular header inside framework module 'google_mobile_ads.FLTAd_Internal'` (and `…FLTAdPreloader`), because the plugin's own headers `#import` `GoogleMobileAds_Beta.h` out of the vendored framework's `PrivateHeaders`, which Clang refuses inside a framework module. **The class, not the incident:** `flutter test` compiles no native iOS, so 1,354 green Dart tests and a clean `flutter analyze` said nothing about whether the app could still be built — a new native dependency is invisible to every gate we run until someone asks for an IPA, which is the release path itself. Found the hard way: the TestFlight build for 0.1.0+99 failed after a 509s Xcode compile. Fix: `CLANG_ALLOW_NON_MODULAR_INCLUDES_IN_FRAMEWORK_MODULES = YES` in `mobile/ios/Podfile`'s `post_install`, scoped to the Pods project (not the app target), with the vendor-header reasoning recorded inline — this is the vendor's layout, not ours to correct upstream. **Guard gap left open deliberately, and named:** nothing in CI compiles an iOS release, so the next native dependency will land the same way; closing it means a build job, which is CR162/CR163's neighbourhood, not a one-line test. Recorded here so the next occurrence is a second instance with a known cause rather than a fresh mystery. | fixed | `mobile/ios/Podfile` | AT:R73 |
