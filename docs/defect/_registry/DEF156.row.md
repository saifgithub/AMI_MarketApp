| DEF156 | 2026-07-29 | prompt | mobile | **A plan upgrade could never clear the journal retention caveat — `copyWith(retentionDays: x ?? this.x)` reads `null` as "unchanged", not as "unlimited".** Found by the **CR120** builder while wiring the plan-aware Journal pointer, disclosed rather than silently fixed, and confirmed by the track-K auditor as out of that lane's scope (`CR120.auditor.md` OUT-OF-SCOPE). Pre-existing, not introduced by CR120. **Mechanism:** `JournalState.copyWith` in [`journal_providers.dart`](../../mobile/lib/state/journal_providers.dart) coalesced every field with `?? this.field`, which is correct for every other field on the class and wrong for exactly this one — `retentionDays` is a **nullable value with meaning in both branches**: a finite `int` is a Floor Pass cap, `null` is *unlimited*. So `refresh()` receiving `retentionDays: null` from the server left a stale finite cap in place. **Live path, not theoretical:** a Floor Pass user who upgrades in-session via RevenueCat gets an unlimited plan, `refresh()` returns `null`, and the app keeps the finite cap until the process is restarted — so the **retention warning stays on screen telling a paying user their journal is capped**, and CR120's Portfolio Journal pointer keeps computing an "older entries" count against a cap that no longer applies. Both surfaces are the ones the upgrade was supposed to change, which is the worst place for the state to be stale. **Same family as DEF155** (the string CR120 fixed, which claimed a data loss that does not happen): both make a paying user believe their journal is more restricted than it is, one by copy and one by state. **Fix:** an explicit `clearRetentionDays` flag, matching the class's own `clearError` / `clearFilter` idiom rather than introducing a sentinel object — `retentionDays: clearRetentionDays ? null : (retentionDays ?? this.retentionDays)`, with `refresh()` passing `clearRetentionDays: resp.retentionDays == null`. **Guard:** four tests, including one that deliberately **documents the trap it replaces** — `copyWith(retentionDays: null)` alone still means "unchanged", because `?? this.x` remains the right default for the rest of the class, so a future edit that drops the flag lands straight back on this behaviour and the test says so by name. **Mutation measured:** removing the flag from `refresh()` and reverting `copyWith` turns the suite **2 RED of 4**.
