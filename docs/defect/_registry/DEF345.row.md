The sweep runs as `docker compose exec`, so the recreate killed it with **no traceback, no non-zero exit, and no final line** — the log simply stopped after a normal `→ completed action=PASS`. **No per-record filter could ever catch this**, and that is the whole difficulty: every one of the 17 records is individually valid and correct. The batch is wrong only in what is *absent*, and absence has no record. A watchdog grepping the log for error signatures (which is what was armed) reports silence for a dead sweep and silence for a healthy one between runs — the two are indistinguishable by construction. Detection came from arithmetic, not instrumentation: 17 runs over 4 h 08 m is 877 s each against convene durations of 160–310 s measured from `room_runs.started_at/finished_at`, so ~10 min per run was unaccounted; the gap query then showed inter-run gaps of a healthy 16–34 s and a single 2.5-hour hole at the end. **This is DEF336's class recurring by a different mechanism.** DEF336 was a dead *provider* producing records shaped like data; this is a dead *process* producing a record set shaped like a batch. Both defeat every downstream consumer for the same reason — the failure removes or degrades output without malforming any of it — and `failure_patterns` already carries the general form: a fail-safe (or a failure) is only safe if its result is distinguishable downstream. **Fix: a completion sentinel, written on the line after the sweep loop ends.** `write_completion_sentinel()` in `backtest_sweep.py` writes `complete_<batch-id>.json` carrying `planned_pairs`, `completed`, `failed`, `outage_failsafes` and `finished_at`. A process that died before reaching that line cannot have written it, so **absence is the signal and cannot be forged by the failure mode itself** — which is exactly what a prompt-level or convention-level check could not give. `backtest_report.py` refuses any batch with no sentinel (exit 5, message names `--allow-partial` as the deliberate override) and the refusal fires **before `init_schema()`**, pinned by test, so it cannot be starved by a slow or unavailable DB.
