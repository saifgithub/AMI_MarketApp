| DEF296 | 2026-08-14 | logic | infra | **The games easter egg's stated containment is disabled by the very flag every alpha build passes.** `scripts/build_testflight.sh:261` prints a banner asserting AMI_GAMES is safe in a store binary *"because a test_… RevenueCat key forces `--internal-only`, and TestFlight INTERNAL groups skip Beta App Review."* That forcing lives at `:150`, guarded by `if [[ "$DO_BILLING" -eq 1 && "$REVENUECAT_IOS_SDK_KEY" == test_* ]]`. `--no-billing` sets `DO_BILLING=0` **and** blanks the key at `:249` (DEF290, correctly — a `test_` key must not be compiled into a shipped binary). So on `--no-billing` the gate short-circuits on its first condition, `--internal-only` is never demanded, and the banner's entire stated basis is absent while the banner still prints. `--no-billing` is not an exotic path: the RevenueCat keys in `infra/alpha.env` are both `test_…` and DEF282 removed the purchase SDK from the app's code path entirely, so it is the **only** honest flag for every build we can currently produce — `0.1.0+90` (2026-08-14, TestFlight + Play internal) shipped exactly this way. **The deeper half:** `--internal-only` is a pure affirmation flag. `grep -n DO_INTERNAL_ONLY scripts/build_testflight.sh` returns its default, its parse, and one read at `:157` — it changes no dart-define, no export plist, and no upload destination. So even when it *is* demanded it contains nothing; the actual containment is a human not adding the build to an external TestFlight group. The script's own DEF290/DEF277 comments name this failure class precisely — *"The banner said 'do not'; a banner is not a control (CR040)"* and *"a gate whose stated reason is untrue is how an operator learns that firing does not mean stop"* — and `--no-games` was added to close it, yet the default remains `DO_GAMES=1` with a conditional affirmation as the only backstop. **Android is not affected and the asymmetry is the tell:** `PLAY_TRACK` is hardcoded `internal` and `publish_playstore.sh:69` refuses a `test_` key on any other track, reading the key from `infra/alpha.env` itself rather than from the build's flags — a real control, unaffected by `--no-billing`. iOS has the banner where Android has the check. **Not a live exposure today** (App Store Connect distribution is a separate manual step and no external group has been used), which is why this is a defect and not an incident — but the one thing standing between a games binary and an external, store-reviewed group is currently that nobody clicks it. Fix belongs on the iOS side of the pair: make the games+external combination structurally impossible the way the Play track guard does, or stop defaulting `DO_GAMES=1` for uploads.
