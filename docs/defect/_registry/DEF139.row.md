| DEF139 | 2026-07-28 | mobile | api-client | **The client renders SSE `error` payloads raw while the backend now escapes them, so a multi-line error message shows a literal `\n` to the user.** Consequence of **DEF127**, disclosed by the lane that caused it rather than left to be found. DEF127 routed every SSE `data:` field through `app/api/sse.py`, which escapes `\` and `\n` so an exception message can no longer end its own event early or forge a new one. For `token` events that is invisible — `mobile/lib/services/api/api_client.dart` calls `unescapeSseText` on them and the round-trip is exact (DEF127's guard pins it against the shipped `0.1.0+56` decoder). For `error` events it is not: the client takes the payload verbatim at two places — `parseRoomSseEvent` returns `{'kind': 'error', 'message': data}`, and the Brief / 1-on-1 loops `throw Exception('Server error: $data')` — so nothing inverts the escape. **Severity is cosmetic and the direction is an improvement, which is why it is a separate low-priority row and not a DEF127 round-2:** before DEF127 a multi-line error was *truncated at its first line* and the actual cause was silently discarded; now the whole message arrives, just with `\n` visible as two characters. No information is lost and no forged event is possible. **Fix shape:** call the existing `unescapeSseText` on error payloads at the two client sites — the function is already exported and `@visibleForTesting`, so this is a one-line change per site plus a test asserting a two-line error renders as two lines. Worth doing in the same lane as any other `api_client.dart` work rather than on its own. **Do not "fix" it by unescaping on the backend** — that would reinstate the framing hole DEF127 closed.
