| DEF169 | 2026-07-29 | audit | backend | **The single-name concentration cap is skipped in silence when `portfolio_value <= 0`.** REL58 MINOR 9. [`safety_floor.py:266`](../../backend/app/agents/safety_floor.py) guards the cap with a `portfolio_value > 0` check and, when it fails, simply does not apply the cap — no log, no flag, no disclosure. Low likelihood (it needs a zero or negative portfolio value), but the class is exactly the one the DEF153 commit message criticises, reproduced two hundred lines away: a safety-floor rule that declines to run and reports nothing, so the trade passes a check that never happened and the compliance verdict the user sees is indistinguishable from one that was actually evaluated. **CR040** in its purest form. **Fix:** log the skip and mark the compliance result as not-evaluated rather than passed, so the absence is visible in the verdict rather than inferred from a division guard. Relates to **DEF153**, **DEF059**, **CR040**. **Fixed:** the skip now logs `safety_floor_single_name_cap_unevaluated` (ticker, portfolio_value) and a new `ComplianceResult.not_evaluated: list[str]` field (`schemas/trade.py`) carries `"single-name cap not evaluated — portfolio_value is not positive"` — distinct from both `passed` and `violations`, so the caller can tell "checked and clear" apart from "could not check" without inferring it from a division guard.
