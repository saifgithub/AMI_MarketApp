All three public POSTs route through this function — `/contact`, `/data-request`, and `/concierge/message`, the last being a **vLLM-backed streaming LLM endpoint** — so each would have accepted every caller as human-verified, with nothing in the logs saying the bot protection was off. **The only reason it has not mattered is an accident of topology:** the container publishes on `127.0.0.1:8001` and Cloudflare has no route to it, so the site 404s publicly. The bypass would have gone live at the exact moment someone added the tunnel ingress rule — i.e. the deploy step, where nobody would be re-reading this function. **This is the rule CLAUDE.md states verbatim** — *any feature gated on config presence must fail visibly, never silently fall back* — and the rule's own stated test applies cleanly: *if this fires constantly and silently, what does the user end up believing?* They believe the widget on the page is protecting the endpoint. **Fixed:** the bypass is scoped to `env == "local"` and logs `turnstile_bypassed_local` on every use; any other env with an unset secret logs `turnstile_not_configured` at ERROR and **fails closed**, the same shape DEF182 gave `ALPACA_ENCRYPTION_KEY`.
