# DEFECT BRIEF — A Room convene where most agents timed out is banked as a full-Room verdict

## 1. What is broken

When an LLM provider is merely *slow*, individual Room agents blow through `room_agent_timeout_s` (default 180.0, `backend/app/core/config.py:151`), and the Room silently replaces each timed-out agent's turn with canned template prose (`backend/app/services/room_runner.py:5036-5042` → `_scripted_for`, `:5610-5617`). The run then reaches `run.status = RoomStatus.COMPLETED` and `_persist_run(run)` (`room_runner.py:4789-4794`) with `error_message` still `None`, a full 12-entry transcript, and a genuine Portfolio Manager verdict — because the PM itself happened to answer. Nothing in `room_runs` (`backend/app/db/models.py:665-692`), in the `Verdict` schema (`backend/app/schemas/room.py:34-92`), or in `llm_audit` (`models.py:909-931`) records how many agents actually contributed.

Measured on batch `cr217-glm-1`, CAT @ 2025-08-08, provider `glm`, one convene: 6 of 10 agent calls returned `resp_chars=0` with `latency_ms` pinned at 180000/180003/180006, `error IS NULL`, and `input_tokens`/`output_tokens` NULL — while `portfolio_manager` completed (82826 ms, 1186 chars, 5352/2127 tokens) and emitted a real verdict. The convene is recorded as a successful, scoreable run built on a Room where 60% of the seats contributed nothing.

## 2. Mechanism

**Step 1 — the guard fires, not the transport.** The Room wraps every LLM call in `asyncio.wait_for`. There are exactly four such sites in `room_runner.py`: `:5000` (general agent), `:5227` (CR201 Risk Officer), `:5445` (PM verdict), `:5546` (PM reformatter). The transport budget always sits *outside* the guard by construction — `_default_transport_timeout_s()` returns `settings.room_agent_timeout_s + _TRANSPORT_TIMEOUT_MARGIN_S` where the margin is 180.0 (`backend/app/services/llm_gateway.py:567,570-578`), and for vLLM a boot-time validator enforces it (`config.py:164-169`). So a slow provider is always killed by the Room's cancel, never by an `httpx` error (DEF389/DEF392's invariant, working as designed).

**Step 2 — the whole stream is discarded.** `_collect_agent_stream` (`room_runner.py:4880-4885`) drains the generator to a list before returning, so a cancel at 179 s throws away every chunk already received. There is no partial-text salvage.

**Step 3 — the audit row is written, blank.** `wait_for` cancels the task; `CancelledError` is thrown into `_collect_agent_stream`'s `async for` → into `stream_chat`'s suspended frame. `CancelledError` derives from `BaseException` (Python ≥3.13, `backend/pyproject.toml:5`), so it slips past `except Exception as exc: error_str = f"{type(exc).__name__}: {exc}"` at `llm_gateway.py:1248-1250`. The `finally:` at `:1251` still runs and calls `record_llm_call` at `:1332` with `error=error_str` (still `None`), `response_text="".join(buf) if buf else None` (buf empty → NULL), and `usage = call_meta.get("usage") or {}` (`:1326`) yielding NULL for all four token columns — the terminal SSE `usage` frame requested at `:671` (`"stream_options": {"include_usage": True}`) never arrived. `latency_ms` is computed at `:1252` from a `perf_counter` started at `:1234`, inside the guard window, so it records the guard value itself, not a measured duration. There is no `except BaseException`/`except asyncio.CancelledError`/`except GeneratorExit` anywhere in `llm_gateway.py`.

**Step 4 — the Room swallows the TimeoutError.** `room_runner.py:5036-5042`:

```python
except asyncio.TimeoutError:
    logger.warning("room_agent_timeout", agent_id=agent_id.value, timeout_s=agent_timeout_s)
    text = _scripted_for(agent_id, formatter)
```

The log line carries no `run_id`, no ticker, no batch_id — unlike its sibling at `:5293-5297` (`room_risk_officer_degraded`, which does carry `run_id=str(run_id)`). `_mark_if_truncated` is called at `:5035`, *inside* the `try`, so it is unreachable on this branch. The `except Exception` branch at `:5043-5051` lands on the same unmarked `_scripted_for`.

**Step 5 — the fallback is indistinguishable prose.** `_scripted_for` (`:5610-5617`) is `_TEMPLATES[agent_id][0].format(**formatter)` — a complete, confident sentence populated with real computed figures. It carries no `[AMI …]` mark. Note the same `_scripted_for` is the destination for five other conditions in `_compute_agent_text` (empty stream `:5015`, DEF376 `stream_error` `:5022-5023`, DEF147 envelope-only `:5034`, generic exception `:5050`, and the non-live demo path `:5053`), so the text alone cannot say *which* degradation fired.

**Step 6 — the caller cannot tell.** The four analysts are gathered with `asyncio.gather` at `room_runner.py:4429-4443` with no `return_exceptions=True` — but that cannot fire, because `_compute_agent_text` returns a well-formed `(text, geom_sig, envelope)` tuple on timeout. Four analysts timing out is byte-identical to four analysts answering. The sequential debate agents go through `_speak_one_agent` (`:4486`, `:5152`) and stream unconditionally.

**Step 7 — the turn is persisted as a normal turn.** `_stream_agent_text` appends `AgentMessage(...)` at `room_runner.py:5105-5116` with `content=text` and the stance envelope. `AgentMessage` (`backend/app/schemas/agents.py:114-153`) has no `source`, `degraded`, or `fallback` field; `token_count` and `model` exist (`agents.py:121-122`) but are never populated by either construction site (`room_runner.py:5105`, `:4747`). The envelope on the fallback path is the all-`None` default `_StanceEnvelope()` (`:4943-4946`) — but `agents.py:127-133` documents that a null stance equally means a malformed tail, a turn cut short, an agent whose role was not to take a side, or a pre-field run, so it is not a discriminator.

**Step 8 — the trade levels survive the trader's silence.** `ctx.trader_entry/stop/target/size_pct` are assigned once at `room_runner.py:4301-4304`, before the phase loop, and nothing parses the trader's turn back into them. They are handed to the PM prompt as `trade_proposal` at `:5399-5406`, so the PM receives a complete money block even when the Execution Desk never spoke.

**Step 9 — the PM answers and the run is banked.** With `raw_text` non-empty, control flows to `else: pm_text, parsed = _parse_pm_verdict(raw_text, ctx)` at `room_runner.py:4627`, skipping the DEF059 branch at `:4614-4626`. `verdict.model_copy(update={"opinions_not_included": [...ctx.withheld]})` at `:4760-4761` stamps an empty list. Then `:4789-4794` sets COMPLETED and persists.

## 3. Why the existing guards miss it

**`is_llm_outage_verdict()` (`room_runner.py:484-497`)** requires `overridden_from_llm` AND `reason.strip() == PM_LLM_UNAVAILABLE_REASON`. The second conjunct is load-bearing: `PM_LLM_UNAVAILABLE_REASON` is assigned in app code at exactly one place, `room_runner.py:4622`, on the `elif not raw_text:` branch (`:4614`) reached only when the PM's *own* stream came back empty. In the observed convene the PM returned 1186 chars, so `overridden_from_llm` stays False and `reason` is the model's own prose. The recognizer is a **PM-liveness test, not a Room-liveness test** — it has no visibility into the other nine seats. Widening it is also blocked: `overridden_from_llm` alone is set on five unrelated branches (`room_runner.py:1780`, `:3204`, `:4623`, `:4675`, and `backend/app/services/safety_floor.py:843`), and `backend/tests/unit/test_cr164_pit_field_coverage.py:364` explicitly pins that the recognizer must *not* fire on a safety-floor override.

Worse: the PM path itself has a partial hole. `settings.pm_self_consistency_samples` defaults to 5 (`config.py:751`), so `room_runner.py:4529-4550` gathers five PM draws, drops empty ones with `) if r` (`:4540`), and takes `raw_text = _raws[0] if _raws else ""` (`:4550`). One to four timed-out PM samples are silently discarded and the fail-safe never fires; only an all-five wipeout trips it.

**`--max-consecutive-outages` (`backend/scripts/backtest_sweep.py:485,501-514`)** computes `outage = is_llm_outage_verdict(verdict)` then `outage_streak = outage_streak + 1 if outage else 0`. A partial Room is `not outage`, so it does not increment the streak — **it actively resets it to zero**. Interleaving partial Rooms with true outages keeps a degrading sweep alive indefinitely. Its own comment (`:495-500`) states the breaker exists because "a provider that dies mid-sweep yields a full batch of records shaped exactly like data" — a *half*-dead provider yields the same thing and additionally disarms the breaker.

**The `error` column** is structurally incapable of recording this (§2 step 3). `except Exception` at `llm_gateway.py:1248` cannot catch a `BaseException`. This is the same shape DEF376 fixed two lines below at `:1317` (`if error_str is None and call_meta.get("stream_error")`), whose own comment reads "it reached `record_llm_call` as `error=None` with an empty response, i.e. recorded as a clean answer the model simply had nothing to add to." That fix was keyed to one specific meta flag, not to "the buffer is empty and the stream did not end normally", so the cancellation case was never covered.

**The asymmetry within `room_runner.py` is the sharpest statement of the defect.** Of the four timeout handlers, three leave a durable trace and one does not:

| site | handler | durable trace |
|---|---|---|
| `:5036` general agent (8 prose agents) | log `room_agent_timeout` (no run_id) + `_scripted_for` | **none** |
| `:5270` CR201 Risk Officer | `fallback_reason = f"no reply within {agent_timeout_s:.0f}s"` + `room_risk_officer_degraded` log with `run_id` (`:5293-5297`) | `[AMI: the Risk Officer's structured assessment was unavailable (…)]` prefixed onto all three rendered turns (`backend/app/services/risk_officer.py:384-390`) |
| `:5478` PM verdict | returns `""` | reaches DEF059 fail-safe, `overridden_from_llm` + sentinel reason, detectable |
| `:5586` PM reformatter | returns `""` | `parsed is None` → PASS with `overridden_from_llm=True` |

The codebase has already decided what correct behaviour looks like and applied it to exactly one of the four handlers. (Note `room_risk_officer_enabled` defaults False at `config.py:795` and is gated at `room_runner.py:4464` — the observed `risk_officer` audit row proves the CR217 batch ran with it ON.)

## 4. Blast radius

- **`backend/scripts/backtest_report.py`** — the primary scorer for every CR164/CR214/CR217 claim. Its exclusion ladder (`:511-537`) has five reasons: `missing_room_run`, `non_completed`, `null_verdict`, `other_action`, `llm_outage`. A partial Room passes all five and enters `pairs`. `grep -n "transcript\|llm_audit\|scripted\|timeout"` over this file returns nothing — it cannot see the timeouts even in principle. Its batch-level refusal (`:542-552`, `return 4` above 5%) counts partial Rooms in the *denominator* as clean data and can never see them in the numerator: a batch where 100% of convenes ran at 40% population reports 0% outage and scores clean.
- **`backend/scripts/weekly_room_retro.py`** — the live twin, grading real user convenes. `select_due_runs` (`:116-154`) applies seven exclusions, none of which inspects the transcript or roster; `is_llm_outage_verdict` at `:145` is the only degradation filter. The transcript is read only at `:353` for the per-agent scorecard, where a timed-out agent lands in the CR106 null-stance gutter — pooled with genuine abstentions, so "analysts with no view" silently inflates with provider slowness. `prompt_partition` (`:157-181`) is the only `llm_audit` read in the scorers and selects `prompt_version` alone, collapsed into a `set` — blind to row count, latency, error, and token nullity.
- **`backend/scripts/backtest_trade_pnl.py`** — the "would a user following the trades have made money" scorer. `load_approvals` (`:70-88`) filters only on `r.status = 'completed' AND r.verdict IS NOT NULL`, then `action in ("APPROVE","MODIFY")` and non-null entry/stop/target. `grep -c is_llm_outage_verdict` → 0. The most user-facing number is computed over the dirtiest population.
- **`backend/scripts/model_decision_diff.py`** — the CR217 GLM-vs-incumbent head-to-head. `classify()` (`:67-71`) reduces a run to `(action, is_failsafe)`; a partial Room flows through as a "clean, comparable pair". Its own docstring warns that "a starved model reads as a conservative one … exactly the wrong conclusion" — and that is precisely the misreading a slow candidate produces here, through a door the guard does not cover. It reads `backtest_sweep`'s `runs_*.jsonl`, whose per-run record (`backtest_sweep.py:430-441,472-478`) discards the transcript it had in hand.
- **`backend/scripts/backtest_sweep.py` + the DEF345 completion sentinel** — a partial Room has `status == "completed"`, so `done += 1` at `:489-490` and it reaches the sentinel as `completed=done + skipped` (`:525-531`). `backtest_report.py:341-353` then stamps the batch `**COMPLETE**` from pair counts alone. The artifact built to make truncation detectable will vouch for a batch that is quantitatively complete and qualitatively hollow.
- **`backend/scripts/agent_call_profile.py`** — reports `errors` as `count(*) FILTER (WHERE a.error IS NOT NULL)` (`:58`), which is 0 on all six rows. `mean_s`/`median_s`/`p90_s` (`:52-55`) average the 180 s censored values in with real durations, while `avg(input_tokens)`/`avg(output_tokens)` (`:56-57`) skip NULLs — latency over 10 calls, tokens over 4, `calls` printing 10 for both. The only surviving signal is `empty_responses` (`:59`), a separate column a reader must think to cross-reference, and whose warning text (`:124-128`) attributes blankness to a starved decode budget, never to the guard.
- **The mobile app** — `mobile/lib/models/room_board.dart:107` defines `statedNoView => stance == null`; `:192-193` `voicesNotStated => voices.where((v) => v.statedNoView && !v.withheld)`; `:218` `statedCount => voices.where((v) => !v.statedNoView).length`. `withheld` only ever means CR098 tenure. So the board reads "12 VOICES · 4 STATED A VIEW" for a Room where six agents never ran, each rendering its `_TEMPLATES` sentence with no marker — the CR040 degrade-loudly rule inverted: silence renders as a considered abstention.
- **The Journal** — `build_journal_entry_for_run` (`room_runner.py:3408-3474`) has the *only* "N of 12 agents" copy in the codebase, at `:3423-3433`, gated on `if run.verdict is not None: … else:` — exactly the condition a partial Room does not meet. `agents_involved` (`:3441-3444`) lists whoever authored a transcript turn, so timed-out agents are credited as involved, and the scripted templates are frozen into `payload['transcript']` for replay.
- **`GET /v1/room/{run_id}` and `/user/{user_id}`** (`backend/app/api/room.py:361,377`, both `response_model=RoomRun`) — `RoomRun` (`schemas/room.py:117-141`) has no partial/degraded field. The one roster-gap field, `Verdict.opinions_not_included` (`schemas/room.py:52`), is fed exclusively from `ctx.withheld` (`room_runner.py:4286` ← `roster.withheld` ← `backend/app/services/entitlements.py:141`, where only FLOOR_PASS is ever degraded and Fundamentals is excluded at `:158`). It structurally cannot represent bull/bear/trader/risk_officer at all. The user is told the roster was complete.
- **Forensic recovery** — `llm_audit` has **no `run_id` column** (`models.py:909-931`), so the rows that do carry the fingerprint can be joined to their convene only by `(user_id, wall-clock)` proximity, which is what `weekly_room_retro.prompt_partition` (`:157-165`) and `backtest_prompt_scan.py:216-223` already do by hand. Any completeness figure derived that way is an estimate. And `room_agent_timeout` exists only in container stdout, which does not survive `docker compose up --build`.

## 5. Constraints on any fix

**House rules (CLAUDE.md).**
- CR040 *degrade loudly*: "if this fires constantly and silently, what does the user end up believing?" — plus the corollary from `docs/initial_specs/08_tech/failure_patterns.md` P2's DEF135 row: "A loud signal that is always on is the same as no signal."
- "Prompt instructions are not controls" — if it must hold, make it structural.
- Second occurrence ⇒ a `failure_patterns.md` entry **with an enforcing check**; "an entry without an enforcing check is not done" (`failure_patterns.md:7`, CLAUDE.md).
- **P26 escalation is live.** `failure_patterns.md:1526` ("a run that failed produces a record set shaped exactly like one that succeeded") lists DEF059 / DEF336 / DEF345 and is **already flagged as a CR185 Dilemma candidate** at `:1566-1570`. This is a fourth mechanism at the same seam (dead provider → dead process → outage fail-safe → dead *subset of agents*). The CR185 trigger is Saiful's call, not automatic — `docs/dilemmas/DILEMMA_PROTOCOL.md:3` — and the same file records deliberate point fixes taken at the threshold before (P1 `:38-40`; P29 `:1809-1813`). Flag it; do not assume it.
- P26's own prescription: *"make absence the signal, and make it unforgeable"*, and *"Refuse at the layer that turns records into claims, not only at the producer"* (`failure_patterns.md:1560-1564`).

**Existing idioms to reuse (do not invent new ones).**
- The `[AMI …]` in-band transcript mark: `_TRUNCATION_MARK` (`room_runner.py:3044`, DEF125), the DEF095 geometry note (`:2227`), the CR201 risk-ladder mark (`risk_officer.py:386`). The Flutter client already amber-flags any turn matching it — `hasAmiAnnotation(String content) => content.contains('[AMI')`, `mobile/lib/widgets/room/room_transcript_rows.dart:40` — so a prose mark needs **zero client change**. It is also unreadable to the scorers.
- The DEF336 named-sentinel + recognizer shape: `PM_LLM_UNAVAILABLE_REASON` (`room_runner.py:478`) + `is_llm_outage_verdict` (`:484`) + two consumer call sites + a >5% batch refusal. Its DEF336 row's stated root cause is "a sentinel with no name … the only way for any consumer to recognise an outage verdict was to match a prose fragment."
- The CR098 structural-event precedent: `agent_withheld` (`room_runner.py:3258` kind list, emitted `:4398`, rendered `api/room.py:321-333`) — deterministic, code-built, never LLM-derived. It required coordinated edits in 8 non-test files plus a wire test (`test_cr098_room_analyst_pullback.py:629`).
- CR104's affirmative-assertion polarity (`backend/app/services/room_prompts.py:75`, `:1904-1936`): only a positive `== "live"` counts as present; absence defaults to refusal. Note its docstring ranks the *structural* event above the prompt string, "which agents drop ~70% of the time."

**Migration.** `RoomRunRow` (`models.py:665-692`) has 16 columns and no degradation field; `Verdict` (`schemas/room.py:34-92`) has 14 fields and none about participation. Any new `room_runs` column **requires an alembic migration and nothing will remind you**: the unit suite builds schema via `Base.metadata.create_all(engine)` (`backend/app/db/session.py:240`, via conftest's autouse `_isolated_db`), so a model-only change is green locally; on Alpha's Postgres `init_schema` creates nothing, `alembic upgrade head` is a no-op with no new revision, and the first ORM read raises `UndefinedColumn` in live traffic (the DEF215/DEF337 failure shape). **Current head is `def335a0b0c0d2`** (`backend/alembic/versions/def335a0b0c0d2_ticker_splits.py:34`, revises `cr210a0b0c0d1`); chain from it or `test_def278_migrations_are_immutable.py:92` goes red. The persisted `verdict` JSONB (`models.py:683`) already carries analogous per-run bookkeeping (`opinions_not_included`, `approve_votes`/`samples`, `level_provenance`) and needs no migration.

**Test guards that will fire.**

- `backend/tests/unit/test_cr106_stance_envelope.py:252,283` deliberately merge scripted/timeout/failure into the null-stance gutter. Any fix that infers "timed out" from a null stance goes red against them.
- `backend/tests/unit/test_cr164_pit_field_coverage.py:364,391` pin `is_llm_outage_verdict`'s shape boundary and its build site. A widened recognizer breaks `:364`; a sibling predicate does not.
- **Adding a `Settings` knob** trips `backend/tests/unit/test_config_compose_parity.py:78` (must be forwarded in `docker-compose.yml`'s `api-alpha` environment block; `_NOT_FORWARDED` at `:31` is the wrong branch for a live knob) **and** `:268` (inline compose default must string-equal the Settings default, e.g. `ROOM_AGENT_TIMEOUT_S: ${ROOM_AGENT_TIMEOUT_S:-180.0}` at `docker-compose.yml:195` vs `config.py:151`).

DEF345 pre-authorises editing both: "The argument is required rather than defaulted on purpose — a default is exactly how a call site forgets to pass it."
- **Surfacing a per-turn marker to clients requires two independent edits**, because the two SSE emit sites read different schemas: the live site `api/room.py:305-320` serializes `RoomEvent` (`room_runner.py:3248-3281`), the cached-replay site `api/room.py:266-278` serializes the validated `AgentMessage`. At the replay site, a new key must go on `payload` right after `:268`, **outside** the `if stance_recorded:` gate at `:269` — a timed-out agent has no `stance` key, so anything nested there is dropped exactly when it matters. `test_def161_room_replay_stance_absence.py:113,136,157` will fail if the gate is flattened.
- **Nothing will catch a forgotten wiring.** `RoomEvent.kind` is a bare `str` with allowed values in a trailing comment (`room_runner.py:3258`), no test pins the set, and `api/room.py:283-342` has no terminal `else` — an unhandled kind is silently dropped before the wire (the Flutter side drops it too: `mobile/lib/state/room_providers.dart:336`). No field-census guard covers `Verdict`, `RoomRun`, or `room_runs` columns (`test_def215_schema_ownership.py:60-61` inspects table names only; `test_prompt_data_parity.py` and `test_wire_contract_parity.py:58-62` do not touch them). The fix must carry its own explicit tests. Consumer-side coverage is currently zero for `backtest_report.py:534`, `backtest_sweep.py:485`, and `model_decision_diff.py:70`.
- **Timeout value is bounded, not pinned:** `test_def389_transport_timeout.py:113-123` sets a floor (`>= 4 * 42.4 / 1.5 ≈ 113.07 s`), `:29` requires transport > agent budget, `:126` requires the budget stay `settings.room_agent_timeout_s` and not a literal. `test_def392_transport_ordering.py:99` exercises a 15 s guard.

**Naming collision.** In `backtest_report.py`, "partial" already means *partial batch* (`--allow-partial`, exit 5, DEF345, `:455-492`, label at `:340-353`). A Room-completeness guard needs a distinct name there.

**Backfill is forbidden.** `Verdict.level_provenance`'s rule (`schemas/room.py:91`): "`None` means 'this run predates the field', NOT '…' — an absent value is never backfilled or inferred (T-BACKFILL)." Any new field inherits it. Historical runs cannot be retro-classified from `room_runs` alone; only the `llm_audit` fingerprint (latency at the guard + all-NULL usage + NULL response) can reconstruct them, and only until that table is pruned (`models.py:896`: "Retention is unbounded until tester count grows").

## 6. Open design questions

1. **Where does the fact live?** A new nullable column on `room_runs` (migration required); a new key inside the existing `verdict` JSONB (no migration, but it is the *verdict* schema and the fact is about the *Room*); a new key on each `AgentMessage` in the `transcript` JSONB; a re-purposing of the never-populated `AgentMessage.token_count`/`model` (`agents.py:121-122`); or nothing persisted at all, with consumers recomputing degradation by matching each turn's `content` against a recomputed `_scripted_for` template (deterministic per `room_runner.py:5610-5614`, but it cannot say *which* of the six fallback causes fired, and it makes every consumer depend on template text).
2. **Per-agent fact or per-run aggregate?** A per-turn provenance marker answers "which seats were empty"; a per-run counter answers "was this Room quorate" in one read. They have different migration costs, different backfill semantics, and different consumers.
3. **Exclude, flag, or both?** DEF336's precedent is *exclude the record and refuse the batch above a share*. But an outage PASS is asserted to be "not a decision", whereas a partial Room's verdict was genuinely reasoned — on a thinner room. Whether that is invalid data, or valid-but-caveated data, is a judgement, and the answer differs between the backtest scorers, the live retro, and the user-facing app.
4. **What counts as partial?** Any single timed-out agent? A fraction of the 10/12 seats? A weighting where the trader or a specific analyst counts more? Note the observed run had 6/10 timeouts but the PM answered — and separately, 1–4 of 5 PM self-consistency draws can time out with no signal at all today (`room_runner.py:4529-4550`).
5. **Should the PM be told?** The PM currently reads six scripted templates as if they were analysis, and receives a fully-specified `trade_proposal` (`:5399-5406`) that the silent trader never justified.
