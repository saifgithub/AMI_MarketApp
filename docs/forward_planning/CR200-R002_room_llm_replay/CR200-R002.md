# CR200-R002 — Room LLM Request/Response Viewer + Prompt Replay

**Date:** 2026-09-25 · **Status:** in_progress · **Track:** AT:R86
**Parent:** CR200 (Management Console) — sixth module, own tab. Filed as a
grouped sub-CR (`CR200-R002`, not a standalone top-level number), same
convention CR200-R001 used at Saiful's request, so every management-console
sub-item lives under one `CR200-R###` namespace instead of scattering across
the flat CR sequence.

## What

An admin-only view of the raw request (system prompt + message list) and
raw response text for every LLM call inside a convened Room, plus a
"resend" action that lets an operator edit a captured prompt and send it to
the LLM again to see how the change affects the output — a
prompt-engineering sandbox for testing prompt changes before they ship.

- `GET /v1/admin/room/runs` — recent Room runs (ticker/user/date filter) to
  pick from.
- `GET /v1/admin/room/runs/{run_id}` — the run's detail (reuses the
  existing `RoomRun` schema `GET /v1/room/{run_id}` already serves).
- `GET /v1/admin/room/runs/{run_id}/llm-calls` — the run's LLM calls in
  order: agent, tier, provider, latency, tokens, and the full
  `system_prompt` / `messages` / `response_text`.
- `POST /v1/admin/room/llm-calls/{call_id}/resend` — replay one captured
  call with optional edits to `system_prompt` / `messages` / `model_tier` /
  `max_tokens`. An **isolated raw LLM call**: no verdict parsing, no
  safety-floor pass, no credit spend, no Decision Journal write, no
  `room_runs` row created or mutated. Returns the new response text
  alongside the original for comparison.
- New "ROOM CALLS" tab in the `/admin` SPA: run picker → per-agent call list
  → expandable request/response view → inline edit-and-resend form.
- **Presets** — four hand-authored, clearly-labelled canned text snippets
  the operator can insert into the editable system prompt before resending:
  cash-only portfolio, conservative risk settings, aggressive risk
  settings, large open drawdown. Frontend-only (`ROOM_CALL_PRESETS` in
  `room_calls.js`), no backend involvement — a preset is plain text
  inserted client-side, not a server-rendered reconstruction from the real
  prompt-building code (`room_prompts.py`'s `_risk_state_block` /
  `_drawdown_snapshot_line` need a real `Mandate` + live run context they
  don't have here; a snippet that *looked* server-authentic but wasn't
  would be a worse trap than one plainly marked as inserted test text).

New: `backend/app/services/room_llm_calls.py`,
`backend/app/api/admin_room.py` (routes under `/v1/admin/room/*`,
`Depends(get_admin)` — same gating as every other `admin_*.py`),
`backend/app/static/admin/room_calls.js`.

## Why

Saiful wants to see what each of the 12 agents was actually asked and what
it actually said, and to be able to test a prompt-wording change against a
real captured call before touching the shipped prompt files
(`content/agents/*.md`) — currently invisible and untestable outside a full
Room convene.

**The data already exists and is unused.** `LLMAuditRow` / table
`llm_audit` (`backend/app/db/models.py:966`) captures full `system_prompt`,
`messages`, and `response_text` for every LLM gateway call already —
`record_llm_call()` writes one row per call from
`LLMGateway.stream_chat()`. Nothing reads it today except an aggregate
cache-hit-rate metric. The Room's own `transcript` column
(`room_runs.transcript`) stores only the rendered response text
(`AgentMessage.content`) — the system prompt and message list
`build_room_messages()` builds are discarded right after the call. This CR
is therefore an exposure + replay layer on top of existing data, not a new
capture mechanism — no schema migration.

**Why an isolated raw call, not a real pipeline re-run.** Saiful's call:
the resend is a sandbox, not a second Room turn. Routing an edited prompt
back through `room_runner`'s real per-agent logic would mean a "just
testing wording" click could parse a verdict, run the safety floor, spend
credits, or write a Decision Journal entry — none of which should be
reachable from an admin debug tool. `POST /v1/llm/translate`
(`backend/app/api/llm.py:46`) is the existing precedent for this shape
(admin-gated, calls `gateway.stream_chat()` directly, no side effects);
this CR generalizes it (full message list, not one turn; tier/max_tokens
overridable) rather than reusing it as-is.

**Why `llm_audit`, not a new `room_run_id`-linked table.** `llm_audit` has
no `room_run_id` FK — linkage to a Room run is a time-window join on
`(user_id, agent_id, created_at ∈ [triggered_at, finished_at])`. Adding the
FK would need a migration and a backfill decision for existing rows; the
time-window join is accurate (a user has at most one running Room at a
time — `_find_active_run`) and ships without touching the schema.

**Why admin-only, never user-facing.** Decision log D-022: "conversational
prompt tuning, not raw markdown editing... removes risk and intimidation of
raw prompt editing" — the product has consistently kept raw prompt text
away from end users in favor of the Brief Your Agent conversational layer.
This CR does not change that; it's an operator tool, gated exactly like
`admin_ticker_interest.py` / `admin_verdict_outcomes.py`.

## Scope

- In: the four routes above, the query layer joining `room_runs` to
  `llm_audit` by time window, the resend action (isolated raw call,
  `audit_flow="admin_prompt_replay"` so replays get their own traceable
  audit row and are excluded from the run's own call list), an
  `admin_audit` row per resend (`record_admin_action`, same helper
  `admin_push.py` uses), the new admin tab, unit tests.
- Out: a `room_run_id` FK migration on `llm_audit` (time-window join is
  sufficient for a debug tool); any user/mobile-facing surface (D-022);
  re-running an edited prompt through the real `room_runner` pipeline
  (verdict parsing, safety floor, credits, journal — a separate, larger CR
  if ever wanted); bulk/batch resend; a structured diff view beyond
  side-by-side text.

## Acceptance

1. `pytest backend/tests/unit/ -q` green, including
   `test_room_llm_calls.py` (time-window join excludes out-of-window and
   `admin_prompt_replay` rows) and `test_admin_room_api.py` (auth gating;
   resend round-trip against the mock provider asserts zero writes to
   `room_runs`, credits, or the Decision Journal).
2. `GET /v1/admin/room/runs/{run_id}/llm-calls` on a real convened run
   returns every agent's captured `system_prompt`/`messages`/
   `response_text`, matching what `room_runner` actually sent (verified
   against `content/agents/*.md` + the run's own transcript on Alpha).
3. A resend with an edited `system_prompt` returns a new response and
   writes exactly one new `llm_audit` row and one `admin_audit` row; the
   original run's `room_runs` row, credit balance, and Decision Journal are
   unchanged.
4. New "ROOM CALLS" tab renders in the admin SPA; unauthenticated access
   403/503s per `get_admin`, same as every other tab.
