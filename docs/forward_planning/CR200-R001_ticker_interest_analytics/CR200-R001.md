# CR200-R001 — Ticker Interest Analytics

**Date:** 2026-09-23 · **Status:** in_progress · **Track:** AT:R83
**Parent:** CR200 (Management Console) — fifth module, own tab. Filed as a
grouped sub-CR (`CR200-R001`, not a standalone top-level number) at Saiful's
request, so every management-console sub-item lives under one `CR200-R###`
namespace instead of scattering across the flat CR sequence.

## What

A new **Ticker Interest** tab in the admin console, statistically breaking
down which tickers/tickets users research and trade, and their order
outcomes (filled vs. not filled):

- `top_tickers` — Room runs grouped by ticker: run count, done/error split,
  distinct researcher count, avg credit cost. From `room_runs`.
- `ticker_orders` — orders grouped by ticker: filled (`sim_trades` opens) vs.
  pending/unfilled (`sim_resting_orders.state='working'`/`triggered`/
  `filling`) vs. terminal-not-filled (`cancelled`/`expired`/`rejected`).
- `ticker_detail(ticker)` — one symbol's full history: Room runs, trades,
  resting orders, watchlist adds.
- `watchlist_interest` — most-watchlisted tickers from `sim_watchlists`.

New: `backend/app/services/ticker_interest.py`,
`backend/app/api/admin_ticker_interest.py` (routes under
`/v1/admin/ticker-interest/*`, `Depends(get_admin)` — same gating as
`admin_verdict_outcomes.py`), `backend/app/static/admin/ticker_interest.js`
(new tab, registered in `core.js`, no build step, matching `analytics.js`'s
pattern).

Reuses `admin_analytics.real_users_where_sql()` / `is_real_user()` so ticker
counts exclude the same CR035 room-benchmark synthetics, seed-burst rows, and
CR125/DEF227-229 probe users already excluded from every other admin metric.

## Why

Saiful: statistical visibility into what tickers/tickets and counters users
are interested in, including which orders get filled vs. not — currently
invisible. CR200's Analytics tab (`admin_analytics.py`) ships platform-wide
KPIs (signups/DAU/room-runs/credits) but has zero ticker/symbol breakdown —
confirmed by grep, not an oversight being duplicated here.

**Known gap, flagged not fixed by this CR:** no table tracks raw ticker
*lookups* (opening a detail screen without running a Room or trading) — no
`research_events`/`ticker_views` exists. This CR reports on Room runs, trades,
resting orders, and watchlist adds — the interest signals that already exist
in the data. A raw-lookup-tracking table is a separate, larger CR (new
telemetry ingest path) if Saiful wants that finer signal later.

## Scope

- In: the four query functions above, their admin routes, the new tab UI,
  unit tests.
- Out: raw ticker-lookup/view tracking (no such telemetry exists yet — see
  Why), any user-facing surface (internal admin-only, same as
  `admin_verdict_outcomes.py`), roles/permissions beyond existing
  `get_admin` gating.
