# CR206 — the dividend feed for D9 early assignment

Authoritative summary: this CR's row in [`cr_list.md`](../cr_list.md)
(`_registry/CR206.row.md`).

Split out of CR172 §11 on 2026-08-24 (AT:R74).

The rule is written. The feed is not, and the reason it is not is worth keeping:
`dividend_rate` on `EarningsInfo` is an **annual** figure, and the rule needs the
**next payment**. Annual ÷ 4 is an assumption about payment frequency dressed as
a measurement, on a rule whose output takes a position away from a user early.
The fix is to read the actual last payment, which means a new provider-protocol
method across the whole fallback chain — a real surface, and the reason this is
its own CR.

Not urgent: `derivatives_allowed` is set on 0 of 42 current mandates.
