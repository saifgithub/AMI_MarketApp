## 1. Why this CR exists

`ami-llm` (the Room's current LLM, `CLAUDE.md`'s Runtime State table) is Qwen3.8-Flash-Next
(125B MoE, 6B active/token), **self-hosted** on a separate LAN box (`192.168.20.74:8000`),
serving the **abliterated** (refusal-stripped) build. This works for alpha but wasn't
sized or bought for production traffic — Saiful's read is that it "is not capable of
running in full production mode." Going to market means either scaling the self-hosted
box or moving to a hosted API provider; Saiful asked for the hosted option, evaluated
against cost and against "same or better" model quality.

This is a production infrastructure + model-quality + safety-posture decision affecting
every Room convene going forward, not a reversible dev-tool choice — hence a CR rather
than a chat-only conclusion.

## 2. What "same or better" than Qwen3.8-Flash-Next means here

Current model, restated from `CLAUDE.md`: **abliterated** — CLAUDE.md's own words, "a
refusal-stripped build... prompt-only refusals hold less often: only the structural
controls (deterministic PM compliance check) are safe to lean on." That's a load-bearing
fact for this comparison: none of the hosted commercial options below will be abliterated
— they'll have each vendor's stock safety/refusal behavior. Whether that matters depends
on whether the Room's structural controls (the deterministic single-name-cap/compliance
check, not prompt instructions) already carry the real safety burden — CLAUDE.md's own
phrasing suggests they do, but this CR does not settle that; it's flagged as an open
question for Saiful, not assumed either way (§6).

## 4. GLM-5.3 vs. GLM-5.3-Flash — same version number, different models

These are **not** a flagship-vs-cheaper-quantization pair of the same model — they are
positioned by Z.ai as different products that happen to share a version number:

| | **GLM-5.3** (flagship) | **GLM-5.3-Flash** |
|---|---|---|
| Role (vendor's own framing) | "text-only coding and cyber model" — long-horizon agent/coding tasks | "cheap, multimodal, high-throughput sibling" — chat, extraction, vision, summarization |
| Architecture | not disclosed in sources checked | 320B total params, 18B active/token (MoE) |
| Modality | text-only | multimodal, native vision |
| Context | not specified in sources checked | 1M tokens |
| KingBench (coding/agentic) | **91.25%** | 78.75% — a ~13-point gap |
| Artificial Analysis Intelligence Index | 60 | 57 — only a ~5% gap |
| Price (DeepInfra, fetched) | $0.563 / $2.50 | $0.075 / $0.25 — ~7.5x cheaper |

**Read:** the two benchmarks disagree on how large the quality gap is. The general
"intelligence index" says the gap is small (~5%); the harder agentic/coding benchmark
says it's substantial (~13 points). The Room's `research_manager`/`trader`/PM stages are
structurally closer to the agentic/coding case than to chat/vision/extraction — so
Flash's real gap on OUR workload could plausibly track closer to the 13-point KingBench
number than the 5% index number, but **this is inference from vendor positioning and one
third-party benchmark, not a measurement on our own prompts.** §5 is how to actually find
out.

## 5. Next step — measure, don't infer (uses the $25 already loaded)

Do NOT pick a provider off the table above alone. Feed a real captured Room prompt (e.g.
a `research_manager` or `trader` system_prompt pulled via
`docs/tools/room_investigation/room_llm_audit_trace.py get --field system_prompt`, the
same tool this session used for the CR228 investigation) to:

1. **GLM-5.3-Flash** on DeepInfra (cheapest credible candidate, $0.075/$0.25)
2. **GLM-5.3** flagship on DeepInfra (quality ceiling check, $0.563/$2.50)
3. Our current **Qwen3.8-Flash-Next** (the baseline being replaced)

...on the SAME captured prompts, several times each (5x, matching this session's
consistency-check pattern), and compare: does the verdict/stance/reasoning quality hold
up on Flash, or does the KingBench-style agentic gap show up concretely on our own
financial-reasoning task? `docs/tools/room_investigation/room_agent_replay.py` already
supports `--provider` as an extension point (currently `kimi`/`vllm` only) — extending it
with a `--provider deepinfra` (OpenAI-compatible endpoint, same `OpenAICompatibleProvider`
pattern already used for Kimi/vLLM in `llm_gateway.py`) is the natural way to run this
without hand-rolled scripts, and keeps the result in the same toolkit for reuse.

The $25 DeepInfra credit is enough for thousands of single-agent replay calls at these
prices (at ~$0.30/1M blended tokens for GLM-5.3-Flash on a ~24K-char prompt, roughly
6,000 tokens/call — call it ~$0.002/call — $25 covers well over 10,000 calls), so cost is
not the constraint on running this properly.

## 6. Open questions for Saiful (not decided by this CR)

- **Abliteration:** does the product need the refusal-stripped behavior, or do the
  structural controls (compliance floor, single-name cap) already carry the real safety
  burden regardless of the underlying model's stock refusal behavior? CLAUDE.md's own
  language suggests the latter, but this has not been tested against a stock (non-
  abliterated) model's behavior in the Room specifically.
- **Aggregator vs. direct:** OpenRouter is cheaper than DeepInfra/Z.ai-direct for the same
  GLM-5.3-Flash model, but it's a routing proxy over other providers' capacity, not a
  first-party host — a different reliability/support posture for a paying product than
  hosting directly with DeepInfra or Z.ai.
- **Major-lab vs. open-weight:** GPT-5-nano is price-competitive with GLM-5.3-Flash and
  comes with OpenAI's SLA/support relationship instead of an open-weight model's — worth
  weighing if reliability/compliance posture matters more than the marginal cost
  difference between the two.
- **Self-hosted scaling vs. hosted:** this CR assumes "hosted" per Saiful's steer, but the
  alternative of scaling the self-hosted box was not evaluated here (hardware cost,
  procurement lead time, ops burden) — if that path is still live, it's a separate
  comparison this CR doesn't cover.
