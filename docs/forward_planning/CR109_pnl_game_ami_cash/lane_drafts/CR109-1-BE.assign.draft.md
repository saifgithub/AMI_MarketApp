# CR109-1-BE — assign (the NAV spine: `portfolio_nav_daily` + `twr.py` + the daily tick)

HOT-FILES: backend/app/db/models.py · backend/app/main.py · backend/app/api/sim.py (coder.api owns) — additive only

**What:** The one table the entire CR109 design rests on, its daily tick, and the pure TWR maths —
plus a read endpoint so the mobile lane can draw an equity curve. **This slice ships against the
TRAINING portfolio only. No game, no score, no board, nothing user-visible that touches D-060.**

Read `implementation_plan.md` in full. Do not re-derive the schema — it is specified there.

**1. `portfolio_nav_daily` + alembic** (plan §4.1 has the column list verbatim):
- Columns: `id`, `user_id` (indexed, not null), `run_id` (indexed, **nullable — NULL = the training
  portfolio**), `as_of_date` (Date, US market date), `nav` `Numeric(12,2)`, `cash` `Numeric(12,2)`,
  `price_source` (`live`/`mock`/`stale`), `capital_event` (nullable: `open`/`restart`/`topup`),
  `created_at`.
- `UniqueConstraint("user_id", "run_id", "as_of_date", name="uq_nav_user_run_date")`.
- **Append-only.** Mirror `ShariaUniverseSnapshotRow` (`models.py:822`) — its docstring documents
  exactly this rationale and is the house pattern.

> **FENCE — NO foreign key to `sim_portfolios`.** `sim_engine.reset_portfolio()`
> (`sim_engine.py:394`) hard-deletes the portfolio row and every `SimTradeRow`. A FK cascades the
> game's entire history away on the first restart. Key on `user_id` + `run_id` — the reset-immune
> shape `reputation_events` already proves. **A test must assert snapshots survive
> `reset_portfolio()`** or this regresses silently and invisibly.

**2. `backend/app/trading_math/twr.py`** — new, pure, no DB, matching the style of the existing
`returns.py` / `risk.py` / `portfolio_stats.py`:
- `sub_period_returns(navs)` — per-sub-period returns, **split at every capital event**.
- `time_weighted_return(navs)` — `TWR = Π(1 + rᵢ) − 1`; `None` below two points.
- `alpha_vs_benchmark(run_twr, benchmark_twr)` — excess return.
- Chain-linking at capital events is the GIPS standard and is the whole point: **a −40% run
  followed by a fresh stake must not read as flat.**

**3. Daily snapshot tick** in `main.py`'s `lifespan` (`main.py:146`):
- **Mirror `_sharia_universe_refresh` (`main.py:111`) or `_classification_universe_refresh`
  (`main.py:129`)** — both are **daily, idempotent** ticks, and their docstrings state the exact
  guarantee this needs: *"a tick that finds a fresh stored row does nothing, so a restart can't miss
  a boundary."* Blocking work goes in `asyncio.to_thread`.
- **Not `_league_roll_tick` (`main.py:95`)** — hourly, and it drives a weekly roll. Wrong shape.
- Write one row per user per US market date. Carry `price_source` from the mark, **never silently**
  — a mock-priced day must be visible in the row (CR040; it is what later voids a scored run).
- Reuse `sim_engine.portfolio_marks_snapshot()` (`sim_engine.py:415`, the one-fetch path from
  DEF120) rather than fetching per holding.

**4. Read endpoint** in `backend/app/api/sim.py` — the cross-lane contract with CR109-1-MOBILE:
- `GET /v1/sim/portfolio/{user_id}/history` → the NAV series for the curve: `as_of_date`, `nav`,
  `cash`, `price_source`, `capital_event`, plus the computed `twr_pct` for the window.
- **Every response carrying a number must carry its basis** — `price_source` per point, so the
  client can mark a mock day rather than draw it as fact. CR040 applied to the wire format.
- Follow the existing `api/sim.py` conventions (see `@router.get("/portfolio/{user_id}")` at
  `sim.py:117`).

**Constraints:** additive only. Do NOT alter `check_mandate_compliance`, `sim_engine.submit()`,
`reset_portfolio()`, or any existing signature — **this slice adds a reader and a writer, it changes
no existing behaviour.** No game tables, no scoring, no career points in this lane (slices 2–3).
Any new env setting must be forwarded in `docker-compose.yml`'s `api-alpha` block or
`test_config_compose_parity.py` fails the build (CR040). AMI by name in any user-facing copy; LLM
fine in code. Every new file gets a header docstring saying what it is and why.

**Tests** (plan §9, rows 1–3 — these three are the slice):
1. **NAV snapshots survive `reset_portfolio()`** — the fence, asserted directly.
2. **The tick is idempotent** across a container restart — running it twice for the same date writes
   one row, not two.
3. **TWR chain-links across a capital event** — a −40% run followed by a fresh stake does **not**
   read as flat. Assert numerically.
Plus: a mock-priced day is flagged in the row, not absorbed.
