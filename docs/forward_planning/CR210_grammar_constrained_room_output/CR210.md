# CR210 — grammar-constrained Room output

**Status:** in_progress (approved 2026-08-26 — Saiful: "Build all three now") · **Filed:** 2026-08-25 · **Origin:** CR196 run-2 acceptance

## Why

CR196 fine-tuned Fastino for ~42 GPU-hours across two runs. Its two solid wins were both
**output structure**:

| check | vanilla | tuned |
|---|---|---|
| S5 `has_side` (Trader block parses) | 26% | 100% |
| S6 `one_per_size` (sizes on the mandate ladder) | 57% | 100% |

The control arm asked whether structure needs training at all. It does not — but see the
withdrawal immediately below for what that control can and cannot be said to have shown.

> **WITHDRAWN 2026-08-27 — the "93%".** This CR originally read: *"Vanilla Fastino with a
> JSON-schema grammar reached 93% on S6 `one_per_size` with no training, and the residual gap was
> a token-cap artifact in the harness, not the method."* **No artifact survives.** There is no
> completions file, no scored JSON, and no row in `run2_results/` — the figure exists only as
> prose, here and in the register. 93% of 69 is 64.2, so the run was almost certainly partial.
> The harness change it depended on (`maxLength` bounds in `run_constrained.py`) is an
> **uncommitted working-tree edit**. And `run_constrained.py` never touched vLLM at all: its own
> header says vLLM was not installed on that box, and it drives `transformers.generate()` with
> `lm-format-enforcer`. Reproducing it would need Fastino weights, alpha-spark, `ami-train:v1`,
> and would answer a question about a model AMI does not serve. The number is withdrawn rather
> than repaired; the measurement that replaces it is in **Acceptance 4** below, on the model AMI
> actually serves.

**Verified on the live server 2026-08-25** — `ami-llm` (vLLM 0.23.1) already enforces schemas:

```
response_format: {"type":"json_schema","json_schema":{"name":"ladder","schema":{...enum...}}}
-> {"recommended": 1.5, "confidence": "high"}     # both values on the enum
```

Note: top-level `guided_json` is **ignored** by this vLLM version — it was silently dropped and
the model answered in prose. Only the OpenAI-standard `response_format` is honoured. That failure
mode is the whole reason §4's guard exists.

**Why it is ignored, established 2026-08-25 from the server's own `/openapi.json`:** `guided_json`
and `guided_regex` are not fields on this build's `ChatCompletionRequest` at all, and that model
declares **`additionalProperties: true`**. So any misspelled, renamed, or stale field is accepted
with HTTP 200 and discarded — permanently, silently, with nothing to catch. There is no status
code and no error to check. This is why the guard cannot be "handle the error" and has to be
"only ever emit a spelling that is pinned by a test."

## DEF376 — the defect this uncovered, and a prerequisite for the guard

`llm_gateway.py`'s SSE loop ended with `choices = obj.get("choices") or []` / `if not choices:
continue`. An in-band error frame has no `choices`, so it was **silently discarded**: nothing
yielded, `meta["finish_reason"]` never written, and `record_llm_call` handed `response_text=None,
error=None`. A refused grammar was byte-for-byte indistinguishable from a model with nothing to
say, and the Room would have failed safe to PASS with nothing anywhere to grep for.

Pre-existing, and true of every in-band error rather than only grammar ones — so it is filed as
**DEF376** and fixed separately, in both streaming providers plus the four `room_runner` call
sites (the `[AMI error: …]` sentinel is non-empty, so every `… or <fallback>` idiom would have
taken the truthy branch and put transport wreckage in the transcript). CR210's guard could not
work until it landed.

So the Room can have the structural guarantee **now**, at inference, independent of whether AMI
ever trains another model.

## Scope

### The measured base rates, which invert the order below (2026-08-27)

Scoring the 136 real convenes in `CR143_agent_prompt_audit/corpus/` — real Alpha traffic on
`ami-llm`, the model this CR actually changes:

| surface | production reality |
|---|---|
| **PM verdict** | **136/136 strict-parse.** 0 APPROVEs missing `size_pct`. 2 reformat calls (1.5%), both DEF352's trailing-prose shape, since fixed. |
| PM `action` off-contract | 4/136 (2.9%) — `MODIFY-AND-APPROVE` ×3, `MODIFY` ×1, rescued by `_normalize_pm_action`'s synonym table |
| **Trader money block** | **99/136 (73%)** on CR196's frozen `Side:` pattern; **119/136 (88%)** bold-tolerant. So ~12% of turns carry no readable block at all. |
| Risk officer | ~0.7% unparseable (CR201 round 2, n=272). No rows in this corpus — the flag went live 2026-08-21. |

This CR was written scoping the PM verdict first and hedging the Trader third. **The measured
failure rates are the inverse.** Decided 2026-08-27 (Saiful): build all three, **Trader first**.
The PM verdict schema stays — it makes the 2.9% off-contract actions unrepresentable and ends the
reliance on the tolerant parser for the safety-floor-adjacent surface — but it ships as a
*structural guarantee*, not as a fix for a measured failure, and any before/after on it must say
so rather than presenting 100% as an improvement on 100%.

Per-agent schemas for the surfaces whose contract is machine-read:

1. **PM verdict** (`_parse_pm_verdict`) — `action` enum, and when `APPROVE`, `size_pct`/`entry`/
   `stop`/`target` all present. This is the safety-floor-adjacent contract; CR143 built a
   tolerant parser to cope with it not holding.
2. **Risk-officer size ladder** — `size_pct` and `recommended` as an **enum of the mandate's own
   ladder**, so an off-ladder size is unrepresentable rather than merely discouraged. This is the
   check the fine-tune won 57% → 100%.
3. **Trader money block** — NOT JSON, so it needs vLLM's regex structured-output rather than
   `response_format`. ~~Verify that path is supported on 0.23.1 before committing to it~~ —
   **verified working 2026-08-25** via `structured_outputs.regex` (see the probe table above).

   **`run_constrained.py::regex_S5` is NOT shippable as written.** It was authored against the
   eval harness, not against production's parsers, and differs from the production contract in
   five places — each of which would have the grammar manufacture a defect:

   1. `R:R: +\d{1,2}\.\d{1,2}\n` emits a bare `R:R: 2.50`. **Measured:**
      `_extract_stated_rr("R:R: 2.50")` returns `None`, because `_rr_ratio` needs a trailing
      `:N` / ` to N` / `x`. `_annotate_rr_against_levels` would then print *"the proposal stated
      no R:R, so AMI rendered it"* under *"These are the figures of record"* — DEF288's exact
      false claim, recreated by grammar. Must force `N.NN:1`.
   2. `HEADLINE: [^\]\n]{1,90}` against production's `STANCE_HEADLINE_MAX_CHARS = 32`. At 90 the
      grammar legalises headlines that `room_runner.py` then nulls — manufacturing gutter entries.
   3. `STANCE: (?:for|against)` omits `neutral` and `none`, both of which `_build_stance_format`
      explicitly offers and production Traders emit.
   4. One branch with `Size/Entry/Target/Stop/R:R` all mandatory **forces a `WAIT` to state a
      price triple it does not believe in** — the grammar manufacturing a fabrication. Nothing
      downstream needs those levels: `ctx.trader_entry/stop/target/size_pct` are seeded
      deterministically before the Desk speaks and are never parsed back out (DEF235). `WAIT`
      needs its own branch.
   5. `[A-Z.]{1,6}` for the instrument, where the run's own ticker is known — pinning it makes a
      proposal for the wrong name unrepresentable, free.

   `Entry: market` stays **allowed**, matching `content/agents/trader.md`. Forbidding it would buy
   a parser guarantee by pressuring the model to invent a price when it means a market order,
   which is the trade this codebase exists to refuse.

## Non-goals

- **Do not constrain prose.** S1 analyst reports, bull/bear turns, Research-Manager synthesis stay
  free. A grammar guarantees form and says nothing about content; constraining prose measures the
  schema author, not the model. Vanilla already scores 43/44 on the S1 basis rubric.
- **Do not delete the CR143 tolerant parser.** It is the fallback for every provider that does not
  enforce schemas (anthropic / kimi / mock). Removing it converts a degraded path into an outage.
- **Not a model swap.** `ami-llm` stays whatever it is; this is a request-shape change.

## Bound every free-text field, or generation hangs

**Measured 2026-08-25, after this CR was first written.** A JSON schema whose string fields
have no `maxLength` can prevent the model from ever finishing. An unbounded string is a state
the grammar can always extend, so the model keeps writing prose inside the field and never emits
the closing quote.

Evidence: with `"case_for": {"type": "string"}`, **3 of the first 11 generations ran to a
2,400-token ceiling**, cut off mid-sentence inside that field. Raising the ceiling from 1,200 to
2,400 did **not** fix it — it only made each failure twice as expensive. Adding `maxLength` is
what terminates generation.

This is the trap in this CR, because it does not look like one:

- The schema is *valid*; nothing rejects it.
- Most calls succeed, so it presents as an intermittent stall, not a bug.
- In the Room it would surface as the PM-verdict path occasionally hanging, with a correct-looking
  schema and no error to grep for.

**Requirement: every free-text field in every schema carries an explicit `maxLength`.** Load-bearing,
not stylistic. Worked values in `CR196.../eval/surfaces/run_constrained.py`: narrative fields 400,
short numeric-reference fields 60, PM `narration` 1200.

A corollary for §4's guard: a constrained call that hits the token ceiling is a **schema failure**,
not a slow success, and must be recorded as one.

## The guard (CLAUDE.md "degrade loudly", CR040)

Structured output is **config-gated per provider**, and that is exactly the shape that has gone
dark twice before (DEF038, DEF063) — plus the `guided_json` silent-drop proven above.

- A schema-constrained call whose response **does not parse** must be recorded as a schema
  failure, not silently handed to the tolerant parser as if nothing happened.
- Providers that cannot enforce schemas must be **explicitly marked** as unconstrained, so
  "the PM verdict parsed" never means two different things depending on which provider answered.
- New env-driven settings must be forwarded in `docker-compose.yml`'s `api-alpha` block or
  `backend/tests/unit/test_config_compose_parity.py` fails the build.
- **The in-band error frame (DEF376) is part of this guard, not adjacent to it.** A refused
  grammar arrives as HTTP 200 with an `{"error": …}` SSE frame, which the gateway discarded in
  silence. Until that was fixed, "schema failure" had no observable to key on.
- **A `maxLength` stop is a SILENT truncation** and needs its own disclosure. The grammar closes
  the JSON validly and `finish_reason` is `"stop"`, so none of the three existing disclosure paths
  fire — not `llm_call_length_stop`, not `room_pm_truncated`, not `_PM_TRUNCATED_NARRATION`. Today
  a clipped PM narration is at least *marked*; under a grammar it would be clipped and unmarked,
  on the one string rendered as the decision's justification. That is a net loss of honesty this
  CR would introduce, so the bound — a known integer — is checked exactly (`len(narration) ==
  PM_NARRATION_MAX_CHARS`) and the existing truncation mark is appended.

## Where it plugs in

- `backend/app/services/llm_gateway.py` — `extra_body` already exists (ctor arg at ~L440, merged
  into the request at ~L490, already used for `enable_thinking` at ~L753). Passing
  `response_format` needs plumbing, not new architecture.
- `backend/app/services/room_runner.py` — per-agent call sites choose the schema.
- Schemas belong next to the prompts they constrain, not in the gateway.

## Acceptance

Re-scoped 2026-08-27 after the measurements above. Each original is kept verbatim with what
replaced it, because three of the five cannot be satisfied as literally written and saying why is
the point.

**1. ~~A real Room run where the PM verdict and risk-officer ladder are schema-constrained, and
`_parse_pm_verdict` receives valid JSON on every turn.~~**
As written this is **unfalsifiable**: the *unconstrained* system already returns valid JSON on
136/136 recorded production convenes, so a constrained run showing 100% is indistinguishable from
the control showing 100%. It can only be passed, never failed. Replaced by:
> **1a.** Across the CR210 Room batch, `room_pm` strict-parse = n/n, `room_pm_reformat` = 0,
> `room_risk_officer_degraded` = 0 — reported **beside** the unconstrained batch's identical
> figures and the historical base rate, so the reader can see the numerator was already zero.
> **1b.** The PM schema's real claim, which *is* falsifiable: the four off-contract `action`
> values measured in production (`MODIFY-AND-APPROVE` ×3, `MODIFY` ×1) become unrepresentable,
> and the run's verdicts do not otherwise move.

**2. ~~An off-ladder size is impossible, demonstrated against the live model.~~**
"Impossible" is a property of the decoder, true by construction — an `enum` state admits no other
token sequence, and no number of probes strengthens that. What a probe establishes is that the
enum is genuinely applied end to end, that the model tries and fails under adversarial pressure,
and that it would have succeeded without it. Replaced by:
> **2.** A committed, re-runnable probe over real S6 prompts × adversarial suffixes, **in two
> arms** — the unconstrained arm is what makes the claim falsifiable. Three separately-scoped
> results: (i) off-ladder `recommended`, (ii) off-ladder `options[].size_pct`, (iii) off-ladder
> numerals in the **free-text** fields. An enum makes a size unrepresentable in the schema-bound
> *numeric* field; it is `risk_officer.py`'s render-from-`rows` that stops a number in prose ever
> reaching a user. Two distinct guarantees — state both, and never "impossible" unqualified.

**3. A provider without schema support degrades loudly — surfaced, logged, and distinguishable
from a constrained success.** *(unchanged, and met)* — the enforcing layer is
`test_cr210_outcome_taxonomy.py`, which pins all five states including NULL-vs-`unsupported`; the
live demonstration is one Alpha convene under `LLM_FORCE_PROVIDER=kimi` (registered, real,
non-enforcing — `mock` is a poor demonstration since everything degrades under mock).

**4. ~~Before/after on the CR196 instrument … so the numbers compare directly to run 2's table.~~**
**Cannot be satisfied.** Run 2's arms are Fastino on local `transformers` at a 4000-token budget;
this CR changes ami-llm (Qwen3.6-35B-A3B-NVFP4) on vLLM. Of seven axes — model, engine, decoding
determinism, thinking mode, output budget, prompts, scorer — only **prompts and scorer** are
shared. Differencing across the two tables would be an extrapolated number stated as a measured
one. Replaced by:
> **4.** A same-model, same-session, **per-`pid`-paired** before/after: ami-llm unconstrained vs
> ami-llm grammar-constrained over the 197 grammar-eligible held-out prompts (S4/S5/S6), through
> the **unmodified** `eval_surfaces.py --stage score`, with an unconstrained replay arm as the
> noise floor (vLLM at `temperature=0` is not bitwise deterministic). Reported with a
> **GUARANTEED / MEASURED column** — under the grammar `S4.parses`, `S5.has_side` and `S6.parses`
> are decoder tautologies (`regex_S5` literally contains the scorer's own pattern), and without
> that column four fifths of the table reads as a model win. Run 2's table is reproduced alongside
> under a fixed header naming the confound. S1/S2/S3 are this CR's own declared non-goals, and
> S7/S8 have no grammar — constraining a *refusal* surface would be actively harmful.

**5. `test_config_compose_parity.py` green.** *(unchanged)*
