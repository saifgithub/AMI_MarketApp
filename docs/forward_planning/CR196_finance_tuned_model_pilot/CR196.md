## §2 Training data plan

Decontamination rule: never train on the 45-ticker `basis_ground_truth` set, the captured AAPL case,
FinanceBench, or any benchmark's dev/test split. Train tickers ∩ eval tickers = ∅, frozen in a committed file.

**Tier A — generated from our own feeds; labels computed, not judged.** The Yahoo feed (yfinance) is the
backbone: statements, `.info`, price history are enough to *generate* grounded briefs with programmatic
labels. (License posture: the raw feed is never redistributed — the dataset stays private and weights carry
derived analytical text; same posture as production's existing yfinance use.) Generator recipes:

1. **Basis-mismatch fixtures** — extend the `basis_fixture.py` pattern (copied into our workspace) to
   ~300–500 train tickers; annual-vs-quarter, definitional (cash vs cash+STI, gross vs net debt), genuine
   conflicts — with target answers that *do* reach L2/L3.
2. **Ratio computation + interpretation** — exact numeric ground truth from statements.
3. **Trend reasoning** — computed deltas/CAGRs as the verifiable spine.
4. **Earnings-quality flags** — accruals vs cash flow, receivables outrunning revenue, inventory builds.
5. **Basis-trap generalization** — TTM vs FY, diluted vs basic EPS, rendered as deliberately ambiguous briefs.
6. **As-of-date discipline** — briefs "as of X" from data available then; refusing post-date knowledge is
   the correct behaviour (targets lookahead contamination, `01_prediction_edge_and_caution.md`).
7. **Mandate-overlay compliance** — briefs × mandate overlays via the salvaged CR032 recipes
   (`original_silent_scout_research/02_data/recipes/`), regenerated against current schemas, overlay
   user-side; labels from the mandate rules.
8. **Structured-output formatting** — our exact Room JSON verdict shapes; trains in what CR143 documented
   as reformatter/tolerant-parser scaffolding.
9. **Refusal/abstention** — missing/invalid-data briefs where "cannot be determined" is correct.
10. **Real prompt distribution** — melehost `llm_audit` prompts as inputs; targets best-of-n from open
    teachers (DeepSeek-R1 / self-distilled Fastino), filtered by the programmatic verifiers. **NOT Claude**
    (Anthropic's terms bar training competing models on Claude outputs — the Silent_Scout "Opus
    distillation ladder" is retired for this purpose).
11. CR164 historical sheet / outcome arm → **eval only**.

Primary-source additions: **SEC EDGAR/XBRL** (public domain; the SEC-Num skill Fastino's mix prioritized)
and earnings-call transcripts (`kurry/sp500_earnings_transcripts`). Recipes 1–7 double as an **RLVR
environment** (verifiable rewards) if a GRPO stage is ever warranted.

**Tier B — public SFT:** FinQA/TAT-QA/ConvFinQA train splits (verify licenses; double as replay protecting
the Fastino skills), Finance-Instruct-500k (Apache-2.0) slice, Fin-R1-Data (gated — verify access/license/
CN-EN split first), financial-rlvr-10k-enterprise (MIT), UltraChat-200k replay slice. Target ~30–60k total,
cutoff 8192, chat-JSONL per `02_data/samples/sample_shape.jsonl`. License gate per the Silent_Scout
checklist (CC-BY-NC ⇒ not for distributed weights; untagged ⇒ skip).

**Mixture/feature optimization (Saiful's pointer): SA-FDR** — simulated annealing over feature subsets
with the Fisher discriminant ratio as a cheap quality proxy (arXiv 2507.23568; finance sibling 2303.02223).
(a) recipe-level: select the *discriminative* brief features against programmatic labels (closed-form, no
training in the loop); (b) mix-level: SA over mixture weights with an embedding-FDR or short-probe
objective, capped at ≤10 probes — replaces the 45/45/10 starting guess with a measured mix.

**How Fastino was trained (card + blog, read 2026-08-19):** LoRA rank 32, lr 1e-4, 2 epochs, packing
disabled, 13,698 dedup examples prioritizing SEC-Num + BizFinBench with FinQA/TAT-QA/FinEntity retained;
produced end-to-end by their autonomous Fine-Tuning Agent (Pioneer Agent, arXiv 2604.09791) in <10 hours;
harness, hardware, and provenance beyond the benchmark families undisclosed.

**Base checkpoint — DECIDED (Saiful, 2026-08-19): the Fastino merged BF16** (`Model/fastino-finance-bf16`,
62G, SHA256-verified on ami-host), with Tier B replay guarding its skills. Clean-base control only if eval
shows regression.

## §3 Build — offsite training kit + pipeline

The training GB10 may be offsite, so the deliverable is a self-contained **`ami_finetune_kit/`** an
operator runs from a runbook: pinned container env (NGC `pytorch:26.01-py3` or Unsloth's DGX Spark image),
`download_base.py` + SHA256 manifest (the 62G travels via HF, not in the package), our train/val JSONL +
license manifest, `smoke_test.sh` (10-step run → save → merge → reload → generate; Unsloth-first,
TRL+PEFT auto-fallback), `train_lora.py` + frozen config (rank 32, α 64, checkpoints ~30 min, resume
proven), `quick_eval.py`, and a return manifest: **the adapter only** (~100s of MB), `trainer_state.json`,
logs, smoke report. Smoke-first go/no-go; **acceptance = returned artifacts, never the operator's word**.
Merge + NVFP4 PTQ (NVIDIA Model Optimizer) + full eval happen on our side; vanilla Fastino gets quantized
first with the same pipeline (the original pilot brief's open question).

Phases: 0 harness smoke (small nemotron_h sibling co-resident on ami-host; full-size smoke is the kit's
gate) · 1 data build + kit assembly · 2 SFT offsite (1–2 GPU-days) · 3 merge+PTQ · 4 eval (held-out basis
rubric, 3-lens batch vs Qwen3.6 + vanilla Fastino, BF16-vs-NVFP4 diff, fixed `mandate_compliance_eval.py` —
the `side=Side.BUY if is_buy else Side.SELL` repair CR032 recorded) · 5 adoption gate.

## §4 Adoption path + decision gate

1. The `ami-llm` alias makes a `:8000` swap invisible to AMI Trade — which is the risk, not the reassurance.
2. Reasoning parser stays OFF in the slot (`--reasoning-parser nemotron_v3` routes the whole answer into
   `message.reasoning`, `content=None` — verified live by the lane 2026-08-19). Acceptance asserts non-empty
   `content` on a real Room call.
3. Token budget: reuse `max_tokens_floor` (CR130 mechanism, `llm_gateway.py`) — value from measurement, or
   a written statement that none is needed with thinking off.
4. CR192's `status="reset"` after a swap-restart is the honest cache answer; no second alarm.
5. A side-port candidate must register as `VLLMProvider` (not bare `OpenAICompatibleProvider`) or it
   silently loses the CR077 startup guard — a decision, not an accident.
6. A/B without touching live traffic: register on its own port + `LLM_FORCE_PROVIDER` (the CR130/CR141
   pattern in `infra/alpha.env.example`). Any new `Settings` field is forwarded in `docker-compose.yml`
   (parity test).
7. **A production `:8000` swap is Saiful's explicit call, not implied by winning the eval.**

Window protocol (only if training lands on ami-host after all): deferred by Saiful; facts on file — kimi is
the only real fallback key on melehost; the Manager watchdog must be paused by its owners or it restarts
production mid-training; our workspace is our own directory, the lane's scripts untouched.
