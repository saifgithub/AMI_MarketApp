# CR212 — `youtube-extract` skill: pull a YouTube transcript, review it against what we ship

**Filed:** 2026-08-30 · **Track:** R · **Status:** done

## Why

Saiful sent a 58-minute trading video and asked what we could learn from it. Getting the
transcript took four failed approaches before one worked, and the review that followed
made a mistake worth encoding against.

**The fetch problem is real and non-obvious.** YouTube's `timedtext` endpoint returns
**0 bytes** without a session token; the innertube `player` fallback (ANDROID client)
returns **HTTP 400**; `youtubetotranscript.com` sits behind a Cloudflare JS challenge.
Only `yt-dlp` works, because it solves the player JS challenge (it shells out to `deno`).
Raw auto-caption VTT is then unreadable — the rolling caption redraws every line 2–3×.
A 58-minute video is 549 KB of VTT that dedupes to 59 KB of text.

**The review problem is the one that matters.** On the first pass I reported the video's
psychology half as a finding — and it was already shipped as **CR062** (EVAL 1–8, lessons
357–364, sourced to Duke/Taleb/Marks, CR060-verified, translated). I also dismissed the
strategy half on instrument and horizon without asking whether its *shape* transferred;
Saiful pushed back ("*he describes when he would trigger a buy*") and he was right — the
two-attempt confirmation rule and structurally-derived invalidation carry over fine, and
they land squarely on `Verdict.entry` being a scalar price with no condition attached, and
on `room_runner.py:1801-1802` minting `entry * 0.94` / `entry * 1.13` as stand-ins for
structural invalidation.

Both failure modes are cheap to prevent with a checklist, and neither is specific to
trading videos.

## What shipped

`.claude/skills/youtube-extract/` — the repo's first `.claude/skills/` entry (it previously
had only `.claude/commands/`).

- **`SKILL.md`** (66 lines) — fetch, then read `meta.txt` *before* the transcript (who
  published this, what do they sell), then a review discipline: segment long videos by
  value; **check what we already ship before recommending anything**; sort every idea into
  *transfers as-is* / *transfers in shape only* / *needs data we don't have*; judge the
  mechanism separately from the medium; never repeat a self-reported performance number as
  fact; separate what a speaker demonstrates from what they assert.
- **`scripts/fetch_transcript.py`** — `yt-dlp --dump-json` for metadata (title, channel,
  publish date, duration, chapters, full description) plus `--write-auto-subs` for captions;
  dedupes the rolling repeats, unescapes HTML entities, merges into `[mm:ss]` blocks.
  Prefers a manually-authored caption track over ASR. Writes `meta.txt` + `transcript.txt`
  to a `--out-dir` (the session scratchpad; transcripts do not belong in the repo).

## Verification

Run against two real videos, both green:

| Video | Result |
|---|---|
| `PL7LKUsCgIQ` (58m, no chapters, `&t=` in URL) | 114 blocks; reproduced the hand-rolled extraction exactly |
| `bXVHsViQuyE` (23m, 10 chapters) | 46 blocks; chapter list rendered from `--dump-json` |

Two defects found and fixed during verification: HTML entities left raw (`&gt;&gt;` instead
of the `>>` speaker marker), and ASR/manual track preference unspecified.

No production code touched. `yt-dlp` installed globally via Homebrew (2026.8.19) at Saiful's
instruction — *"install it so that it can be used by other repo as well"*.
