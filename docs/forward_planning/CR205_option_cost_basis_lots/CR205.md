## The correction: option lots are not FIFO, and forcing them would be wrong

FIFO matches a *sell* against earlier *buys* of a fungible thing. Option legs
in this schema are not accumulated into a running position the way shares are:
each `SimOptionLegRow` **is** one position, opened once and closed once,
carrying its own `state` / `close_price` / `realised_pnl`. There is nothing to
match. Running FIFO over them would invent a queue the ledger does not have,
and the result would disagree with the leg's own recorded `realised_pnl` the
moment two legs on one `occ_symbol` overlapped.

`OptionLot` is also a separate type from `Lot` rather than a reuse, because two
fields would silently change meaning: `entry_price` on an equity lot is dollars
per share, on an option it is **premium per share**, and the dollars that moved
are `premium × multiplier × contracts`. One type would put $9.10 next to $195
in the same column and invite the reader to add them.

## What the §11 audit found

- **`merge_service` — DEF368, filed and fixed in the same pass.** Claiming an
  anonymous account **silently destroyed every option position**. The orphan
  portfolio is `DELETE`d and `sim_option_legs.portfolio_id` is
  `ondelete="CASCADE"`, so the legs went with it — no error, because a CASCADE
  is not a failure. Not reachable today (0 of 42 mandates permit derivatives),
  which is the only reason it was latent rather than live.
- **`day_trader_outcomes`** — clean. Scores equity day-trades; models no
  option position and needs none.
- **`price_alert_store`** — clean. Alerts on underlying tickers; options carry
  no alerts of their own.

`derivatives_allowed` is on **0 of 42** mandates.
