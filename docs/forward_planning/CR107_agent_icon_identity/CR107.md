# CR107 — Agent icons: one identity mark, sized by surface

**Status:** proposed · no code, no icons drawn yet
**Track:** UI Designer · **Raised:** 2026-07-28 · **Depends on:** CR106 Phase 1 (sequencing only)

---

## 1. Why

Saiful, 2026-07-28, on the CR106 comb comparison: *"I like the icons, but we now need to see how we can
use the icons elsewhere too, like the floor landing page. But customers will need to learn the symbols."*

The learning concern is real and it is answerable. The other half of the case is stronger than aesthetics:

**Agent identity is hardcoded English with zero ARB coverage.** `abbreviation` and `displayName` are
`const` strings in [`agent.dart`](../../../mobile/lib/models/agent.dart); a grep of `app_en.arb` returns no
agent-name keys. **AR and MS ship at v1.0.** An Arabic user today reads `FUND`, `RES-M`, `TRADE` in Latin
script on the Floor honeycomb, in the lesson reader, and in every 1-on-1 header. An icon needs no
translation. That is the argument for this CR; CR080 already found the same untranslated-label class live
in `tabFloor` / `tabPortfolio`.

---

## 2. The rule

> **Icons at ≥44pt. Letters at ≤32pt. Same identity, different zoom — never competing schemes.**

Evidenced, not asserted: 12 draft icons rendered at 56pt read cleanly as a set; the identical set at 26pt
collapses into blobs while the letters stay legible. The app's shipped sizes split cleanly on that line.

| Surface | Size | Mark |
|---|---|---|
| `agent_unlocked_screen` | 160pt | **icon** |
| `one_on_one_screen` header | 120pt | **icon** |
| Floor honeycomb (`floor_screen.dart:172`) | 56pt | **icon** |
| Lesson reader — agent unlocked (`:911`) | 48pt | **icon** |
| Lesson reader — chat-with (`:337`), brief, brief history, 1-on-1 row | 44pt | **icon** |
| League row | 32pt | letters |
| Room transcript avatar, lesson-reader callout | 28pt | letters |
| CR106 consensus comb | 26pt | letters |

**Why the learning problem solves itself.** At every icon size the agent's name already sits beside or
below the hex — `floor_screen` labels its honeycomb, `lesson_reader_screen.dart:337-345` prints
`CHAT WITH {displayName}` next to a 44pt hex, and `:911-921` pairs a 48pt hex with `displayName`. So icon
and name always appear together, the way app icons on a home screen teach themselves. No legend, no quiz.
By the time a user meets a 26pt comb they have seen the pairing many times — and the comb shows letters
anyway.

---

## 3. Scope: 12 agents (+ Concierge), not 25

An earlier read of this put the program at 25 marks — 12 agents plus the 13 lesson-track hexes. That was
wrong, and Saiful corrected it: *"lessons (the actual lessons) are tied to agents."* They are —
`Lesson.agentCallouts` / `gatesAgents` / `chatWithAgent`, rendered as
`HexAvatar(label: agentById(id).abbreviation, …)` at all three lesson-reader sites. **There is no separate
two-letter lessons scheme to migrate.** The same 13 strings serve everywhere: `FUND MKT NEWS SOC BULL BEAR
RES-M AGG CON NEU TRADE PM CNC`.

So **13 icons buy the whole program** — Floor, agent detail, 1-on-1, Brief, Brief history, and the lesson
reader.

**Explicitly out of scope: the 13 lesson-*track* hexes on the lessons landing.** Different entity
(`honeycombTrackLabel` — `FOUNDATIONS`, `NEWS & MACRO`, `ISLAMIC FINANCE`…), full-word labels, and its real
problem is a layout one that needs no icon: `hex_clipper.dart:85` records `ISLAMIC FINANCE` with 4.7pt of
headroom at 1.0 text scale and **none at 1.15**. Moving that label *below* the hex fixes it outright. File
separately if it is still wanted afterwards.

## 4. Two `HexAvatar` defects this CR must fix first

Both found while sizing the CR106 comb labels; both are live today.

1. **White ink on the family fill** ([`hex_avatar.dart:156`](../../../mobile/lib/widgets/hex/hex_avatar.dart#L156)) —
   `Colors.white` measures **1.8:1** on `hexAmber` and **2.1:1** on `hexGreen`, below even the 3:1
   large-text floor. Affects all three Risk debators and the Trader, on every surface. Ink must be
   `slate900`, which clears 7:1 on all six family fills and serves both themes because fills keep their
   tone in light mode.
2. **`fontSize: size * 0.16`** ([`:154`](../../../mobile/lib/widgets/hex/hex_avatar.dart#L154)) — tuned for
   the 96pt Floor hex, where it gives 15.4px. Everywhere else it is a smudge:

   | Hex | Label |
   |---|---|
   | 28pt (Room transcript, lesson callout) | **4.5px** |
   | 44pt (lesson chat-with, brief, 1-on-1 row) | **7.0px** |
   | 48pt (lesson agent-unlocked) | **7.7px** |
   | 56pt (Floor) | 9.0px |

   This is almost certainly why the lesson hexes read as "two letters" — `RES-M` and `TRADE` at 7px are
   indistinguishable shapes. A ratio is the wrong model; small avatars need a floor.

Fixing #2 alone materially improves the surfaces this CR touches, so it is worth landing **before** any
icon work — it is also the honest control: if legible letters at 44pt turn out to be enough, the icon
program is optional rather than necessary.

---

## 5. Risks

- **An icon set fails collectively, not individually.** Two of the 12 drafts already fail at 56pt:
  `research_manager` (a hook that means nothing) and `portfolio_manager` (an arch that says nothing).
  `trader`'s plain right-arrow is generic. These need redrawing before anything ships.
- **Semi-permanent.** Changing an icon after users have learned it costs more than never shipping one.
- **Hand-authored inline SVG only** — the design system forbids icon CDNs and libraries
  (`README.md:155-168`). A 14th agent means a new drawn mark, not a new string.
- **Half-conversion is worse than either end state.** If icons land on Floor but not the lesson reader,
  the same agent has two identities.

---

## 6. Acceptance

1. All 13 marks distinguishable **as a set** at 56pt by someone who has not seen the legend — tested on
   the real Floor honeycomb layout, not a grid.
2. Every icon surface pairs the icon with the agent's name; no surface shows an icon alone.
3. No surface below 44pt uses an icon.
4. `HexAvatar` ink is `slate900` and its label has a size floor; both verified at 28 / 44 / 48 / 56pt.
5. Icons render identically in light and dark (they sit on accent fills, which do not change tone).
6. Consistent with CR106: the comb, the transcript avatar and the league row keep letters.

---

## 7. Not decided yet

Whether to draw the set at all is Saiful's call. §4 is worth doing regardless — those are live defects.
The icon program is worth doing **if** the i18n argument carries; if AR/MS agent names get ARB coverage
instead, letters remain defensible and this CR can be dropped.
