# CR200 — Management Console

**Date:** 2026-08-20 · **Status:** in_progress · **Track:** AT:R74
**Elicitation:** [`.deliveryos/elicitation/management-console.md`](../../../.deliveryos/elicitation/management-console.md)

## What

Grow the existing `/admin` vanilla-JS SPA (users + messages tabs, CR102/CR103)
into the operations console for AMI Trade. Slice 1 ships six tabs total:

| Module | Today | After |
|---|---|---|
| Users / support | ✅ exists | unchanged |
| Messaging | ✅ exists | unchanged |
| **Bug triage** | psql over SSH (`/fix-bugs`) | list / claim / resolve / reopen / attachment over `/v1/admin/bugs` |
| **Health & status** | hand-typed curls | `GET /v1/admin/overview` — readiness, build, LLM + cache rate, release floor, market data, open bugs |
| **Push console** | `docker exec` only (CR193) | `POST /v1/admin/push` wrapping `notify()`, preview-before-send |
| **Analytics** | nightly offline HTML (CR051) | live `/v1/admin/analytics/*` + persona segments (CR181), SVG charts |

Foundation (this CR's first commit):

- **Operator identity via Cloudflare Access.** `get_admin` now returns an
  `AdminIdentity`: a verified `Cf-Access-Jwt-Assertion` (CF email = human,
  `common_name` = service token) or the legacy ADMIN_SECRET bearer
  (`static_bearer`). Verification reuses `services/oidc_verifier.py` — zero
  new dependencies. CF path enabled only when `CF_ACCESS_TEAM_DOMAIN` +
  `CF_ACCESS_AUD` are both set; half-set logs `cf_access_half_configured`
  loudly and stays off (CR040).
- **`admin_audit` table.** Every admin write records operator, auth_kind,
  action, target, payload — added to the caller's session so the audit row
  commits iff the action commits. Excluded from `trim_audit_tables()`.

## Why

Operating the live Alpha means SSH + psql archaeology; auth is one shared
secret with no operator identity and no action audit. Saiful: operators are
"saiful, agent and future staff", platform choice "whats the least work?",
access "cater for beta and prod — CF is a better answer". Decisions and the
full question log live in the elicitation ledger.

## Scope

- In: the four modules above, CF Access identity, `admin_audit`, SPA
  modularization into `backend/app/static/admin/` (no build step).
- Out (deferred): roles/permissions, content/config ops module, per-device
  push targeting, replacing the `/fix-bugs` psql workflow (coexists, same
  claim semantics), covering `/v1/admin` with CF Access (phase B — after
  agent scripts carry service-token headers).

## Acceptance

1. `pytest backend/tests/unit/ -q` green; compose-parity guard covers
   `CF_ACCESS_TEAM_DOMAIN` / `CF_ACCESS_AUD`.
2. A console bug claim and a `/fix-bugs` psql claim can never double-claim
   (atomic UPDATE, 409 on loss — test-proven).
3. Push to a named user from the browser; failures (`not_configured`,
   `rate_limited`, `duplicate`, `failed`) surface loudly.
4. `GET /v1/admin/overview` returns every block; a failing probe degrades to
   an `{"error": …}` block, never a 500.
5. Every admin write leaves an `admin_audit` row naming the operator; with CF
   configured, the row carries the CF email / service-token name.
6. After Saiful's CF setup ([cf_access_checklist.md](cf_access_checklist.md)):
   incognito `/admin` shows the CF login; a service-token curl reaches the
   API; bearer-only LAN access still works.
