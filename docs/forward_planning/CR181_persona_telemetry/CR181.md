# CR181 — persona telemetry: the four segments, actually measured

**Status:** proposed
**Filed:** 2026-08-13 · AT:R71, carved out of CR173 acceptance #11 (see CR173 Amendment C)

---

## 1. Why this exists as its own CR

CR173 §5.11 asked for the four persona segments — **bounce / convene / depth / locale** —
to be tagged on the shipped surfaces, and justified it in one clause: *"events already exist
in the queried tables."*

That clause is false, and it was checked rather than assumed while building CR173:

```
grep -n "persona\|segment" backend/app/db/models.py   → no matches
grep -rn "logEvent\|analytics\|telemetry" mobile/lib/ → no matches
```

The four event tables that do exist — `subscription_events`, `reputation_events`,
`revenuecat_events`, `career_events` — are all written by billing, reputation or the game.
None carries a user segment, and **none is written from a UI interaction at all.** There is
no client emitter, no ingest endpoint and no table.

So #11 was not a tagging job on top of an existing pipeline; it was the pipeline. Building
it inside CR173 would have contradicted that CR's own §4 ("the only candidate backend
surface is the price lookup") and, worse, invited the half-version: a segment written to a
column nobody queries, which reads as measurement and is not.

## 2. What it is for

Research 08's persona work is the evidence base for the whole Floor v0.2 redesign — 172
real alpha users, 73% taking no core action, ≤6% opening a 1-on-1, Brief Your Agent at 0%.
Those numbers came from a manual read of the database. The redesign shipped against them
and there is currently **no way to tell whether it moved them.**

That is the actual deliverable: not "tagging", but being able to answer *did A′ change what
users do* without another manual archaeology pass.

## 3. Scope sketch (to be firmed up before build)

- The four segments, defined so they are derivable rather than guessed:
  **bounce** (opened, no core action), **convene** (ran a Room), **depth** (opened a 1-on-1,
  the firm screen or a lesson), **locale** (the app locale in force).
- A minimal client emitter and one ingest endpoint. Cheap, batched, and **explicitly
  fail-quiet in a way that does not fake success** — a dropped event must be countable.
- One table + migration, with a retention decision made at file time, not deferred.
- `docker-compose.yml` forwarding for anything env-gated, or
  `test_config_compose_parity.py` fails the build (CR040).

## 4. What must not happen

- **No segment written that nothing reads.** If the query that answers §2 is not written in
  the same CR, the column is decoration.
- **No LLM anywhere near segmentation.** These are deterministic predicates over recorded
  behaviour (CR038).
- **No PII beyond the device user id the app already carries.** Locale is a setting, not a
  location.

## 6. Backend delivery record (AT:R73, 2026-08-20)

The backend half is in-tree; the mobile emitter and the `main.py` router wiring are
deliberately NOT here (emitter is the mobile lane's; wiring is the orchestrator's).

**What landed**

| Piece | Where |
|---|---|
| Table `persona_events` + migration `a181a000002a` (revises `a135a000001f`) | `backend/app/db/models.py::PersonaEventRow`, `backend/alembic/versions/a181a000002a_cr181_persona_events.py` |
| Ingest `POST /v1/telemetry/events` (auth user, batched, idempotent) | `backend/app/api/telemetry.py` |
| §2 answering query `GET /v1/telemetry/segments?since=&until=` (ADMIN_SECRET bearer) | same router → `persona_telemetry.segment_counts` |
| Segment predicates + wire vocabulary | `backend/app/services/persona_telemetry.py`, `backend/app/schemas/telemetry.py::TELEMETRY_EVENT_TYPES` |
| Tests (boundaries, idempotency, isolation, drops, window edges, retention) | `backend/tests/unit/test_cr181_persona_telemetry.py` |

**The predicates, exactly** (deterministic, no LLM — §4 held):

- `bounce` = ≥1 `app_open` AND zero engagement events. Engagement = §8.1 core
  (`room_convene`, `one_on_one_open`, `lesson_open`, `trade_place`,
  `challenge_attempt`, `brief_edit`) ∪ `firm_open` — someone who opened the firm
  screen explored (depth), so they are not a door-bouncer.
- `convene` = ≥1 `room_convene`.
- `depth` = ≥1 of `one_on_one_open` | `firm_open` | `lesson_open`.
- `locale` = latest event's non-null locale by (`occurred_at`, `received_at`).
- Windows are half-open `[since, until)` on `occurred_at`, UTC.
- `client_drop` marker rows carry the emitter's discard count (`count` column) —
  countable, and never read as engagement.

**Decisions made at file time**

- **Retention: 400 days raw rows** (covers a year-over-year window read), enforced
  per-user on the ingest path itself — no scheduler to ship dark. One line for
  Saiful: shout if you want a different number; changing `RETENTION_DAYS` is one
  constant + its test.
- **Idempotency**: client-generated `event_id`, unique per (user_id, event_id),
  settled by dialect-native `INSERT .. ON CONFLICT DO NOTHING` — the DB decides,
  not deployment topology (CR095 lesson). Replays report `duplicates` (CR040).
- **No new env settings** — the segments read reuses the existing `ADMIN_SECRET`
  gate, so there is nothing to forward in `docker-compose.yml`
  (`test_config_compose_parity.py` unaffected).
- **Prompt-data parity**: no telemetry field feeds any Room-prompt surface;
  `test_prompt_data_parity.py` untouched.

**Still owed on this CR**: mobile batched emitter (fail-quiet-but-countable →
`client_drop`), router wiring in `main.py` (orchestrator), promotion + migration on
Alpha.
