# CR237 — "Ask the CIO again" after a CIO outage

**Status:** proposed. Build after the +113 store build (Saiful, 2026-09-25: "After +113").
**Filed by:** Architect (AT:R85), from Saiful's suggestion while ruling on DEF432.

## Why

When every analyst desk answers but the CIO is unreachable, the Room ends in the DEF059 fail-safe
PASS ("AMI's analyst room lost its model connection before the Chief Investment Officer could
rule…"). Since DEF432's follow-up (27da3d06) that Room is refunded and says so. The analysts' work
is still saved on the run, though, and the only offer the user has is to reconvene the whole Room.

Saiful: "we could also retry the CIO run. maybe offer the option to the customer."

An automatic instant retry is not the fix: the CIO already draws `pm_self_consistency_samples`
(default 5) reads in parallel, and the outage means all of them came back empty at that moment.
A retry the user starts later, on the saved desks, is.

## Scope

1. **Backend.** A route that re-runs only the CIO step for a run whose verdict is the CIO-outage
   PASS (`is_llm_outage_verdict`), using that run's persisted transcript and mandate snapshot. The
   CIO step goes through the same decision tail (`enforce_safety_floor`, compliance, sizing) as a
   normal Room: no separate path. Allowed only on the user's own run, only while the verdict is
   still the outage PASS, and at most once in flight per run.
2. **Free.** Saiful: "free". No spend and no second refund. The original Room was already
   refunded (DEF432); a successful retry does not re-charge it.
3. **Result.** A successful retry replaces the outage PASS with the CIO's real verdict on the same
   run, and the Decision Journal entry is updated rather than duplicated. A retry that hits the
   outage again leaves the outage PASS in place and says so.
4. **Mobile.** On the outage PASS result only, an "Ask the CIO again" action next to reconvene,
   with copy saying it is free and uses the analysts' existing work. Never shown on the
   desks-unreachable NO_VERDICT (DEF432's other case): too few desks answered for a CIO ruling
   to be worth asking for, so reconvening is the right offer there.

## Acceptance

- CIO-outage PASS → retry with a live CIO → real verdict on the same run, floor applied, no
  credit movement, journal entry updated once.
- Retry while the CIO is still down → outage PASS kept, user told, no credit movement.
- Retry refused for someone else's run, for a non-outage verdict, and while one is in flight.
- The button renders only on the outage PASS; not on NO_VERDICT, not on a reasoned PASS.
- Independent audit (Tier A: touches the verdict path and the safety floor).
