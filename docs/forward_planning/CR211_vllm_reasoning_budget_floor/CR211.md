# CR211 — decode-budget floor for a reasoning vLLM server

**Status:** built, awaiting promotion
**Filed:** 2026-08-28 · **Trigger:** Saiful, live — "Raise the budget so we can test it before making code change"

## What happened

The on-prem vLLM server moved. `:8000` (`ami-llm`, `Qwen3.6-35B-A3B-NVFP4`,
non-reasoning) and `:8040` (`allam-7b-instruct`) are both dead; the host is up.
A new serve answers on **`:8048`** with **`qwen3.8-flash-next`** (262k ctx,
vLLM `0.1.dev20073+g8e685d198`).

Alpha's `.env` still pointed at the dead `:8000`, so every LLM call was failing
past vLLM into the preference chain. Alpha was repointed to `:8048` at
2026-08-28 11:41Z (`.env` backup: `~/ami_trade/.env.bak.20260828T114002Z`).

The first live convene after the repoint failed on **every one of eight agents**:

| market_analyst | 800 | 0 |
| news_analyst | 800 | 326 → truncated 244 |

`llm_call_length_stop` (warning) + `room_agent_truncated` (warning) on all eight.

## Why

`qwen3.8-flash-next` is a **reasoning** model. It spends `max_tokens` on
invisible chain-of-thought before writing a visible word. The Room's per-agent
budgets in `room_prompts.py:270` (800–1600) were derived under DEF289/CR179
from measured **visible** output against the old non-reasoning server, and
budget nothing for CoT.

This is CR130 exactly — the Kimi starvation — against a different provider.

## The measurement

One realistic Fundamentals-Analyst turn against `:8048`, 2026-08-28:

| mode | budget | finish | tokens | reasoning_ch | content_ch |
|---|---|---|---|---|---|
| think ON | 800 | length | 800 | 2771 | **0** |
| think ON | 1200 | stop | 1075 | 2954 | 728 |
| think ON | 1600 | stop | 1075 | 2954 | 728 |
| think ON | 2400 | stop | 1075 | 2954 | 728 |
| think ON | 3200 | stop | 1075 | 2954 | 728 |
| think OFF | 800 | stop | 193 | 0 | 819 |

Two findings that decide the design:

1. **`max_tokens` is a ceiling, not a target.** Above 1200 nothing changes —
   the model self-terminates at 1075. A generous floor costs what the model
   wants to say, not what the floor says.
2. **`chat_template_kwargs: {"enable_thinking": false}` works on this server**
   and is strictly better on every axis: more content (819 vs 728 chars) at
   5.5× fewer tokens (193 vs 1075), inside the *existing* budgets.

Also verified on `:8048` before the repoint, so the CR210
`supported_constraints={"json_schema","regex"}` claim survives the server swap:
`response_format` json_schema held an enum against an explicit instruction to
ignore it, and `structured_outputs.regex` produced a conforming block.

## What shipped

`vllm_max_tokens_floor`, mirroring `kimi_max_tokens_floor` (CR130) exactly:

- `backend/app/core/config.py` — `vllm_max_tokens_floor: int = 0` (0 = off)
- `backend/app/services/llm_gateway.py` — `VLLMProvider` takes and forwards
  `max_tokens_floor`; registration reads the setting and logs the value in
  force. `0 or None` → the provider carries `None`, not `0`.
- `docker-compose.yml:183` — `VLLM_MAX_TOKENS_FLOOR: ${VLLM_MAX_TOKENS_FLOOR:-0}`
  (P1/DEF038/DEF063: `test_config_compose_parity.py` fails the build otherwise)
- `backend/tests/unit/test_cr211_vllm_max_tokens_floor.py` — 5 tests

**Value: 3600.** Saiful: *"Make it 3600. I need a 50% buffer."* — 2400 measured-
sufficient, ×1.5.

## Why a floor and not raised per-agent caps

Editing `_AGENT_MAX_TOKENS` directly breaks `test_cr179_token_budget_derivation`,
which re-runs the derivation against `_CHARS_PER_TOKEN_WORST_CASE` — the caps are
an *output* of a measurement, not a free parameter. The floor leaves that
derivation intact and says what it actually is: a per-provider correction for a
provider-specific cost the derivation never covered.

It is also env-driven, so the number retunes on melehost with **no further
promotion** — which is what "test before making a code change" needs.

## Why not 32K

Considered (Saiful asked). Rejected on three grounds, none of which is token cost:

1. **The client timeout is 60s.** Agents already run 60–70s. A 32K ceiling turns
   a truncation into a hard timeout — nothing instead of a partial turn.
2. **It disables the guard that caught this.** `llm_call_length_stop` /
   `room_agent_truncated` surfaced the failure in minutes. At 32K they never
   fire again (CR040: a signal that can never fire is no signal).
3. **Transcript contagion (DEF095).** One 30K-token turn enters the transcript
   every downstream agent reads and blows their context.
