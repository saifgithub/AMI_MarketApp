| CR241 | 2026-09-26 | **Fix `users.locale`: currently write-once and effectively always "en".** Filed from Saiful asking "are we able to tell what language the user is using the app in?" Investigation found the infrastructure exists but is broken in practice: `users.locale` (`backend/app/db/models.py:170`) is written once at signup from `POST /v1/auth/anon`, but the mobile `bootstrapAnon()` call (`mobile/lib/state/auth_providers.dart:149`) never sends the real locale — it silently defaults to `"en"` (`api_client.dart:1488`), so the column is effectively pinned to English for virtually every user. Settings → Language (`locale_provider.dart`'s `LocaleNotifier.setLocale()`) only writes to local `SharedPreferences`, never the backend, so later language changes never sync either — no write path exists after signup. The only currently-reliable per-user signal is CR181 persona-telemetry, which logs live device/Settings locale per event but isn't a queryable "current locale" field on the user. Silent-degradation case (CR040): nothing errors, the field is just wrong for almost everyone. Proposed fix (not built): (1) `bootstrapAnon()` sends the real resolved locale instead of omitting it, (2) add a write path (e.g. `PATCH /v1/users/{id}`) so Settings language changes sync to `users.locale`.
