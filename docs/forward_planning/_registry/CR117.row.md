| CR117 | 2026-07-29 | **The app's "hexagons" are octagons — add a real hexagon clipper, migrate the controls that should be hexagonal, and stop the class name lying.** Saiful, bug report `589e7607` (Platinum Anchor, `0.1.0+57`), on the ticker period toggle: *"the buttons are octagonal, not hexagonal."* **Correct, and the code already admits it.** [`hex_clipper.dart:11-14`](../../../mobile/lib/theme/hex_clipper.dart#L11-L14) declares `class FlatTopHexagonClipper` whose own docstring reads *"Cut-corner octagon — what the design system spec calls a 'hex clip-path'"*, and `getClip` emits an **8-point path**: it cuts all four corners of the rect, producing two angled ends **plus** angled top and bottom. A flat-top hexagon has six sides — angled ends, flat top and bottom — which is exactly what the sibling `FlatTopRegularHexagon` (:47) draws for agent avatars and the honeycomb. **So the app ships two different shapes under one name**, and every "hex" *control* is an octagon: `HexButton`, `HexChip`, `GlassPanel` accents, `ticker_chart.dart:185`'s period toggle, and the BOARD segment of the Room toggle. Only the avatars and honeycomb are genuinely hexagonal. On a small chip the difference is subliminal; on the wide, saturated, selected period pill in the screenshot it is unmistakable, which is why this surfaced on the toggle first. **This reframes DEF146 and is the reason it cannot ship without this CR.** The AT:Designer's toggle (`df515c35`) is a **true hexagon** — angled cuts on the outer edges only, flat top and bottom, straight internal divider. That shape is **not producible** by `FlatTopHexagonClipper` at any `cornerCut`, so DEF146's fix was mis-scoped as "apply the same clipper to both halves"; it needs the new path this CR builds. **RULED (Saiful, 2026-07-29 0900 check-in): "Add a real hexagon clipper, migrate controls to it."** Rejected: rename-only (leaves DEF146 unbuildable) and a two-shape rule with no principle for choosing. **Scope:** (1) add a true flat-top hexagon path for *rect-proportioned* controls — note this is **not** `FlatTopRegularHexagon`, which is locked to a 2:√3 bounding box and will not stretch to a button's aspect ratio without distorting the angle; the new clipper takes a corner inset and cuts only the left and right edges. (2) Migrate the controls that should read as hexagonal, **starting with the DEF146 toggle**, which is the one with a signed-off design. Do **not** sweep them all — the octagon has shipped for months and reads as intentional; migrate on evidence (a design, or a report like this one), not on tidiness. Note **CR113** removes the shape from large CTAs entirely, so those are out of scope here, and **CR108** edits `TrackHexButton`, which already uses the true-hexagon clipper and must not be caught in the migration.
