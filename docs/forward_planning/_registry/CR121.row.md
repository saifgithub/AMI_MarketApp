| CR121 | 2026-07-29 | **Client version gate: a server-driven minimum build, with a message per raise.** Saiful: *"research how I can force an update on the app on the users phone"* → *"Create a CR for the gate. Make it such that we can send a message as well to the user when we ask them to update. Message will be added for each time we move the bar."* **Measured: no gate exists at any layer** — zero hits for `min_version`/`force_update`/`upgrade_required` across `backend/app/**/*.py` and `mobile/lib/**/*.dart`. But the plumbing is already half-built and terminates in a DB column instead of a decision: the client computes its own version (`device_user.dart:46` → `"0.1.0+57"`), ships it on bootstrap (`api_client.dart:980-992` → `schemas/auth.py:65` → `api/auth.py:119`), and the server stores it (`models.py:120,189`) — it just never acts on it. **The honest ceiling:** iOS has **no** force-update API, so "force" = the app refuses to run below the floor and hands the user a one-tap route to the store. That is the only mechanism working on both platforms and every channel we use (TestFlight, Play internal/closed, App Store, cable). **Design:** the floor is *append-only, one row per raise* (`client_release_floors`), not a mutable setting — each raise carries its own `headline`/`body_en`/`body_ar`/`body_ms`, active floor = highest `min_build`, and `active=false` retracts a bad raise without losing the history. Unauthenticated `GET /v1/client/release-floor` (sibling of `/v1/health`, `main.py:209` — must answer *before* a session exists, since a blocked client may be too old to authenticate) returns a server-decided `action: block|nag|ok` plus locale-resolved copy, so policy changes without a client release; `426 Upgrade Required` enforces server-side off a new `X-App-Version` header added at the single existing choke point (`api_client.dart:52-64`), with `/v1/health`, the floor endpoint itself and the feedback POST exempt so a stuck user can still report it. Mobile catches the 426 in a `_VersionGateInterceptor` modelled on DEF073's `_ServerErrorInterceptor` (`api_client.dart:72-89`), checks on launch **and** on foreground-resume, and raises a non-dismissible screen. Write side is `POST /v1/admin/release-floor` behind the existing `ADMIN_SECRET` bearer (`api/admin.py:54-63`) — a raise is one API call, no deploy, no container recreate, which is why it's a table and not an env var. **Floor is one integer, not a per-platform pair:** `pubspec.yaml` carries a single `version: <semver>+<build>` that `build_testflight.sh:81-99` bumps and `publish_playstore.sh --no-bump` reuses, so comparison is integer `>=` on the build number, no semver parsing. **Deliberate exception to degrade-loudly:** the gate **fails open** — a fail-closed gate turns any melehost outage into a simultaneous brick of every installed client, strictly worse than briefly serving a stale build; the failure is logged and surfaced in the admin config check, never swallowed. **Sequencing constraint:** a gate only binds builds that already contain it, so `0.1.0+57` and everything before is permanently ungateable — worth landing before the next TestFlight round so `+58` is the first gateable build. **Operational footgun guarded:** the admin write path refuses a `min_build` above the highest build ever observed in `user_devices.last_app_version` without an explicit force flag, because raising the floor above what TestFlight has approved bricks every iOS tester with nowhere to go. iOS store deep link needs a numeric App Store ID we do not have (falls back to the TestFlight join link; same provisioning dependency as DEF100/CR084), and the bundle IDs differ per platform (`ai.agenticmarketintel.amiTrade` vs `ai.agenticmarketintel.ami_trade`) so nothing may derive a store URL from one value. ~5 new ARB keys need ar/ms; the per-raise message itself is operational copy with EN fallback, not shipped content. **Out of scope:** Play In-App Updates immediate flow (Android-only polish on a tap this already covers; `inAppUpdatePriority` is Publishing-API-only and unsupported on internal app sharing), Shorebird OTA (Dart-only, own CR), and bricking the legacy base by refusing `/v1/auth/device` (documented emergency lever, not built).
