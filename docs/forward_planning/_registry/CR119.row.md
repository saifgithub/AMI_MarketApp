| CR119 | 2026-07-29 | **Portfolio screen redesign — watchlist, holdings and trades all grow without bound; commission AT:Design.** Saiful, bug report `9d51ce11` (Platinum Anchor, `0.1.0+57`): *"in Portfolio, the watchlist, holding and trades will all increase in numbers. we need a better way to view them. we need a AT:Design to work on this."* Filed as a **design commission**, not an implementation CR — the instruction names the owner, so no solution is proposed here and none should be inferred from this row. **The structural problem, stated so the designer has the constraints rather than the symptom.** [`portfolio_screen.dart:137-160`](../../../mobile/lib/screens/sim/portfolio_screen.dart#L137-L160) is a single top-level `ListView` whose children are laid out in full: `_ValueCard` → `_SectorAllocationSection` → `_WatchlistSection` → the holdings block (one `_HoldingCard` per position) → the trades block. **Three of those five are unbounded**, and every one of them grows through exactly the behaviour the product is trying to teach — watch more tickers, hold more positions, trade more often. A user the app has succeeded with is a user whose portfolio screen is unusable. Today's reporter sits at 89.3% cash with 4 sector rows and a short list, so nothing is broken yet; this is a scaling ceiling, filed before it is hit. **Interactions the design has to absorb, all decided today and all in this file:** **CR116** moves holdings above the watchlist, **CR118** caps and scrolls the sector legend, and CR116's row flags that the holdings block is a conditional (`if (p.holdings.isEmpty)` renders `_NewTraderHint`), so the empty state is a distinct layout, not a degenerate case of the populated one. A redesign that ignores the empty state will regress the new-trader experience DEF060 exists to protect. Also live in this screen: `_watchlistKey`, a `GlobalKey` used as a scroll/coach-mark target, which any restructure must keep attached. **Open questions for the design, not for this row:** whether the three lists become tabs, sections with independent scroll, or separate screens; what the summary state of a collapsed list shows (count? top holding? total value?); and whether trades — the least-referenced and fastest-growing of the three — belongs on this screen at all rather than behind the Journal, which is already the durable record surface. **Sequencing:** CR116 and CR118 are small, ruled and land first; they are not blocked on this and should not wait for it. This CR stays `proposed` until AT:Design delivers, at which point it gets a spec folder and a normal build lane.
