| CR075 | 2026-07-23 | **Download the Sharia universe once a day and hold it.** Saiful: *"Why don't we download and hold it for other users? We can do the download every day."* Today the universe lives only in **process memory** — each container builds its own copy on first use, re-fetched no more often than every 900 s — so network sits on the request path (the first halal trade after a restart pays for the fetch), every restart re-downloads, two workers can hold two different as-of dates, and **a source outage of any length means `UNAVAILABLE` ⇒ every halal-flagged trade blocked** ([DEF093](../defect/DEF093_disabled_flag_blocks_every_halal_trade/)'s blast radius triggered by a bad minute on a host we don't control). For a filter a user turned on for religious reasons, *"we couldn't reach a CSV, so you may not trade"* is a poor answer when yesterday's list was fine and the standard itself only changes at rebalance. **It also closes the freshness gap nothing else could:** the parent-index mirror publishes no as-of of its own, so SPUS's date is currently the only staleness signal and a frozen parent list would go unnoticed — a stored row carries **`fetched_at`**, stamped by us, which *is* the missing signal. And it makes the claim defensible: constraint 1 requires naming standard + source + as-of wherever a verdict shows, and holding the list makes that date a fact we recorded rather than a property of whatever we happened to fetch — if anyone asks which companies AMI treated as compliant on a given day, a row answers it. **Design:** a small `coder.api`-owned table (standard, source URL, file `as_of`, our `fetched_at`, compliant set, parent set — two lists of a few hundred tickers, size is a non-issue); refresh via a background task in the **existing** pattern (`main.py` already runs `_nightly_audit_trim()` and `_league_roll_tick()` as startup asyncio tasks — **no new dependency, no new mechanism**), with a tick that finds a fresh row doing nothing so restarts can't miss a boundary; read path resolves from the row, so no network, no `asyncio.to_thread`, no first-request stall, and the in-process cache becomes a read-through rather than the source of truth. **Unchanged:** no failover/union/intersection (one named primary standard, §3a — holding one standard's list is not blending two); `sharia_screen()` stays dormant (constraint 4); blocking on genuine staleness stays (constraint 3 — this only buys a longer runway before it fires); G3 unknown-permits unchanged. **Open for the build lane:** whether a *held* list should be servable longer than a *fetched* one (stated, not inherited); first-boot seeding with an empty table and an unreachable source is still correctly `UNAVAILABLE`; and a refresh failing three days running while the list is still in-window must be visible to **us** even though it's invisible to the user — degrade-loudly applied to the refresher, not the reader. `GATE: independent` recorded upfront — it changes what an observance filter enforces and how it fails, and it touches the schema. | proposed | [CR075_persist_the_sharia_universe/](CR075_persist_the_sharia_universe/) | AT:architect |
