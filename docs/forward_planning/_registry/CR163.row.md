I need you to create a framework where we can do this autonomously."* The existing harness (CR080, CR162) only finds bugs someone already imagined — every check is an assertion a human wrote about a screen a human listed — which does not scale for a one-person team and structurally cannot find the surprising defects, which are the expensive ones. **CR162 made the alternative possible:** once the accessibility semantics tree is exposed the app is *enumerable*, so the harness can list every addressable control and explore on its own; coverage then grows by walking further rather than by writing more tests. Three separated parts: **explorer** (`crawler/explorer.py`, breadth-first walk under a wall-clock budget), **oracles** (`crawler/oracles.py` + `crawler/errorsink.py` — anything that can call a screen wrong with no screen-specific assertion: Flutter framework errors, layout overflow, controls under the safe area, sparse screens, unlabelled controls), and **ledger + triage** (`crawler/ledger.py`, `tools/triage.py` — fingerprint, suppress what is already triaged, promote the rest). Entry point `scripts/crawl_ios_sim.sh`. **The finding that redirected the design, measured rather than assumed:** the first implementation read Flutter's errors from the device log, and that does not work — a `simctl spawn log stream` capture of a live `Runner` process, taken while the app was actively calling `debugPrint`, returned **5,685 lines and zero Dart-origin entries**; every apparent "flutter" match was a CFBundle resource lookup. Dart stdout/stderr goes to the process's own stdout, which `os_log` never sees (`flutter run` shows those lines only because it holds the pipe). So the app records its own errors instead — `mobile/lib/qa/error_sink.dart` installs `FlutterError.onError` + `PlatformDispatcher.onError` behind CR162's existing `--dart-define=AMI_QA_SEMANTICS=1` and appends de-duplicated JSONL to the app container, which the crawler reads back via `simctl get_app_container`; uniform across platforms, survives the crawler crashing, no new transport. **Debug build by Saiful's call** — Flutter compiles most framework assertions out of release, so a release crawl finds only hard crashes; the trade is that timing-sensitive findings are leads, not measurements. **The crawler deliberately files nothing.** CR080 twice had a harness bug written up as application failures, the worst being one `TypeError` reported as 27 failing tests, none real — and Saiful's pipeline puts a **fixer agent waiting on whatever is filed**, so an auto-filing crawler plus an auto-fixing agent turns one bad build into a branch full of fixes for defects that never existed. `tools/triage.py` is the gate; it writes **intake stubs**, not `DEF###` rows, because ids are minted by a single owner to avoid collisions and a script minting them autonomously is exactly that race. From the stub the existing machinery takes over: Architect mints + writes the assign lane → `coder.*` fixes → auditor verdict (`DISPATCH_PROTOCOL.md`). **Decisions not to re-litigate:** the frontier holds *replayable paths*, not screen fingerprints (the first version queued fingerprints, which is unimplementable — there is no `goto(fingerprint)` — so depth > 1 silently never worked); the budget is wall-clock, not step count (steps range 200ms–seconds, so a step budget makes runs incomparable); destructive controls are never tapped, and the deny-list is asserted in `tests_offline/` rather than trusted, because this drives the real Alpha backend with a real account; the scroll oracle runs LAST because it swipes, and the explorer re-reads controls afterwards rather than tapping nodes enumerated before the screen moved; a missing error sink is a hard failure and never "no errors found"; and seen ≠ triaged, so a merely-reported finding keeps being reported until an explicit `filed`/`false_positive`/`wontfix` decision silences it. **Out of scope:** scheduling (Saiful chose "on-demand now, scheduled once it's proven"), Android (the design is platform-neutral — the sink is a file on both — but only the iOS simulator path is built here), and auto-fixing (the fixer + auditor already exist in `orchestration/dispatch/`; this feeds them).
