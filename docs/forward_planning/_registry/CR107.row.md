| CR107 | 2026-07-28 | **Agent icons: one identity mark, sized by surface (icons ≥44pt, letters ≤32pt).** Out of the CR106 comb comparison — Saiful: *"I like the icons, but we now need to see how we can use the icons elsewhere too, like the floor landing page. But customers will need to learn the symbols."* **The real argument is not aesthetics, it is i18n:** `abbreviation`/`displayName` are `const` strings in `agent.dart` with **zero ARB coverage** (grep of `app_en.arb` returns no agent-name keys), and AR+MS ship at v1.0 — so an Arabic user today reads `FUND`/`RES-M`/`TRADE` in Latin script on the Floor honeycomb, in the lesson reader and in every 1-on-1 header. An icon needs no translation; CR080 already found this untranslated-label class live in `tabFloor`/`tabPortfolio`. **The rule, evidenced not asserted:** 12 draft icons render cleanly as a set at 56pt and collapse into blobs at 26pt, where letters stay legible — so icons at ≥44pt (`agent_unlocked` 160, `one_on_one` 120, Floor 56, lesson-reader 48/44, brief/brief-history/1-on-1 rows 44) and letters at ≤32pt (league 32, Room transcript 28, CR106 comb 26). Same identity at different zoom, never competing schemes. **The learning problem solves itself** because every icon-sized surface already prints the agent's name beside the hex (`floor_screen:172`, `lesson_reader_screen:337-345` `CHAT WITH {displayName}`, `:911-921` hex+displayName) — icon and name always appear together, the way app icons teach themselves, no legend. **Scope corrected from 25 marks to 13** on Saiful's *"lessons (the actual lessons) are tied to agents"*: they are (`Lesson.agentCallouts`/`gatesAgents`/`chatWithAgent`, all three lesson-reader sites render `agentById(id).abbreviation`), so **there is no separate two-letter lessons scheme to migrate** — the same 13 strings serve everywhere and 13 icons buy Floor + agent detail + 1-on-1 + Brief + lesson reader. The 13 lesson-*track* hexes on the lessons landing are **out of scope** (different entity, full-word `honeycombTrackLabel`s; its real problem is layout — `hex_clipper.dart:85` records `ISLAMIC FINANCE` with 4.7pt headroom at 1.0 scale and **none at 1.15** — fixed outright by moving the label below the hex, no icon needed). **Two live `HexAvatar` defects must land first** (both found while sizing the CR106 comb labels): `Colors.white` on the family fill measures **1.8:1 on hexAmber / 2.1:1 on hexGreen**, below even the 3:1 large-text floor, hitting all three Risk debators and the Trader on every surface (ink must be `slate900`, 7:1 on all six fills, one ink for both themes since fills keep their tone); and `fontSize: size * 0.16` — tuned for the 96pt Floor hex where it gives 15.4px — yields **4.5px at 28pt, 7.0px at 44pt, 7.7px at 48pt**, which is almost certainly why the lesson hexes read as "two letters" (`RES-M`/`TRADE` at 7px are indistinguishable shapes); a ratio is the wrong model, small avatars need a floor. Fixing the ratio is also the honest **control**: if legible letters at 44pt turn out to be enough, the icon program is optional rather than necessary. **Risks:** an icon set fails collectively — 2 of 12 drafts already fail at 56pt (`research_manager` a meaningless hook, `portfolio_manager` an arch that says nothing) and `trader`'s arrow is generic; icons are semi-permanent once learned; hand-authored inline SVG only (the DS forbids icon CDNs); half-conversion gives one agent two identities. **Not yet decided** — §4 is worth doing regardless, the icon program only if the i18n argument carries; if AR/MS agent names get ARB coverage instead, letters remain defensible and this CR can be dropped.
