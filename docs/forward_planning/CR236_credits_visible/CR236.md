## CR236 — a small credits chip: Convene sheet, Settings, and the Room says what it cost

## What

A compact, shared credits line (`mobile/lib/widgets/credits_line.dart`) rendered on four
surfaces:

1. **Convene sheet** — before the user convenes: "Room: 8 credits · you have 63 · resets
   1 Oct" (`ConveneCreditsLine`). Says plainly when the balance is below the cost
   (`creditsLineInsufficient`); shows an unknown-state line, never a guessed number, while
   the mandate hasn't loaded.
2. **1-on-1 composer** — "You have 63 credits" (`OneOnOneCreditsLine`), because 1-on-1
   turns bill the same credit ledger as the Room (`one_on_one_credit_cost`,
   `app/api/one_on_one.py`).
3. **Settings → Profile → Credits row** — "63 · resets 1 Oct", localized date formatting
   (`intl`'s `DateFormat('d MMM')`), never the hard-coded `'the 1st'` fallback style. Shows
   "—" when the balance is unknown (DEF437).
4. **After a Room** — a quiet line under the settled verdict: "This Room used 8 credits ·
   55 left", or "Not charged — the desks were unreachable" when the run was refunded
   (`RoomResultCostLine`). Backed by a new `credit_cost`/`refunded` pair on the `done` SSE
   event (`backend/app/api/room.py`) — the single place the stream's final event is built —
   and the mandate is refreshed after every Room completion so the new balance reaches every
   surface (`room_providers.dart`'s `'done'` case now calls
   `mandateNotifierProvider.notifier.refresh()`).

Alongside, **DEF437**: `UserMandate.creditBalance`/`creditAllowance`/`roomCost` become
nullable. A missing/null value used to fabricate `75` (`mandate.dart:476`, pre-fix) — now it
stays `null` (unknown), and every consumer (Settings, the new chip, `HouseAdSignals.
fromMandate`'s ad targeting) treats unknown as "say nothing" / "fail closed", never as 0 or
the old 75.

## Why

Saiful, 2026-09-25: **"How does a user check how many credits they have left?"** Today the
only place is a read-only Settings row. The convene sheet shows neither the Room's cost nor
the balance; nothing says what a Room cost after it finished
(`room_screen.dart`'s own comment: `duration_ms` and `credit_cost` live on `RoomRun`
server-side but never reach the live stream); the reset date only appears in the upgrade
sheet and the out-of-credits wall.

The Architect proposed, Saiful approved verbatim ("Yes"): *"a small credits chip. It would
sit on the Convene sheet ('Room: 8 credits · you have 63') and in Settings, with the reset
date ('resets 1 Oct'). The Room would then say what it cost when it finishes."*

DEF437 surfaced while implementing this: showing a credits number *more often* makes a
fabricated one *more visible* — CR040's "if this fires constantly and silently, what does
the user end up believing?" applies directly. A user who never sees Settings' one read-only
row might never notice a stuck `75`; a user who sees the same chip on every convene would.

## Scope

### 1. Shared widget — `mobile/lib/widgets/credits_line.dart`

Three widgets (`ConveneCreditsLine`, `OneOnOneCreditsLine`, `RoomResultCostLine`) and one
formatter (`creditsResetDateLabel`, `DateFormat('d MMM')` — "1 Oct", not `MMMd()`'s US
"Oct 1" ordering). All read `null` as unknown and render an unknown-state line rather than a
guessed number.

### 2. Convene sheet — `mobile/lib/screens/room/convene_sheet.dart`

`ConveneCreditsLine` inserted between the sub-heading and the ticker field, reading
`mandate.roomCost` / `mandate.creditBalance` / `mandate.creditsResetAt`. The sheet's body is
now wrapped in a `SingleChildScrollView` (a real vertical overflow at 320dp/1.3x text scale
that the extra line introduced, fixed by making the sheet scrollable — the sheet's
pre-existing, unrelated horizontal overflow on the "CONVENE THE ROOM" heading Row at the
same size/scale is untouched, out of this CR's scope).

### 3. 1-on-1 composer — `mobile/lib/screens/agent/one_on_one_screen.dart`

`_InputBar` becomes a `ConsumerWidget`; `OneOnOneCreditsLine` renders above the text field,
reading `mandate.creditBalance`.

### 4. Settings — `mobile/lib/screens/settings/settings_screen.dart`

The Credits row's value is now `_creditsRowValue()`: `"{balance} · resets {date}"` once both
are known, else the bare balance, else `settingsProfileCreditsUnknown` ("—") when the
balance is null.

### 5. Room result — backend `done` event + mobile wiring

- `backend/app/api/room.py`: the `done` event (built in exactly one place, the end of
  `event_stream()`, shared by the live and cached-replay paths) now carries `credit_cost`
  (re-read via `runner.get_run(run_id)`, the same read the cached-replay branch already
  does) and `refunded` (`status == "failed"` — CR039/DEF425/DEF432's only refund path). A
  raced-away row degrades to `credit_cost: null, refunded: false`, never a fabricated
  number.
- `mobile/lib/services/api/api_client.dart`'s `parseRoomSseEvent`: `credit_cost`/`refunded`
  forwarded via `containsKey`, matching the CR106/CR098 discipline already used for
  `stance`/`agent_withheld` fields — a pre-CR236 backend that sends neither key must read as
  "unknown", not as an explicit zero/false.
- `mobile/lib/state/room_providers.dart`: `RoomState` gains `creditCost`/`refunded`; the
  `'done'` case parses them and calls `mandateNotifierProvider.notifier.refresh()` so every
  surface reflects the new balance.
- `mobile/lib/screens/room/room_screen.dart`: `_RoomResultCostRow` renders
  `RoomResultCostLine`, gated on `state.done && state.creditCost != null` — not just `done`
  — so a `done` event carrying no cost (older backend, or the many existing test fixtures
  that construct `RoomState(done: true)` without it) renders nothing and never mounts the
  mandate watch. Watching `mandateNotifierProvider` unconditionally on every settled Room
  regressed three unrelated test files (`room_briefing_test.dart` ×2,
  `room_agent_withheld_test.dart`) via a pending-Dio-timer assertion, because
  `MandateNotifier`'s creation schedules a real network `refresh()`; the `creditCost != null`
  gate fixes this while keeping the real-app behaviour (which always has a cost once
  `done`) unchanged.

### 6. DEF437 — nullable credit fields

- `mobile/lib/models/mandate.dart`: `creditBalance`/`creditAllowance`/`roomCost` become
  `int?`, `fromJson` drops the `?? 75` / `?? 0` fallbacks.
- `mobile/lib/services/ads/ads_models.dart`: `HouseAdSignals.fromMandate` fails closed —
  `outOfFreeOneOnOnes` / `usedFreeRoom` / `nearCreditCap` are all `false` when the field(s)
  they read are null, never inferred from a fabricated 0 or 75.

## Acceptance

- Convene sheet renders cost + balance + reset (widget test), low-balance wording (widget
  test), unloaded/unknown state shows no number (widget test).
- Settings row shows balance + reset date, or "—" when unknown (widget test).
- The `done` event's `credit_cost`/`refunded` round-trip: backend test
  (`test_cr236_room_done_credit_cost.py`, 5 cases: completed, failed+refunded, zero-cost,
  cancelled-not-refunded, row-raced-away) and mobile parser test
  (`api_client_room_stream_test.dart`, 4 cases including the pre-CR236 no-keys shape).
  Full-stack DEF437 credit-field nullability: `mandate_def437_credit_fields_test.dart` +
  `def437_house_ad_signals_unknown_credit_test.dart`.
- Balance refreshes after a Room completes (`room_providers.dart`'s `'done'` case calls
  `mandateNotifierProvider.notifier.refresh()` — asserted implicitly via the result-line
  test reading the refreshed balance from a fixed post-refresh mandate state).
- Widget tests at 320dp and 1.3× text scale, scoped to each CR236 surface's own content
  (two of the four surfaces — the Convene sheet's heading Row and the 1-on-1 header's
  fixed-height Container — carry pre-existing, unrelated overflow at that size/scale,
  confirmed present on `main` before this CR and left untouched).
- `flutter analyze`: baseline 11 issues, 0 errors. `flutter test`: full suite green
  (1770 tests). Backend: the four CR236/DEF437-relevant test files plus
  `test_def200_ratchet.py` / `test_no_blocking_io_in_async_routes.py` /
  `test_wire_contract_parity.py` all green.

## Attack surface (can any surface show a number the user doesn't have?)

- Every new widget reads `null` as unknown and renders an explicit unknown-state string —
  never a placeholder number, never a stale cached value re-shown as current.
- `HouseAdSignals.fromMandate`'s three credit-usage ad signals all fail closed on a null
  input field, so an unknown balance can neither over- nor under-target ads.
- The `done` event's `credit_cost` is a plain re-read of the persisted `RoomRunRow`, not a
  value threaded through in-memory state that could drift from what was actually charged;
  `refunded` reads `status`, the same field CR039's refund logic itself sets — this CR adds
  no new refund *decision*, only a report of one already made.
- A raced-away row (`get_run` returns `None`) degrades to `null`/`false` on the wire, and the
  mobile side's `RoomResultCostLine` renders nothing at all rather than a guess.
