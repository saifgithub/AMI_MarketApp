## Why this CR exists — the gap, and why it wasn't already closed

Users currently have no way to see basic reference information about a
company they're trading — business description, sector/SIC classification,
share structure, recent SEC filings, or insider trading activity. Users
also have no way to review this before or alongside convening the 12-agent
Room, even though the backend already fetches EDGAR and yfinance data for
other purposes.

Separately, the Room's agents receive only one narrow slice of EDGAR data
today: 8-K Item 5.02 executive-change filings, feeding the News Analyst.
This is not an oversight — **CR221** ("Sourcing the Room's measured data
demand," 2026-09-03, in_progress) is a demand-driven census of 127 agent
asks across 7 convenes, and it built exactly and only what agents
demonstrably asked for. The News Analyst's persona (`content/agents/news_analyst.md`)
explicitly names the rest of the regulatory-filings surface ("S-1, 10-K
text, etc.") as a preserved, honest "not connected" denial — a deliberate
scope boundary, not a bug. That boundary is circular by construction: an
agent can't demand data it was never shown exists. This CR is the
follow-up that tests demand for a broader feed rather than assuming the
narrow one already found the ceiling.

## Part 2 — Room agent feeds

Same underlying data, routed to specific agents by persona fit (full
per-agent analysis in the elicitation doc):

| Data | Agent(s) | Why |
|---|---|---|
| Filings list + financials | News Analyst | Extends its existing 8-K Item 5.02 precedent; its own persona already names the rest of "regulatory filings" as the current gap |
| Filings list + financials | Fundamentals Analyst | Extends its existing sector/ownership/float fields; already has the "cite the filing, don't infer content" discipline this needs |
| Insider trades (Form 3/4/5) | Bull Researcher, Bear Researcher | Both personas already have an attribute-and-quote evidence discipline ("the Fundamentals Analyst's 18.2 P/E," not "valuation is undemanding") that a Form 4 line slots into directly; Bear's "specific, probabilistic risk, not FUD" requirement is exactly what non-scheduled insider selling satisfies |
| Share float / liquidity (ADV) | Trader (Execution Desk) | Natural extension of its existing stop-sizing job (ATR-based today) — thin float means higher slippage/gap risk on a stop, something its persona has the *function* for but no field for yet |
| Share float / ownership concentration | Conservative Risk Officer | Natural extension of its "tail risk stays on the table" framing — a thin float or high insider-ownership concentration is a latent overhang/liquidity risk none of the 3 Risk Officer personas currently have a field for |

Every new field follows the **same 5-point pattern CR221 established** for
the 8-K Item 5.02 feature — this is the template to replicate, not a new
mechanism to invent:

1. **Extraction module** (fetch/parse/filter/excerpt + a `..._line()`
   renderer), plus an offline ingest script and new DB table(s).
2. **A `field_state` key** (per-field provenance — LIVE / withheld / not
   available, never silently blank).
3. **A lane-gated header disclosure bullet** in `_format_profile`
   (`room_prompts.py`), modeled on the existing 8-K bullet at
   `room_prompts.py:2449-2465`.
4. **A lane-gated body line**, modeled on `room_prompts.py:2916-2939`.
5. **A persona-file sentence** in each affected agent's `content/agents/{id}.md`
   `## Inputs` section, in the same register as the existing 8-K sentence
   (attribute to the filing, don't infer beyond what's stated).

### Structural control on insider-trade data (not prompt-only)

Insider Form 4 data is exactly the kind of thing agents (and users) tend to
over-read directionally ("insider selling = bearish"). Per CLAUDE.md's
degrade-loudly rule and CR038's finding that prompt-only instructions hold
only ~70% of the time: **the extraction layer must tag each transaction's
Rule 10b5-1 plan status as a structural fact** (`plan_type`:
`scheduled_10b5-1` / `discretionary` / `unstated`), read directly from the
Form 4's own checkbox — not left to the agent to infer from context. Bull's
persona must be told a scheduled sale is not sell-side conviction; Bear's
persona must be told a non-plan sale is the stronger signal.

## Architecture / module plan

- **Filings-list feed** — extends `edgar_8k.py`'s existing submissions-JSON
  fetch with a broader form-type filter (`filings.recent` already contains
  every form type an issuer filed); reuses its existing HTML-filtering,
  excerpt-capping, and rate-limit-etiquette helpers. Not a new integration.
- **Insider-trade feed** — genuinely new module (e.g. `edgar_ownership.py`)
  — Form 3/4/5 data is not in the submissions JSON at all; requires EDGAR's
  separate ownership-forms endpoint.
- **Company-profile feed** — new module (`company_profile.py`), blending
  yfinance `.info` + the EDGAR submissions JSON (legal name, SIC, address
  win from EDGAR; description/employees/website win from yfinance, per the
  earlier session's data-model plan).
- **Float/liquidity fields** — extend `fundamentals.py`'s existing yfinance
  `.info` read (already-open connection, unread fields — no new
  integration).
- New read-only endpoint (`GET /v1/sim/company-profile/{ticker}`, following
  `app/api/sim.py`'s existing per-ticker GET conventions) backs Part 1's
  display screen.

## Non-goals

- **No new lane-gating infrastructure.** Bull and Bear are full-sheet
  agents (not lane-firewalled like the 4 domain-gated analysts) — whatever
  lane insider-trade data is tagged with, it reaches all 8 full-sheet
  agents (Research Manager, Trader, Portfolio Manager, all 3 Risk Officers,
  plus Bull/Bear), not just the two named here. This is an accepted
  tradeoff (elicitation D2): building a mechanism to restrict data to only
  two specific full-sheet agents is materially larger scope than a
  data-feed CR, and no real misuse risk from the other 6 seeing it has been
  demonstrated.
- **No 10-K/10-Q narrative extraction** (MD&A, Item 1A risk factors) — no
  existing parser for this anywhere in the codebase, and it's NLP-adjacent
  work far beyond a data-feed CR's scope. Filings feed here is dates/
  types/links only, same shape as the existing 8-K precedent.
- **No S-1/S-1/A content parsing.** No demonstrated agent or user demand;
  "no S-1 on file" (already-public issuer) is itself a valid, informative
  display state, not a gap to fill.
- **No fix for the I1 (8-K exec-change) re-scan staleness gap** — the
  existing feature has no scheduled re-scan and goes stale after 180 days
  (due ~2027-03-24). Filed separately as **DEF447**; unrelated pre-existing
  gap, bundling it here would blur this CR's acceptance criteria.
- **No liquidity-adjusted position-cap compliance logic for the Portfolio
  Manager.** Surfaced during persona research as a good future idea (a 3%
  position in a $50M-float microcap is a different risk than 3% of a
  mega-cap), but it needs new compliance logic, not just a data feed —
  flagged for a future CR, not this one.
- **No fix for the PM scoreboard's undefined STANCE semantics** — a
  separate, pre-existing gap found while explaining the Room's PM-prompt
  mechanism to Saiful (2026-09-27): the VERDICT-phase scoreboard
  (`_room_scoreboard`, `room_prompts.py:3544`) shows every agent's `STANCE`
  (for/against/neutral) with no definition of what "for"/"against" means
  per persona type (a Risk Officer's "for" carries a proposed size; an
  analyst's "for" is a directional data read, no position ever proposed) —
  the PM must infer this from column headers alone. Touches the same
  prompt-assembly file and some of the same agents (Bull/Bear) as this
  CR's Part 2, but is unrelated to the new EDGAR/company data this CR
  adds. Filed separately as **DEF448**, following this CR's own precedent
  (DEF447) for splitting out adjacent-but-unrelated prompt gaps.

### Correction to the mockup: an option exercise is not a buy

The v5 Insider frame shows "BUY · option ex." That is wrong and must not be
built. Only Form 4 transaction codes **P** (open-market purchase) and
**S** (open-market sale) are buys or sells. Everything else (M exercise,
A grant, F tax withholding, G gift, …) is `other`. `other` rows are listed
with their code label and never counted in the buy/sell summary.

### API contract (backend and mobile build against this in parallel)

Both endpoints are public, like `/quote` and `/earnings`, and use typed
`response_model`s. Every section carries its own `state` so that one source
failing never blanks the whole screen (CR040):

`state` ∈ `live` | `partial` | `not_available`. `reason` is a short
user-readable string, and it is required whenever `state != live`.

**`GET /v1/sim/company-profile/{ticker}`** (server cache 6h):

```json
{
  "ticker": "NVDA",
  "as_of": "2026-09-27T11:02:00Z",
  "cik": "0001045810",
  "overview": {
    "state": "live", "reason": null, "sources": ["edgar", "yfinance"],
    "legal_name": "NVIDIA CORP", "display_name": "NVIDIA Corporation",
    "description": "…", "sector": "Technology", "industry": "Semiconductors",
    "sic": "3674", "sic_description": "Semiconductors & Related Devices",
    "exchange": "Nasdaq", "employees": 29600, "website": "https://…",
    "address": "2788 San Tomas Expressway, Santa Clara, CA 95051", "phone": "…"
  },
  "financials": {
    "state": "live", "reason": null, "sources": ["yfinance"], "currency": "USD",
    "market_cap": 4.3e12, "revenue_ttm": 1.65e11, "gross_margin": 0.72,
    "operating_margin": 0.61, "net_margin": 0.53, "trailing_pe": 52.1,
    "forward_pe": 31.0, "eps_ttm": 3.4, "debt_to_equity": 0.11,
    "free_cash_flow": 7.2e10, "dividend_yield": 0.0002
  },
  "filings": {
    "state": "live", "reason": null, "sources": ["edgar"],
    "items": [
      {"form": "10-Q", "description": "Quarterly report",
       "filed_date": "2026-08-27", "report_date": "2026-07-27",
       "accession_number": "0001045810-26-000123",
       "url": "https://www.sec.gov/Archives/edgar/data/1045810/000104581026000123/nvda-20260727.htm"}
    ]
  },
  "ownership": {
    "state": "live", "reason": null, "sources": ["yfinance"],
    "shares_outstanding": 2.44e10, "float_shares": 2.34e10,
    "pct_institutions": 0.674, "pct_insiders": 0.042,
    "holders": [
      {"name": "The Vanguard Group, Inc.", "kind": "institution",
       "pct_held": 0.0824, "shares": 2.0e9, "date_reported": "2026-06-30"}
    ]
  }
}
```

- `filings.items`: newest first, up to 20, every form type except
  3/4/5 (those belong to the Insider tab), from the submissions JSON
  `filings.recent` block `edgar_8k.py` already fetches. `description` is a
  fixed form→label map (10-K "Annual report", 10-Q "Quarterly report",
  8-K "Current report", DEF 14A "Proxy statement", S-1 "Registration
  statement", …). Unknown forms fall back to the SEC's own
  `primaryDocDescription`, then to the bare form code.
- No CIK match (a foreign or OTC symbol): `cik: null`, `filings.state =
  not_available`, `reason = "No SEC registrant found for this symbol"`.
  Overview is `partial` (yfinance fields only). Never a 404 for a ticker
  yfinance knows.
- Unknown ticker (neither source knows it): 404.
- **Events tab** needs no new endpoint. It reads the existing
  `GET /v1/sim/earnings/{ticker}` plus the 8-K rows of `filings.items`.

**`GET /v1/sim/insider/{ticker}`** (server cache 6h; this is the slow one,
since it fetches up to 25 Form 4 XMLs at ≤10 req/s under SEC's User-Agent
rule):

```json
{
  "ticker": "NVDA", "as_of": "…", "cik": "0001045810",
  "state": "live", "reason": null, "sources": ["edgar"], "window_days": 90,
  "summary": {"buys": 2, "sells": 5, "other": 3,
              "net_direction": "selling"},
  "transactions": [
    {"form": "4", "filed_date": "2026-09-16", "transaction_date": "2026-09-15",
     "insider_name": "Kress Colette", "role": "EVP & CFO",
     "code": "S", "code_label": "Open-market sale", "direction": "sell",
     "shares": 45000, "price": 178.32,
     "plan_type": "scheduled_10b5-1",
     "url": "https://www.sec.gov/Archives/edgar/data/…"}
  ]
}
```

- `net_direction` ∈ `buying` | `selling` | `mixed` | `none`, computed from
  P/S rows only.
- **`plan_type` is the structural control (see above).** It is read from
  the Form 4 XML's Rule 10b5-1 checkbox (added April 2023). `scheduled_10b5-1`
  means the box is ticked, `discretionary` means the box is present and
  unticked, and `unstated` means the element is absent (older forms). It is
  never inferred from footnote text or by a model.
- Rendering the Insider tab: each P/S row carries a small `10b5-1` tag when
  scheduled. The state-line from the mockup stays.
