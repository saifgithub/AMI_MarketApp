# WP-22 code grader over WP-20 arm 2 (cards on): tables

Generated by `docs/tools/room_investigation_V2/tools/wp22_score.py report` from `~/cr267_wp20/out/wp22_code/` on melehost (`scores_arm2.jsonl`, `scores_arm2_tradeaction.jsonl`) against `runs_wp20-arm2.jsonl`. Grader `code_cards cards-1` (`backend/app/services/room_graders/code_cards.py`), question set `q1`, decision rule r1 with the default policy. Run: `wp22_run.sh code_arm2 score --grader code --runs /out/arm2/runs_wp20-arm2.jsonl --out /out/wp22_code/scores_arm2.jsonl` (no model call, no key, $0, 0.1 s for 300 Rooms). CIO numbers in every table are on the same arm-2 Rooms.

Two runs over the same 300 Rooms and the same cards:

1. **Part A, as production hands the grader its input.** The proposed-trade block is `{size_pct, entry, stop, target}` with no `action` or `side` (this is what `room_runner._coded_transcript` and the harness both build), so `trade_proposed` is not computable in every Room.
2. **Part B, sensitivity: `--trade-action buy`.** The same block with `action: buy` added, which is what "the Execution Desk always proposes a trade" would give if the block carried it. Only `trade_proposed` changes: the other five answers are identical in all 300 Rooms.

Not run: `wording` and `inputs`. The grader reads typed cards and the structured trade, never turn prose, so a rephrased question does not exist for it and every WP-22 §3.3 perturbation (planted flaw, bear text removed or strengthened, turns reordered, ticker renamed) edits prose it does not read. Its answers cannot change under them, by construction. Regrading the same Room is also identical by construction (verified: the two runs agree on every answer they share).

Cards are not stored on the Room: the runner strips the card blocks from the persisted transcript. They were rebuilt per Room from `llm_audit` (the four evidence desks' last successful turn across the `room`, `room_envelope_repair` and `room_cards_repair` flows inside the arm's exact time window) with the backend's own `parse_claim_cards`, the fact-sheet registry coming from `verdict.sheet_state`. A cards re-ask that is still incomplete is rejected in favour of the earlier turn, as the runner does (18 Rooms). The rebuilt census matches `evidence_card_report.py`: 277/300 complete.
