# CR133 — The bottom nav, and what `YOU` holds

**Status:** proposed · design stage. Spec + prototype delivered; no Flutter written.
**Filed:** 2026-07-30 · `AT:UI Designer`
**Prototype:** <https://claude.ai/code/artifact/3f4e97ca-753c-4e82-98b0-070d806795ff>
**Supersedes:** [CR109](../CR109_pnl_game_ami_cash/CR109.md) §9.0 "Where it lives in the app"

---

## 1. Why

CR109 adds a game. [`home_shell.dart:29`](../../../mobile/lib/screens/home_shell.dart) ships five
bottom-nav destinations — `FLOOR · PORTFOLIO · JOURNAL · LESSONS · SETTINGS` — and all five are
taken, so something has to move. Saiful's call:

> *"consider moving settings to a less prominent real estate."*

Three proposals existed. CR109 §9.0 (GAME at slot 3, Settings to "an app-bar gear"); a nav-pattern
survey artifact (GAME at slot 3, a `RECORD` tab at slot 5 absorbing the Journal); and mine (GAME at
slot 5, inheriting Settings' index so nothing renumbers). **Saiful chose the survey's structure**,
then revised it: runs and trophies go back inside GAME, and slot 5 becomes `YOU`.

Two premises in the earlier proposals do not survive the code, and this CR records them so they are
not re-proposed:

- **There is no app bar to put a gear in.** Seven `AppBar(` instances exist in `mobile/lib`, every
  one on a *pushed* screen (legal, alpaca-connect, league, sign-in, coach, daily-challenge,
  ticker-detail). Each of the five tab screens rolls its own private `_Header`
  ([portfolio:227](../../../mobile/lib/screens/sim/portfolio_screen.dart),
  [journal:204](../../../mobile/lib/screens/journal/journal_screen.dart),
  [lessons:262](../../../mobile/lib/screens/lessons/lessons_screen.dart),
  [settings:262](../../../mobile/lib/screens/settings/settings_screen.dart)) and **Floor has none
  at all** — its logo + streak row sits inside a `SingleChildScrollView`
  ([floor_screen.dart:352](../../../mobile/lib/screens/floor/floor_screen.dart)) and scrolls away.
- **A pure career/profile tab is empty on day one.** Onboarding is anonymous-first; Amendment A
  deletes badges and streaks; a new user has zero runs and zero career points. The survey rejects
  the avatar pattern for exactly this reason and then recommends a tab with the same defect. Saiful
  resolved it by moving runs and trophies back under GAME, which is where §9.0 put the career
  record originally.

## 2. The bar

| Slot | Today | Phase 1 | Phase 2 (with CR109) |
|---|---|---|---|
| 0 | FLOOR | FLOOR | FLOOR |
| 1 | PORTFOLIO | PORTFOLIO | PORTFOLIO |
| 2 | JOURNAL | LESSONS | **GAME** |
| 3 | LESSONS | **YOU** | LESSONS |
| 4 | SETTINGS | — | **YOU** |

Phase 1 ships **four** tabs. The Journal is not missing — it moved inside `YOU`. An empty
"coming soon" GAME cell would be a promise sitting in prime real estate, so the slot arrives with
the thing that fills it. `HexBottomNav` maps `items.length`
([hex_bottom_nav.dart](../../../mobile/lib/widgets/hex/hex_bottom_nav.dart)), so a four-item list
needs no widget change, and each cell gets **wider** than today's five.

**Measured in the prototype at 390pt** (read from the DOM, not estimated): five cells give
**77.6pt** each and `PORTFOLIO` renders at **52.4pt**; four cells give **97.0pt**. DEF043 — the
label that wrapped because `labelMono`'s 1.8 tracking overflowed its cell — does not recur at
either count. Note that `FittedBox(scaleDown)` hides a wrap by shrinking type instead, so the
acceptance check is rendered size, not line count.

## 3. What breaks silently, and the structural fix

GAME lands on index 2 in phase 2 and **inherits everything that pointed at the Journal**. Neither
of these fails loudly:

| Site | Literal | Consequence |
|---|---|---|
| [`portfolio_screen.dart:1528`](../../../mobile/lib/screens/sim/portfolio_screen.dart) | `state = 2, // Journal` | Portfolio History's **"Review in Journal" opens the game** |
| [`journal_screen.dart:96`](../../../mobile/lib/screens/journal/journal_screen.dart) | `if (next != 2) return;` | The Journal's coach-mark tour **fires on the game tab**, once, then is marked seen forever |

Surviving untouched: `floor_screen.dart:67,320` (`!= 0`), `portfolio_screen.dart:123` (`!= 1`),
`lessons_screen.dart:79` (`!= 3`). **Three of five keep working, so a smoke test passes** — which
is what makes this dangerous rather than merely wrong. It is the same class as DEF190.

**Fix — `AmiTab`, shipped in phase 1, before any reorder.**

```dart
enum AmiTab { floor, portfolio, game, lessons, you }
```

`activeTabIndexProvider` becomes `activeTabProvider` typed on it; `tour_providers.dart:13`'s
mapping comment is deleted because the type now states it. Every site above becomes a **compile
error** instead of a wrong tab. `flutter analyze --no-fatal-infos` clean is the proof no literal
survived, and CR109's later insert of `game` is then one line rather than a renumbering.

**Two-part navigation.** "Review in Journal" must land on *tab + segment*. The enum alone does not
carry that, so the provider takes a small intent (`AmiTab` + optional segment). Otherwise the deep
link lands on whichever segment `YOU` happens to be showing and the entry the user asked for is one
more tap away, invisibly.

**The Journal's tour loses its trigger.** `TourSection.journal` fires on tab index 2; the Journal is
no longer a tab. It must fire when the JOURNAL segment is first shown inside `YOU`. Cheap, but
silent if missed — the tour would simply never run again.

## 4. `YOU` — the surface the app never had

Portfolio owns the money, Lessons owns the curriculum, GAME owns the score. Nothing owned *you*.

It takes **CR120's shape** — a pinned card over segmented tabs (`cornerCut: 8`, fill flip only, no
sliding indicator, no swipe) — so this is the second use of a decided idiom, not a new one.

| | Holds | Source |
|---|---|---|
| Pinned card | path, horizon, primary goal, mandate version, plan | read-only fields already on `MandateRow` |
| **`MANDATE`** | risk score, max drawdown, risk limits, compliance/halal screens | Settings sections 1–3, lifted whole |
| **`JOURNAL`** | the Decision Journal | `JournalScreen`, moved in whole |
| **`INSIGHTS`** | what your decisions look like in aggregate | aggregated from journal rows already written |
| ⚙ header | Settings | pushed route |

**Name.** `YOU` — three characters. `DESK` is avoided: `games_roadmap.md` reserves "desk" for team
modes scored on median member placement. `CEO` is the on-brand alternative.

**Why the mandate is here and not behind the gear.** Settings is 13 sections in one `ListView` and
the first three *are* the mandate; the header already carries the mandate version and the Save
button. It is a mandate editor with settings appended, which is why it lifts out cleanly. The
mandate is the most identity-defining object in the app — your standing order to the team — and a
training instrument the curriculum tells users to revisit. It keeps its in-context deep links from
Portfolio and Lessons: one screen, several doors.

**Why INSIGHTS and not credits, badges or progress.** AMI's product claim is that it makes you a
better decision-maker, and nothing in the app tells you what your decisions look like. The Journal
is a log; INSIGHTS is what makes the log educational.

Rejected: **membership/credits** (real, but billing — behind the gear); **agents unlocked** (the
Floor's entire job); **streaks/progress** (Lessons owns it, and Amendment A deletes streaks).

INSIGHTS is the least-settled segment. If it does not survive review, `YOU` still works at two
segments — the tab's reason to exist is the mandate, not the insights.

### 4.1 What INSIGHTS can actually show — checked against the schema, not assumed

The first draft of this section claimed every figure was computable from shipped data. **Two of the
five were not**, and the check is recorded here so the claim is not re-made.

**The five cards, each rendered at full size with its source, empty state and edge case in the
prototype's §07 build reference.** Nothing below needs a new table or a migration.

| Card | Query | Written by |
|---|---|---|
| **How your trades ended** — target hit / stop hit / closed by hand | `SIM_TRADE` where `'closed' in tags`, bucket on `won` / `lost` / `manual` | `sim.py:395`, `sim.py:448` |
| **What PM decided** — APPROVE / MODIFY / REJECT / PASS / NO_VERDICT | `ROOM_RUN` grouped by `payload.verdict.action` | `room_runner.py:1610`, `schemas/room.py:33` |
| **Analysts you sought out** | `ONE_ON_ONE` / `AGENT_COACH` / `AGENT_UNLOCK`, count `agents_involved[0]` — exactly one agent, the one the user chose to open | `one_on_one.py:137`, `brief.py:165`, `lessons.py:154` |
| **How your mandate has moved** | `MANDATE_EDIT` ordered by `created_at`, diffing `payload.before` vs `payload.after` per field | `mandate.py:147`, `:259` |
| **Daily challenge, by type** | `DAILY_CHALLENGE` grouped by `payload.type`, correct where `outcome = WIN` | `daily_challenge.py:223` |

**"How your trades ended" is the strongest card in the set and the cheapest.** A user who closes by
hand before stop or target is overriding the plan they wrote — that is a habit, and habits are what
the product exists to change. The tags already distinguish it; nothing needs building.

**"How your mandate has moved" was the surprise.** `MANDATE_EDIT` stores **full before/after
mandate snapshots**, so every limit's trajectory is reconstructable — including whether a limit was
loosened right after a loss. No new table.

**Edge cases that will bite, spelled out in the reference:**

- **`NO_VERDICT` is not a rejection.** It is the PM declining to rule because the run had no market
  read (CR098). Bucketing it with `REJECT` tells the user their idea was turned down when it was
  never judged — and that exact mis-render is already a flagged defect elsewhere.
- **`payload.verdict` is `null`** on a failed or cancelled run. Exclude; never count as `PASS`.
- **The Day Trader preset** sets seven limits in one edit (`mandate.py:140`). Render it as one
  event, not seven loosenings, or it swamps the drift ledger.
- **A trade closed manually at the target still tags `manual`** — correctly, because the user acted
  rather than the level. Do not reclassify by comparing prices.
- **Daily-challenge rows carry `difficulty`.** 40% on hard is not worse than 80% on easy, so either
  weight or state the row is unweighted; do not imply a comparison the number cannot support.

**Measured:** the assembled INSIGHTS segment is **3.4 screens** of scroll at 390×844 — the deepest
segment in the app, and acceptable only because it is read through rather than scanned. If a sixth
card is added, one comes out.

**Not computable — and the panel must say so rather than render zeros:**

- **"Voices you actually read" from Room runs is a wrong number.** `room_runner.py:1603` sets
  `agents_involved` to *every agent in the transcript*, and all 12 speak in every run. A chart built
  on it would report participation and label it readership. This is why the panel is sourced from
  one-on-ones and briefs instead, and titled **"analysts you sought out"**.
- **Followed-PM vs overrode.** Nothing links a Room run to the trade that followed:
  `reference_id` holds the run on one entry and the trade on the other. Correlating by ticker and
  time is a guess. Costs one line — stamp `from_run_id` into the `SIM_TRADE` capture's `payload`
  (already JSON, so no migration).
- **Times the safety floor stopped you.** A blocked trade never reaches the journal at all: capture
  at `sim.py:307` runs only after `result.trade is not None`, and a blocked trade has no trade. So
  **the app never records that it stopped you** — for a training product that is the teaching moment
  going unlogged, and it is worth its own item regardless of this CR.

Both are specified as **absent**, not as `0`. Do not approximate followed-vs-overrode by matching
ticker and time window: a heuristic rendered at the same weight as a fact is the exact failure the
gaps card exists to avoid.

**One dead enum found on the way through.** `EntryType.DRIFT_ALERT` exists at
`schemas/journal.py:31` and **has no writer anywhere** — no capture site ever produces one. It is
the natural home for *"your mandate loosened right after a loss"*, which is the sharpest version of
the drift card. Flagged for the Architect, not claimed by this CR.

**Family colour is sacred, and this panel is where it would break.** Bars are coloured by
**family** — cyan Analysts, amber Risk, purple Research, green Execution — never by member. Four
analysts sharing one cyan is correct; giving each its own hue would be the bug. Labels use the
Room's own abbreviations (`FUND`, `MKT`, `CON`, `BEAR`, `TRADE`) so the vocabulary matches what the
user already sees.

### 4.2 The one hazard this layout creates

The mandate has a dirty state and an explicit Save. **In a segmented screen, switching segments
mid-edit is silent data loss.** The Save affordance stays pinned in the header while MANDATE is
active, a dirty marker appears on the segment, and a segment switch with unsaved edits must prompt
rather than discard. This is the class CR040 exists for: it must fail visibly.

## 5. Copy that becomes false — replaced by an affordance, not a rename

Two shipped strings **name a screen by its position in the nav**, and one fires at the worst
possible moment: when a compliance breach has just blocked the user's trade
([`trade_ticket_sheet.dart:416`](../../../mobile/lib/screens/sim/trade_ticket_sheet.dart), rendered
inside the violations block right after the blocking Sharia verdict banner).

| String | Where | Today |
|---|---|---|
| `tradeTicketChangeMandate` | `app_en.arb:1121` | *"Change what is enforced via **Settings → My Mandate**."* |
| `floorRestartOnboardingConfirmBody` | `app_en.arb:85` | *"…change that in **Settings → My Mandate**."* |

The obvious fix is to rename the path to `YOU → Mandate`. **We are not doing that** — Saiful:
*"always make it easier for the user!"* A rename leaves the same trap armed for the next nav change
and still makes the user walk there themselves.

**Replace the instruction with the control.**

| | Was | Becomes |
|---|---|---|
| Blocked trade ticket | *"Change what is enforced via Settings → My Mandate."* | *"Change what is enforced."* + a button **`OPEN MY MANDATE`** that pushes the mandate directly |
| Restart-onboarding dialog | *"…change that in Settings → My Mandate."* | *"…that stays as it is, and you can edit it any time."* — no path named |

The dialog gets no button on purpose: it is a two-action confirm about restarting the interview, and
a third action that navigates away mid-decision is worse, not easier. Removing the path is enough —
there is nothing left to go stale.

**This is not a new pattern.** `floorLockedGoToLessons` (`app_en.arb:101`) is already
**`"GO TO LESSONS"`** — a button, not directions. CR133 applies the pattern the app already ships
consistently.

Both strings carry **`retranslate:[ar,ms]`**.
[`safety_floor.md:182,190`](../../initial_specs/02_agents/safety_floor.md) repeats the instruction
in spec/prompt copy — *"edit your halal flag in Settings → My Mandate first"* — which is worse than a
label because it reads as AMI's own reasoning. Flagged for the agents track; **not** in shipped
`.py` (grepped).

### 5.1 The guard — this string has already been wrong once

`@floorRestartOnboardingConfirmBody`'s own metadata records that **DEF158 corrected it before**, for
claiming a data loss that did not happen. Same string, same class: confident copy asserting
something the code contradicts. Per the failure-patterns rule, a second occurrence gets a guard.

Nothing couples `app_en.arb` to `home_shell.dart` — no test, no type, no grep — so the next nav
change breaks any surviving path silently, and the AR/MS copies stay wrong longer because the fix
has to flow through the i18n lane per-`id`.

Extend [`mobile/test/l10n_key_parity_test.dart`](../../../mobile/test/l10n_key_parity_test.dart)
(it already loads and walks every ARB) with: **no message value may name a bottom-nav destination
followed by `→`** — `RegExp(r'(Floor|Portfolio|Journal|Lessons|Settings|YOU)\s*→')` over unprefixed
keys in every locale. Verified safe against today's file: the other `→` uses are CTA arrows
(`"Next →"`, `"Try it now →"`, `"Tap to attempt →"`, `"Include the {agent} →"`) and the label
`"RISK → REWARD"`, none of which match. The two offenders are the only hits.

## 6. The bug-report door — filed separately

The only way to file a bug report is Settings → scroll past 13 sections → **long-press an
unlabelled grey version string**
([`settings_screen.dart:249`](../../../mobile/lib/screens/settings/settings_screen.dart),
`_AppVersionChip` at `:1139`). `bug_report_sheet.dart:5` documents *"call this from anywhere"* and
exactly one caller exists. No label, no hint, no second door.

This is already a defect, and demoting Settings two taps deeper makes it worse while we are trying
to get reports out of alpha testers. **Flagged for the Architect to mint as its own DEF** — it is a
live problem whether or not CR133 ships. CR133 adds the labelled entry as part of the Settings
rehome.

## 7. One shared header

Extract `AmiScreenHeader` into `widgets/hex/`: 64pt, `glassChrome`, `slate700` bottom border, mono
accent title, optional back, optional trailing actions. `YOU` needs one with a gear; four
independent renderers of the same chrome is the **DEF098** class, and hand-adding a fifth is how it
stays that way. `SettingsScreen` becomes a pushed route — it appears nowhere today but
`home_shell.dart:34` — so it needs a back affordance; reuse Lessons' `showBack`.

Floor is left alone this CR. Its scrolling logo row should become the shared header for
consistency, but nothing here needs to be pinned there — phase 3.

## 8. Phasing

**Phase 1 — the restructure minus the game. No backend.**
`AmiTab` enum · shared `AmiScreenHeader` · `YouScreen` (identity card + three segments + gear,
absorbing `JournalScreen` and Settings sections 1–3) · Settings as a pushed route with a labelled
bug-report door · Journal tour re-triggered on its segment · the two arb strings.
Ships at four tabs.

**Phase 2 — with CR109.** `game` inserted into the enum at index 2 (one line). Runs, trophies and
the career record live inside GAME per §9.0. `LeagueCard` → game summary card;
`_LeagueSection` and `streak_chip.dart` deleted per Amendment A
([CR109.md:589](../CR109_pnl_game_ami_cash/CR109.md)).

**Phase 3 — separate.** Group Settings' remaining 10 sections; Floor gets the shared header;
mandate deep-link from the lesson that tells users to revisit it.

## 10. Acceptance

1. `flutter analyze --no-fatal-infos` clean after the enum swap — **the proof no integer tab
   literal survived**.
2. `flutter test` green; `pytest backend/tests/unit/ -q` unaffected (no backend change).
3. Walk the tour **cold**: all four sections still fire, Journal's included on its new trigger.
4. Portfolio History → "Review in Journal" lands on `YOU`'s **JOURNAL** segment — not MANDATE, not
   INSIGHTS, not GAME.
5. **Edit the mandate, switch segments without saving.** The prompt fires; the edit does not vanish.
6. **The blocked-trade sheet offers a working `OPEN MY MANDATE` button** — one tap from the block to
   the rule that caused it — and neither it nor the restart dialog names a nav path at all.
   The new `l10n_key_parity_test` guard (§5.1) is green, and **fails** if either path is reinstated.
7. Nav labels render on one line at the largest supported text scale, checked by **rendered size**
   rather than line count, at both four and five cells.
8. Settings, My Mandate and *file a bug report* are each reachable in ≤2 taps, and the bug-report
   entry carries a visible label.
9. **INSIGHTS renders no figure it cannot derive.** Specifically: the analyst chart is built from
   `ONE_ON_ONE`/`AGENT_COACH` entries and **not** from `ROOM_RUN.agents_involved`; and
   followed-vs-overrode and safety-floor-stops are either absent or labelled as not yet measured —
   never shown as `0`. CR040: a number that cannot be computed must not be rendered as one that can.
10. **Each INSIGHTS card honours its empty-state threshold** rather than rendering a degenerate
    ratio: trades card hidden under 3 closes, challenge rows omitted under 5 attempts, drift hidden
    at one version, verdict card hidden with no rooms. A `1/1` bar reading 100% is the failure mode.
11. **`NO_VERDICT` is counted as its own outcome, never folded into `REJECT`**, and a run with
    `payload.verdict == null` is excluded from the verdict mix rather than counted as `PASS`.

## 11. Prototype

[`prototype/template.html`](prototype/template.html) is the source; `nav.html` is **generated** by
[`prototype/build.py`](prototype/build.py), which inlines Inter + JetBrains Mono as subsetted base64
woff2 because an Artifact's CSP blocks font CDNs. **Never hand-edit `nav.html`.** Rebuild with:

```bash
python3 docs/forward_planning/CR133_bottom_nav_restructure/prototype/build.py
```

Nav icons are **inline SVG, not glyphs** — the geometric codepoints (U+25xx) are absent from Inter
and from `build.py`'s `UNICODES`, so a glyph icon would silently vanish. This is the trap that
turned a caret into a full stop in the CR120 prototype.

Every number printed under a phone in the prototype is read out of the DOM at render time.
