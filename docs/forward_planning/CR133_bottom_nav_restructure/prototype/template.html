The bottom nav, and what YOU holds

CR109 adds a game. hex_bottom_nav.dart shows five destinations and all five are taken, so Settings comes off the bar. This is the structure Saiful chose, built out — plus the two things it silently breaks, and how they get caught at compile time instead of in the field.

Decided 2026-07-30. GAME takes slot 3. Slot 5 becomes YOU — your mandate, your journal, your insights, and Settings behind the gear. Career points, runs and trophies stay inside GAME, where CR109 §9.0 put them.

02 — slot 5

YOU — the surface the app never had

Portfolio owns the money, Lessons owns the curriculum, GAME owns the score. Nothing owned you. It takes CR120's shape — a pinned card over segmented tabs — so this is the second use of a decided idiom, not a new one. Tap the segments and the nav.

Why the mandate sits here, not behind the gear

It is the most identity-defining object in the app — your standing order to the team — and a training instrument the curriculum tells you to revisit. Today it is the first three sections of a screen labelled "Settings", which is why it reads as configuration. Portfolio and Lessons still deep-link straight into it: one screen, several doors.

Why INSIGHTS, and not credits or badges

AMI's claim is that it makes you a better decision-maker, and nothing in the app tells you what your decisions look like. The Journal is a log; INSIGHTS is what makes the log educational. Every number in it comes from journal rows already being written — entry_type, agents_involved, outcome, mandate_version. No new tables, no CR109 dependency.

Rejected: credits/membership (it's billing — behind the gear), agents unlocked (the Floor's entire job), streaks (Amendment A deletes them).

The one hazard this layout creates. The mandate has a dirty state and an explicit Save. In a segmented screen, switching segments mid-edit is silent data loss. Edit a slider in MANDATE and try to leave — the amber pip appears on the segment and the switch must prompt. This is the class CR040 exists for: it has to fail visibly.

03 — what breaks silently

GAME inherits the Journal's index

Tab identity is an integer literal scattered across five files. When GAME lands on index 2 it inherits everything that pointed at the Journal — and nothing fails loudly. This is the same class as DEF190.

mobile/lib/screens/sim/portfolio_screen.dart:1528
ref.read(activeTabIndexProvider.notifier).state = 2, // Journal

Portfolio History's "Review in Journal" opens the game.

mobile/lib/screens/journal/journal_screen.dart:96
if (next != 2) return;

The Journal's coach-mark tour fires on the game tab, once, and is then marked seen forever.

the fix — ships before the reorder
enum AmiTab { floor, portfolio, game, lessons, you }

Both become compile errors. flutter analyze clean is the proof no literal survived — and CR109's later insert is then one line, not a renumbering.

Survives untouched either way: floor_screen.dart:67,320 (!= 0), portfolio_screen.dart:123 (!= 1), lessons_screen.dart:79 (!= 3). Which is exactly why this is dangerous: three of five keep working, so a smoke test passes.

05 — directions replaced by a door

Don't tell them where to go. Take them.

Two shipped strings name a screen by its position in the nav, and one fires at the worst possible moment: a compliance breach has just blocked your trade and you want to know how to change the rule. Renaming the path to "YOU → Mandate" would work — and would leave the same trap armed for the next nav change, while still making the user walk there.

TRADE BLOCKED
BUY 40 PYPL @ $71.20
Your mandate excludes this position. The compliance check is a hard floor — PM cannot be coached past it.
Shipped today · app_en.arb:1121
"Change what is enforced via Settings → My Mandate."
Directions. The user still has to walk there, and the path goes stale the moment the nav moves.
After CR133
"Change what is enforced." OPEN MY MANDATE
One tap from the block to the rule that caused it. No path in the copy, so nothing left to go stale.

Not a new pattern — one the app already ships

app_en.arb:101 floorLockedGoToLessons is already "GO TO LESSONS" — a button, not directions. CR133 applies it consistently.

The full list

app_en.arb:1121 tradeTicketChangeMandate — on a blocked trade (trade_ticket_sheet.dart:416). Becomes copy + button.
app_en.arb:85 floorRestartOnboardingConfirmBody — the restart-onboarding dialog. Path removed, no button: it is a two-action confirm, and a third action that navigates away mid-decision is worse, not easier.
safety_floor.md:182,190 has the PM say it — worse than a label, because it reads as AMI's own reasoning. Agents track. Not in shipped .py.

Both app strings carry retranslate:[ar,ms].

And a guard, because this string has been wrong before. @floorRestartOnboardingConfirmBody's own metadata records that DEF158 already corrected it once, for claiming a data loss that never happened. Same string, same class. Nothing couples app_en.arb to home_shell.dart, so l10n_key_parity_test.dart gains one rule: no message value may name a nav destination followed by →. Checked against today's file — the other arrows are CTAs ("Next →", "Try it now →") and the label "RISK → REWARD". Only the two offenders hit.
