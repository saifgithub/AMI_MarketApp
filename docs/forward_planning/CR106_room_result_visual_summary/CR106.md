# CR106 — Room result: graphical Verdict Board + collapsed transcript

**Status:** design spec + prototype delivered · no code shipped
**Surfaces:** Convene the Room **and** the Decision Journal replay (scope extended 2026-07-28)
**Track:** UI Designer · **Raised:** 2026-07-28 · **Prototype:** [`prototype/room_board.html`](prototype/room_board.html)

---

## 1. Why

Saiful, relaying user feedback:

> *"the long technical result from convene the room \[is not\] good, most users do not want to read too
> much, so a graphical/iconical response (with the option to look at the full details) might be easier
> for the users."*

The complaint is measurable, not a matter of taste:

| Measure | Today | Source |
|---|---|---|
| Agent contributions stacked in one scroll | 12 | [`room_screen.dart:115-120`](../../../mobile/lib/screens/room/room_screen.dart#L115-L120) |
| Prose per completed run | **~3,500–6,000 chars / 30–40 sentences** | `_LENGTH_GUIDE`, [`room_prompts.py:65-78`](../../../backend/app/services/room_prompts.py#L65-L78) |
| Phone screens before the verdict is reached | **4–7** | derived from the above at `AmiTypography.stream` (13pt / 1.5) |
| Summary, sectioning, collapse or truncation anywhere | **none** | zero `ExpansionTile` / `ExpansionPanel` / `AnimatedCrossFade` in `mobile/lib` |
| Where the user is left when the run ends | pinned to the bottom of the wall | `_scrollToBottom()`, [`room_screen.dart:50`](../../../mobile/lib/screens/room/room_screen.dart#L50) |

Two aggravating details. The metric rows (size / entry / stop / target / horizon) render **only when the
verdict is APPROVE** ([`room_screen.dart:957`](../../../mobile/lib/screens/room/room_screen.dart#L957)), so a
PASS is prose and nothing else. And the Journal replay of the same run is strictly worse than the Room —
[`journal_detail_screen.dart:272-308`](../../../mobile/lib/screens/journal/journal_detail_screen.dart#L272-L308)
re-renders the transcript with no markdown parsing, no metric rows and no hex avatars.

No existing CR or Defect covers this (checked CR001–CR105, DEF001–DEF130). The original spec already
anticipated the idea — [`convene_the_room.md:95-105`](../../initial_specs/02_agents/convene_the_room.md)
describes a v1.0 *"visual deck above the Matrix Console, console collapsible"*. CR106 is that idea,
redirected from **animated theatre** to **readable summary**.

---

## 2. Decisions taken with Saiful (2026-07-28)

1. **Both modes ship.** A graphical **Verdict Board** *and* a **collapsed transcript** whose rows expand
   per agent. Saiful: *"I like the verdict board, but I also like the collapsed transcript, leading to the
   ability to uncollapse full detail per agent. Let's give the user the option to show the verdict board
   or to see the detail of the agent response as a default."* → a persisted user preference, not a
   hard-coded default.
2. **Per-agent stance comes from a backend structured envelope**, not a client-side keyword heuristic.
   Rationale is CR038: *prompt instructions are not controls* — a mis-tinted hex is a confident lie about
   what an agent said, the DEF059 class.
3. **This round is spec + prototype only.** No Flutter, no backend. Nothing is implemented until Saiful
   has reviewed the visuals on a phone.

## 3. The design

Content width on a 390pt device: `390 − 16×2 page − 16×2 card = 326pt`. Every dimension below is
budgeted against that number and verified in the prototype.

### 3.1 The mode toggle

A new **44pt sub-header strip** below the existing 88pt `_Header`:

```
‹  ⬢ CONVENE  NVDA                      88pt  (unchanged)
   ● COMPLETE
──────────────────────────────────────────────
 41s · 3 CREDITS        [ BOARD | TRANSCRIPT ] 44pt  (new)
```

- Two-segment control, `FlatTopHexagonClipper(cornerCut: 8)`, ~152×32pt, `labelMono` 10pt.
  Active segment = solid `hexBlue` fill + white. **Fill flip only, 200ms `AmiMotion.easeOut` — no sliding
  pill**, per the design system's *no motion on text*.
- Not inside `_Header`: the back button plus `THE ROOM · NVDA` already consume ~140pt there, and the
  toggle needs ~152pt — it overflows in AR.
- The strip's leading half surfaces `duration_ms` and `credit_cost`. Both exist on `RoomRun` today and are
  displayed nowhere.
- **The toggle appears only when `verdict != null`.** While streaming, the screen is always in transcript
  mode — a comb filling in live reads as a running vote count (see §6, T-VOTE).
- Persistence mirrors [`theme_provider.dart`](../../../mobile/lib/state/theme_provider.dart) exactly:
  `StateNotifierProvider`, prefs key `ami_room_view_mode`, async `_hydrate()` with try/catch fallback, and
  **write only inside `setMode`**. Never eagerly persist a default the user did not choose, or a future
  change of default will silently never reach existing users.
- **First run defaults to BOARD.** The complaint is "too much to read"; the default has to answer the
  complaint. A user who wants prose will find a toggle; a user drowning in prose will not go looking for a
  shortening control. No first-run modal — it is a view control, not a setup decision.

### 3.2 Mode A — the Verdict Board

#### Hero — a hex-marked KPI tile, not a giant hexagon

[`hex_clipper.dart:85`](../../../mobile/lib/theme/hex_clipper.dart#L85) records that sizing a label against
a hexagon's *bounding box* left `ISLAMIC FINANCE` 4.7pt of headroom at 1.0 text scale and **none at 1.15** —
usable width at the label line is only `0.724` of the box. So the hexagon carries **one glyph**; the tile
carries the words and the number.

The tile itself is `_VerdictCard`'s shipped treatment — `slate800`, 12px radius, 1.5px accent border on
all four sides (see §3.3b; it is **not** hex-clipped). Two internal rows: row 1 = 56pt outcome hex +
heading in `labelMono`; row 2 = the number full-width, with `FittedBox(scaleDown)` applied **to the number
only** — never to a mono label, which breaks its letter-spacing rhythm.

| `verdict.action` | Mark | Colour | Row 2 |
|---|---|---|---|
| `APPROVE` | `✓` | `hexGreen`, 14% fill | `3.0%` + dim `OF PORTFOLIO · 42-DAY HORIZON` |
| `PASS` | `—` | `slate500`, 14% fill | `NO POSITION` — **not** `0%` |
| `REJECT` | `✗` | **`hexRed`**, 14% fill | `BLOCKED` + violation count |
| `NO_VERDICT` | *(none)* | `slate500`, **outline only, no fill** | `NOT ISSUED` |
| `done && verdict == null` | `✗` | `hexRed`, outline only | `NO RESULT` + `CONVENE AGAIN` |

Five states, not four. The last one is reachable today and renders as a single bare sentence
([`room_screen.dart:129`](../../../mobile/lib/screens/room/room_screen.dart#L129)) — **an outage must never
be shaped like an outcome.**

Three notes on the table:

- **`REJECT` moves from amber to red.** [`colors_motion_rtl.md`](../../initial_specs/05_design/colors_motion_rtl.md)
  assigns red to mandate violations; amber stays reserved for the violations list and the safety-floor pill.
- **`NO_VERDICT` carries no glyph at all.** An empty outline hex *is* the statement; any mark inside it
  would read as a decision.
- **`PASS` and `NO_VERDICT` share `slate500`** and are told apart by fill-vs-outline, mark, heading, and
  what else is on the card. This copies [`sharia_verdict_banner.dart`](../../../mobile/lib/widgets/sharia_verdict_banner.dart)
  verbatim: *"unknown → NEUTRAL slate, deliberately… amber here would read as 'this trade was risky'."*
- Outcome colour is a **status** colour, sanctioned cross-family by the design system. The PM being purple
  is irrelevant to it.

#### Consensus comb — 11 hexes, not 12

The obvious encoding — tint each agent hex green for bullish, red for bearish — **violates "family colour
is sacred"**. An Analyst hex must read cyan, a Risk hex amber. Resolution:

> **Stance is the band a hex sits in. Conviction is the underline bar. Hue stays the family colour.
> The label inside the hex says who it is.**

```
11 VOICES                             11 STATED A VIEW
FOR      8
⬢⬢⬢ ⬢⬢ ⬢ ⬢⬢        ← (cyan cyan cyan)(purple purple)(green)(amber amber)
NEUTRAL  1
⬢
AGAINST  2
⬢ ⬢
NOT STATED  2                          ← a separate gutter, never a lane
⬡ ⬡
────────────────────────────────────
THE PM DECIDES — THIS IS NOT A VOTE
```

- Three stacked horizontal **bands**, not vertical lanes — lanes force 6-deep stacks 208pt tall.
- Hex cell **26pt** wide (22.5pt tall). Width budget, worst case (all eleven in one band):
  `11×26 + 6 intra-family gaps ×2 + 4 inter-family gaps ×6 = 322pt ≤ 326pt`. ✔
  Band = 14pt label row + 22.5pt hex + 3pt gap + 3pt conviction bar; three bands + gaps ≈ **143pt**,
  plus a 32pt gutter when non-empty. `band-row` wraps, so a large text scale costs height, never clipping.

##### Each hex carries its agent's label

Saiful, 2026-07-28: *"we will need to be able to identify the agents in the voices… since the groups share
the icon colours."* Correct, and it is the one thing colour cannot fix: family colour is shared **by
design**, so three cyan analysts, two purple researchers and three amber debators are mutually
indistinguishable without a mark. BULL vs BEAR — the pair a reader most wants to tell apart — are the same
purple.

**Decision: a mono label inside the hex.** Three options were built and compared at real size in the
prototype (rail control *Hex identity*), and the comparison is kept there so the call is auditable:

| Option | Verdict |
|---|---|
| **Letters** (chosen) | Every agent identifiable at 1.0× and 1.15×, in both themes. No legend to learn. Reuses names the user already sees everywhere else in the app. |
| **Icons** (minimal inline SVG, 2px stroke) | Rejected. At 14pt only the arrows, chevrons, equals and zigzag survive; the ledger, document, bubble, shield and merge glyphs are mush, and all eleven would require the user to learn a legend for a mark that has a perfectly good name. |
| **Colour only** | Rejected — it *is* the reported problem. |

Labels come from a new `combLabel` field on `Agent`, capped at 4 characters so it fits: `FUND MKT NEWS
SOC BULL BEAR RES TRD AGG CON NEU`. Only two differ from the shipped `abbreviation` — `RES-M → RES` and
`TRADE → TRD` — i.e. a truncation, not a second naming scheme. 4-character labels set at 7.5pt with
tightened tracking; 2–3 characters at 9pt. Both scale with text scale.

**Ink is `slate900`, never white.** `Colors.white` on `hexAmber` measures **1.8:1** and on `hexGreen`
**2.1:1** — below even the 3:1 large-text floor. Dark ink clears 7:1 on every family fill, and because
accent fills are identical in light mode (§7), one ink serves both themes. This is a live bug in
`HexAvatar` today — see §8.

- Families are grouped with a wider seam. That spatial cue plus the label is what rescues colour-blind
  users: cyan/green and amber/green converge under deuteranopia and protanopia, so grouping and text —
  not hue — carry identity.

##### Conviction is an underline bar, not a ring

A hexagonal conviction ring was the first design and is still the better *pure* meter — but it cost 9pt of
diameter, which is exactly the room a legible label needs. Given the choice between "how strongly" and
"who", **who wins**: an unidentifiable hex is not worth a finer magnitude read.

So conviction moves beneath the hex as a **22×3pt bar whose filled length** encodes it — still a magnitude
channel (length), just a cheaper one. Quantised to **three** levels **server-side**; the number is never
printed. Unknown conviction renders **no bar and no track at all** — absence must not look like "low".

The hexagonal ring stays in the design system's vocabulary for single-mark contexts where nothing competes
for the centre; `_DoughnutPainter` ([`track_hex_button.dart:107`](../../../mobile/lib/widgets/hex/track_hex_button.dart#L107))
remains the shipped precedent to generalise.
- **The Portfolio Manager is excluded.** Its position *is* the hero tile. Eleven voices with the caption
  `THE PM DECIDES — THIS IS NOT A VOTE`, because `_parse_pm_verdict` is the sole decision path and the
  safety floor can override even that. Transcript mode still shows 12 rows; that inconsistency is
  deliberate and labelled, which beats a graphic that implies democracy.
- Each hex needs a **44pt hit slug** (a transparent expanded tap area); tapping opens that agent's row.

**Encodings considered and rejected:**

| Rejected | Why |
|---|---|
| Fill-opacity / saturation ramp for conviction | `hexCyan` on `slate900` clears the 4.2:1 floor only above ~70% alpha (20% → 1.46:1, 50% → 2.8:1). Worse, `_RosterRow` ([`room_screen.dart:323`](../../../mobile/lib/screens/room/room_screen.dart#L323)) **already uses `Opacity(0.35)` on this very screen** to mean "hasn't spoken yet" — a low-conviction analyst would look like one that never ran. |
| Continuous lean axis (beeswarm) | Placing a hex at x = 0.63 asserts a precision an LLM-sampled stance cannot support. Three ordinal bands assert only membership, which the envelope *can* honestly deliver. CR038 applied to a chart. |
| Size for conviction | Area decodes poorly, and "small" reads as *weak* rather than *absent*. |
| Tinting the hex by stance | Breaks family colour, the one inviolable rule in this design language. |

##### Tapping a hex — a peek, not a mode switch

Saiful, 2026-07-28: *"when an agent is selected from the Board screen, do you think it makes sense to
switch to transcript and to the agent's exploded/detailed transcript?"*

**Half of it.** That destination is right; making it the *tap* is not. Three reasons:

1. **Back-out cost.** A 26pt mark is a small, casual target. Tearing down the whole surface in response
   loses the board's scroll position and obliges the user to find the toggle again to get back to what
   they were reading.
2. **Comparison is the normal case.** The comb exists to invite "why is BEAR against?" — and then, almost
   always, "what did CON say?" Under a mode switch that is four round trips through the toggle; under a
   sheet it is four quick peeks.
3. **It would switch a mode the user has a stored preference for.** A tap on content must never rewrite
   that default — see T-MODESIDE in §6.

**So: tap a hex → a bottom sheet.** It carries the agent's name and phase, `STANCE` / `CONVICTION` chips
when known, the full contribution as parsed markdown, and the AMI geometry annotation if the runner made
one. The board stays behind it; dismiss is a swipe or a scrim tap.

**And the sheet carries the destination Saiful asked for**, as an explicit action:
`READ THE FULL DEBATE →` switches to Transcript, expands that agent's row, scrolls it into view and
briefly tints it so the eye lands. The mode switch then happens when the user asks for it, not as a side
effect of curiosity.

Details that matter:

- **A withheld or empty agent gets no jump action.** A trip to a row that reads `NOT HEARD` is a wasted
  one; the sheet says what happened and the only action is dismiss.
- **The sheet hosts the same expanded-row widget** the transcript uses — no third rendering of an agent's
  contribution (T-TWICE).
- **In transcript mode a row still expands in place.** No sheet there, so there is no inconsistency: the
  sheet exists only where the full text has nowhere to go.
- Sheet discipline per DEF075: scrollable body, capped at ~72% height, bottom padding from
  [`sheetBottomInset(mq)`](../../../mobile/lib/widgets/sheet_insets.dart) — the guard CR080 flagged
  `convene_sheet.dart` for missing.

#### Risk / reward ribbon — gated on backend provenance

```
                    $178.40
                     ENTRY
 ▐████████▌▐███████████████████████████▌      RISK → REWARD   2.8 : 1
 $168.90                            $205.00
 STOP                                TARGET
```

- 8pt track, ends cut with `FlatTopHexagonClipper(cornerCut: 4)`. Risk segment (stop→entry) `hexRed` @45%;
  reward segment (entry→target) `hexGreen` @45% — sanctioned cross-family status colour.
- Entry marker: 14pt solid flat-top hex in `textHigh`, riding **above** the track. Stop and target labels
  sit **below** it. Splitting the rows is not cosmetic: with all three labels on one line they collide
  whenever entry falls within ~22% of either end, which is exactly what a tight stop looks like.
- **R:R is computed client-side from the same three prices the widget draws** — `(target − entry) / (entry − stop)`,
  1dp, rendered `—` unless `0 < stop < entry < target`. It must mirror
  [`trading_math/trade.py::risk_reward`](../../../backend/app/trading_math/trade.py). **Never accept an
  `rr` from the wire**: a sent value that disagreed with the drawn geometry would be a visible lie.
- **Provenance is rendered structurally.** Filled cap + `textHigh` label = a level the PM stated.
  **Hollow cap + dashed segment fill** = a level AMI derived. One 9pt mono footnote:
  `⬡ STOP · TARGET SET BY AMI, NOT THE PM`. Same colour, same size, **no amber and no ⚠** — hollow-vs-filled
  says *a different kind of thing*, not *danger*, and `⬢`/`⬡` is the brand's sanctioned pair.
- **The ribbon is locked to `TextDirection.ltr`.** It is a numeric magnitude axis and the design system
  already rules that numbers stay LTR inside RTL text. Verified necessary: without bidi isolation on the
  ratio, `2.8 : 1` renders as `1 : 2.8` in RTL — a *wrong number*, not a layout nit. Flag for a native
  Arabic reader before shipping.
- **Degradation when provenance is unavailable:** render the levels as today's `_MetricRow` list, with
  **no ribbon and no ratio**. The geometry *is* the claim.

#### Mandate override

When `overridden_from_llm` is set, a mandatory mono line sits between hero and comb:

```
MANDATE OVERRIDE — YOUR RULES CHANGED THE PM'S CALL
• Position would take semiconductor exposure to 34.2% — your mandate caps a single sector at 25%.
```

`violations[]` renders inline. **Violations never go behind an expander.** Without this line the board
contradicts itself — the comb shows 8 FOR while the hero says PASS, and the graphic reads as broken,
taking the user's trust in every other graphic with it.

#### Reason

APPROVE clamps `verdict.reason` to two lines behind a `WHY →` expander. **PASS and NO_VERDICT render it
unclamped.** The rule: *the board's prose budget is inversely proportional to its numeric content.*

**PASS board** — the comb is promoted into the hero slot. "The room split 4 FOR / 3 NEUTRAL / 4 AGAINST
and the PM declined" is the most informative board in the whole feature, and it is precisely the case that
today gets zero graphics. CTAs: `SEE CHART` + `ADD TO WATCHLIST` ([`watchlist_sheet.dart`](../../../mobile/lib/widgets/watchlist_sheet.dart)
already exists) — a PASS is a "not now", and the honest next action is to watch it.

**NO_VERDICT board** — the ribbon's slot is taken by **the roster gap**: the withheld agents' hexes in
their own family colour, dashed outline, no fill, under a `THE ROSTER GAP · N NOT HEARD` caption with their
names in mono. Not `slate700` — that token means *locked / unearned*, a different thing. The upgrade CTA
stays app chrome, physically separate from the reason block (CR098 acceptance #13 forbids plan names in
the PM's voice).

### 3.3 Mode B — collapsed transcript

Row budget at 390pt: `[28 hex][8][46 abbr][8][gist][8][20 mark][4][16 chevron]` → **220pt of gist ≈ 32
Latin characters**. That is a fragment, not a sentence. So: **extract, never summarise.** Ranked sources,
all available from today's raw prose:

| # | Source | Example | Note |
|---|---|---|---|
| 1 | **First `**bold**` span, verbatim, in mono** | `$30.8B · 4` | `_PROSE_FORMAT` ([`room_prompts.py:121`](../../../backend/app/services/room_prompts.py#L121)) instructs agents to bold key metrics — this is the agent's own designated headline number. It is a quotation, so it cannot be wrong. |
| 2 | **The Trader's level triple** | `$178.40 → $205.00 stop $168.90` | `_LEVEL_PATTERNS` ([`room_runner.py:956`](../../../backend/app/services/room_runner.py#L956)) already extracts these; the regexes port to Dart cheaply. |
| 3 | **AMI-annotation mark** | amber `⬢` | `content.contains('[AMI')` means the runner corrected or verified that agent's arithmetic. Highest-value bit in the transcript, a substring test, and exactly the row a user should be nudged to open. |
| 4 | `content.isEmpty` | `NO RESPONSE` | Never a blank row. |
| 5 | Withheld agent | `NOT HEARD` | Requires the `agent_withheld` SSE event to be handled (see B3). |
| — | ~~First sentence, truncated~~ | — | **Rejected.** The Bull/Bear prompts explicitly ask for *"thesis + evidence + falsifier"*; truncating an adversative sentence at 32 characters strands the negation and inverts the meaning. A line that looks like a summary but is an artifact of a character count is the DEF059 failure class. |

Rows are grouped under the six phase headers already defined in `room_runner.PHASES`. The expanded row is
today's `_AgentLine` markdown, unchanged. The avatar hex carries **no text** — the abbreviation is printed
8pt to its right, and `RES-M` does not fit in a 28pt hex anyway.

**Post-envelope**, source 1 is replaced by the envelope's `headline` and the row hex gains the conviction
ring. The headline must be **length-capped in the schema**, with the server nulling an over-length value —
otherwise the truncation bug has simply relocated somewhere prettier.

### 3.3b Surface shape — corrected against the shipped app

Saiful, 2026-07-28: *"the groups does not use hex-like design. look at the current journal design. It uses
rounded edges rects."* Correct, and the first pass of this prototype got it wrong.

The design-system mount specs `--clip-angle-panel` (20px cut corners) for cards and modals. **Nothing in
`mobile/lib` implements that.** What ships is: rounded rects for every content surface — `AmiRadii.card`
(8) generally, `AmiRadii.sheet` (12) for `_VerdictCard` — with hex clipping reserved for **marks and
controls**: agent avatars, chips, toasts, the bottom nav, and the period toggle in
[`ticker_chart.dart:185`](../../../mobile/lib/widgets/ticker_chart.dart#L185) at `cornerCut: 8`. Room CTAs
carry no `shape:` override at all, so they are Material 3 defaults (stadium).

**The app wins over the mount** — this feature lives inside those screens. It is also the better rule on
its own terms: cutting the corners off every card spends the hexagon on chrome and leaves nothing to
distinguish the marks that should carry it.

Applied: hero = `_VerdictCard`'s treatment (`slate800`, 12px radius, 1.5px accent border all round);
ribbon / comb / levels = the standard card (`slate800`, 1px `slate700`, 8px); reason = the inner `slate900`
block at 8px, exactly as [`room_screen.dart:1002-1010`](../../../mobile/lib/screens/room/room_screen.dart#L1002-L1010);
CTAs = stadium. **Hexagonal geometry survives on exactly three things: the agent marks, the hero's outcome
mark, and the BOARD|TRANSCRIPT toggle** — the last matching `ticker_chart`'s period chips verbatim.

Written up as a system rule in [`data_viz_and_meters.md`](../../initial_specs/05_design/data_viz_and_meters.md) §4.0.

### 3.4 The Journal replay surface

Saiful, 2026-07-28: *"we need to implement this also in the journal when we display room results."*
In scope, and it is the surface in the worse state — see §1.

#### One widget, two callers

The Room and the Journal must render from **one shared widget**, with a normaliser at each boundary.
This is not a tidiness preference. DEF098 named the exact failure class in this codebase — *two
independent renderers of the same data, neither a superset of the other, drifting because a developer has
to remember both* — and shipped a parity guard for it on the prompt side. The Room-vs-Journal split is
that same shape one layer up in the UI, and it has already produced the divergence: today the Journal
drops markdown parsing, the metric rows and the hex avatars that the Room has. Rebuilding the board
twice would recreate the bug the CR is fixing.

Concretely: extract `RoomBoard` and `RoomTranscriptRows` against a plain view-model, and give
`room_screen.dart` and `journal_detail_screen.dart` each a small mapper into it. Neither screen should
own board layout.

#### What the Journal snapshot actually has

The payload is written once by
[`build_journal_entry_for_run`](../../../backend/app/services/room_runner.py#L1277-L1332) and is **not** a
`RoomRun`:

| Field | Live Room | Journal | Where |
|---|---|---|---|
| `verdict` (all fields, incl. `opinions_not_included`) | ✔ | ✔ | `payload["verdict"]` |
| `transcript[{agent_id, content}]` | ✔ | ✔ | `payload["transcript"]` |
| `model_tier` | ✔ | ✔ | `payload["model_tier"]` |
| `ticker`, `mandate_version`, `created_at` | ✔ | ✔ | on the `JournalEntry`, not the payload |
| `duration_ms`, `credit_cost` | ✔ | **✘** | never serialised |
| `live_data_notice`, `agent_withheld` | stream only | **✘** | never persisted |

So the sub-header strip carries `{TIER} TIER · MANDATE v{n}` on the Journal where the Room shows
`41s · 3 CREDITS`. Everything else the board needs is present.

#### Vintage degradation — the part that matters

The payload is a **snapshot taken at write time**. An entry written before a field existed will never have
it, and **re-fetching `GET /v1/room/{reference_id}` does not fix this** — `RoomRunRow.verdict` is the same
JSONB, written in the same moment. So the board degrades **per entry**, not per app version:

- **No `level_provenance`** → no ribbon, no ratio. Falls back to the `_MetricRow` list under a
  `TRADE GEOMETRY · PROVENANCE UNAVAILABLE` caption. (§4.2 B1 — the geometry *is* the claim.)
- **No per-agent stances** → the comb renders **one honest sentence**, not three empty bands and eleven
  hexes in a gutter: *"Agent stances were not recorded for this run. Open the transcript to read what each
  one said."*
- **Never backfill.** A provenance or stance value inferred later is a guess about a past run, presented
  with the authority of a record.

The collapsed transcript degrades to nothing at all — it needs only `content`, which every entry has. That
is the strongest argument for shipping mode B on this surface first.

#### A journal entry is a record, not a setup

Two consequences, both verified in the prototype:

- **No `OPEN TRADE TICKET` on the Journal.** A June entry's `$118.20` entry price is not a live setup, and
  offering a one-tap ticket against it invites a trade at a stale price. CTAs are `SEE CHART` +
  `RE-RUN WITH CURRENT MANDATE` — which is what
  [`screen_inventory.md:120`](../../initial_specs/05_design/screen_inventory.md) already specifies for this
  screen.
- **The geometry is dated:** `LEVELS AS OF 02 JUN 2026 — A RECORD, NOT A CURRENT SETUP`, above the ribbon
  or the metric list.

#### Bugs this fixes on the way

`journal_detail_screen.dart:290-308` renders each contribution as `Text(content)` with **no markdown
parsing**, so `_PROSE_FORMAT`'s `**bold**` metrics reach the user as literal asterisks. Adopting the shared
rows fixes that, the missing metric rows and the missing hex avatars in one move.

## 4. Data contract

### 4.1 Bindable today — zero new parsing

`verdict.action` (four real values, **not** buy/hold/sell — the Room is long-only, `Side.BUY` is hardcoded
at [`room_runner.py:2279`](../../../backend/app/services/room_runner.py#L2279)), `size_pct`, `entry`,
`stop`, `target`, `time_horizon_days`, `reason`, `violations[]`, `overridden_from_llm`,
`opinions_not_included[]`, `status`, `duration_ms`, `credit_cost`, `model_tier`, `ticker`, and the ordered
12-item transcript keyed by `agent_id`. Family, colour and phase resolve client-side from the static maps
already in [`agent.dart`](../../../mobile/lib/models/agent.dart).

**Absent at every layer:** any confidence or conviction number, any per-agent stance, any structured
bull-case/bear-case object. A grep for `confidence|conviction|stance` across `backend/app/schemas`,
`room_runner.py` and `mobile/lib` returns only prose inside prompt text.

### 4.2 What the backend must add

A graphical board makes every unsupported claim louder. Prose hides these three; a board cannot.

#### B1 — `verdict.level_provenance` · **blocks the ribbon**

```python
level_provenance: dict[str, Literal["pm", "trader", "ami_default"]]
# keys: entry, stop, target
```

[`room_runner.py:859-862`](../../../backend/app/services/room_runner.py#L859-L862) **mints** a missing stop
at `entry * 0.94` and a missing target at `entry * 1.13`, and discloses it **only by appending a sentence
to `reason`**:

```python
_defaulted = [n for n, raw in (("stop", stop_raw), ("target", target_raw)) if raw is None]
if _defaulted:
    reason += f" ({'/'.join(_defaulted)} not stated by the PM — defaulted to a ~6%/13%-from-entry protective level, not a PM-chosen price.)"
```

There is no boolean flag. Today that sentence at least renders unclamped
([`room_screen.dart:1009`](../../../mobile/lib/screens/room/room_screen.dart#L1009)). Clamping it behind a
`WHY` expander **while** promoting the same numbers into a to-scale ribbon with a computed ratio would make
an existing DEF059-shaped problem strictly worse. `entry` needs three values, not two, because
`entry = _safe_float(parsed.get("entry")) or ctx.trader_entry` silently substitutes the Trader's number.

> **Side effect worth knowing:** a minted pair always yields R:R of exactly **2.2 : 1** with entry at
> **31.6%** of the track. Every defaulted verdict will be pixel-identical. Users will notice the pattern
> before we disclose it. (Scenario 2 in the prototype shows this.)

#### B2 — per-agent structured envelope · **blocks the comb**

```json
{ "stance": "for" | "against" | "neutral" | null,
  "conviction": "low" | "medium" | "high" | null,
  "headline": "<= N chars, server nulls an over-length value>",
  "body": "<the prose that renders today>" }
```

Follows the PM's existing JSON-envelope precedent ([`room_prompts.py:99-107`](../../../backend/app/services/room_prompts.py#L99-L107)) —
the one structured-output contract in this codebase that already works in production. Requirements:

- `null` survives all the way to the pixel. **Missing → the gutter, never `neutral`, never `0.5`.**
  `neutral` must mean *the agent expressed neutrality*, never *the parser gave up*.
- Band counts are computed **only over non-null stances**; the caption reads `9 STATED A VIEW`, not a
  total that always sums to 11.
- Conviction is quantised **in the envelope**, not in the renderer — make the imprecision structural
  rather than trusting every future widget to be tasteful about it.

#### B3 — surface what already exists but is dropped

- `opinions_not_included` is emitted by the backend and **never read** by
  `RoomVerdict.fromJson` ([`models/room.dart:33`](../../../mobile/lib/models/room.dart#L33)).
- The `agent_withheld` SSE event is **dropped** by the switch in
  [`room_providers.dart`](../../../mobile/lib/state/room_providers.dart).

A withheld analyst is currently invisible end to end — which reads as a rendering bug and hides a
monetisation-relevant fact.

## 6. Traps — things that must not happen

| Tag | Trap |
|---|---|
| **T-PROV** | The board demotes the only existing disclosure of an invented number. `reason` renders unclamped today; clamping it while upgrading the same numbers into a graphic is a net loss of honesty. **No `level_provenance` → no ribbon.** |
| **T-SUM11** | Band counts that always sum to 11. Unparseable envelopes bucketed to `neutral` would state a consensus that never occurred. |
| **T-VOTE** | Any `CONSENSUS 78%` statistic. There is no defensible weighting — the PM is not 1/11 of a vote, and the safety floor can override the PM. Excluding the PM from the comb resolves this structurally instead of with a disclaimer. |
| **T-LIVE** | Rendering the board mid-stream. A comb filling in live looks like a running tally. Transcript mode during streaming, always. |
| **T-OVERRIDE** | Omitting the mandate-override line. Comb says FOR, hero says PASS, board looks broken. |
| **T-UNKNOWN** | `RoomVerdict.fromJson` coerces an unknown action to `PASS` ([`models/room.dart:35`](../../../mobile/lib/models/room.dart#L35)) — a new backend action value silently becomes a real outcome. Must map to explicit `unknown` → `NO RESULT`. |
| **T-SHARE** | `ShareService.shareVerdict` takes `isApprove`/`isPass` booleans ([`share_service.dart:26`](../../../mobile/lib/services/share/share_service.dart#L26)) — a 2-bit encoding of a 4-value enum, so REJECT and NO_VERDICT produce **identical** share cards. This one goes public. |
| **T-UNIT** | A bare `3.0%` next to APPROVE reads as expected return. Always paired with the dim `OF PORTFOLIO` unit line. |
| **T-MOTION** | Animating the comb assembling. One 200ms opacity fade of the whole comb; hexes flying into bands imply live computation and blow the motion budget. |
| **T-BIDI** | Numeric runs without `unicode-bidi: isolate` invert in RTL. Confirmed in the prototype: `2.8 : 1` became `1 : 2.8`. |
| **T-TWICE** | Building the board separately for the Room and the Journal. That is DEF098's named class — two renderers, neither a superset — and it is exactly how the Journal's rendering fell behind in the first place. One widget, two mappers. |
| **T-STALE** | A trade CTA on a Journal entry. `OPEN TRADE TICKET` against a June entry price offers a trade at a stale level. The Journal gets `SEE CHART` + `RE-RUN WITH CURRENT MANDATE`, and its geometry is captioned with the run date. |
| **T-MODESIDE** | A mode switch triggered as a side effect writing the persisted default. Only the segmented toggle calls `setMode`; the sheet's `READ THE FULL DEBATE` changes the mode for this screen only. Otherwise one curious tap silently rewrites what every future Room opens as. |
| **T-BACKFILL** | Inferring `level_provenance` or a stance for an old journal entry so the graphic can render. That is a guess about a past decision wearing the authority of a record. Old entries degrade; they are never reconstructed. |

## 9. The prototype

[`prototype/room_board.html`](prototype/room_board.html) — one self-contained file, no external requests.

Eight scenarios across both surfaces — **Room:** `APPROVE` with PM-stated levels · `APPROVE` with
AMI-derived levels · `PASS` with mandate override · `PASS` room split · `NO_VERDICT` with five analysts
withheld · `NO RESULT`; **Journal:** a recent entry · a pre-CR106 entry showing the vintage degradation
(no ribbon, comb says "not recorded", transcript still perfect). Both modes throughout, with live switches
for **dark/light**, **LTR/RTL** and **1.0× / 1.15× text scale**.

The rows, gists, ribbon geometry and R:R are computed from the scenario data at render time, so the
extraction rules in §3.3 are demonstrated on real prose rather than mocked up. Scenario objects use the
real field names from `backend/app/schemas/room.py`, so the file doubles as a readable statement of the
B1/B2 contract.

Rebuild after editing `template.html`:

```bash
python docs/forward_planning/CR106_room_result_visual_summary/prototype/build.py
```

`build.py` inlines two faces as base64 `woff2` — Inter and JetBrains Mono, subsetted to the Latin range the
page uses (~35 KB total). They are the app's own bundled cold-launch fallbacks from `mobile/assets/fonts/`,
not Google-hosted copies: a published Artifact's CSP blocks every external host, so an `@import` would fall
back silently and the review would be of the wrong typeface.

## 10. Acceptance

1. On a 390×844 device at 1.0 text scale, the APPROVE board reaches its **primary CTA within one screen
   plus at most one short scroll**; hero, R:R ratio and comb heading are above the fold with no scrolling.
   Nothing clips at 1.15.
2. All **five** hero states are visually distinct, and none of PASS / NO_VERDICT / NO RESULT reads as a
   rejection.
3. The ribbon renders **only** when `level_provenance` is present; AMI-derived levels are hollow-capped and
   footnoted; the ratio is computed from the drawn prices and shows `—` for an incoherent triple.
4. Comb band counts are computed over non-null stances only; unknown stances land in the gutter; the comb
   holds 11 hexes and carries the `THE PM DECIDES` caption.
5. No transcript row shows a truncated sentence — every gist is a verbatim quotation, a parsed level
   triple, or an explicit `NOT HEARD` / `NO RESPONSE`.
6. `overridden_from_llm` always renders the override line with `violations[]` inline, never collapsed.
7. Light and dark both clear the 4.2:1 floor; accent fills keep tone, accent ink darkens.
8. RTL mirrors the board but not the ribbon; no numeric run inverts.
9. The persisted mode is written only on explicit user choice; a fresh install lands on BOARD.
10. **The Room and the Journal render from the same widget.** A test asserts that a `RoomRun` and the
    `JournalEntry` built from it by `build_journal_entry_for_run` produce the same board for every field
    both surfaces carry — the UI-layer counterpart of DEF098's parity guard.
11. A journal entry whose payload predates `level_provenance` renders the metric list with no ribbon and
    no ratio; one whose payload has no stances renders the comb's "not recorded" line, not empty bands.
    Neither value is ever inferred.
12. No Journal surface offers a trade ticket, and any Journal geometry carries the run date.
13. Journal contributions render as parsed markdown — `**bold**` never reaches the user as asterisks.
14. Tapping a comb hex opens the peek sheet and leaves the board's scroll position intact; dismissing
    returns the user to exactly where they were.
15. `READ THE FULL DEBATE` switches mode, expands and scrolls to that agent — and **does not** write
    `ami_room_view_mode`. A test asserts the stored value is unchanged after the jump.
