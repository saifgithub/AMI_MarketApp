## D3 — Saiful's reframing, 2026-09-28: the four real questions
*status: active framework — all CR247 work hangs off these*

The 12 teammate prompts and the base prompts are **suggestions**, not the
object of study. The object of study:

1. **Are we feeding the LLM all the right information?**
2. **What additional information do we need to supply?**
3. **Are the scores generated by one LLM and consumed by the others mutually
   consistent and robust?** (producer→consumer semantics)
4. **Does the LLM know what to do with the data?**

## D4 — Q3 preliminary finding: conviction semantics are per-role, not shared
*2026-09-28 · status: finding, needs verification pass*

The same word "conviction" is deliberately defined differently per agent
(CR197 prompt rebuild): Aggressive = "would the numbers move a sceptic";
Conservative = "is there a specific quantified downside"; Neutral = "how
clearly the evidence separates the two cases". A consumer (PM, or the
scoreboard reader) sees one column labelled CONVICTION whose cells measure
three different quantities. This is exactly the class of inconsistency Q3
asks about. Candidate fix directions: per-agent conviction relabelled in the
scoreboard, or one shared definition. NOT yet verified against the current
scoreboard renderer.

## D6 — (a) CIO ensemble: 5× same prompt, ratio → verdict by risk score; or 5 different LLMs
*2026-09-28 · status: under discussion*

Saiful's proposal: run the CIO prompt 5 times; the APPROVE/PASS ratio,
thresholded by the user's risk_score, determines the final verdict. Variant:
send to 5 different LLMs.

Points raised (Kimi):
- CR197 measured the same-prompt noise floor directly: resampling the
  identical PM prompt flips ~12% of verdicts (8 up / 8 down, net 0). A 5-round
  same-prompt ensemble mostly measures that stochasticity — it converts a coin
  flip into a probability estimate of a coin flip. The reasoning path doesn't
  diversify if the prompt doesn't.
- 5 different LLMs diversifies priors (real value against correlated
  hallucination) but costs: 4 new provider integrations, latency, user data
  to 4 external APIs, and refusal/alignment differences that inject
  non-evidence disagreement. Also collides with tier_policy (per-plan model
  routing).
- The verdict is not just APPROVE/PASS — it carries size/entry/stop/target/
  horizon/kill_criterion. An ensemble needs an aggregation rule for those
  fields, not just the action.
- Cheaper variant capturing most of the value: single CIO + the completed
  scoreboard (D5) + a targeted second pass only on APPROVEs (adversarial
  re-check), if measurement shows false-approves are the costly error.

Open: what decision metric would the ensemble improve? (Approval-rate
stability? Verdict quality vs outcomes? Teaching value?) — needs a measurable
hypothesis before any build, per CR247 scope item 7.
