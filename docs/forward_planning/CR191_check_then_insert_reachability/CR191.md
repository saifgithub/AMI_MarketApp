# CR191 — the eleven unreviewed check-then-INSERT sites

**Status:** proposed · **Filed:** 2026-08-17 (AT:R70) · **Split from:** DEF308

## What

Give each of the eleven sites pinned in `_UNREVIEWED`
(`backend/tests/unit/test_p15_check_then_insert_guard.py`) its own reachability
answer, and delete it from the pin when it has one.

```
auth_service.py          _claim_or_create        User
auth_service.py          ensure_anonymous        User
auth_service.py          sign_in_with_apple      User
auth_service.py          sign_in_with_google     User
client_release_floor.py  create_floor_raise      ClientReleaseFloorRow
games_desks.py           ensure_desk_users       User
games_service.py         ensure_field            GameFieldRow
lessons_service.py       grant_activation        AgentActivationRow
lessons_service.py       mark_started            LessonProgressRow
lessons_service.py       submit_quiz             LessonProgressRow
watchlist_store.py       add                     SimWatchlistRow
```

Each reads a row, finds nothing, and inserts — correct in one process, an
`IntegrityError` in two (failure_patterns.md **P15**).

## Why it is a CR and not the rest of DEF308

DEF308 was *"the guard cannot see half the pattern"*. That is fixed and
mutation-verified. These eleven are what the fixed guard then revealed, and they
are not one change: DEF220 answered its six sites **three different ways**
(re-read-and-update, retry-then-raise, skip-because-idempotent), which is the
evidence that a blanket `except IntegrityError: pass` across all eleven would
satisfy the guard and answer nothing.

Four of them are the auth path, where the loser of a race is a duplicated or
orphaned account rather than a skipped badge. Three gate agent unlocks.

## Why it is not urgent, stated as a measurement and not a feeling

No live failure is known. Alpha runs one uvicorn with no `--workers`, and
CR136-M01's auditor measured **0 races in 60 trials** on this stack.

That is a **deployment fact, not a guard**. CLAUDE.md's Beta stack is GCP Cloud
Run, where instances share no state and every one of these becomes reachable the
day a second instance exists.

## Trigger

**This CR gates the move to more than one backend instance.** It is not
calendar-driven backlog: it is due when horizontal scale is, and not before.

## Scope

In: the eleven sites, one reachability answer each, the `_UNREVIEWED` entries
deleted as they are answered, a test per non-obvious answer.

Out: widening the P15 rule again (DEF308 closed that), and any change to the six
DEF220 already answered.

## Acceptance

1. `_UNREVIEWED` is empty, or holds only entries with a *newer* defect ID and a
   stated reason.
2. `test_no_new_unguarded_check_then_insert_sites` green — including the `gone`
   assertion, which fails on a stale entry left behind after a fix.
3. Each answer is one of the three DEF220 shapes, or a fourth with its reasoning
   written down. Not a uniform wrap.
4. The concurrency claim is re-measured on whatever stack is current at the
   time, not carried over from CR136-M01's 60 trials.
