## Three deviations from the verdict, each with its reason

The verdict was followed except where following it literally would have produced a worse guard.
Recorded here rather than quietly absorbed.

### 1. `UNVERIFIED` is ratcheted, not a hard failure on day one

The verdict: *"`UNVERIFIED` is a hard failure in CI, never a silent pass."* The principle is right —
a surface nobody observed has not been checked, and treating no-evidence as no-problem is exactly
DEF169/DEF190.

But **40 of 85 surfaces are unverified today**. Failing all of them ships a gate that is red the day
it lands, and a gate whose failing state is its normal state teaches the operator that firing does
not mean stop. This project has paid for that three times: DEF277's audit gate, the tree gate, and —
this same week — DEF200's own vacuity guard, which asserted on the number that was supposed to reach
zero and went red the moment the work got done.

So: today's unverified surfaces are **enumerated by name** in `unverified_baseline.json`, a **new**
unverified surface fails immediately, and the baseline may only shrink. Nothing passes silently —
every one is written down and in the way. A **FAIL is never ratcheted**, because a key the server
cannot emit is a live disagreement, not coverage debt.

### 2. Layer 3 needed two corrections and still finds nothing

The verdict says to take `haiku4.5`'s unreachable-`fromJson` scan *"as-is"*. As-is it could not fire:
it searched `\bClassName\s*\(`, which matches the class's own constructor in its declaring file.

Corrected, it then reported `GameBoardRow` as dead — also wrong. `games.dart:1476` parses with it on
every board fetch via the **tear-off** form `.map(GameBoardRow.fromJson)`, which has no parentheses.
Verified by hand before it was believed.

With both fixed: **132 classes carry a `fromJson`; zero are unreachable.** Recorded rather than
hidden, because a guard that has never fired is worth exactly as much as its next firing, and
knowing it currently fires zero times is what stops a future zero from reading as proof.

### 3. The verdict's claim about instance 1 is wrong

`VERDICT.md` states Layer 3 *"is the only proposal that directly catches instance 1
(`OptionProposalTicket`) by construction"*. It cannot. `OptionProposalTicket` is a Flutter **Widget**
(`mobile/lib/widgets/sim/option_proposal_ticket.dart:65`) with no `fromJson` factory, so no scan over
wire models could ever reach it. The layer is still worth having — cheap, covers a real class — but
not for the reason given.

## The mandatory correction, proven on the case that motivated it

`SimSubmitResult` reads `j['order']`. Across **21 observed** `/v1/sim/submit` responses `order` never
appeared, and the prototype called that its one real FAIL. It is not one: `sim.py` emits `order` on
the `resting: True` branch only, and none of the 21 captured submissions rested.

Live output from the shipped check:

```
"class": "SimSubmitResult", "status": "UNVERIFIED", "observations": 21,
"missing_and_unemittable": [],
"missing_but_branch_conditional": ["order"]
```

`branch_scan` answers exactly one question — *is there anywhere in the server that could emit this
key?* — and a `yes` **downgrades** the finding to `UNVERIFIED` rather than clearing it. It does not
claim the branch is reachable or that it is the branch the client expects; claiming more from a
lexical scan would manufacture the certainty this module exists to withdraw.

## Known limits, stated rather than discovered later

- **The Dart extractor is lexical, not an AST parse.** It reads commented-out code: a
  `// j['foo']` counts as a read key. Verified while mutation-testing. Erring toward flagging is the
  safe direction, but it is a false-positive source.
- **Semantic disagreement is out of scope** — the right key carrying the wrong meaning or unit. All
  three ISS002 contributors said so; it stays out.
- **`branch_scan` proves possibility, not reachability.** A key emitted only by dead server code
  still downgrades to `UNVERIFIED`.
- **One hop of nesting.** A list inside a list inside a model is not recursed.
