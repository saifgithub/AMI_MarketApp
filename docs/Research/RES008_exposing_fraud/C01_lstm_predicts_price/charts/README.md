Notes:

- Colour roles follow `common/ami_style.py`: blue/cyan/purple/pink = the four arms (measured), muted grey = buy-and-hold / benchmark, amber = the always-up reference line, red = an interval that literally excludes zero.
- Arm labels used on every chart: "as taught, 100-day window" (A1), "as taught, 60-day window" (A2), "fair scaler, same target" (B-price), "fair scaler, return target" (B-return) — plain-language versions of RESULTS.md's A1/A2/B-price/B-return.
- `04_tracks_tomorrow_vs_echo.png` carries the one non-obvious annotation on screen ("red = interval excludes zero — why the verdict is NOT SUPPORTED, not DISPROVED"); it is a direct restatement of RESULTS.md §2/§6 (H2), not a new claim, so it is not `S.stamp()`-ed.
- `05_equity_curves.png` carries `S.stamp(fig, "SEED 0 OF 3 — ONE RUN PER ARM")` because a single-seed equity curve is illustrative, not the pooled result the verdict rests on (that is `03_traded_vs_holding.png`, median-of-30 runs). It also **excludes A2**: A2's test segment (2023-09-21 → 2026-08-28, 80/20 split) is a different, shorter window than A1 / B-price's (2021-07-12 → 2026-08-28, 65/35 split), so its curve is not comparable on the same trading-day x-axis or against the same buy-and-hold line. A2's own numbers are in charts 01–04 and RESULTS.md.

## Figures NOT produced, and why

Two brief figures are intentionally missing. Per the pack's hard rules ("if a number you want
is not in `out/`, do not invent it and do not re-run the research code — leave that figure out"):

- **The `overlay_AAPL.png` restyle** (beats 1/4/5, thumbnail). The brief asks for it redrawn in
  the AMI style. `out/results.json` and `out/results_full.json` carry only per-cell *summary
  metrics* (RMSE, correlations, hit rates) and, for M4, per-day *returns* — never the raw price
  levels, the model's predicted-price series, or the persistence ("tomorrow = today") series
  that the overlay actually plots. That series only exists inside
  `code/make_overlay_figure.py`, which trains a fresh AAPL network to produce it
  (`out/overlay_AAPL.png` itself, read for reference only, confirms this — see its own
  docstring: "Trains its own AAPL A1 model … does not read run_c01.py's saved state"). Redrawing
  it would mean re-running research code, which this chart pack must not do.
- **The lag animation and the 30-day recursive-forecast redraw** (beat 6). Same reason: the
  brief's own chart-pack table marks both "(to draw)" and flags the recursive-forecast series
  as needing a re-run (`M6` in `results.json` holds only the summary ratio, not the forecast
  path or the realised path). The "typical daily move" figure beat 6's script also cites is
  separately flagged in `VIDEO_BRIEF.md` as "not in `results.json`; recompute before recording" —
  also out of scope here.

If these are needed for the edit, they have to come from a deliberate, separate re-run of
`code/make_overlay_figure.py` / `code/run_c01.py`'s recursive-forecast path — not from this
chart-only pass.
