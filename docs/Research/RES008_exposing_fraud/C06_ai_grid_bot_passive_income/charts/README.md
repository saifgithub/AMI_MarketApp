# C06 chart pack

Generated by `make_charts.py`. Every number is read from `../out/results.json`
at run time; nothing is typed in. Run from the RES008 root:

```bash
.venv/bin/python C06_ai_grid_bot_passive_income/charts/make_charts.py
```

There is no saved per-run series in `out/` — only pooled aggregates (median,
p05/p95, shares, counts). `out/grid_dashboard_vs_truth.png` and
`out/band_grid_equity.png` (the brief's two named source figures) are
per-run/per-day plots that were rendered once by the original research code
and never saved back to structured data, so they cannot be redrawn from
`results.json` in the AMI style — see "What the brief asked for that could
not be supported" below.

Notes:

- Colour roles follow `common/ami_style.py`: amber (`S.CLAIM`) = the bot's own
  "grid profit" number / the claim; blue (`S.MEASURED`) = what the account
  actually did; muted grey (`S.BENCHMARK`) = buy-and-hold; green/red
  (`S.GOOD`/`S.BAD`) only where good/bad is literally what's plotted (share
  ruined, share liquidated, upside vs. downside of the range).
- `01_two_number_card.png` and `02_positive_vs_negative_by_arm.png` both
  present the headline gap; `01` is the cold-open two-number card the brief's
  thumbnail concept asks for, `02` is the supporting evidence that the same
  gap holds across all four hourly/daily × 1×/5× arms (not cherry-picked from
  one arm).
- `05_by_setting_share_nonnegative.png` answers the brief's "what would have
  convinced us" pre-registration point directly: a 90% reference line marks
  the bar that would have supported "any market," and every one of the 18
  daily 1× settings falls short of it (best is BTC ±20% / 10 lines at 69.9%).
- `07_predictions_scorecard.png`'s H4 "best" monthly-return figure is computed
  at run time as the max of `median_monthly_return_while_alive` over all 6
  `(constant|martingale) × (0.5x|1.0x|2.0x)` *pooled* sizings (martingale 2×,
  0.7259%), not hand-copied from RESULTS.md's prose. It displays as 0.73%,
  matching RESULTS.md's "max 0.73%" at the same two-decimal precision.
  RESULTS.md's figure comes from the same pooled cell; a single (coin ×
  sizing) cell not shown on this chart (GBPUSD, constant 2×) is close but
  slightly higher (0.7467%) and is not the number charted here.
- `08_band_grid_ruin_table.png` reuses the exact `RESULTS.md` §3 table
  contents (win rate, median monthly return, ruin shares) but only plots the
  two series named in the beat sheet (median monthly return, 5-year ruin) to
  keep the figure legible; the 1-year/3-year ruin columns are in
  `results.json` but not charted.

## What the brief asked for that could not be supported

- **`grid_dashboard_vs_truth.png` (the scatter of "grid profit" vs. true P&L,
  one point per run)** — the brief's beat-1/beat-5 figure calls for rebuilding
  this scatter "point by point" in the AMI style, shaded by quadrant with the
  36.8% share printed on it. `results.json` has no per-run array of
  `(grid_profit, true_pnl)` pairs — only the pooled shares, median and
  percentiles for each arm. There is nothing in `out/` that supports
  redrawing individual points or a real quadrant share (the 36.8% *is* on
  screen, in `01_two_number_card.png` and `02_positive_vs_negative_by_arm.png`,
  just not as a scatter). Per the task's hard rule ("if a number you want is
  not in `out/`, do not invent it and do not re-run the research code"), this
  figure is replaced by the two-number card, the by-arm bar chart, and the
  percentile bar, which carry the same finding as milestones/distributions
  instead of a reconstructed point cloud.
- **`band_grid_equity.png` (an EURUSD daily equity curve, plus a 2× martingale
  run that ruins, to match the 51.5% figure)** — this needs one or more daily
  equity *time series* for specific start dates (a "2005-Q1 start" run and a
  "median-outcome run, start 2011-01-03" in the reference PNG, plus a new
  martingale-2× run that ruins). `results.json` has no daily equity curve for
  any individual run, only cross-run pooled statistics
  (`median_monthly_return_while_alive`, `share_ruined_within_5y`, etc.) and
  `median_time_to_ruin_days`. There is no way to pick out "the run that
  ruins" or draw its path from these aggregates. `08_band_grid_ruin_table.png`
  carries the same point the equity curve was meant to make (bigger size →
  more income and much more ruin, with the exact 51.5% figure) as a bar
  comparison across sizings instead of a time series.
- **Percentile bar (beat 5)** — this one *is* supported and is
  `03_percentile_bar.png`; no gap here, noting it only because the brief
  lists it as "to draw."
- Everything else in the beat sheet's "source of every number" column
  (`share_grid_profit_positive`, `share_true_pnl_negative`, `n_total_runs`,
  `median_true_pnl_frac`, `p05`/`p95`, `share_left_range*`,
  `share_liquidated` at 5×, `share_beat_buy_hold`, and the band-grid win
  rates / monthly returns / ruin shares) is a plain top-level or `by_setting`
  key in `results.json` and is charted above.
