# 18 — Rejected Features Register (Reference)

**Folder:** `18_rejected_features/`  
**Purpose:** Single register of features evaluated and rejected for v1.0. Prevents re-proposal without context.  
**Status:** Reference document.

---

## How to use this folder

When a feature request comes in:
1. Check `rejected_features_register.md` first
2. If it's listed with a clear rejection rationale, read the why
3. If pre-conditions have changed, re-evaluate; otherwise, defer

---

## The register

See `rejected_features_register.md` for the full table.

**In brief:** 9 features were evaluated and rejected:

- OCO / bracket orders
- Pre/after-hours quotes
- Screeners / filters
- Brokerage integration
- Copy-trading
- Options / derivatives
- Tax features
- Order-book / Level 2
- Rewarded ads

All have locked rejection reasons. None are pre-conditions; all are "not for this product at this time."

---

## Adding to the register

When a new feature is rejected:
1. Add a row to the table in `rejected_features_register.md`
2. Include the date, rejection reason, and any pre-condition to re-open
3. Link this README from the relevant design doc
