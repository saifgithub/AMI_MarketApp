# AT:R43  (2026-06-01)

Hotfix: yfinance ≥0.2 nested news format.

## What shipped

**Backend only (`backend/app/services/market_data.py`):**

`YfinanceProvider.news()` was reading `article['title']`, `article['link']`, etc. directly from each dict. yfinance 0.2+ wraps all fields under a `content` key: `article['content']['title']`, `article['content']['canonicalUrl']['url']`, etc.

Fix: read from `article.get('content', article)` so both the nested (≥0.2) and flat (<0.2) formats work. Publisher key also moved to `article['content'].get('provider', {}).get('displayName', '')` with flat fallback.

Single file changed, 21 ins / 6 del. No migration, no mobile changes, no test changes (mocked stubs weren't affected by the format change).

## Deploy

Promoted to Alpha — tags `alpha-2026-06-02-1` + `alpha-2026-06-02-2` (two promotes: build bump to `0.1.0+29` went separately).

## Gotchas

No API contract change — the route response shape is identical; only the yfinance parsing logic changed. If yfinance releases another breaking change to article structure, look at `market_data.py::YfinanceProvider.news()` first.
