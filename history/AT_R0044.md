# AT:R44  (2026-06-02)

Android device install tooling + first APK on test devices.

## What shipped

**`scripts/install_android.sh`** — new script mirroring `install_iphone.sh`:
- Builds a release APK with the correct dart-defines (`ALLOW_BACKEND_SWITCH=true`, `AMI_API_URL_ALPHA`, `GOOGLE_OAUTH_WEB_CLIENT_ID`, `SENTRY_DSN`)
- Installs via ADB on any connected known device; skips offline ones gracefully
- Hardcoded known serials: Galaxy Note Fan `ce10171a8017590d01`, Galaxy A17 `R5CY91AY99Y`
- `--list` flag shows connected devices + model names
- Works with one or both devices connected simultaneously
- The produced APK at `mobile/build/app/outputs/flutter-apk/app-release.apk` is also the right file to share via WhatsApp for manual sideload

**APK installed on both test devices:**
- Galaxy Note Fan (SM-N935F, Android 9) — `ce10171a8017590d01`
- Galaxy A17 (SM-A176B) — `R5CY91AY99Y`

**Dependency bumps (uncommitted before this session):**
- `sentry_flutter ^8.11.2` → `^9.0.0`
- `device_info_plus ^11.1.0` → `^12.4.0`
- `mobile/pubspec.lock` updated accordingly

## Lessons learned

1. **Always pass dart-defines on `flutter build apk --release`.** The bare `flutter build apk --release` produces an APK with empty backend URL strings — the app spins forever with no error. The `build_playstore.sh` script already does this correctly; manual one-off builds need the same flags.
2. **Galaxy Note Fan is Android 9** — meets `minSdk 28` requirement.
3. **ADB path on this Mac:** `"/Volumes/Extreme Pro/Android/sdk/platform-tools/adb"` (set in `~/.zshrc` via `ANDROID_HOME`). The `install_android.sh` script resolves it via `$ANDROID_HOME` or falls back to `which adb`.
