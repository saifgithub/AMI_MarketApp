# AT:R47 (2026-07-05)

## What shipped

### Alpaca API key auth mode (`POST /v1/alpaca/link_apikey`)

The Alpaca OAuth flow requires a registered client_id + client_secret from
Alpaca — credentials Saiful doesn't have yet. To unblock testing the full
Alpaca integration now, we added a second link path: paste in a Paper Trading
API key + secret directly from the Alpaca dashboard.

**Backend changes:**
- New migration `b2c3d4e50013_alpaca_auth_mode` — adds `users.alpaca_auth_mode
  VARCHAR NULL` (`"oauth"` | `"apikey"`; NULL = unlinked). Chains after
  `a1b2c3d40012` (alpaca_credentials, AT:R45); both apply together on the next
  `/promote-to-alpha`.
- `_paper_get()` in `alpaca_service.py` now accepts `auth_mode` + `api_secret`
  — sends `APCA-API-KEY-ID` / `APCA-API-SECRET-KEY` headers for apikey mode,
  `Authorization: Bearer` for oauth mode.
- New `validate_api_key(key, secret)` — hits `GET /v2/account` with apikey
  headers to verify credentials before storing.
- New route `POST /v1/alpaca/link_apikey` — validates then stores key/secret,
  sets `alpaca_auth_mode="apikey"`.
- `DELETE /v1/alpaca/unlink` now also clears `alpaca_auth_mode`.
- `/portfolio` + `/positions` read `auth_mode` from the user row and pass it
  through to the service layer.
- `agent_runner.py` + `room_runner.py`: `snapshot_text()` calls now propagate
  `auth_mode` + `api_secret` from the fetched User row.
- +7 tests (532 → 539 in this commit; AT:R48 added 2 more → 541 total now).

**Mobile changes:**
- `AlpacaConnectScreen` converted to a two-tab design: **API KEY** tab (default,
  paste key+secret with reveal toggle) + **OAUTH** tab (existing WebView flow,
  shows "not available" message when `ALPACA_CLIENT_ID` build define is empty).
- `alpacaLinkApiKey(String key, String secret)` added to `api_client.dart`.

### TestFlight build `0.1.0+34`

Three build attempts during this session (each bumped the version):
- `0.1.0+32` — failed: `AmiColors.slate400` didn't exist (fixed inline)
- `0.1.0+33` — failed: `altool` error 19 (transient, same underlying issue)
- `0.1.0+34` — IPA built successfully (33.1 MB, archive at `mobile/build/Runner.xcarchive`)
  but upload blocked by: **Apple Developer Program Agreement pending acceptance**

Root-cause of the upload failure:
```
REQUIRED_AGREEMENTS_MISSING_OR_EXPIRED — A required agreement has not been signed.
```
Discovered by switching from deprecated `xcrun altool --upload-app` (Xcode 26.5
gives error 19 on that path) to `xcodebuild -exportArchive destination:upload`,
which surfaces the real Apple-side error.

**To unblock TestFlight:** Saiful must accept the pending agreement at
[appstoreconnect.apple.com/agreements](https://appstoreconnect.apple.com/agreements),
then run `scripts/build_testflight.sh --no-bump` to upload `0.1.0+34`.
