## Gotchas learned
- **A session that ships real work must still run `/handover`** — AT:R56 didn't; this
  session had to backfill it before starting its own work. Same failure mode already on
  record for AT:R48/R50.
- **Never type a raw secret literally into a Bash command** — even via `curl -H
  "Authorization: Bearer <key>"` — the harness's credential-materialization safeguard
  will (correctly) block it. Use `export KEY=$(grep ... | cut -d= -f2)` then reference
  `${KEY}` — the value never appears in the command text.
- **Never send a live credential to a domain/endpoint inferred from third-party search
  summaries** — the harness will (correctly) block it too. Confirm the base URL from
  the provider's own site (homepage, official docs) before the first live call.
- **A provider's own docs page can be a JS-rendered SPA that WebFetch can't read** —
  hit this on LunarCrush, Finnhub, and Adanos, all three. When that happens, either
  find a GitHub-hosted docs mirror / OpenAPI spec, or fall back to one careful live
  probe (with a real key) to learn the actual shape — same discipline either way: never
  guess a response schema, verify it.
- **`402` vs `429` matter** — a `402` means the plan doesn't cover this endpoint at all;
  a `429` from a rapid-fire test burst can look like "some access, rate-limited" but
  may just be a burst-throttle artifact. Space out probe calls and re-check before
  concluding a tier grants partial access.
- **A prompt/overlay/template honesty fix written for "no real data exists" must be
  revisited the moment real data lands** — this session's own Social Media rewrite
  hardcoded "no live feed connected" mid-session, then had to be corrected again an
  hour later when Adanos went live. Prefer "where configured" / value-carries-the-
  honesty phrasing over "categorically none exists" whenever a provider integration
  might land later in the same session.
