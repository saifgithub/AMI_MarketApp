## What shipped (CR005, 1 commit — `f1e4c01`)

**Problem:** the CR/Defect registers (CR001) record *what* changed and
*why*, but nothing independently re-verifies a change does what its
architect claims before it's marked done — the session that builds a
CR also self-certifies it.

**Port, not clone** — adapted via a bindings file rather than editing
the source protocol:

- `audit/handshake/PROTOCOL.md` — byte-identical copy of the source;
  never edited here, so upstream fixes propagate by plain `cp`.
- `audit/handshake/AMI_TRADE_BINDINGS.md` — translates the protocol's
  generic terms (WORK ITEM, shared branch, gate commands, deploy
  target) into this repo's real paths/conventions.
- `ARCHITECT_LOOP_PROMPT.md` / `AUDITOR_LOOP_PROMPT.md` — rewritten
  per-repo for AMI Trade's actual workflow: sequential single-session
  builds (no MABP), `pytest backend/tests/unit/ -q` as the Mac-safe
  gate, melehost/Alpha as the live-measurement target.
- `watcher.sh` — copied verbatim (portable POSIX `sh`, already
  parameterized). Verified: `sh audit/handshake/watcher.sh state` runs
  clean, reports no lanes yet.
- `docs/governance/CR_DEFINITION_OF_DONE.md` — new, lightweight
  AMI-Trade-scoped DoD checklist (the source had no local equivalent).
- **Roles map to tracks**: track **R** (Development) is the architect;
  new track **U** (Auditor) is a genuinely separate Claude Code session
  that independently verifies R's work from a committed/pushed SHA —
  never trusts R's shared working tree.
- One-line pointer added to `CLAUDE.md` under Change governance.
- `docs/forward_planning/cr_list.md` gained the CR005 row (`done`).

**Optional and additive** — doesn't replace the CR/Defect register
process, doesn't touch `/handover` or `/start-fresh` beyond adding
track U to config (those skills already work generically once a track
exists). No code or runtime behaviour changes. Saiful invokes the
handshake per item, typically something risky he wants a second,
independent look at before `/promote-to-alpha`.

## Aside: concurrent-session race on session-config.yml

A parallel `/session-setup` walkthrough (this same conversation) was
mid-flight adding a *different* new track (`A`, also labelled
"Auditor", for the same underlying purpose) when this session's CR005
work landed track `U` first. Reconciled by dropping the in-progress

two Claude Code sessions editing `.claude/session-config.yml`
concurrently can collide. Worth serializing `/session-setup` runs
across parallel sessions going forward.
