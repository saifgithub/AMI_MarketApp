# AT:R46 (2026-06-12)

## What shipped

### iOS build fixed + 0.1.0+30 to TestFlight

The app was broken after AT:R45 added `webview_flutter` — no Podfile.lock
existed because `platform :ios, '13.0'` was commented out in the Podfile.
CocoaPods couldn't resolve `Sentry/HybridSDK 8.58.3` without the explicit
platform declaration.

Fix: uncommented `platform :ios, '13.0'`, ran `pod install --repo-update`
(fetched `webview_flutter_wkwebview` + updated Sentry). Build came up clean
at 33.6 MB.

Shipped to TestFlight as **0.1.0+30** (`ebf84db` bump commit was already

Delivery UUID: `fd1a11ac-3f8f-42e7-9fcd-1b0a28ed924d`. Internal testers

### Android AAB 0.1.0+31 built for Play Console

Two-layer root cause:
1. **Gradle daemon used Java 25** (system JVM, `temurin-25.jdk`) when invoked
   directly. Fix: always use
   `JAVA_HOME=/Applications/Android Studio.app/Contents/jbr/Contents/Home`
   (Java 21) for Android builds. The `flutter build appbundle` path already
   does this; the direct `./gradlew` path did not.
2. **`apkanalyzer` space-in-path failure.** `/Users/saiful/android-sdk` is a
   symlink → `/Volumes/Extreme Pro/Android/sdk`. The `apkanalyzer` shell
   script uses `pwd -P` (physical path) to set `APP_HOME`, which resolved
   to the space-containing real path; Java then mis-parsed the classpath and
   reported `ClassNotFoundException: Pro.Android.sdk.cmdline-tools.latest`.
   Fix (Saiful ran manually):
   ```bash
   sed -i '' 's/APP_HOME="`pwd -P`"/APP_HOME="`pwd`"/' \
     ~/android-sdk/cmdline-tools/latest/bin/apkanalyzer
   ```
   This one-time patch affects all cmdline-tools with the same symlink issue
   (sdkmanager, avdmanager, etc. may need the same fix if used directly).

AAB built as **0.1.0+31** (signed with upload keystore), 52.4 MB.
Awaiting manual upload to Play Console → Internal testing.
