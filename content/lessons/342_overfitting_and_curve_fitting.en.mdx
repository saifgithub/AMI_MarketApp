# Overfitting & curve-fitting

Overfitting happens when a strategy gets tuned with enough free parameters — moving averages, thresholds, filters — that it starts fitting the noise in a specific historical dataset rather than a real, repeatable pattern. More parameters relative to the amount of data always makes the in-sample backtest look better; it does not make the strategy more likely to keep working. A rough sanity check: divide the number of historical trades by the number of tunable parameters — the fewer trades you have per parameter, the more of that backtest's "edge" is probably just curve-fit to this one specific history.

## Example

Take a rule tested on 50 historical trades. With **1** tunable parameter (say, a single moving-average length), that's **50 trades per parameter** — a reasonable amount of data to estimate one setting from. Now add filters until the rule has **10** tunable parameters (moving-average length, RSI threshold, volume filter, volatility filter, time-of-day filter, and so on) tested on the *same* 50 trades — that's only **5 trades per parameter** (50 ÷ 10 = 5). With 10 free parameters and only 50 data points to fit them to, the optimizer has enormous freedom to find a combination that happens to explain this specific history well, whether or not any of those filters reflect a real, repeatable market pattern.

The in-sample backtest for the 10-parameter version will almost always show a higher win rate and EV than the 1-parameter version — that's not evidence the 10-parameter version is a better strategy; it's the expected result of giving an optimizer more knobs to turn against the same fixed amount of data. The extra "edge" it found is exactly as likely to be noise fit to this one history as it is to be real.

## The trap

The trap is treating a strategy's rising in-sample performance as more parameters get added as proof each new filter is finding a real pattern, when it's equally consistent with the optimizer simply having more freedom to fit the specific noise in that one dataset. It feels like progress because the backtest number keeps improving with each tweak. The correct habit: check the trades-per-parameter ratio before trusting an "improved" backtest — a rule with 10 parameters and 5 trades per parameter earns far more skepticism than a rule with 1 parameter and 50 trades per parameter, even if the 10-parameter version's backtest number looks better.

## Try it

Look at any strategy you've built with multiple filters or conditions. Count the tunable parameters, divide your backtest's trade count by that number, and ask whether each individual filter is justified by something other than "it improved the historical number." Remember: AMI's training output is a practice artifact, not investment advice.

## Takeaway

More parameters always make an in-sample backtest look better — that alone is never evidence of a real edge; check trades-per-parameter before trusting the improvement.
