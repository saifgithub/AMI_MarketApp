# Walk-forward analysis — backtesting without peeking

The backtest foundation (057) said the only real defence against overfitting is out-of-sample testing. Walk-forward analysis (WFA) is the disciplined version of that defence. You split your history into rolling windows: optimise parameters on an in-sample window, freeze them, test on the next out-of-sample window, roll the windows forward, repeat. The aggregated out-of-sample performance is what you trust — never the in-sample fit. After this lesson you can design a walk-forward test for your own rule, set window sizes that match your strategy's bar frequency, and interpret the in-sample-vs-out-of-sample efficiency ratio that tells you whether the rule is real.

## How this plays out in real markets

Take a momentum rule on the S&P 500: each month, buy the top-decile 12-month return names, equal-weight, rebalance monthly. Backtest naively over 2005-2024 returns 11.8% CAGR with 22% max drawdown. Looks fine, but you optimised the "12-month lookback" knob by trying 6, 9, 12, 15, and 18 months and keeping 12. That's a hidden overfit.

Walk-forward: split 2005-2024 into 4-year in-sample / 1-year out-of-sample windows, rolled annually. In-sample 2005-2008 picks lookback=15 (best on that window); test it on 2009 — returns 28% (factor recovery). Roll: in-sample 2006-2009 picks lookback=9; test on 2010 — returns 14%. Continue through 2024. You get 16 out-of-sample years, each tested on a parameter set chosen WITHOUT seeing that year's data.

The aggregate out-of-sample CAGR comes in at 9.1% with 26% max drawdown — meaningfully below the in-sample 11.8% but still positive. The walk-forward efficiency ratio (OOS CAGR / IS CAGR) is 0.77 — anything above 0.5 is considered robust. Crucially, the rule survived 2008, 2011, 2020, and 2022 drawdowns in the OOS portion, which is the only evidence that matters. The strategies that don't survive WFA usually show efficiency ratios below 0.3 — the in-sample peak was overwhelmingly selection bias.

## The trap

The beginner mistake is running WFA but then "fixing" the rule mid-stream when a window underperforms. Every adjustment you make after seeing OOS results contaminates the next OOS window with hindsight — you're peeking, and the discipline of WFA evaporates. The correct mental model: WFA is a one-shot ritual. You design the parameter grid, the window sizes, and the optimisation criterion BEFORE running it. You run it once. You accept whatever the OOS aggregate says. If the result disappoints, you don't tune — you either deploy the rule at its honest OOS performance level or you discard it and design a different rule from first principles. The second trap: choosing window sizes after seeing the data. The third: using anchored (expanding) windows in regimes that change, which lets ancient data dominate parameter choice — rolling fixed-length windows are more honest in non-stationary markets.

## Try it

Pick one strategy currently in your candidate set. Define the parameter grid, in-sample window length, out-of-sample window length, and roll cadence — all BEFORE running the test. Submit the design to the Research Manager in <Term id="ami_one_on_one" /> with: "Is this WFA design honest? What windows would you change?" Then run it once and log the OOS aggregate + efficiency ratio in the <Term id="ami_decision_journal" /> as a pre-deployment artefact.

## Takeaway

Walk-forward analysis is a one-shot ritual: design before, accept after. The efficiency ratio is the rule's honesty score, and anything below 0.5 means the in-sample number was mostly a mirage.
