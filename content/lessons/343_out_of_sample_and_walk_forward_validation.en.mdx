# Out-of-sample & walk-forward validation

Out-of-sample testing means checking a strategy on data it was never tuned on — a holdout period the optimizer never saw. Walk-forward validation extends this into a repeatable process: tune on one window, test on the next untouched window, then roll forward and repeat. The holdout is sacred because it's the only honest answer to the overfitting problem — a strategy that only performs well on the data it was fitted to hasn't been tested at all; it's just been described.

## Example

Recall the 65%-win-rate rule from the backtesting lesson: in-sample EV was (0.65 × $150) + (0.35 × -$100) = **+$62.50 per trade**, on the 300-trade history the rule was built and tuned on. Now run that same rule, unchanged, on a fresh out-of-sample period it never saw during tuning. Suppose the win rate drops to 35% out-of-sample, with the same average win and loss sizes: EV = (0.35 × $150) + (0.65 × -$100) = $52.50 - $65 = **-$12.50 per trade**. The rule didn't just get weaker out-of-sample — its expected value flipped from clearly positive (+$62.50) to clearly negative (-$12.50), on the exact same rule with nothing changed except which data it was tested on.

That flip is the honest test working as intended: it shows the "edge" the in-sample backtest found was substantially a product of fitting to that specific historical window, not a real, repeatable pattern. A strategy that survives walk-forward validation — tuned on window 1, holding up on untouched window 2, then window 3, and so on — has cleared a much higher bar than one that only has an in-sample number to show.

## The trap

The trap is skipping the holdout entirely, or worse, "peeking" at out-of-sample data and re-tuning the strategy until it performs well there too — which quietly turns the holdout into just more in-sample data, destroying the one honest test available. It feels efficient to use every data point to improve the strategy. The correct habit: set aside out-of-sample data before any tuning begins, never adjust the strategy based on how it performs there, and treat a strategy's out-of-sample result — not its in-sample result — as the number that actually matters.

## Try it

Take a rule you've backtested and split its historical trade log into an earlier tuning window and a later holdout window you haven't looked at yet. Compute the rule's EV separately on each, without adjusting anything based on the holdout result. Remember: AMI's training output is a practice artifact, not investment advice.

## Takeaway

A strategy's in-sample number tells you what it fit; only an untouched out-of-sample result tells you whether it actually works — never adjust the strategy based on the holdout, or you've destroyed the one honest test you had.
