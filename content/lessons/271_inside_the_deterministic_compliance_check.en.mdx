# Inside the deterministic compliance check

The phrase "deterministic compliance check" sounds technical because it has to be. The underlying language models that drive <Term id="ami" />'s <Term id="twelve_agent_team" /> are probabilistic — same question asked twice can land in slightly different places. That kind of variance is fine for analysis and synthesis; it is not fine for "is this trade allowed?". So the part of AMI that answers that question is not a prompt and is not a model call. It is a plain function, written in Python, that reads your <Term id="ami_mandate" /> and the proposed trade and returns PASS or BLOCK. Same inputs, same answer, every time. By the end of this lesson you will understand why that determinism is the whole point.

## How this plays out in real markets

Imagine the simplest version of the check. The proposed trade arrives with fields:

```
ticker: NVDA
side: BUY
proposed_size_pct: 7.0
estimated_max_loss_pct: 4.5
sector: technology
region: us
is_fossil: false
is_halal_compliant: true
```

Your Mandate fields:

```
max_position_pct: 5
max_drawdown_pct: 20
halal: false
no_fossil: false
region_allowlist: [us, bursa_malaysia]
long_only: false
```

The check runs in order, deterministically. *Is `proposed_size_pct` > `max_position_pct`?* 7.0 > 5 → BLOCK. *Is `region` in `region_allowlist`?* us → ok. *Does `no_fossil` apply?* No. *Does `halal` apply?* No. *Is `long_only` violated?* No. The first failure stops the chain and returns BLOCK with the specific clause. The PM persona then takes that result and explains it in plain English in the <Term id="ami_verdict" /> footer. Run the same Verdict ten times — you get the same block. Edit your Mandate to `max_position_pct: 8` and run again — you get PASS. The model has not been re-prompted; the function read different data.

Now contrast: if the check were "ask the PM agent nicely whether this trade fits", the answer would drift. A persuasive Bull case in the same context window could shift the agent's response. A coaching note saying "be more flexible" could change the wording. The function does not see the Bull case. The function does not see coaching. It sees two structured objects and a list of rules.

## The trap

The trap is thinking the compliance check is sophisticated AI judgment. It is not. It is deliberately *unsophisticated* — basic comparisons, exclusion flags, lookups — because sophistication is exactly what you do not want at the <Term id="ami_pm_safety_floor" />. You want a check that cannot be argued with, cannot be charmed, and cannot drift. The trade-off is real: a deterministic check cannot catch every edge case a smart human reviewer would. It will pass a 5% position in a stock with deteriorating fundamentals because the size is within mandate. That is not a bug; it is the contract. The trading team's debate is where nuance happens. The PM check is where bright lines hold.

## Try it

Open **Settings → Mandate**. Set `max_position_pct` to 5. <Term id="ami_convene_the_room" /> on a US ticker until you see a proposal at 6% or higher get blocked. Now change `max_position_pct` to 10 and re-run the *exact same Verdict*. The block disappears even though the trading team's debate is identical. You just watched the deterministic function read different data.

## Takeaway

The compliance check is a function, not a conversation. Same inputs, same output — that immovability is why the safety floor binds inside the simulator, and why AMI can teach you to read the architecture honestly. AMI is a training simulator; the Verdict is a practice artifact for your evaluation, not investment advice.
