# Coaching changes style and priority — not the safety floor

**<Term id="ami_coach_your_agent" />** lets you shape *how* an agent thinks: which catalysts to weight higher, what scepticism level to bring, which patterns to prefer. It does not let you change *what an agent is for*. It does not let you turn the Trader into an executor. It does not let you tell the PM to ignore your <Term id="ami_mandate" />. It does not let you make <Term id="ami" /> predict prices. The coachable surface is a deliberate sub-set of the system, and knowing where its edges are is what makes briefing useful instead of frustrating. By the end of this lesson you will be able to write briefing notes that land and recognise the ones that won't.

## How this plays out in real markets

Three examples of effective briefing.

1. **Bull Researcher, on TSLA:** *"When discussing TSLA, weight Cybertruck production ramp and energy-storage backlog above autonomy speculation. Treat FSD claims as a roadmap input, not a near-term revenue input."* This works. It changes the catalyst weighting in the Bull Researcher's prompt. The next time the Bull case is written on TSLA, the prose reflects the priority shift.

2. **Bear Researcher, on financials:** *"When analysing US regional banks, prioritise commercial real-estate exposure and unrealised AFS losses over consumer credit deterioration. Be specific about CRE concentration as a percentage of the loan book."* This works. The Bear case will now lead with CRE and AFS for regional bank tickers.

3. **Market Analyst, generally:** *"Default to multi-timeframe context — always describe weekly trend before discussing daily setup."* This works. It is a stylistic priority change.

Three examples of briefing that fails to land — and why.

1. *"Coach the Trader to place orders automatically when confidence > 0.8."* Fails. There is no execution surface to coach. The Trader proposes; nothing in AMI executes; briefing cannot create a code path that does not exist.

2. *"Coach the PM to be flexible on size when confidence is high."* Fails. The PM's compliance check is a deterministic function reading your Mandate. Briefing modifies prompts; the function does not consume prompts.

3. *"Coach the Research Manager to predict a 30-day target price."* Fails. Point-price prediction is not in any agent's surface. The Research Manager synthesises debate into a position with conditional levels (entry/stop/target/horizon); it does not produce a point forecast for a fixed future date. Coaching cannot enable a behaviour the architecture deliberately excludes.

The pattern: briefing can shape *what an agent emphasises within its role*. It cannot give an agent a new role.

## The trap

The trap is treating briefing as a configuration knob for the whole app. It is not. It is a per-agent style-and-priority editor that lives entirely within the trading-team layer (Researchers, Risk Debators, Analysts, Trader). The PM's compliance function is outside that layer. The execution surface does not exist. The prediction frame is excluded by design. Users who burn briefing credits trying to bend these limits walk away frustrated; users who use briefing for what it is — making each agent more useful within its actual role — get a measurable lift. *"Make the Bear Researcher more aggressive on EM tickers"* is great briefing. *"Make the Bear Researcher overrule the PM when bearish enough"* is not briefing; it is asking for a feature that does not and will not exist.

## Try it

Open **Brief Your Agent** and pick the Bear Researcher. Write a focused briefing note for one ticker class — e.g., *"For Bursa Malaysia bank tickers, prioritise CASA ratio and provisioning coverage over headline ROE."* Save it. <Term id="ami_convene_the_room" /> on MAYBANK or CIMB. Read the Bear case and check whether the priorities you set show up in the writing. If they do, you used briefing as intended.

## Takeaway

Briefing shapes how an agent thinks within its role inside the simulator. It does not change the role, create execution, or bend the <Term id="ami_pm_safety_floor" />. Write briefing notes that ask for emphasis, not for new abilities — and remember AMI is a <Term id="training_simulator" />, not a financial advisor.
