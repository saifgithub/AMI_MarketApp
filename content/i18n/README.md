# content/i18n/ — Language Manager domain

Process/tooling home for AR + MS translation delivery (CR083, GTM milestone M5). No
runtime strings live here — the app never reads this directory. Translated content
lives where the app actually consumes it:

| Tier | Runtime location | Translated via |
|---|---|---|
| 1 — UI strings | `mobile/lib/l10n/app_{ar,ms}.arb` | `scripts/translate_arb_lan.py` |
| 2 — glossary / AI Coach / daily challenges | `content/glossary/terms.{ar,ms}.json`, `content/{ai_coach,daily_challenges}/{ar,ms}/*.json` | `scripts/translate_content_lan.py` |
| 3 — lessons | `content/lessons/*.{ar,ms}.mdx` | `scripts/translate_lessons_lan.py` |

An earlier spec (`docs/initial_specs/07_localization/i18n_architecture.md`) proposed a
`content/i18n/{locale}/strings.json` + `flutter_intl` design. **That was never built.**
The shipped system uses Flutter ARB + `flutter gen-l10n` instead
(`docs/initial_specs/08_tech/flutter_implementation.md`). Don't re-derive the old
design from that spec doc — it's stale.

## Files in this directory

| File | Purpose |
|---|---|
| `coverage_status.md` | Generated by `scripts/i18n_coverage_report.py` — do not hand-edit. Per-tier/per-locale completion. |
| `sensitive_keys.json` | Sharia/observance-sensitive content carve-out (generalizes DEF094). Two policies: `exclude` (held to EN, routed to Saiful/SME) and `strict_review` (auto-translated, but needs a stricter confidence bar before counting as verified). |
| `style_guide_ar_ms.md` | AR/MS terminology + tone rules pulled out of the translate scripts' prompt strings. |
| `lesson_confidence_log.json` | Per-lesson/locale/model semantic-fidelity scores from `scripts/i18n_verify_lesson_translation.py`. |
| `qa_spotcheck_log.md` | Automated-check run history + the non-blocking native-QA follow-up note. |

## Runbook

**Tier 1 (ARB):**
```
python scripts/i18n_apply_exclusions.py --stage arb --pre   # pre-seeds the 10 sensitive keys with EN
backend/.venv/bin/python scripts/translate_arb_lan.py --locales ar ms
flutter gen-l10n   # from mobile/
```
The pre-seed step writes the EN value directly into `app_ar.arb`/`app_ms.arb` for the
`exclude`-listed keys, so the translate script's skip-unless-`--overwrite` logic then
leaves them untouched.

**Tier 2 (glossary / ai_coach / daily_challenges):**
```
python scripts/i18n_apply_exclusions.py --stage content --pre   # relocates islamic_finance.json
backend/.venv/bin/python scripts/translate_content_lan.py --type glossary
backend/.venv/bin/python scripts/translate_content_lan.py --type ai_coach
backend/.venv/bin/python scripts/translate_content_lan.py --type daily_challenges
python scripts/i18n_apply_exclusions.py --stage content --post  # restores it
```
Never run these in parallel — a prior parallel attempt saturated the single-instance
vLLM host (AT:R35 carry-over note in `project_plan.md`).

**Tier 3 (lessons):**
```
backend/.venv/bin/python scripts/translate_lessons_lan.py --locales ar ms
python scripts/i18n_coverage_report.py   # syncs locale_versions frontmatter + reports
python scripts/i18n_verify_lesson_translation.py --all
```
The confidence tool is a repeatable pass, not a one-shot check — see
`lesson_confidence_log.json`'s format and the "reasonable confidence" rule below.

## Confidence verification (Tier 3)

The only model diversity available is **manually swapping which model is loaded on
the on-prem vLLM host** — there's no second always-on API to call automatically.
`scripts/i18n_verify_lesson_translation.py` reads the currently-loaded model's
identity from `GET {vllm_base_url}/v1/models`, scores EN-vs-translation semantic
fidelity, and appends the result to `lesson_confidence_log.json`. Run it again after
Saiful swaps the loaded model — results accumulate across passes.

- **Ordinary lessons**: verified once >=2 distinct models agree, min confidence >=4/5,
  zero unresolved `critical_issues`.
- **`strict_review` lessons** (the Islamic-finance unit, 347-356): verified once >=3
  distinct models agree, zero issues of **any** severity (critical or minor).

## Ongoing cadence

No cron — this is a manual pre-release habit. Before any release/promotion touching
content, run `scripts/i18n_coverage_report.py` and diff against the committed
`coverage_status.md`. New/changed EN content only re-triggers the affected script
(all four skip-unless-`--overwrite`, so re-runs only translate the delta).
