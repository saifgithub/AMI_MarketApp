### Seven mutation-tested claims — six caught cleanly, one revealed a real (but safely-directioned) gap

1. **The DEF059 inversion trap** — added `UNKNOWN` to `ClassificationVerdict.is_blocking`'s tuple.
   `test_unknown_is_permitted_with_disclosure_not_blocked` caught it immediately. This is the
   single most safety-critical property in the whole change (an unclassified name must never be
   rejected, or the filter blocks every name AMI hasn't tagged) and it's genuinely guarded.
2. **Fossil-fuel sector gate** — removed the `sector == Energy` requirement from `classify_info`.
   Caught by the dedicated cross-sector fixture (`Industrials` + `Oil & Gas Integrated` →
   correctly `False` today, `True` under the mutation).
3. **Dash normalisation** — removed the em-dash/en-dash/minus flattening. Caught by 3 tests
   (the parametrized table plus the dedicated dash-variants test) — the exact real-world yfinance
   drift class ("Beverages—Brewers") this code exists to survive.
4. **Flags-off no-op** — disabled the `if not flag: continue` skip. Caught by
   `test_flags_off_is_a_noop`, which also proves the *reverse* safety property: a user who never
   opted into any of these filters is never affected by this whole feature, even for a ticker
   (XOM) that would otherwise be excluded.
5. **Floor guard** — gutted `_CLASSIFIED_MIN_ROWS` from 400 to a no-op. Caught by
   `test_network_classify_raises_below_floor`.
6. **`classification_universe=` dropped from the live PM's `enforce_safety_floor` call site** (the
   final-verdict path) — **the full 1200-test suite still passed.** No test in either file exercises
   this specific call site's wiring the way CR055's `test_runner_injects_portfolio_snapshot_at_every_call_site`
   pinned its own two call sites. This is a real coverage gap, not present for the sibling
   `_assemble_verdict` call site (exercised indirectly by many DEF061 tests via `_check`, which
   calls `check_mandate_compliance` directly, not through `RoomRunner`). Confirmed the *consequence*
   is fail-safe, though: `classification_universe` defaults to `None`, which the safety-floor
   loop's `getattr(None, "resolve", None)` branch treats as UNAVAILABLE — i.e. a regression here
   would **pause every trade** for any user with one of the three flags on, going through this
   specific live-Room path — the correct degrade-loudly direction (over-blocking), never a silent
   permit of an excluded name. Reverted.
7. Verified the one existing-test edit (`test_safety_floor.py::test_compliance_halal_with_passing_universe`,
   now passing an `NVDA`-clean `ClassificationUniverse`) is a legitimate isolation fix, not a mask:
   read the fixture and confirmed `halal_mandate` genuinely also sets `no_tobacco_alcohol_gambling=True`,
   so without the fix the newly-enforced sin check would correctly pause on a `None` universe —
   exactly the loud-degrade DEF061 exists to produce, just not what that particular halal-focused
   test is about. Also verified the sibling `..._with_excluded_ticker` test's stability is genuine,
   not an oversight: it only asserts `violations[0]`, and check 4 (halal) fails first in that
   fixture, so it's insulated from whatever the classification block does after it — confirmed by
   reading, not assumed.

### Findings

**MINOR** — the `enforce_safety_floor` call site inside `RoomRunner`'s live-PM path (the one that
issues the actual final Room verdict) has no dedicated wiring guard analogous to CR055's
`test_runner_injects_portfolio_snapshot_at_every_call_site`; a future edit could silently drop
`classification_universe=` from this specific site without the suite noticing. Materially lower
severity than a comparable gap would be elsewhere in this codebase because the failure direction
is safe by construction: the parameter's `None` default resolves to UNAVAILABLE, which blocks
(pauses) rather than silently permits — a regression here would be immediately visible as
"every trade blocked" for opted-in users, not a silent values violation. Recommend a follow-up
structural test mirroring CR055's pattern, not blocking this round.
