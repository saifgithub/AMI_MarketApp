## F1 (MAJOR, reproduced) — a NaN close raises `ValueError`, failing the whole Room Convene

`compute_technicals` wraps only the `history()` call in try/except — **not** the
computation. On a NaN close price it raises `ValueError: cannot convert float NaN to
integer` at `round(rsi)` (technicals.py:132; `round(support)`/`round(breakout)` at
:136-137 are exposed the same way).

- **The provider passes NaN through unsanitized.** `YfinanceProvider.history()`
  (market_data.py:485-499) builds a `Candle` per row guarded only by
  `except (KeyError, TypeError, ValueError)` — but `float(nan)` returns `nan` and does
  **not** raise, and there is no `df.dropna()`. pandas/yfinance use NaN as the
  missing-value sentinel; a `Candle(c=nan)` is a type-valid `list[Candle]` element the
  "never raises" module must tolerate. Reachable via user-selectable tickers (thin /
  recently-IPO'd / halted names) on the live `use_real_market_data` path.
- **The `if technicals:` guard doesn't help** — it only catches a `None` return, not a
  raise. And the `_profile_for_ticker(ticker)` call site (room_runner.py:1078) is
  **before** `run()`'s own try (opens at :1118), so the raise isn't caught by the
  `run.status = RoomStatus.FAILED` handler (:1233) either. It propagates to `_pump()`
  (:939), which turns it into a client **error event with no verdict** — the **entire
  12-agent Convene fails**, not just the Market Analyst's technicals.
- **Defeats the stated guarantee.** The module docstring says "Never raises… callers
  fall back to the synthetic profile block," and DoD acceptance #6 claims "…never
  errors the Room/1-on-1 turn." Reproduced counterexample below shows both are false
  for a NaN close. All three sibling modules (fundamentals/news/social) wrap the full
  computation and return `None` here.

**Reproduced (unit-level, my own probe):**
```
candles[-1] = Candle(t=60, o=100, h=101, low=99, c=float('nan'), v=1e6)  # 60 clean + 1 NaN close
compute_technicals('AAPL')  → RAISED: ValueError - cannot convert float NaN to integer
```
(A NaN *low* alone doesn't reliably raise — `min()` skips it — but silently yields a
wrong support; the NaN *close* is the definitive failure.)

**Minimal remedy (round 2):** wrap the `compute_technicals` body in
`try/except Exception: return None` (match `news_context`/`social_context`/
`fundamentals`), **or** drop NaN candles / guard the `round()` calls (e.g.
`math.isfinite`). Either restores true never-raise → synthetic fallback. A regression
test with a NaN-close candle asserting `compute_technicals(...) is None` would pin it.
