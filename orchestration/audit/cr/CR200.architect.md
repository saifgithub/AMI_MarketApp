## Mutation proof (fresh, this lane)

Acceptance item 2's atomic-claim guarantee is the one concrete race-safety claim in this CR,
so I re-proved it rather than trusting the 2026-08-21 submission's own claim. The actual guard
is not in `admin_bugs.py` (that file just calls `get_feedback_store().admin_claim(...)` and
checks the bool) — it's `services/feedback_store.py:154-162`,
`FeedbackStore.admin_claim()`'s guarded UPDATE:

```python
result = s.execute(
    update(BugReportRow)
    .where(BugReportRow.id == report_id, BugReportRow.status == "open")
    .values(status="in_progress", assigned_branch=branch)
)
return result.rowcount == 1
```

In the verify worktree, dropped the `BugReportRow.status == "open"` clause (unconditional
UPDATE on `id` alone — two concurrent claims would both report rowcount 1). Re-ran
`test_cr200_admin_bugs.py::test_claim_is_atomic_double_claim_409`:

```
FAILED backend/tests/unit/test_cr200_admin_bugs.py::test_claim_is_atomic_double_claim_409
assert r.status_code == 409
E       assert 200 == 409
```

Exactly the second-claimer's expected 409 now returns 200 — the guard is load-bearing.
Reverted (`git checkout -- backend/app/services/feedback_store.py`); `git status --short`
clean except the intentional `.venv` symlink; full `test_cr200_admin_bugs.py` back to 6/6.
