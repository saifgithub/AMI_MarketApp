## Adversarial-focus notes (where to attack this)

- **(a) The three checks bite on REAL fixture names.** `no_fossil_fuels`→XOM/CVX EXCLUDED;
  `no_tobacco_alcohol_gambling`→MO/BUD/STZ/WYNN/LVS EXCLUDED; `esg_lite`→LMT/RTX (defense) AND
  XOM/MO (union) EXCLUDED, all `blocked_by="compliance"`. Attack: find a real S&P name in one of the
  pinned industries that slips through. The map is `_FOSSIL_INDUSTRIES` / `_SIN_INDUSTRIES` /
  `_DEFENSE_INDUSTRIES` in `classification_universe.py`; matching lowercases + flattens em-dash/en-dash/
  minus → hyphen (the beverages labels use an em-dash upstream), so a cosmetic dash swap can't
  silently un-classify. `test_classify_info` + `test_classify_info_dash_variants_normalise` pin it.
- **(b) UNKNOWN is PERMITTED-with-disclosure, NOT blocked** — the DEF059 inversion trap, asserted
  explicitly (`test_unknown_is_permitted_with_disclosure_not_blocked`): a name absent from the
  classified set resolves UNKNOWN under all three kinds → `passed`, no violation, but the disclosure
  verdict travels on the successful result. Attack: prove an unclassified name ever lands in
  `violations` (that would reject every name AMI hasn't classified).
- **(c) None / stale / disabled / seed → paused (loud degrade), never silent-permit.** UNAVAILABLE is
  blocking; a None universe or a disabled/seed/aged provider resolves everything to UNAVAILABLE →
  blocks with a pause message (`test_none_universe_pauses_loudly`, `test_provider_*`). This mirrors the
  halal-paused branch. **Operational consequence to weigh (stated, not buried):** with
  `CLASSIFICATION_SCREEN_ENABLED=false` (the default), `default_classification_universe()` returns a
  paused universe, so any user who has one of these flags ON gets EVERY sim trade paused until the flag
  is enabled AND a classify row is seeded — identical to the halal precedent. The flag stays false
  until the live classify pass is verified on promote; the coupled mobile-copy follow-up (stop
  presenting the toggles as active until enabled) is filed as `DEF061-MOBILE`.
- **(d) No request-path socket** (the CR075 lesson): the provider fetcher is `_snapshot_fetcher` (a
  local DB read); the ~500 yfinance `info` calls live ONLY in `run_classification_refresh_tick`, run
  from `main.py`'s daily task via `asyncio.to_thread`. `test_default_universe_disabled_pauses_without_db_or_socket`
  resolves through the real accessor with the feature off (no fetch, no row). Attack: find a read path
  that opens a socket.
- **(e) The halal `resolve` seam is byte-unchanged.** `safety_floor.py` checks 1–4 (allowlist /
  blocklist / long_only / halal three-state) are untouched; the new code is an added kwarg + a new
  block after check 4 + one added field on the return. `sharia_universe.py`, `schemas/sharia.py`,
  `overlay_generator.py`, `agent_runner.py`, `api/mandate.py`'s `check_holdings_against_mandate` NOT
  touched. The existing `halal_universe` callers gain ONLY the added `classification_universe` arg.
  Attack: diff for any change to a halal line.
- **(f) The migration's down_revision is the real head + applies clean.** `alembic heads` = single
  `c9f0a1b20022`; `down_revision = b2d3e4f50021` (verified sole prior head). Verified on sqlite by
  stamping `b2d3e4f50021` and upgrading only this revision → the 8-column table + index create; the
  downgrade drops both and reverts to `b2d3e4f50021`. (The full fresh-sqlite `upgrade head` fails on a
  pre-existing Postgres-only data migration far upstream — unrelated; that's why the unit suite uses
  `create_all`, not alembic. The target is melehost Postgres, where this migration's op types are
  identical to CR075's audited-clean `b2d3e4f50021`.)
- **(g) The one existing-test edit.** `test_safety_floor.py::test_compliance_halal_with_passing_universe`
  used the `halal_mandate` fixture, which ALSO sets `no_tobacco_alcohol_gambling` — now a
  deterministically-enforced flag. The test passed only a `halal_universe`, so the newly-enforced sin
  flag paused it (correct loud degrade). Fixed by passing a classification universe that classifies
  NVDA clean, isolating the halal check the test is actually about. Blast radius was exactly this one
  test (`1 failed / 1199 passed` before the fix); the sibling `..._with_excluded_ticker` still asserts
  `violations[0]` == the halal message because check 4 (halal) runs before the classification block.
