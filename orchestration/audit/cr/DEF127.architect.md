# Round 1

## The headline: DEF127's own row said this was not live. It was.

The row states the invariant *"is not fail-open in current code; it is a correct
cross-file invariant that no test pins."* That is true of the four **token** senders the
DEF114 auditor checked. It is false for the **error** senders, which nobody had looked at.

I measured this on the real `/v1/brief/message` route before writing any fix:

```
b'event: token\ndata: before \n\n
  event: error\ndata: upstream failed\n\n
  event: verdict\ndata: {"action": "BUY"}\n\n      <-- the server never sent this
  event: done\ndata: {"chars": 7}\n\n'
```

The exception message was `'upstream failed\n\nevent: verdict\ndata: {"action": "BUY"}'`.
A blank line inside a `data:` field terminates the event, so everything after it is parsed
as further events — here a **forged verdict**, byte-identical to a real one, on the Room
stream whose entire purpose is delivering a verdict.

Second, quieter failure: a multi-line message delivers only its first line. Per the SSE
spec, continuation lines have no field name and are dropped. A pydantic `ValidationError`
message is *always* multi-line, so the actual cause was being discarded silently.

Three live sites: `brief.py:118`, `one_on_one.py:118` (both `str(e)[:300]`) and
`room.py:271` (`ev.text`, itself `str(exc)[:300]` from three sites in `room_runner.py`).

## What I have NOT established

**I did not demonstrate an end-to-end exploit.** The forgery needs attacker-influenced text
inside an exception message. Pydantic v2 renders `input_value=` into its error strings, and
LLM output does get validated, so the path is plausible — but plausible is not measured, and
I am not claiming it. The framing break itself is measured and is enough on its own.

## The fix — a choke point, not three escape calls

`backend/app/api/sse.py`, two framers:

- `sse_text(event, text)` **escapes**, using byte-for-byte the chain already on the wire.
  This is not a format change: build `0.1.0+56` shipped today with `unescapeSseText` compiled
  in, and a test asserts the round-trip against a transcription of that decoder.
- `sse_json(event, payload)` **does not escape** and raises `SseFramingError` on a raw
  newline. `json.dumps` already renders newlines as two characters; running the text chain
  over it would double every backslash and corrupt the payload. Loud, per CR040.

All 20 emission sites across the three surfaces now route through it. No `data:` literal
survives anywhere outside `sse.py`.

I chose the choke point over patching three sites deliberately: the acceptance asked for
"the invariant, not the four call sites — an enumeration would miss a fifth sender, exactly
the allowlist-vs-invariant failure CR104 round 1 hit." With one choke point the guard's rule
is *"nobody frames an SSE event by hand"*, which is checkable over the whole tree.

## Guard — three layers, each covering a hole in the others

1. **Static, whole-tree AST.** Any `yield` under `app/` whose literals contain `data:` or
   `event:` and which is not a call to a framer → fail. Catches a fifth sender in a new file.
2. **Non-vacuity companion.** Asserts the framers are still used by ≥15 senders in exactly
   those three modules. DEF120's pin taught this: a guard whose subject vanished is green for
   the wrong reason.
3. **Behavioural, on the real route.** Drives `/v1/brief/message` with the forged-event
   message and with a multi-line one. Exists because layer 1 alone is satisfied by a no-op
   escaper.

## A process mistake worth recording

I ran the first matrix **before committing the fix** and reverted each mutation with
`git checkout -- <path>`. That reverts to the *committed* state — which was pre-fix — so it
silently deleted the fix from all three files, and `sse.py` (untracked) kept its mutation.
Every number after M1 in that first run was contaminated. I re-applied the fix, committed it,
and re-ran the whole matrix against a committed baseline; the table above is the clean run.

Rule: **never revert a mutation with `git checkout` while the fix is uncommitted.** Alongside
DEF136's *never run a mutation matrix with `-x`*, both belong in the governance writeup.

## What I want you to attack

1. **The static matcher's breadth.** It flags any `yield` whose literals contain `data:` or
   `event:`. Deliberately broad, but it only inspects `yield` — an SSE frame built into a
   variable and returned from a helper, then yielded bare, would not match. I judged that
   acceptable because `sse.py` is now the obvious place to add one; disagree if you can build
   a plausible sender that slips past.
2. **`sse_json`'s refusal.** Raising on a raw newline is right for `json.dumps` output, but
   `model_dump_json()` is pydantic's and I did not prove it can never emit one. If it can,
   this converts a corrupt frame into a 500 mid-stream — arguably worse.
3. **The escape chain is now load-bearing against a shipped binary.** If you think the
   round-trip test is a transcription rather than a real check of `api_client.dart`, say so —
   it is a Python re-implementation of the Dart function, and that is a real weakness.
4. **Whether M4's static-green is a gap or a design.** I claim it is why layer 3 exists.

## What I did NOT verify

- **Nothing on melehost, nothing against the real LLM.** Mac is a pure editor. The promotion

- **No end-to-end exploit**, as above.

  covered statically plus by the existing Room SSE tests, which stayed green. A behavioural

- **The client side.** Not touched. The consequence for `error` events is filed as **DEF139**.
