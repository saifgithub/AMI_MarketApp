### Four mutation-tested claims — each caught by the exact named test, then reverted

1. **Idempotency guard** — disabled the `if not force:` freshness-skip in
   `run_sharia_refresh_tick`. `test_a1_refresh_is_idempotent_a_fresh_row_skips_the_fetch` caught
   it immediately (`'stored' == 'skipped_fresh'` mismatch).
2. **Hold-window staleness gate** — made `_is_stale` always return `False` (except the `as_of is
   None` case). `test_a3_held_row_aged_past_window_pauses` caught it (`u.stale` was `False` when
   it should have been `True`).
3. **Refresh-failure counter** — no-opped `_record_refresh_failure`'s increment. Both
   `test_refresh_failure_is_loud_on_the_refresher_not_the_reader` and
   `test_a_successful_refresh_resets_the_failure_counter` caught it.
4. **Seed-path explicit raise** — removed `_snapshot_fetcher`'s `raise ShariaSourceError` on an
   empty table, returning empty frozensets instead. **Notable result**: the end-behaviour test
   (`test_a6_..._is_the_only_outage_path`) still **passed** under this mutation, because
   `_is_stale(None, ...)` unconditionally returns `True`, so the empty-`as_of` path independently
   produces the same UNAVAILABLE outcome — a genuine defence-in-depth, not a gap. A **separate**,
   dedicated test (`test_seed_fetcher_raises_on_empty_table`) does pin the explicit-raise
   implementation detail directly and caught the mutation. Verified this is two independent layers
   of coverage, not one test papering over the other.

### `main.py` background-task wiring

`_sharia_universe_refresh()` is registered in `lifespan`'s `tasks` list alongside
`_nightly_audit_trim()`/`_league_roll_tick()`; runs `run_sharia_refresh_tick` via
`asyncio.to_thread` (correctly off the event loop for its two ~15s httpx round-trips); wrapped in
its own `try/except Exception: logger.exception(...)` so an unexpected error in the tick itself
can't kill the daily loop — matches the existing `_league_roll_tick` pattern exactly.
