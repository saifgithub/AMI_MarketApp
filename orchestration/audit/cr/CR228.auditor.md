## MAJOR-1 — `_derive_risk_score` silently changed the scenario-only base, not just added nudges

**Where:** `backend/app/services/concierge_engine.py:499` (the `base = ...` line).

The submission describes Change 2 as adding bounded nudges "around the unchanged scenario-derived
base". The base did not stay unchanged. The rounding moved:

```python
# before                                   # after
base = round((a + c) / 2)                  base = (a + c) / 2 + asym
return max(1, min(5, base + asym))         ...
                                           return max(1, min(5, round(base)))
```

Old: round the `(a+c)/2` midpoint **first**, then add `asym`. New: add `asym` to the unrounded
midpoint, round **last**. For any profile where `(a+c)` is odd, `(a+c)/2` ends in `.5`, and
Python's banker's rounding then resolves it differently depending on whether `asym` has already
shifted the value to a different half-integer.

**Measured, running the real `_derive_risk_score` with `session.answers = {}`** (no
`max_drawdown_pct`, no `horizon`, no `primary_goal` — so not one nudge fires), over the values the
classifiers can actually return (`_classify_drawdown_response` → 1-5, `_classify_regret` → -1/0/+1,
`_classify_concentration` → 1/3/5 only):

```
reachable combinations: 45   changed vs the old formula: 10  (22%)

  dd=2 regret=-1 conc=3:  1 -> 2      dd=4 regret=-1 conc=1:  1 -> 2
  dd=2 regret=-1 conc=5:  3 -> 2      dd=4 regret=-1 conc=3:  3 -> 2
  dd=2 regret=+1 conc=1:  3 -> 2      dd=4 regret=-1 conc=5:  3 -> 4
  dd=2 regret=+1 conc=3:  3 -> 4      dd=4 regret=+1 conc=1:  3 -> 4
  dd=2 regret=+1 conc=5:  5 -> 4      dd=4 regret=+1 conc=3:  5 -> 4
```

**Driven end-to-end through the real interview** (`process_answer` over all 8 steps, not a
reimplementation of the formula), for a user who answers "I'd sell my worst losers" / "Losing money
stings worse" / "30% (balanced)" — i.e. an explicitly **loss-averse** profile:

```
components landed: {'drawdown_response': 2, 'regret_asymmetry': -1, 'concentration_tolerance': 3}

  pre-CR228   risk_score=1   single-name cap 1.5%
  at f5c5af0c risk_score=2   single-name cap 2.0%

  new formula with NO nudge inputs at all: 2   <- the rounding order alone, not the nudges
```

The last line is the point: this user has `max_drawdown_pct=30`, `horizon=very_long`,
`primary_goal=retirement` — but their score is 2 even with `answers` emptied entirely. The nudges
are not what moved them.

Both `_derive_risk_score` call sites matter: `concierge_engine.py:222` (the Q6 suggestion) and
`:524` (`_build_readback_summary`, whose `risk_score` becomes the persisted mandate at
`:604`). So these are live mandate values, not an internal intermediate.

**Why MAJOR rather than MINOR.** Three things together:

1. **It is undocumented.** The submission is otherwise unusually candid — it volunteers its own
   missed-test finding and flags the diversification gap unprompted — which makes this omission
   read as genuinely unnoticed rather than elided. The README, the docstring and the audit
   submission all describe the base as unchanged.
2. **It is unguarded.** I reverted the rounding order while leaving every piece of the new nudge
   machinery in place, and ran the 243 tests matching
   `risk_score|derive_risk|concierge|onboarding|mandate|cr228`: **243 passed**. The full
   `test_concierge_engine.py` also passed, all 23. Nothing anywhere pins the scenario-only base.
3. **It moves a safety-relevant number in the permissive direction for the wrong users.** Two of
   the ten shifts move a user *up* a tier, and the clearest one is a user whose regret asymmetry is
   toward **loss** — the most risk-averse signal Q4 can produce. Their enforced single-name cap
   goes up 1.33x. CR228's stated purpose is to make risk tiers *more* discriminating; this makes
   the most conservative scenario profile less so.

**What I am not claiming.** I am not claiming the new rounding is *wrong*. Rounding last is
arguably the more defensible choice — `asym` is a half-step-ish signal and rounding it into the
midpoint first discards information. The defect is that a deliberate change to how every user's
risk score is computed was shipped undescribed and untested, inside a commit whose stated scope is
"add three bounded nudges". If it is intended, it needs to be stated, justified against the
loss-averse cases above, and pinned.

**Suggested fix (either is fine):**
- Keep the new rounding, document it in the README + docstring as a deliberate second change, and
  add a table-driven test pinning the scenario-only score for all 45 reachable `(a, asym, c)`
  combinations with `answers={}`; or
- Restore `base = round((a + c) / 2) + asym` and apply the nudges to that, so Change 2 is only what
  it says it is.

## MAJOR-2 — the round-1 fix made Q6's answer unable to move the score on its own, and that is the CR's stated purpose

`docs/forward_planning/CR228_risk_appetite_differentiation/README.md:39-41` states the problem
this CR exists to fix, verbatim:

> **the causality runs backwards**: `q6_text` (:99) uses risk_score to *suggest* a drawdown, and
> the user's actual answer never feeds back. **A user offered 50% who picks 10% is saying the
> score is wrong, and nothing listens.**

I tested that exact sentence as a predicate, driving the real classifiers, with `horizon` and
`primary_goal` held at values whose nudge tier is 3 (the documented do-nothing nudge — verified as
a true no-op by harness self-assertion before measuring anything):

```
profiles where q6_text SUGGESTS 50% (Q1/Q2 neutral):     16
  of those, score MOVES when the user instead picks 10%:  0
=> the CR's own headline case: STILL NOT LISTENING
```

Same probe at round 1's `f5c5af0c`: **5 of 19 moved.** So this is a regression introduced by the
round-2 fix, not a pre-existing gap.

Wider measurement — how often Q6's answer alone changes anything, sweeping all five drawdown
answers across all 45 reachable scenario bases, Q1/Q2 neutral:

```
                 bases where Q6's answer changes the score
  round 1 (f5c5af0c):   16 / 45
  round 2 (7664fe39):    0 / 45      <- Q6 is now inert unless another question is non-neutral
```

**Why, arithmetically.** With only Q6 present the nudge list is `[dd_tier-3, 0, 0]`, so
`nudge_total = (dd_tier-3)/3/2 = (dd_tier-3)/6`, bounded at **±0.3333**:

```
  dd= 10% tier=1 -> nudge_total = -0.3333      dd= 50% tier=4 -> +0.1667
  dd= 20% tier=2 -> nudge_total = -0.1667      dd=100% tier=5 -> +0.3333
  dd= 30% tier=3 -> nudge_total = +0.0000
```

Round 1's base was `(a+c)/2 + asym` — a **half-integer** whenever `(a+c)` is odd, and
`round(x.5 ± 0.3333)` can cross. Round 2's base is `round((a+c)/2) + asym`, an **integer**, and
`round(int ± 0.3333) == int` always. The half-integer base was silently load-bearing for Q6's
own reachability; restoring the correct rounding order removed it.

This is not an argument for reverting the MAJOR-1 fix — the round-2 base is right, and I said in
round 1 that pinning the pre-CR228 base was the better of the two options. The defect is that the
`/2` damping was tuned against a base that no longer exists, and nothing re-derived it afterwards.

**Unguarded, and the existing guard passes by fixture accident.**
`test_cr228_disagreeing_drawdown_answer_nudges_the_score_at_readback` asserts `risk_score > 3`
after "No cap", and it passes — but only because its fixture uses `Q2 = "10+ years"`
(`very_long` → tier 4), itself a `+1` nudge. Change that one answer to the neutral `"3–10 years"`
and hold everything else identical:

```
  horizon='10+ years'  horizon_tier='very_long'  max_dd=100 -> risk_score=4   PASSES (>3)
  horizon='3–10 years' horizon_tier='long'       max_dd=100 -> risk_score=3   FAILS the assertion
```

The test named for Q6's influence is actually measuring Q2's. A mutation making Q6 **fully inert**
(`nudges.append(0)`) does fail that test — so the guard is not vacuous — but it cannot see the
real defect, which is Q6 working *only* when a second question happens to be non-neutral.

**Why MAJOR.** It is the CR's own stated purpose, measured against the CR's own words, and it is
silently gone; it is unguarded, with the one test that names it passing for the wrong reason; and
it fails toward "the user's explicit risk statement is ignored" — the same not-listening the CR was
filed to end. A user who is offered 50% and deliberately picks 10% is making the most direct risk
statement the interview accepts, and today it changes nothing.

**Not prescribing the fix** — the bound is a product decision, not mine. Two directions that both
close it: divide by a constant 3 rather than `len(nudges)` so a lone nudge keeps its full ±0.5
weight; or keep the mean but drop the `/2`. Either way the pin belongs on the CR's own sentence —
*offered 50%, picked 10%, score moves* — at neutral Q1/Q2, not on a fixture where another nudge
can carry it.
