# DEF094 — audit lane (auditor)

**Item:** DEF094 — the Sharia verdict is computed, enforced, and never sent to the
client. `ComplianceResult.sharia_verdict` existed and was populated by the
safety-floor resolver, but `sim.py`'s hand-built response dicts dropped it on every
trade — including the **accepted** path, which carried no compliance block at all.
A PASS ticker and an UNKNOWN ticker returned byte-identical bodies on a successful
trade, so G3 (unknown is permitted, WITH the disclosure attached) could not render
client-side.

stores; DEF084's exact surface one layer out.

`6b24833`). Audited in an isolated worktree `.claude/worktrees/audit-DEF094/`

### Mutation-tested the delivered fix (3 probes, all reverted)

1. **Dropped `sharia_verdict` from `submit_trade`'s accepted-path dict** (the
   defect's headline case) → exactly the 3 expected tests failed
   (`test_submit_accepted_carries_the_verdict`,
   `test_submit_accepted_unknown_ticker_is_permitted_and_discloses`,
   `test_pass_and_unknown_accepted_bodies_are_not_byte_identical`).
2. **Dropped the explicit `response_model=` kwarg from `/preview` alone** — suite
   stayed green. Not a real gap: FastAPI infers the schema from the function's
   own `-> PreviewTradeResponse` return-type annotation regardless — the explicit
   kwarg is redundant-but-harmless, not what the OpenAPI claim actually rests on.
3. **Dropped the `sharia_verdict` field from `ComplianceBlock` itself** (the real
   load-bearing element) → 5 tests failed including
   `test_shariaverdict_appears_in_the_openapi_schema` — confirms the OpenAPI claim
   is genuinely backed by the field, not an artifact of route wiring.

All reverted; suite re-confirmed 1269/1269 clean before the next probe.

### A sibling defect found by extending the hand-off's own question

The hand-off flagged this for me to check: *"`classification_verdicts` (DEF061's
parallel field) was NOT touched — worth confirming it isn't a second dark field the
auditor expects fixed here versus tracked separately."* Confirmed by grep: it is

Going one step further: `classification_verdicts` is populated in
`safety_floor.py` (lines 138-249) by the **exact same mechanism** as

`no_tobacco_alcohol_gambling` / `esg_lite` flag, with the identical four-state

fix. `test_def061_compliance_enforcement.py::test_unknown_is_permitted_with_disclosure_not_blocked`
proves the disclosure text exists on the pure `ComplianceResult` object — the same
"resolver correct, contract dark" gap DEF094's own diagnosis named
("verifying the component is not verifying the contract that reaches a client").

Not hypothetical: `mobile/lib/models/mandate.dart:55-69` already round-trips

`classification_verdict` — no existing entry tracks this.

**Severity: MAJOR** — same failure class and same safety-critical surface as
