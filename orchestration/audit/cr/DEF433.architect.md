## What and why

`agent_runner.py::_stream_concierge`'s `try/except` only ever caught a RAISED exception (the
transport-down shape, hardened under RETRO-SECURITY MAJOR-2 round 3). The in-band `[AMI error:
HTTP 503 from the upstream provider (vllm). Check backend logs.]` sentinel
(`llm_gateway.py`'s non-200 / in-band-SSE-error branches) never raises — it sets
`meta["stream_error"]` and yields its own sentinel text as an ordinary chunk. That chunk landed
straight in `buf`, and the trailing `if not "".join(buf).strip():` empty-buffer fallback never
fired once `buf` held anything — so the raw sentinel (provider name, HTTP status, operator
instruction) sailed out to the Concierge chat verbatim. Brief, non-Concierge 1-on-1, and price-alert
commentary already got the DEF424 fix for the identical gap; the Concierge was deliberately left
alone there because it has its own distinct fallback design (`concierge_scripted_reply`, not
`canned_agent_fallback`) and its own separate, already-hardened exception handler.

**The fix** (`agent_runner.py::_stream_concierge`):

- New `_scripted_fallback()` closure (dedupes the five-argument `concierge_scripted_reply(...)` call
  that was previously repeated at three call sites — no behaviour change, pure extraction).
- `had_stream_error = bool(meta and meta.get("stream_error"))` captured before the stream starts;
  each yielded chunk checks `newly_errored = meta.get("stream_error") and not had_stream_error` —
  structural detection of the key transitioning unset→set on *this* chunk, never string-matching the
  sentinel's own prose (same contract `one_on_one.py`'s refund gate already reads).
- **`buf` empty when the sentinel arrives** (the defect's own repro shape — a non-200 reply as the
  very first response): the sentinel chunk is swapped for `_scripted_fallback()` before being
  appended/yielded. This is the DEF424-MINOR-1 shape, applied to the Concierge's own branded copy.
- **`buf` non-empty when the sentinel arrives** (real content already streamed, then the provider
  refuses mid-body): concatenating a whole scripted reply after real partial content would read as
  nonsense (same call DEF424's MINOR-2 made) — but unlike DEF424's own MINOR-2 case (a RAISED
  exception, no provider text ever reaches a chunk), here the sentinel chunk *is* the text on the
  wire. Leaving it as-is (DEF424's MINOR-2 approach for its own shape) would still leak "vllm" /
  "refused this request" / "backend logs" after real content. Fixed by swapping that one chunk for
  the same short branded cut-off line the exception handler already uses:
  `"— AMI lost the connection mid-reply; this turn wasn't charged."` — found and closed during this
  lane's own mutation testing (the first-draft patch left this case unfixed; see "What changed in
  review" below).
- **Raised exception with `buf` already non-empty** (DEF424 MINOR-2's own shape, but for the
  Concierge's separate exception handler, which predates DEF424 and was never given the `else`
  branch): the existing `except Exception` handler's `if not buf: yield _scripted_fallback()` now
  has an `else` appending/yielding the same cut-off notice. The refund itself is untouched — same
  `meta["stream_error"]` write immediately above, same key `one_on_one.py` already reads.

**Charged-or-free finding.** Concierge turns ARE charged and refunded exactly like every other 1-on-1
turn. `one_on_one.py:119`'s "Concierge is always free" comment refers only to the DEF179 lesson-unlock
GATE at `one_on_one/start` (`if plan == Plan.FLOOR_PASS and req.agent_id != AgentId.CONCIERGE:` skips
the unlock check for Concierge) — the credit charge at `one_on_one/message` (`cost =
one_on_one_cost(); spend(...)`, line ~179) runs unconditionally for every agent including Concierge,
and the refund (`if failed and cost > 0: refund(...)`, driven by `stream_meta.get("stream_error")`)
is likewise agent-agnostic. Confirmed by the ledger assertions in every test below, not just asserted
in copy.

**Onboarding-interview path.** `concierge_engine.py` (the deterministic welcome/mandate-readback
state machine) has no import of `llm_gateway`, `agent_runner`, or any LLM/gateway module — verified
by reading its full import block and grepping every caller (`app/api/onboarding.py`,
`app/api/auth.py` call `concierge_engine.process_answer`/etc. directly; `agent_runner.py`'s only
references to `concierge_engine` are docstring/comment mentions, not imports). It cannot reach
`_stream_concierge` or this defect's code path.

## Mutation evidence

All mutations reverted after confirming red, then re-confirmed green (full targeted suite above).

1. `if not buf: chunk = _scripted_fallback()` → `if False: chunk = _scripted_fallback()` (disable
   the empty-buffer swap-in). Killed —
   `test_http_503_sentinel_yields_branded_scripted_reply_no_leak` failed (raw "vllm" text present).
2. `newly_errored = (...)` → `newly_errored = False` (disable structural detection entirely). Killed
   — same test, same failure mode.
3. Mid-stream sentinel swap (`else: chunk = "...wasn't charged."`) → `else: pass` (leave the raw
   sentinel chunk unmodified). Killed —
   `test_partial_reply_then_inband_sentinel_keeps_partial_no_leak` failed (raw "vllm"/"refused this
   request" text present). This mutation is what proved the draft's own version of this test was
   vacuous before the fix+test were both corrected (see "What changed in review" #2).
4. Exception handler's `else:` branch (cut-off notice on a raised exception with `buf` non-empty) →
   `elif False:` (skip it, silently truncate instead). Killed —
   `test_partial_reply_then_raised_exception_appends_cutoff_notice` failed (no cut-off notice, `r.text`
   ends mid-sentence). This mutation is what proved the draft had zero coverage for the Concierge's
   own raised-exception-with-partial-buffer case (see "What changed in review" #3) — it passed the
   full pre-existing suite silently before this test was added.

Each mutation was killed by exactly the test written for that behaviour; no other test in the
135-test targeted run moved.
