## 1. Why this lane, and a binding note on how to verify it

**Scope note first:** like `CR136-M06`, this lane is outside Rev 4's named
audit scope (line 832-839 names M02 and M05 only). It is here on a risk
argument, raised by Saiful directly, and the auditor should feel free to
return it as misallocated effort.

The argument is that **M09 is the only layer the user actually sees**. Every
module upstream can be correct and M09 can still show a wrong number, because
the failure mode here is not arithmetic — it is *unit and state
interpretation*:

1. **The units pin is the whole ballgame.** Tier-1 values arrive as decimal
   FRACTIONS (×100 to display), Tier-2 `realised_*` values arrive ALREADY
   PERCENT, and `beta`/`effective_bets`/`weight_concentration` are dimensionless
   RATIOS that take no percent sign at all. M06's round-0 blocker was exactly
   this class on the server — a Tier-2 value double-scaled and rendered as
   **"1969.00%"**. The client holds the mirror-image risk, and it holds it for
   every metric at once.
2. **The repo has a proven history of exactly this failure class going dark for
   months.** DEF210: a backend `EntryType` member was never mirrored into the
   Dart enum, and a `?? JournalEntryType.oneOnOne` coercion made the entry
   *impersonate* a different type — blank body, wrong label, wrong filter, for
   ~10 weeks. Nothing went red. The same shape is available here in every
   `fromJson`.
3. **CR040 lives or dies on this layer.** A metric the server marked
   insufficient must not render with the visual grammar of a real measurement.
   My own pass found precisely that defect (`0762f02d`: an unrecognised
   `status` rendered as a result) — which means the guard exists because it was
   already got wrong once.
4. **No Flutter code in this CR has had any independent verification**, and the
   device passes (iPhone 13 / iPhone 17, checklist 3.2-3.3) have not run either
   — melehost is off-LAN and no build has shipped. So today this module's only
   scrutiny is mine.

## 2. What the module is, and the decisions worth challenging

### 2.1 The units pin is structural, not documentary

`kMetricValueUnit` maps every metric id to `fraction | percent | ratio`.
`HealthMetricBlock.unit` **throws `StateError`** on a metric with no pinned
unit rather than guessing, and `valuePercent` **throws** for a `ratio` metric,
which has no percent reading at all. A new backend metric therefore fails
loudly on the client instead of rendering at 100× or with a spurious `%`.

The 11 pinned metrics must mirror the backend's `METRIC_VALUE_UNIT`
(`portfolio_health_constants.py`). There is no automated parity test across
that boundary — see §5.1, it is the gap I most want checked.

### 2.2 Seven card states, and `closed` is the conservative fallback

Populated · insufficient · empty book · refusal · transport error · unknown
status · loading. `HealthGateStatus` defaults to **`closed`** when the envelope
carries no `gate` object — a missing gate must never read as permission.

### 2.3 The bars ship COLLAPSED, and that was a measurement, not taste

The card measured **803pt** expanded, which pushed the Positions tab from 2.99
to 3.99 screens and broke CR120's accepted scroll budget. Saiful chose
collapse-by-default over the alternatives; the card is **563pt** collapsed, the
tab is 3.71 screens, and CR120's cap was re-pinned 3.0 → **3.75** with the
measurement written into the test itself. The mandatory caveat ships inside the
same expanded block as the bars, so no state can draw a bar without it.

### 2.4 `risk_money_bars.dart` owns its own `Directionality`

The shared-axis geometry (`RiskMoneyBarGeometry`) is LTR-pinned deliberately: a
signed numeric axis does not mirror under RTL, and Arabic ships at v1.0. The
widget wraps itself rather than relying on an ancestor.

## 5. What I would attack if I were the auditor

1. **The backend↔Dart units parity has no automated guard.** `kMetricValueUnit`
   (11 entries) must mirror `METRIC_VALUE_UNIT` in
   `portfolio_health_constants.py`. Nothing fails if they diverge — the client
   throws only for a metric it has *never seen*, not for one it has pinned
   *wrongly*. This is DEF210's exact shape one layer over, and DEF210 went dark
   for ten weeks. **If you find one thing in this lane, I expect it to be this.**
2. **Every `fromJson` coercion.** DEF210 was caused by `?? someDefault` making a
   value impersonate a different one. Audit each `?? ` and each `as num?` in
   `portfolio_health.dart` and ask whether the fallback is *conservative* (fails
   visible) or *impersonating* (fails silent). `PortfolioHealth.fromJson` reads
   `(json['metrics'] as Map?) ?? json` — is that a real dual-shape contract with
   M07, or a guess that would silently accept a malformed envelope?
3. **`deriveHealthCta` and the refusal panels.** The Finding screen keys four
   panels off the server's `detail.code` (409/402/429/else). Confirm the codes
   match what M07 actually emits, and that the `else` branch cannot render an
   empty panel.
4. **The negative-share caveat gate** — `rows.any((r) => (r.risk * 100).round() < 0)`.
   Check the boundary: a small negative share that rounds to `0` draws no
   caveat (there is a test asserting this). Is that the right call, or does a
   genuinely negative risk contribution deserve disclosure regardless of
   magnitude?
5. **The CR120 scroll-budget re-pin.** I moved an accepted acceptance criterion
   (3.0 → 3.75 screens) to accommodate this card. That is the kind of change
   that should be challenged: is 3.75 defensible, and does the test actually
   measure what it claims?
6. **`_BarsSection`'s collapsed state and the mandatory caveat.** The caveat is
   inside the expanded block. Verify no code path can draw a bar with the
   caveat absent — including a rebuild, a state restoration, or a
   `disableAnimations` accessibility path.
7. **Loading state is untestable on device** and is excluded from the device
   checklist as transient. Confirm it cannot become a stuck terminal state on a
   slow or hung request.

### M1 CLOSED — one guard, both contracts, on the pytest collection path

`backend/tests/unit/test_cr136_dart_parity.py` — a **backend** test that reads
the `.dart` sources, in the same shape as

- **Contract 1** parses the `kMetricValueUnit` literal and asserts equality with

  list this as a parity surface; it is one, and it fails quieter than a wrong
  number.

  is a symbol the guard imports rather than a literal re-typed in a third place.
  Its two siblings already were (`health_gate.GATE_CLOSED_CODE`/`DAILY_CAP_CODE`).
- **Non-vacuity leg**: `test_the_dart_source_is_where_this_guard_thinks_it_is`
  fails if either `.dart` file moves or if the map literal's shape changes such
  that the parse comes back empty. Without it, a moved file turns both parity
  assertions into comparisons against `{}` — the same silence in a new costume.

### m1 CLOSED — the fallback is gone, not narrowed

I took your first option rather than the "gate it on block-shaped keys" one, on

The two round-1 tests that asserted the flat shape parsed are replaced by one

drops the wrapper, and that its root `status` really is `ok`, which is what made
the old behaviour look healthy.
