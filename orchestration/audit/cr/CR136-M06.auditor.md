Three compounding mechanisms:

1. **One flat set per scale.** `Allowlist` (`portfolio_finding.py:180-182`) binds

   (`_register` `:603-608`, dps at `:619`) — ±1 *percentage point* on values
   spanning 0.4% to 118%. Traced: `risk_contribution`'s leaf
   `0.040160642570281124` → 4.02% → dp=0 → 4 → ±1 → {3,4,5}, which is what makes

3. **Both signs register.** `scenario_panel`'s COVID constant **−0.339** → 33.9 →
   dp=0 → 34 → ±1 → {33,34,35} at positive sign. Leaf scan confirms the only leaf
   in ±[0.315,0.345) is `('scenario_panel','episodes',-0.339)` — a benchmark
   drawdown licensing a positive 33% volatility claim.

BLOCKER, not MAJOR, because: it defeats the module's sole stated purpose and
metric-swapping is a *more* likely model failure than invention (the payload's own
numbers are the plausible wrong answers); the path is on by default
(`config.py:147` `= True`, `docker-compose.yml:119` `:-true`); the artefact is

published externally — methodology v2.2 §2/§7 tells reviewers "the instruction to
behave is not the control; the validator is", when the validator constrains the
vocabulary of numbers, not their assignment. That sentence needs correcting
whatever happens to the code.

**What is genuinely working, and must not be lost in the fix:** the strip stage is
a real structural control — an insufficient block is removed before any prompt
exists, so the model cannot narrate a metric it never saw. And the deterministic
path is unaffected; it emits only registered tokens by construction.

**Cheap mitigation that unblocks promotion:** ship with
`PORTFOLIO_HEALTH_LLM_ENABLED=false` until attribution is enforced. The
deterministic report is complete and correct by the module's own design, so this
costs prose quality and nothing else.

**Directions for a real fix** (a decision, not a patch): bind each registered

or keep the model to connective prose and re-inject every number deterministically

### Fix — two structural shapes, both avoiding the heuristic this lane has twice rejected

I am not proposing a sentence→metric matcher. That is the thing round 1 and round 2
both said not to build, and it would fail the same way.

1. **Self-labelling slots.** `{{vol_ann_pct}}` renders *"annualised volatility of
   19.0%"* rather than *"19.0%"* — the metric's name and its value become one
   inseparable token. A misplaced slot then reads as a visible non-sequitur ("Your
   beta to the market is annualised volatility of 19.0%") instead of a plausible false
   claim. Cheap, local to `build_slot_map`, and it degrades into nonsense rather than
   into a wrong number. It does not *prevent* misplacement; it makes misplacement
   unable to produce a false statement, which is the property that matters.
2. **The model selects, the system phrases.** For §F1 — the headline section, where
   every figure lives — let the model choose *which* metrics to headline and in what
   order, and render each headline from the metric's own template. The model keeps
   §F2/§F4 connective prose, where the number screens already hold. Strongest option;
   also the largest change, and it costs some of the plain-language quality the LLM
   path exists for.

Which of these, or a third, is the architect's call and Saiful's. Shipping the LLM
path off (`PORTFOLIO_HEALTH_LLM_ENABLED=false`) remains the cheap unblock for
promotion if CR136 needs to move before this lands — the deterministic renderer is
unaffected by all of this and has been clean in all three rounds.

## MAJOR M5 — the closed number-word set is not closed over the multiplier family

`_NUMBER_WORD_RE` is `\b(?:word|…)\b`, and `\b` cannot see inside a compound word.
Every one of these is accepted:

```
ACCEPTED  twofold   threefold   fourfold   fivefold   tenfold   hundredfold
ACCEPTED  quintuple sextuple    septuple   octuple    decuple
ACCEPTED  unity     score       naught     nought     umpteen
```

`twofold` is *"roughly double"* — the M3 example that produced this fix — written in
the one form the fix does not see. `\btwo\b` does not match inside `twofold`, and
`quadruple` is in the set while `quintuple` onward is not.

Checked the other direction too, and these are correctly handled: `twenty-five`,
`two-thirds` and `one-and-a-half` all reject (hyphens are word boundaries, so the
component words are caught), and `percentage` stays legal while `percent` rejects,
which is the intended `\b` behaviour.

MAJOR on the same footing M3 was: it is the same class, published the same way, and
it is the unclosed residual of the fix M3 asked for. A closed set that is missing a
whole productive morphological family is not closed.

Fix, in the lane's own blunt idiom rather than as an exception list: add a `\w*fold\b`
alternative (over-rejecting "manifold" is consistent with already rejecting
"concentrated in one name"), and extend the multiplier run past `quadruple`. `score`,
`naught` and `unity` are archaic enough to be judgement calls — I would add them
because the set costs nothing to widen and the whole design premise is that a false
number costs more than a lost narration.

Not in scope, and I agree with the lane's written boundary: unquantified language
("most of the risk", "a handful of names") and ranking ordinals ("first", "second").
Also noting without grading: ASCII Roman numerals ("your top XII holdings") are
letters and are not screened. Vanishingly unlikely; mentioned so it is on the record
rather than rediscovered.
