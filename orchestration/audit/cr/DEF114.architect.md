# DEF114 — audit lane (the SSE unescape corrupts every streamed text surface)

SUBMITTED: round 1

**Item:** every streamed text surface in the app — Room `agent_token`, Brief Your Agent, 1-on-1 chat
— decoded the backend's escape with two sequential `replaceAll`s that **cannot invert it in either
order**, silently corrupting any text containing a backslash immediately followed by `n`.

Acceptance: `docs/defect/_registry/DEF114.row.md` + `docs/defect/DEF114_room_sse_parser_untested_paths/`
Assign (carries **D1–D6**): `orchestration/dispatch/lanes/DEF114.assign.md`
Hand-off: `orchestration/dispatch/lanes/DEF114.coder.mobile.md`

**Code branch:** `lane/DEF114.coder.mobile` @ **`2895970`**, off `main` @ `98c6a07`.
Scope **6 files, +402/−128**; 5 incremental commits. Worktree clean.

**GATE: independent** — corrupts text the user reads, on three shipped paths.

## Provenance — the row understated the defect, and the Architect re-graded it before laning

DEF114 was filed from the CR090-MOBILE auditor's mutation set as a **coverage gap**: M1 swapped the
unescape order and the suite stayed green; M2 made `done` not terminate the generator and the suite
stayed green.

**Before laning, the Architect ran the actual round-trip in real Dart against the real backend
encode** (`chunk.replace("\\","\\\\").replace("\n","\\n")` — identical at `room.py:213`/`:236`,
`one_on_one.py:115`, `brief.py:115`) and found the shipped decode is **live corruption, not merely
untested**:

| Analyst text | Shipped order | Swapped order (M1) |
|---|---|---|
| `line one⏎line two` | OK | OK |
| `the token \n means newline` | **CORRUPTED** → `\` + line break | **CORRUPTED** → line break |
| `C:\next\report` | **CORRUPTED** → `C:\` + break + `ext\report` | **CORRUPTED** |

**This changed the assign materially: M1 is not fixable by pinning the current order, because both
orders are wrong.** A test asserting today's behaviour would have enshrined the bug — the obvious
reading of the row, and the wrong one. The row was rewritten to record this before dispatch.

Two further pre-lane measurements settled decisions the worker would otherwise have had to guess:

- **Dropping the redundant backend pre-escape is unsafe.** `json.dumps` already escapes, so the
  manual pre-escape is pure redundancy and tempting to delete — but measured against an
  already-shipped client it **regresses** `a\\b`, which round-trips correctly today. Fix was
  therefore scoped **client-only**, needing no coordinated release (D2).
- **Per-chunk decoding is safe** — each sender escapes each chunk independently and completely, so no
  escape sequence spans a chunk boundary. Told the worker not to build a stateful decoder (D3).

## Deviation from the assign — D3 was answered by inspection, not by test

The worker reports D3 (*"confirm per-chunk decoding is safe"*) as **"confirmed by inspection —
nothing to flag."** The Architect had already measured the same conclusion pre-lane, and it is
correct, so the finding stands — but **it rests on a backend property no test pins.** If a future
sender ever escapes across a chunk boundary, nothing goes red and the corruption returns silently.

Offering it to the auditor as a judgement call, not asserting it is fine: is an untested cross-file
invariant acceptable here, or does it want a guard on the backend side? Note the backend was
deliberately out of scope (D2), so any such guard is a **new** item, not a round-2 fix.

## Not verified

- **On-device behaviour.** Unit-level only; nothing exercised against a running backend or a real
  Room stream. `main` is under an active promotion hold (`infra/PROMOTION_HOLD.md`).
- **The real-world firing rate.** Requires counting backslash-followed-by-`n` in stored transcripts
  via `llm_audit` on melehost — not reachable from the Mac. The trigger is rare in equity prose
  (paths, regexes, an agent explaining what `\n` means) but **silent** when it fires, and it has been
  shipping on all three surfaces. **Neither the worker nor the Architect has measured how often.**
- **`flutter analyze`** — the worker reports it clean; the Architect ran `flutter test` only.
