## M1 — CLOSED. The guard is real, and I tried five ways to get past it

`backend/tests/unit/test_cr136_dart_parity.py`. Every mutation below was applied to
the worktree, the guard re-run, then reverted; tree byte-identical afterwards.

```
baseline                                                          3 passed
MUT-A  one Dart unit flipped fraction → ratio (DEF210's shape)     1 failed, 2 passed
MUT-B  one Dart key dropped ('mcr')                                1 failed, 2 passed
MUT-C  a backend refusal code renamed (DAILY_CAP_CODE + "_v2")     1 failed, 2 passed
MUT-D  the Dart map literal genuinely renamed                      2 failed, 1 passed
MUT-E  trailing comma removed from the last map entry              1 failed, 2 passed
restored                                                          3 passed
```

MUT-A, MUT-B and MUT-C are the three drift directions the finding was about, and
each is now red. MUT-D and MUT-E are mine, aimed at the **non-vacuity leg** — the
thing that decides whether the other two assertions are comparing anything at all:

- **MUT-D.** My first attempt was a bad mutation and I am recording it because the
  correction is the interesting part: renaming `kMetricValueUnit` → `kMetricValueUnitX`
  left all 3 green, because `source.index(...)` is a **prefix** match and found the
  same literal. A real rename (`kHealthMetricUnits`) fails 2 of 3 — the non-vacuity
  test *and* the units comparison. The leg works; a suffix-only rename is the one
  edit that slips past it, and that is not a drift shape anyone produces by accident.
- **MUT-E.** `_ENTRY_RE` requires a trailing comma, so dropping the last entry's
  comma silently drops that entry from the parse. It fails — because the comparison
  is whole-map equality, a *partial* parse is as red as an empty one. That was the
  question worth asking of a regex-over-source guard, and the answer is the right one.

Two calls in the fix I want to record as correct rather than merely accepted:

- **Whole-map equality, not `issubset`.** It fails on an added key, a dropped key
  *and* a changed unit. The client's own `unit` getter only ever covered addition;
  drift was the uncovered direction and is now the covered one.
- **Putting it on the backend side.** The bindings regression command is pytest, so
  a guard living there runs on *every* lane in the repo rather than only mobile ones.
  Same reasoning as DEF141's pins. A mobile-side guard would have been dark on
  exactly the lanes most likely to touch the backend constant.

`HEALTH_UNAVAILABLE_CODE` promoted from a re-typed literal to a symbol in
`app/api/portfolio.py:48` — its two siblings already were, so this removes the odd
one out rather than adding a convention.

## m1 — CLOSED

`kUnrecognisedEnvelopeStatus` (`'unrecognised_envelope'`, `portfolio_health.dart:32`).
Traced through the card by hand: every branch in `_body` keys on an exact status
string (`refused_mock_data`, `no_holdings`), so an unrecognised envelope reaches

The replacement test carries both vacuity guards, and they are the right two —
that the fixture really drops the wrapper, and that its root `status` really is

second one the test would pass against a fixture that was never dangerous.

Taking the "read one shape" option over "gate it on block-shaped keys" is the right
call for the reason given: a heuristic that decides *which shape this is* fails
silently, and silent failure was the thing being defended against.

One observation, not a finding: the card-side test
(`portfolio_health_card_test.dart:693`) parametrises over `''`, `'refused_stale_data'`
and `'partially_ok'` but not `'unrecognised_envelope'`. The chain is still pinned at
both ends — the model test asserts `isOk == false`, the card test asserts the
branch — so adding the string to that loop is a nicety, not a gap.
