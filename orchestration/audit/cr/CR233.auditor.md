### What must hold, and whether it does

- **No silent type conversion. Holds.** `buildAlpacaOrderPayload` maps each type to its own wire
  value. `SimOrderType.unknown` is refused before any call (`alpaca_client.dart:180-185`). Nothing
  falls back to `'market'`.
- **Validation runs before the POST. Holds.** `validateAlpacaOrder` is the first statement of
  `submitOrder` (`:435`), and the paper-host re-check comes before `_dio.post` (`:446-452`).
- **Every Alpaca placement sits behind an accepted preview. Holds.** `_submitAlpacaOnly` and
  `_legAlpaca` return before `_placeAlpacaOrder` unless `preview.accepted`
  (`trade_ticket_sheet.dart:785,969`). Preview and placement run in one sequence, with no user step
  between them.
- **The order log records what was sent. Holds.** `_alpacaOrderLogDetail` is built from the same
  `limitPrice`/`triggerPrice`/`bracket` locals that are passed to `submitOrder`
  (`trade_ticket_sheet.dart:1037-1063`). There is no second computation.
- **Resting vs filled. Honest.** `isResting` covers `new/accepted/pending_new/accepted_for_bidding/held`.
  Every other status prints Alpaca's own raw status (`— partially_filled.`, `— filled.`), so a
  resting order is never called "filled" (`:1078-1082`).
- **Destination lock. Holds.** `_destinationLocked` is exactly `coverTicker != null ||
  sellTicker != null` (`:360-361`).

### MINOR-1 — a GTD-30/GTD-90 Alpaca leg becomes good-till-cancelled, and the user is never told

`alpacaTimeInForce` maps `gtd30`/`gtd90` to `'gtc'` (`alpaca_client.dart:121-125`). The docstring
says *"the ticket's result copy must not claim the two expire together"*. The copy makes no such
claim, but it says nothing at all. No user-facing string mentions `gtc` or good-till-cancelled:
the only hits under `lib/` are that docstring and the mapping. The result line reads
*"accepted, resting at Alpaca (new)."*

A user who chose a 30-day expiry gets an Alpaca order that outlives it, with no sign of that.
It is recoverable, because it is paper and CR234 adds an in-app cancel. Hence MINOR.
**Fix:** when TIF is `gtd30`/`gtd90` and the destination includes Alpaca, add one line to the
Alpaca outcome: *"Alpaca has no 30-day expiry — this order stays open until filled or you
cancel it."*

### MINOR-2 — the short-side take-profit check has no test (attack surface §2)

M4 survives. With the sell-side take-profit wrong-side check disabled, all 77 Alpaca tests stay
green. The code is correct (`target >= entry` refuses on a sell, `:225`). The stop-side twin is
covered (M3). **Fix:** add a test for a short-open bracket whose take-profit is above the entry.
