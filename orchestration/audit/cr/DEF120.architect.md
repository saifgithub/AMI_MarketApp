# DEF120 — audit lane (the portfolio and trade routes block the single event loop)

SUBMITTED: round 1

**Item:** the other half of the MVP blocking-I/O show-stopper. `backend/app` runs **one uvicorn
process, no `--workers`**. `SimEngine`'s valuation and trade-execution methods call
`self.current_quote` **synchronously and internally**, so the blocking call never appears at the
route — which is why DEF116's re-derived call-site table missed the entire class. Nine handlers
park the one event loop: `get_portfolio`, `submit_trade`, `preview_trade`, `reset_portfolio`,
`close_trade`, `evaluate_trades`, `audit_holdings`, `sector_allocation`, `stream_room`.

Root shape, `sim_engine.py:271` — `{t.upper(): self.current_quote(t) for t in tickers}`: one sync
network fetch per ticker, **serially, on the event loop**.

## Architect-supplied context this lane was built on

Two things were measured **before** dispatch and written into the assign as settled decisions,
because getting either wrong would have produced a plausible-looking wrong fix:

- **`get_portfolio` does FOUR N-ticker passes, not one** — `sim.py:126` (`current_marks`), `:147`
  (`total_value` → `sim_engine.py:386`), `:148` (`current_drawdown_pct` → `:391`), `:149`
  (`aggregate_source`). The 60s `CachingProvider` collapses passes 2–4 to cache hits once pass 1
  warms it, so the *network* cost is ~N not 4N — the assign told the lane to **report what it
  measures, not the scary number**. The redundancy is unconditional regardless.
- **`quotes_batch`'s `loop.run_in_executor` fan-out is a trap here.** It is asyncio-bound, so it
  breaks the moment it is called from inside a `to_thread` worker — copying that pattern would have
  produced code that passes a direct unit test and explodes under D1. The assign required a **plain
  `concurrent.futures.ThreadPoolExecutor`** instead (D2).

### A contrived mutation that did NOT fire — reported so the auditor doesn't rediscover it as a finding

The Architect first tried routing the snapshot through an indirection
(`(lambda *a, **k: _sync_call(*a, **k))(sim.portfolio_marks_snapshot, user_id)`) and the guard stayed
green. **That is not a defect.** The guard resolves by call *name*, best-effort, and is documented as
such; passing a leaf by reference through a helper is invisible to it by construction, the same way
the correct `to_thread(leaf, arg)` shape is. The **realistic** regression shape — a direct sync call
from the async route — is caught, proved above. Recording the negative result so it isn't re-run.

## The worker's best disclosure — its own mutation initially did not fail

Acceptance item 6(a) **did not go red the first time**. The sync-pool fan-out introduced *new* leaf
names (`portfolio_marks_snapshot`, `valuation_snapshot`) that the guard's leaf set did not know, so
**the fix silently widened the guard's blind spot**. The worker found this, added the names, re-proved
red, and **reported it in the hand-off rather than shipping the working second version quietly**.

This is the third time in two days that a *fix* has degraded the guard meant to protect it (DEF122:
a pin keyed on `file:line`; CR104: a guard matching an unrelated empty dict literal). Worth a
`failure_patterns.md` entry in its own right — **"a structural guard must be re-proved against the
code that changed it, not the code it was written against"** — but that is a Governance call, not
something to fold into this lane.

## ⚠️ The empty pin set is a BLIND SPOT, not a clean bill of health — and the lane says so

`_DEF120_KNOWN_BLOCKING_PAIRS` is now empty, which reads like "nothing left to fix". It is not.
`_build_room_sector_context` remains the one waiver, and the lane documented in-source that the
walker **cannot see that pair even with zero waivers** — it reaches `room_runner.py` through a
`room.py:76` call-site alias. Keeping the name in the waiver set is what keeps the fact greppable.

**This is the honest shape** (contrast DEF116, whose waiver prose claimed removing a name "should turn
this guard red again" — the claim this lane had to make true). But it means **DEF120 does not fully
close the MVP show-stopper either**: the Room's sector-context build is still on the event loop.
That remainder must be laned against the CR104 → DEF124 → DEF125 Room queue, since `room_runner.py`
is under active contention and D7 forbade touching it here.

## What the Architect did NOT verify

- **Concurrency behaviour under real load.** Nothing was exercised against a running server; the Mac
  is a pure editor and `main` is under an active promotion hold (`infra/PROMOTION_HOLD.md`). The
  latency evidence is a stubbed-provider unit measurement, not a melehost smoke test.
- **That the 60s cache assumption holds in production.** The 4-passes-collapse-to-~N reasoning is
  read from `market_data.py:384-412`, not measured against live traffic.
- **Whether moving `submit`/`manual_close` onto a worker thread is safe under concurrent writers.**
  Item 8 proves a single request round-trips correctly through a real ASGI call; it does not prove
  two simultaneous writers behave. The worker reports no session-scope rework was needed.
