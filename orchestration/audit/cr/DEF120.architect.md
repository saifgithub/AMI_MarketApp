## D9 — deny-by-default at the `SimEngine` boundary

The round-1 walker follows `ast.Call` nodes, and `_marks_with_quotes` hands `current_quote` to
`pool.map` **by reference** — so the walk went blind past the fan-out, and round 1's own remedy
(naming the two methods that broke) closed those names, not the mechanism.

D9 inverts it. It does not walk *into* the engine from routes; it walks `SimEngine`'s own methods
against each other **using attribute references as edges, not just calls**, so a leaf handed to
`pool.map` by reference is exactly as visible as one called directly. Every method transitively
touching `self._provider.<quote|history|news|earnings>` must be declared in one of two sets —
`_BLOCKING_LEAF_METHOD_NAMES` (route may call it, every site `to_thread`-wrapped) or
`_SIM_ENGINE_SYNC_SAFE_METHODS` (never called directly from an async route). **A method in neither
set is undeclared, and undeclared fails red.** There is no allowlist to extend.

## Architect-supplied context this lane was built on

Two things were measured **before** dispatch and written into the assign as settled decisions,
because getting either wrong would have produced a plausible-looking wrong fix:

- **`get_portfolio` does FOUR N-ticker passes, not one** — `sim.py:126` (`current_marks`), `:147`
  (`total_value` → `sim_engine.py:386`), `:148` (`current_drawdown_pct` → `:391`), `:149`
  (`aggregate_source`). The 60s `CachingProvider` collapses passes 2–4 to cache hits once pass 1
  warms it, so the *network* cost is ~N not 4N — the assign told the lane to **report what it
  measures, not the scary number**. The redundancy is unconditional regardless.
- **`quotes_batch`'s `loop.run_in_executor` fan-out is a trap here.** It is asyncio-bound, so it
  breaks the moment it is called from inside a `to_thread` worker — copying that pattern would have
  produced code that passes a direct unit test and explodes under D1. The assign required a **plain
  `concurrent.futures.ThreadPoolExecutor`** instead (D2).

### A contrived mutation that did NOT fire — reported so the auditor doesn't rediscover it as a finding

The Architect first tried routing the snapshot through an indirection
(`(lambda *a, **k: _sync_call(*a, **k))(sim.portfolio_marks_snapshot, user_id)`) and the guard stayed
green. **That is not a defect.** The guard resolves by call *name*, best-effort, and is documented as
such; passing a leaf by reference through a helper is invisible to it by construction, the same way
the correct `to_thread(leaf, arg)` shape is. The **realistic** regression shape — a direct sync call
from the async route — is caught, proved above. Recording the negative result so it isn't re-run.

This is the third time in two days that a *fix* has degraded the guard meant to protect it (DEF122:

code that changed it, not the code it was written against"** — but that is a Governance call, not
