## 2. What the module is

Four stages, all pure except the last:

| Stage | Function | Contract |
|---|---|---|
| Strip | `build_stripped_context` | drops every insufficient block BEFORE prompt assembly, so the model never sees the metric's name — Rev 4's "nothing to narrate" enforcement |
| Render | `render_deterministic_sections` | head disclosure + §F1–§F5 from templates and computed slots only; this is also the FALLBACK output |
| Validate | `build_allowlist` + `tokenize_numbers` + `validate_sections` | closed allow-list: every number in generated text must be in the payload, at one of the admitted roundings, in the correct scale set |
| Register-check | `register_check` | §F1/§F2/§F5 are plain-language — technical lexicon, over-long headlines, and imperative/advice phrasing are rejected (the compliance-sensitive §F5 speech act) |
| LLM path | `_llm_sections` / `generate_and_persist_finding` | model output is used ONLY if it passes both checks; any failure falls back to the deterministic rendering and logs at ERROR |

The load-bearing design decision: **the two scale sets are never unioned.**
`Allowlist` carries `pct` and `raw` separately, and a token's scale is decided
by whether a `%` follows it in the text. A single merged set would admit "19.7"
as a percentage because 19.7 exists somewhere as a raw ratio — which is exactly
the class the Tier-2 blocker was in.

## 6. What I would attack if I were the auditor

1. **`tokenize_numbers`' scale detection.** `_PCT_SUFFIX_RE` looks 20 chars
   ahead. Construct a sentence where a number's `%` falls outside that window,
   or where an intervening word makes a percentage read as RAW — that token
   then validates against the wrong set. This is the most likely live hole.
2. **The ULP window.** `_register` admits `value ± 1 ulp` at each dp. Two
   genuinely different payload numbers that are one ulp apart at 1dp would make
   each other's neighbourhood legal. Is the window ever wide enough to admit a
   number the payload does not contain?
3. **`_numeric_leaves` recursion** — it walks the whole stripped context and
   registers every numeric leaf. Does it register numbers from parts of the
   context the model was never shown (making the allow-list wider than the
   prompt), which would let a model "guess" a legal number it had no basis for?
4. **`register_check`'s imperative detection** is first-word-of-sentence plus a
   phrase list. Write a §F5 sentence that is unambiguously advice ("it would be
   prudent to trim AAA") and see whether it passes — a prompt-shaped bypass of
   the compliance control matters more than a number bypass.
5. **The fallback path itself.** Every rejection falls back to
   `render_deterministic_sections`. If the deterministic renderer raises on the
   same context that produced the rejection, what does the user get? Check
   `_f5`'s `ValueError` on a fired rule with no template, and whether any
   rejection path can reach it.
6. **Head-disclosure persistence.** Rev 4 requires disclosures stored INSIDE
   the archived artefact (a user can reopen a year later and screenshot it).
   Confirm the stored payload carries them, not just the live render.

Both new MAJORs are on the boundary of the guard I built, and both are the same

### M3 CLOSED — the screen is over quantities, not over digits

Two screens now run on the model's own words (well-formed slot spans removed
first, so a slot's value can never trip them):

- **`numeric_chars()`** replaces the `\d` rule. The test is the Unicode
  **numeric value** property, which spans Nd, Nl *and* No — so `½`, `²` and `Ⅻ`
  join the Arabic-Indic and fullwidth digits `\d` already covered. Your
  observation that `\d` on a `str` pattern was doing more work than it looked
  like is what made the gap visible: the property, not the category, is the
  thing that means "this glyph is a number".
- **`_NUMBER_WORD_RE`**, a closed set: zero…twenty, the tens, hundred/thousand/
  million/billion, the fraction words (half, third, quarter, fifth, …), the
  multipliers (double, twice, thrice, triple, quadruple), the vague counts
  (couple, pair, dozen, single), and — not on your list — the percent **unit**
  words (`percent`, `per cent`, `pct`, `percentage point(s)`). Every percentage
  the narration may carry arrives from a slot already rendered with `%`, so the
  model has no legitimate reason to type one; that one addition also kills your
  `'Your volatility is XX percent.'` case, which no number-word set would catch.
  `\b` keeps the word "percentage" itself legal.

All eight of your accepted narrations are now rejected, as
`reason=number_word`, and they are the test table verbatim
(`test_a_number_spelled_out_in_words_is_rejected`), with a vacuity guard
asserting each carries **no digit** — otherwise the test would pass on the old
rule and prove nothing.

**The prompt is reworded to match**, and this is where CR038 says not to stop:
it now bans numbers "in any form", enumerates the notations, and — the part
that matters — states plainly that the model has *no way* to write an
approximation and must not try. Your read of the failure's cause was the useful
part of M3: the old instruction set demanded plain language, forbade digits, and
left spelling-it-out as the only legal-looking way to hedge. That is a prompt
pushing toward the one form the guard could not see.

**On the cost, stated rather than discovered by you later:** these screens are
blunt in the other direction. "concentrated in one name" is ordinary prose and
is now rejected, because a count is a number. I did not carve exceptions — an
exception list is a matching heuristic, which is the thing this lane has now
twice been told not to build. `test_the_number_screens_still_admit_ordinary_prose`
pins that a narration written the way the prompt asks still passes, so a screen
that rejects everything is a test failure rather than an LLM path that looks
healthy and is dark.

Not screened, deliberately and now written down: **unquantified** language.
"most of the risk sits in one name" carries no number and nothing rejects it.
Also unscreened: ordinals used as ranking ("first", "second"), which are common
connective prose and are not quantity claims.

### M4 CLOSED — and the reason code got fixed on the way

Any residual `{` or `}` after well-formed slot spans are removed is now
`reason=malformed_slot`. All four of your published-verbatim forms and the
`{{vol_ann_pct2}}` near-miss are the parametrised test table.

Building it surfaced a second-order defect you did not see, because it only
exists once the screens coexist: with the checks in their natural order,

Correct outcome, wrong telemetry. Since promotion checklist 2.12 measures what
the serving model gets wrong by breaking down `reason=`, a malformed slot
logged as a number word would have corrupted exactly the reading Saiful is
waiting on. The brace check now runs first, and the ordering carries a comment
saying why.
