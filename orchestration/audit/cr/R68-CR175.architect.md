## Why — the shape, measured not argued

DEF038, DEF063, DEF215, the AT:R66 audit incident, DEF260, DEF271. **Not one was the shipped code
being wrong.** Every one was *the pipeline's own verification checked the wrong thing, or nothing, and
reported green.* Six correct local fixes; nobody asked whether the layer they all passed through was
sound. Eight findings when it was asked:

- **F1** `main.py:465-467` returned a hardcoded literal, and was **both** the container healthcheck
  (`docker-compose.yml:400-405`) **and** the promotion's step-7 smoke check. DEF215's outage state is
  one it returns 200 for. `"version": "0.1.0"` never moved — a constant occupying the place an operator
  looks for a deploy identity.
- **F2** `grep -rn "GIT_SHA\|BUILD_SHA\|IMAGE_TAG\|APP_VERSION" backend/app/core/config.py docker-compose.yml`
  → no matches. Nothing answered *"is what is running what I shipped?"*
- **F3** `/v1/admin/config-check` reported a hand-written 9-gate list against **98 `Settings` fields**
  (43 key/token/secret/URL-shaped) — 9.2% coverage. **`adanos_api_key_secondary` absent**, the key wired
  the same week *because* 250 paid calls/month sat idle undetected. The guard could not see the newest
  instance of the bug it was built for.
- **F4** `promotion_protocol.md` — the doc `/promote-to-alpha` names as owning the design — still
  prescribed container-up-then-migrate, verbatim DEF215's ordering; blocking-checks list omitted both
  the AT:R65 hold gate and AT:R66 audit gate; claimed *"Currently 152 tests"* against 3,123. **DEF275.**
- **F5** rsync ships the *worktree*, the tag names a *commit*. Between them, a `git status --short`
  printed for the operator to judge with no `exit 1` — and it printed **21 lines**, routinely, from
  other lanes.
- **F6** `api-alpha` bind-mounts `./backend/app`, `./backend/scripts`, `./backend/tests`, `./content`
  **read-only over the image**. The running Python is the rsync'd host filesystem. `GIT_SHA` therefore
  answers *"which commit built this image"* and never *"which bytes is uvicorn importing"*.
- **F7** `dispatch.sh inbox` exits 1 on `dead>0` (stale watcher) as well as `hot>0` (real verdict). Not
  fixed unilaterally — **DEF277**, Saiful ruled promote-now-fix-after 2026-08-13.
- **F8** the one manual gate asked *"did you click through onboarding on the local backend"* while
  CLAUDE.md and `promotion_protocol.md` both state the Mac runs no backend. Unanswerable as written.

## What was built

**Tier A** — `GIT_SHA`/`ALPHA_TAG` as Dockerfile **build args** (last layers before `EXPOSE`, so a new
commit does not invalidate the uv-sync layer). Build arg not runtime env deliberately: a value a restart
can change is not an identity. Excused in `test_config_compose_parity.py` with that reason.
`/v1/health` stays liveness (a healthcheck failing on a dependency blip restart-loops a healthy
container) but reports the real stamp. New **`/v1/ready`** (`backend/app/services/readiness.py`) probes
db, schema `current==head`, llm provider resolution; 503 when a **gating** probe fails.
Redis is reported `gating: false` with the reason attached — `redis_url` is configured, `redis>=5.2` is
a main dependency, compose blocks `api-alpha` on `redis: service_healthy`, and `grep -rn "import redis" app/`
returns **nothing**. Failing a promotion over an unused service is a check that fires without meaning.

**Tier B** — `_settings_coverage()` derives the config-gate set from `Settings.model_fields`.
`_FEATURE_GATES` survives as the annotation table; `dark_count` and `gates` are unchanged so the
promotion protocol's reading of them still holds.

**Tier C** — `scripts/promotion/postflight.py`. Five checks, **three** exit codes: `0` pass, `1` a check
failed, `2` a check could not run. `2` is not a pass; conflating it with `1` is most of the incident
record. The `tree` check is an `rsync --dry-run --itemize-changes` against melehost and exists because
of F6 — it is the only check that catches a partial rsync, which the stamp reports as fine.

**Tier D** — `scripts/promotion/preflight_tree.py`. Classifies rather than blanket-fails: BLOCKING =
reaches the container (derived from compose's build context + bind mounts), SHIPPED = rsyncs but the
container never reads it, NOT SHIPPED = excluded. Blanket-failing would have taught the operator to
force past it, which is F5 with extra steps.

**DEF276** — found by the `tree` check on its first run against the real box, before it was wired into
anything: `rsync --delete` would have destroyed melehost's `backtest_results/`, holding
`runs_r68-def230-n40.jsonl` — the 40-pair replay DEF230's controlled-arm result rests on. DEF081's exact
class, third instance, because DEF081 was fixed with a *list*. Rule now stated: **any path bind-mounted
`rw` into a container is host-generated and must be excluded from `--delete`**, derivable from
`docker-compose.yml` rather than from memory.

## What the tooling found about itself, disclosed rather than buried

The **previous** promotion (`alpha-2026-08-13-1`, `c539af12`) ran postflight and `config` **FAILED on
six keys. All six were false positives, both causes bugs in this CR's own code:**

1. `SUPPRESS_ANALYST_CONSENSUS=false` flagged as the DEF038/DEF063 bug. It is not: for a `bool` field
   `configured` means *the feature is on*, not *the key exists*. Checked the `Settings` field, the
   compose line (`:268`) and the container's live value before believing the tool.
2. Five keys flagged as "not a Settings field" — the RevenueCat client SDK keys and the two website
   keys, **all already excused with written reasons** in
   `test_config_compose_parity.py::_ENV_KEYS_WITHOUT_SETTINGS`, while postflight kept its own shorter
   copy. **This is F3 committed by F3's own fix.**

Left in, `config` would have failed on every promotion forever — a check whose failing state is its
normal state, exactly the F5 pathology this CR exists to remove. Fixed in `71e97378`: the excuse table
is now **imported** from the one place that owns it (with a test that breaks if the import path breaks,
rather than silently reverting to the short list), falsey literals are off-switches, and the
*"is this a Settings field"* direction is left to the static test that already asserts it at preflight —
two verdicts on one question eventually disagree.

Two robustness bugs from the same run: an unhandled exception in one check took the other four down
behind a traceback (now `COULD NOT RUN`, exit 2, never a pass), and the excuse-table import needed
`backend/` on `sys.path`.

## Known gaps — stated, not hidden

1. **`/v1/ready` is unauthenticated by default.** Deliberate: a readiness probe a platform cannot call
   is not a readiness check, and that is how `/v1/health` ended up carrying a job it could not do. The
   anonymous body is `{ready, env, failed_probes}` only; revision ids, build stamp and provider name
   require the admin bearer, same category CR123 C2 gated `/v1/llm/status` for. **Worth attacking:**
   whether `failed_probes` names alone leak anything actionable.
2. **F2 is closed by two checks, not one.** `GIT_SHA` describes the image; the bind mounts mean it
   cannot describe the running bytes (F6). `identity` + `tree` together answer it; either alone
   overclaims. If the auditor thinks the pair is still insufficient, that is the finding to write.
3. **`dark_count` semantics unchanged on purpose** — the promotion protocol's step 7b reads it, and
   redefining it under that reader was not in scope. `settings_coverage` is added alongside.
4. **DEF277 open, and `alpha-2026-08-13-1` shipped past the audit-lane gate** on Saiful's explicit
   ruling. Recorded in `PROMOTION_RESULT_2026-08-13.md` §5 rather than left implicit — a gate that was
   reasoned past should be written down as having been reasoned past. `alpha-2026-08-13-2` cleared
   every other gate; the audit gate still exits 1 on the same dead-watcher condition.
5. **Not claimed:** that promotions are now incident-free. What is demonstrated is narrower — the
   checks can now fail, and on their first real outings three of them did.
