# CR236 — audit submission (architect → auditor)

**Item:** CR236 — a small, shared credits chip on the Convene sheet, the 1-on-1 composer,
Settings' Credits row, and a quiet post-Room cost line. Filed alongside **DEF437** (nullable
credit fields, discovered while building this).

**Built SHA:** `5eb0a620ddc176e651f605e8a2085f5f891df3e4` on `worktree-agent-a72de3f44b724bb9c`
(isolated worktree, not yet merged to `main`).

**depends-on:** — (touches `backend/app/api/room.py` only, not `room_runner.py` — DEF432's Room-
refund-on-outage lane owns `room_runner.py` and the two lanes' file sets are disjoint).

## What / why

Saiful, 2026-09-25: *"How does a user check how many credits they have left?"* Today the only
place is Settings' read-only Credits row; the Convene sheet shows neither the Room's cost nor the
balance; nothing says what a Room cost after it finished; the reset date only appears in the
upgrade sheet and the out-of-credits wall.

The Architect proposed, Saiful approved verbatim (**"Yes"**): *"a small credits chip. It would sit
on the Convene sheet ('Room: 8 credits · you have 63') and in Settings, with the reset date
('resets 1 Oct'). The Room would then say what it cost when it finishes."*

Full what/why/scope in `docs/forward_planning/CR236_credits_visible/CR236.md`.

## What I most want attacked

**The `creditCost != null` gate on the result row, `room_screen.dart` ~line 222.** My first
version watched `mandateNotifierProvider` unconditionally whenever `state.done` was true. That
regressed three unrelated, pre-existing test files
(`room_briefing_test.dart` ×2, `room_agent_withheld_test.dart`) with a "Timer is still pending"
assertion failure — merely *creating* `MandateNotifier` schedules a real network
`Future.microtask(n.refresh)`, and any settled-Room test that never expected to touch mandates now
does. I fixed this by gating the whole row (and therefore the mandate watch) on `creditCost !=
null`, reasoning that a `done` event with no cost renders nothing anyway. **Please check**: is
there a real-app path where `state.done` is true, the mandate widget legitimately should render
(because a real cost DID arrive), but this gate's timing accidentally skips the mandate refresh
that CR236 needs (balance visible on every surface)? I believe not — the gate only skips
*rendering*, and the refresh itself already happens unconditionally in `room_providers.dart`'s
`'done'` case, decoupled from what `room_screen.dart` chooses to show — but this is exactly the
kind of "fixed the test, maybe broke the feature" move CR040 warns about, and I'd rather have it
checked than assumed.

**The refund derivation, `refunded = status == "failed"`.** I did not add a CANCELLED case (a
client-disconnect mid-run charges and is never refunded per `room_runner.py`'s own comment: "NOT
marked CANCELLED, NOT refunded here" for the shutdown path, and the ordinary disconnect path
charges too). Covered by `test_cancelled_run_is_not_reported_as_refunded` — please confirm this
reads the real enum values right and that no other terminal status exists that I've missed.

## Attack surface — can any surface show a number the user doesn't have?

- Every new widget reads `null` as unknown and renders an explicit unknown-state string, never a
  placeholder number.
- `HouseAdSignals.fromMandate`'s three ad-targeting signals fail closed on a null input field —
  proven both directions in `def437_house_ad_signals_unknown_credit_test.dart` (unknown → false;
  known-and-true → still fires).
- `credit_cost` on the wire is a plain re-read of the persisted row, never a value threaded through
  in-memory state that could drift from what was actually charged.
- `refunded` reads `status`, set by the SAME code CR039 already uses to decide refunds — this CR
  makes no new refund decision, only reports one already made.
- A raced-away row degrades to `null`/`false` server-side, and the client renders nothing rather
  than guessing.

## Architect follow-up at merge (before round 1 is audited)

Merged as 2141cf39; follow-up commit on main changes three things:

1. **Stale balance on the post-Room line.** `_RoomResultCostRow` read the mandate as cached
   before the Room, so until the post-`done` refresh landed the line said "used 8 · 63 left".
   Now `RoomState.balanceAfter` is set only after that refresh succeeds (a failed refresh
   keeps the stale mandate and sets `error`, so it is not used). Until then the line reads
   "This Room used 8 credits" (`roomResultCostNoBalance`). The row no longer watches
   `mandateNotifierProvider` at all. Test: `test/state/room_cr236_balance_after_test.dart`
   drives the real `RoomNotifier.start()` through `done`. Mutation (drop the `error == null`
   check) fails it.
2. **Copy.** Refunded line was "Not charged — the desks were unreachable", which names a
   cause a FAILED run need not have; now "Not charged — this Room didn't reach a verdict".
   Insufficient suffix was "Not enough — the Room refuses at convene"; now "not enough to
   convene". ar/ms re-seeded with `translate_arb.py --seed-missing` after dropping the two
   stale seeds.
3. **Known cross-lane gap, closed at DEF432's merge:** DEF432 refunds an outage NO_VERDICT
   run while its status stays COMPLETED, so `refunded = status == "failed"` would read
   false for it. The `done` event's `refunded` will be aligned with DEF432's predicate
   when DEF432 merges; until then no outage refund exists on main, so the two agree.
