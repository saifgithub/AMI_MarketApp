## MINOR-1 — the test named for judgement call 1 does not test it

`test_the_record_survives_a_safety_floor_override`
(`test_def397_thin_room.py:277`) imports `enforce_safety_floor` with `# noqa: F401` and **never calls
it**. It hand-builds a `Verdict`, applies `model_copy(update={"agents_degraded": …})` itself, and
asserts `is_thin_room_verdict`. It would pass under any stamp ordering, because no ordering is
exercised.

The submission half-says this ("I wrote that test, and it constructs the verdict rather than driving
a real floor-override run"), so this is confirmation, not news. What is news is the measurement:

- The property **is** real. `safety_floor.py:839` builds a fresh `Verdict(...)` naming ~6 fields, so a
  stamp applied before the floor would be dropped on override. Confirmed by reading the constructor.
- The ordering **is** guarded — but by a different test. Mutation: skip the stamp when
  `verdict.overridden_from_llm` is true (i.e. reproduce "someone moved it back above the floor").
  Result: `1 failed, 125 passed`, red at
  `test_room_runner.py::test_room_agent_timeout_falls_back_to_scripted` —
  `AssertionError: a live run that timed out must record it`.
- Under that same mutation, `test_the_record_survives_a_safety_floor_override` **passes**
  (`1 passed in 0.49s`).

So the coverage is real but incidental: it depends on that pre-existing test's scenario happening to
produce a floor-overridden verdict. If that scenario is ever changed for an unrelated reason, the
ordering silently loses its guard and the test named for it will keep passing. Make the named test
drive a real override, or rename it to say what it actually asserts.

Also: the submission cites the floor call at `room_runner.py:4703`. It is at `:4826`. The ordering
conclusion is unaffected (`:4826` < `:4895`, same flow), but the line reference is wrong.
