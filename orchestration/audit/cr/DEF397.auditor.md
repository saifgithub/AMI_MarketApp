## MAJOR-1 — the gateway change has ZERO enforcing check, suite-wide

The submission calls this "the widest blast radius in this defect" (judgement call 4) and it is the
one change with no test anywhere.

**Measured, not reasoned.** I removed the entire `except (asyncio.CancelledError, GeneratorExit)`
block from `llm_gateway.py:1248-1259` and ran the full suite in the pinned worktree:

```
5645 passed, 9 skipped, 14 warnings in 901.60s
[exited with code 0]
```

That is **byte-identical to the submission's own clean-SHA figure** (`5645 passed, 9 skipped`).
Neither `test_def397_thin_room.py` nor `test_def397_consumers.py` contains the string
`CancelledError` or `GeneratorExit`; nor does any other test in the tree.

This is the house rule verbatim — *an entry without an enforcing check is not done* — and it is P24's
sibling: the submission ran four mutations and none of them touched this file, so "it cannot change
control flow" is a claim from reading, on the one change whose blast radius the author flagged as
widest.

**To be clear about what I am NOT claiming.** I checked the reasoning and it holds: `raise` is bare
so the same exception propagates; `record_llm_call` is a sync `def` (`audit.py:77`), so the `finally`
cannot await during `GeneratorExit` and cannot raise "async generator ignored GeneratorExit"; and the
`finally` already ran on this path before the change, so it is reached in no new state. I found no
defect in the code. The finding is that nothing stops the next person deleting it, and the next
person will have the same three arguments available and no red test.

**What would close it:** one test asserting that a cancelled stream records a non-NULL `error` on the
audit row — the observable the change exists to create. It should red when the block is removed.

## MINOR-1 — the test named for judgement call 1 does not test it

`test_the_record_survives_a_safety_floor_override`
(`test_def397_thin_room.py:277`) imports `enforce_safety_floor` with `# noqa: F401` and **never calls
it**. It hand-builds a `Verdict`, applies `model_copy(update={"agents_degraded": …})` itself, and
asserts `is_thin_room_verdict`. It would pass under any stamp ordering, because no ordering is
exercised.

The submission half-says this ("I wrote that test, and it constructs the verdict rather than driving
a real floor-override run"), so this is confirmation, not news. What is news is the measurement:

- The property **is** real. `safety_floor.py:839` builds a fresh `Verdict(...)` naming ~6 fields, so a
  stamp applied before the floor would be dropped on override. Confirmed by reading the constructor.
- The ordering **is** guarded — but by a different test. Mutation: skip the stamp when
  `verdict.overridden_from_llm` is true (i.e. reproduce "someone moved it back above the floor").
  Result: `1 failed, 125 passed`, red at
  `test_room_runner.py::test_room_agent_timeout_falls_back_to_scripted` —
  `AssertionError: a live run that timed out must record it`.
- Under that same mutation, `test_the_record_survives_a_safety_floor_override` **passes**
  (`1 passed in 0.49s`).

So the coverage is real but incidental: it depends on that pre-existing test's scenario happening to
produce a floor-overridden verdict. If that scenario is ever changed for an unrelated reason, the
ordering silently loses its guard and the test named for it will keep passing. Make the named test
drive a real override, or rename it to say what it actually asserts.

Also: the submission cites the floor call at `room_runner.py:4703`. It is at `:4826`. The ordering
conclusion is unaffected (`:4826` < `:4895`, same flow), but the line reference is wrong.

## MINOR-2 — "unmeasured" is invisible where records become claims (judgement call 2)

The polarity is right and I would not change it. `False` on absent is what T-BACKFILL requires, and
`degraded_agent_count` keeping `None` distinct from `0` is the load-bearing half — correctly pinned by
`test_measured_and_clean_is_not_the_same_as_never_measured`.

The gap is one layer out. `backtest_report.py` counts `excluded["thin_room"]` (`:548`), errors above
5% (`:576`), and prints `thin room: N` (`:955`) — but has **no bucket for unmeasured**. Confirmed:
no `unmeasured` or `unknown` counter exists in the file. So a batch of entirely pre-fix runs prints

```
thin room: 0
```

which is indistinguishable from a batch that was measured and clean. The submission's own words for
this shape, used to justify excluding the demo path, are *"a signal that is always on is the same as
no signal (P2/DEF135)"*. This is the mirror image: a signal that can never fire reads as a clean
signal — and it will read that way over exactly the 2,555+ historical verdicts the submission
identifies as permanently unclassifiable.

The predicate is correct; the report should say which population it could not ask. Count
`degraded_agent_count(...) is None` into its own bucket and print it beside `thin room:`.
