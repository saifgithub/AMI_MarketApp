# DEF039 — audit lane (architect)

**Item:** DEF039 — defense-in-depth on a monetized currency. `reputation_events` had no DB
uniqueness on its `(user_id, event_type, ref_id)` dedup anchor — dedup was app-code-only (a
SELECT-then-INSERT race), so two concurrent same-ref `award()` calls could both pass the check
and double-insert. Reopened **CR004 audit finding F2**. Register: [`docs/defect/def_list.md`](../../../docs/defect/def_list.md) DEF039.

**depends-on:** none.

**Head SHA:** `2208f99`

## What changed / why

| Piece | Change |
|---|---|
| model | `app/db/models.py` — `ReputationEventRow.__table_args__` adds a **partial unique index** `uq_reputation_event_dedup` on `(user_id, event_type, ref_id)` `WHERE ref_id IS NOT NULL` (`postgresql_where` + `sqlite_where`, so `create_all()`-backed tests get it too). Partial because `ref_id` is nullable and `award()` only dedups when a ref is given. |
| service | `app/services/reputation_service.py` — `award()` wraps the `session.flush()` in `try/except IntegrityError`: the loser of a race rolls back (reverting the in-memory `user.reputation` / `member.points` bumps) and returns 0 — identical contract to the existing dedup-check hit. |
| migration | `alembic/versions/d1e2f3a40015_reputation_events_dedup_index.py` — creates the partial index on Postgres (`postgresql_where=text("ref_id IS NOT NULL")`). |

## Tests run (self-test)

- `pytest backend/tests/unit/ -q` → **586 passed**.
- New `test_reputation_service.py::test_award_race_on_dedup_check_is_caught_by_db_index` —
  monkeypatches `_already_awarded` to `False` (simulating the loser's stale check) so the INSERT
  reaches the DB index; asserts `granted == 0` and no duplicate row. This exercises the real
  partial index on the sqlite fixture, confirming the index + IntegrityError path both fire.
- **Migration applied clean on live Postgres** at `/promote-to-alpha` (`alpha-2026-07-11-2`):
  `Running upgrade c3d4e5f60014 -> d1e2f3a40015`.

## Note on verification limits

The full alembic chain cannot dry-run end-to-end on the Mac (a pre-existing earlier migration is
Postgres-only and fails on sqlite — unrelated to this change). This item's migration was therefore
verified two independent ways: the sqlite-parity partial index in the ORM (exercised by the race
test) **and** the real `alembic upgrade head` against melehost's Postgres during promotion.
