# Round 1

## What and why

Bug `583602ee` (Saiful, off `0.1.0+57`): *"when the room is running, we are still getting the full
text displayed to the user. we are supposed to only show the status of what is running."* CR106
restructured only the **finished** run (Verdict Board + collapsed transcript); the live stream was
untouched, so the complaint survived. The assign was amended same-day to add the headline half back
in, once the REL58 auditor measured the DEF147 stance-envelope gate cleared on live traffic (2.3%
null, both `research_manager`, envelope simply absent — the null-is-not-neutral case the gate exists
for — against a 132/132 no-parse pre-fix baseline under the same shipped parser).

## The change

`mobile/lib/screens/room/room_screen.dart`. Only the non-settled branch changes, exactly as the site
scoped it (`room_screen.dart:191-202` in the assign's line numbers, before other commits shifted them
— confirmed by reading the file before touching it).

- **`_RoomLiveRoster`/`_AgentStatusRow`** replace the old `_RoomRoster` (pre-order skeleton only) and
  the per-order `_AgentLine` prose loop. The roster is now FIXED — all 12 `kAllAgents` seats, always,
  from the first frame — because a fixed roster has nowhere to scroll to (the assign's own words for
  why auto-scroll goes). Status per seat is derived from `RoomState` alone, no new field:
  - `responded` = `state.agentStances` carries a key for the agent (set the instant `agent_done`
    lands, whatever it recorded).
  - `thinking` = not responded, the stream is still `streaming`, and `state.activeAgent == agent.id`.
  - `interrupted` = not responded, not thinking, the agent DID start (`state.order` contains it), and
    the run itself has already stopped (`!streaming && !reconnecting`) without ever completing this
    agent's turn. This is the "an agent's turn fails" case the assign specified is not backend-
    modelled as a distinct event — the backend always falls back to scripted text and still emits a
    normal `agent_done` on a per-agent timeout/exception (`room_runner._compute_agent_text`, read
    before writing this to confirm), so the ONLY client-observable "turn failed" signal is the RUN
    itself breaking (stream `error`, or a reconnect timeout) while an agent was mid-turn. `thinking`
    is gated on `state.streaming` specifically so a lingering `activeAgent` from before a break does
    not read as still-in-progress forever.
  - `waiting` = none of the above.
  - **Headline, three states, three different widgets** (acceptance #9, the one the assign says it
    reads first): `!stance.recorded` → no headline row at all (this run carries no stances at all);
    `recorded && headline == null` → the Verdict Board's own `roomCombNotStated` ("NOT STATED") label,
    reused rather than a new string so the same fact reads identically on both surfaces; `recorded &&
    headline != null` → the headline itself.
  - **DEF125 truncation** (acceptance #6): reuses `hasAmiAnnotation` (exported, unmodified, from
    `room_transcript_rows.dart`) against the raw `state.transcript[agentId]` text — the same amber
    `⬢` mark the settled comb already uses for the same fact, on `responded` only.
  - CR098's `_WithheldAgentChair` is untouched, called from the new roster in the agent's own fixed
    seat instead of wherever `state.order` happened to place it (see "what I did NOT do" below for why
    that ordering change is intentional, not a scope creep).
- **Auto-scroll removed outright**, not just the call site: `_scrollToBottom()` method deleted AND
  the `ref.listen<int>(...transcript.length...)` block that fired it deleted, per the assign's
  explicit instruction that a listener firing on every token and doing nothing is worse than none.
- `_AgentLine` (the old prose renderer) and the unused `_agentMarkdownStyle` helper + the
  `flutter_markdown_plus` import are deleted — nothing else in the file used them.

## A pre-existing test this CR necessarily invalidated

`room_agent_withheld_test.dart`'s `'locked chair sits ahead of a real agent line in the same order'`
asserted ordering by `state.order` (arrival order) and found the real agent's row by its PROSE TEXT —
both premises this CR removes on purpose (acceptance #1 kills the prose; the fixed roster reorders by
`kAllAgents`, not arrival). Updated in place: renamed to state what actually holds now (fixed roster
order — Fundamentals sits before Market in `kAllAgents` regardless of who spoke/was withheld first),
finds the real row by NAME not prose, and asserts the prose is genuinely absent. A second test in the
same file (`'renders in seat with a roster-level countdown naming the OTHER agent'`) needed a
narrower finder for the same structural reason: the fixed roster now ALSO renders a plain
`"Social Media Analyst"` row for that agent's own seat, so the old bare-name finder became ambiguous
(2 matches) — fixed by matching the full countdown sentence instead. Both are real consequences of
the acceptance criteria, not incidental breakage; called out explicitly per the audit protocol's
"revert-proof QA" ask.

## What I did NOT do

- **Did not touch `room_providers.dart`** — confirmed via `git diff --stat`, quoted above.
- **Did not touch `RoomTranscriptRows` or the settled branch** — `room_transcript_rows.dart` is
  imported for its one exported pure function (`hasAmiAnnotation`), never edited.
- **Did not fix DEF161** (the `agent_done` replay path always emitting the three stance keys on a
  pre-B2 run reconnect) — out of scope per the fence, backend-side, already minted.
- **Did not keep seating by `state.order`.** The assign's own wording ("a fixed roster... nothing to
  scroll to") reads as a genuinely fixed roster, not a relabeled growing list, so I built it that way
  — which changes WHERE a withheld chair sits relative to a real agent's row (by `kAllAgents` order,
  the agent's own canonical seat, rather than by who happened to speak/withhold first). I consider
  this MORE consistent with CR098 D4's "renders inline... never drifting out of seat position" intent
  than the old arrival-order seating was, but it is a real behavioural difference from before and I
  want it looked at rather than assumed correct.
- **Did not render `roomAgentThinking` anywhere** — I minted the string per the assign's original
  wording ("waiting → thinking → responded") expecting to need visible text for the thinking state,
  then built it visual-only (pulsing dot on the hex avatar, matching the pre-existing `_RosterRow`
  convention for the same state) once I saw the existing pattern didn't use text for it either. The
  key exists in all three ARBs, translated nowhere, and is unused. Flagging rather than silently
  leaving an orphaned string — happy to either wire it in (e.g. as a semantics label for
  accessibility) or delete it, whichever you'd rather.
