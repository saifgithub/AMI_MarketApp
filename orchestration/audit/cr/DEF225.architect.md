## 1. What was broken, measured

`test_cr136_health_gate.py` did `ast.parse(Path("app/api/portfolio.py").read_text())`
and the same for `app/services/health_gate.py`. Those resolve only when pytest is
invoked from `backend/`.

Measured on a clean `d6e9d618`, same SHA, same interpreter:

```
# from the repo root — the command CLAUDE.md documents
$ backend/.venv/bin/python -m pytest backend/tests/unit/ -q
2 failed, 2346 passed
# from backend/
$ .venv/bin/python -m pytest tests/unit/ -q
2348 passed
```

Both failures were `FileNotFoundError: [Errno 2] No such file or directory:
'app/services/health_gate.py'`.

## 2. Why it is worth a defect rather than a tidy-up

Both are **structural** guards — "the free tiles route must be structurally incapable
of calling `enforce_gate`" (CR136's free-surface guarantee) and "the gate module must
not import M08's journal enum" (a build-order independence claim). Run from the repo
root they raised, so **they verified nothing**, in a form that reads as an environment
quirk rather than a failure. The visible cost (two permanent red lines taxing every
future bisect) is the smaller half.

Found by running the documented command at session start, not by anything failing
where someone was looking.

## 3. The fix, and the guard

Fix: `_BACKEND_ROOT = Path(__file__).resolve().parents[2]`, both sites anchored to it.

Guard: `test_def225_tests_are_cwd_independent.py` walks the AST of every `test_*.py`
in `tests/unit/` and fails on any `Path("<repo-source-path>")` literal that is not
absolute. **Matches the shape, not a filename list** (P15) — a `Path(...)` call whose
string argument starts with a source-dir prefix — so it catches the next one whoever
writes it. Only `Path(...)` calls are inspected; a bare string containing `app/` is
usually a route or a log key and flagging those would make the guard noisy enough to
be disabled.

It carries its own **vacuity check** asserting the detector fires on DEF225's exact
original line and stays silent on the anchored form. Without it, a later narrowing of
the detector would leave every parametrised case passing on an empty result set, which
is indistinguishable from a clean codebase.

**It immediately caught a second, latent instance**: CR124's own new test file used
`Path("backend/Dockerfile")` in a parametrize list. Harmless there (joined to
`_REPO_ROOT` at the use site) but ambiguous — I changed the fragment to a plain string
rather than weakening the guard to accept it.

## 6. Known gaps for the verdict

- The guard covers `backend/tests/unit/` only. Other test roots (`mobile/test/`,
  anything under `qa/`) are untouched; Dart has no equivalent construct so the class
  may simply not exist there, but I did not verify that and am not claiming it.
- The `_SOURCE_PREFIXES` tuple is a judgement call about what "looks like a repo source
  path" means. A source directory added later under a new top-level name would not be
  covered until someone extends it — a name-shaped residue inside an otherwise
  shape-matching guard, and the honest weak point of the design.
- Anchoring uses `parents[2]`, which encodes the `tests/unit/` depth. Moving the file
  changes the required index silently. A `pytest` `rootdir` fixture would be
  sturdier; I judged the added indirection not worth it for two call sites, but that
  is a defensible finding.
