# DEF048 — audit lane (architect)

**Item:** DEF048 — `POST /v1/onboarding/readback/confirm` with `confirm: "edit"` applied the edits
to `session.answers` and **persisted them before raising `501 Not Implemented`** — a client told
the call failed had actually already had its session mutated underneath it (an atomicity bug). CR004
Plan-A audit finding #6. Register: [`docs/defect/def_list.md`](../../../docs/defect/def_list.md) DEF048.

**depends-on:** none. (Shares commit `fd0ab6f` with DEF047; independent concerns audited separately.)

**Head SHA:** `fd0ab6f`

## What changed / why

| Piece | Change |
|---|---|
| backend | `app/api/onboarding.py` — the `confirm == "edit"` branch now raises the `501` **before** touching session state. Previously it looped `session.answers[k] = v` and `await store.save(session)` first, then raised — so the "this failed, restart" 501 left a half-edited session behind. |

## Scope honesty (why "hide the option" was already true)

The audit's suggested disposition was "schedule the edit flow or hide the option." Mobile **never
calls this path** — the readback screen (`onboarding_screen.dart::_readbackControls`) only offers a
single confirm button, no edit UI — so "hidden" was already the case. The real, latent bug found
alongside it is the pre-raise mutation; that's what this fixes. **Building the actual edit flow
stays a future CR**, not part of this defect.

## Tests run (self-test)

- `pytest backend/tests/unit/ -q` → full suite green (585 at this commit; 587 by end of session).
