### MAJOR-1 — `liquid_only` cannot refuse any real microcap: the only names it measures are the S&P 500

`resolve_liquidity` returns EXCLUDED only for a ticker with a market cap or volume reading in the
snapshot. The snapshot's liquidity maps are filled in the same classify pass as `sectors`, over
`_parent_universe_to_classify()`, which is *"the ~503 S&P parent constituents"*
(`classification_universe.py:333-347`). Every S&P 500 member sits far above both a $500M cap
floor and a $1M/day volume floor. Every microcap is outside the set, resolves UNKNOWN, and
UNKNOWN is permitted (`liquidity.py`, `is_blocking` is EXCLUDED-only). So EXCLUDED cannot be
reached for any real ticker.

**Measured on live data, read-only:**

```
sharia_universe_snapshots (latest, 2026-09-24): parent = 503 tickers   (the only names liquidity is ever measured for)
ticker_reference: 13,246 active tradable symbols; 12,743 (96%) are NOT in that parent set
  e.g. GNS  (Genius Group, NYSE American)  active, in_sp=false
       SNDL, CLOV, BBAI, SIRI                active, in_sp=false        AAPL  in_sp=true
```

**Driven end to end through the real `SimEngine.submit`**, with `liquid_only=ON` and a fresh,
non-stale universe in the only shape production can build (liquidity maps keyed by S&P names):

```
PROBE real microcap, prod-shaped universe:        GNS  accepted=True  blocked_by=None        liquidity=unknown   advisories=[]
PROBE fixture microcap placed IN the map (lane):  NANO accepted=False blocked_by=compliance  liquidity=excluded  advisories=[]
```

The lane's 25 tests pass because the fixture puts a fictional microcap (`NANO`, cap 120) *inside*
the market-cap map (`test_def417_liquid_only_enforcement.py:48`). The refresh can never produce
that state. The design doc does name UNKNOWN for "outside the ~503-name classified universe"
(`:91,96`). It never states the consequence: every name that could fail the filter is outside
that set.

Ruling 1 was given on the premise that microcap buys would be refused. They are not, for any
ticker a user can actually type. The promotion summary told Saiful that *"buys of stocks worth
under $500M or trading under $1M a day are now blocked."* The safety floor still does not
enforce `liquid_only` for any real ticker. That is the defect as filed, now with a green test
file and a user-facing claim that it is fixed.

**Fix:** needs a data source for the names that can actually fail the filter. The most direct
option is an on-demand, daily-cached `yf.Ticker(t).info` read of `marketCap` / `averageVolume`
at floor time, for a buy of a ticker outside the snapshot. The sim already prices every trade
live. Failing that, this is a product call. Re-ask Saiful with the coverage fact (12,743 of
13,246 tradable symbols unmeasured). The other two options are both worse:
- block-unless-measured is the DEF059 inversion, refusing 96% of symbols by default;
- disclose-only would be honest, but it is not what ruling 1 says.

Add a test whose universe is S&P-only and whose ticker is outside it.

### MAJOR-2 — the "permitted + disclosed" UNKNOWN verdict is not disclosed anywhere a user can see

UNKNOWN is neither `is_blocking` nor `is_disclosed_pause`: `is_disclosed_pause` is
UNAVAILABLE-only (`liquidity.py:148-152`). The branch at `safety_floor.py:430-434` therefore
adds it to neither `violations` nor `advisories`. The verdict does travel on the wire as
`compliance.liquidity_verdict` (`api/sim.py:942-944`). The app never reads it: there are zero
occurrences of `liquidity` under `mobile/lib`. The GNS probe above confirms it: `advisories=[]`.

The lane test `test_unknown_is_permitted_with_disclosure_not_blocked` asserts that
`message()` *contains* "hasn't measured". It never asserts that the message reaches
`advisories` or the client.

Taken with MAJOR-1, this is the case CLAUDE.md's degrade-loudly rule asks about: *"if this fires
constantly and silently, what does the user end up believing?"* It fires on 96% of tradable
symbols. A user with `liquid_only` ON, the default, believes microcaps are being refused. They
are being bought without a word.

**Fix:** append the UNKNOWN message to `advisories`, the way UNAVAILABLE already is, so the trade
ticket shows it. Assert the delivery in a test.

### Verdict

The mechanism is sound and correctly wired on four of five sites. Ruling 3 is met, and ruling 2
is met for outages. But the goal of the defect, a structural refusal of microcap buys, is not
achieved for any real ticker. The filter only measures S&P 500 names, and 96% of tradable
symbols fall through as UNKNOWN, which is permitted and never shown to the user. A user with the
default mandate believes they are protected when nothing has been checked.
