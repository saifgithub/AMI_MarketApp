### What I checked, and how

The submission is unusually honest: it named six gaps in its own evidence rather than
defending them. I attacked all six. **Five resolve in the builder's favour** — the
submission was more modest than the code deserved. The sixth is a real defect, and the
submission pointed me at the right test while getting the shape of the problem wrong.

#### 1. The D-5 guard — MINOR-1, the one real finding

The submission's top-priority ask: does `test_d5_flag_off_replays_byte_identical` actually
diff bytes, or something looser? **Neither, exactly.** It compares a hand-enumerated dict
built by `_portfolio_fields` (`test_cr222_training_toll.py:115`). The test *name* overstates
("byte_identical"); the module docstring is honest and says "FIELD BY FIELD".

The guard is genuinely load-bearing — I mutated the `toll_off` fixture to `True` and
**6 tests caught it**, the D-5 guard among them:

```
test_d5_flag_off_replays_byte_identical                         FAILED
test_d5_flag_off_leaves_the_submit_response_field_null          FAILED
test_an_option_structure_carries_no_toll_with_the_flag_off      FAILED
test_a_short_open_is_unchanged_with_the_flag_off                FAILED
test_build_toll_returns_no_block_at_all_with_the_flag_off       FAILED
test_twin_output_is_byte_identical_to_slice_b_with_the_toll_off FAILED
6 failed, 25 passed
```

(Fixture restored; worktree re-verified clean.)

**But its comparator cannot run on a book that holds a short, and under-covers options.**
`_portfolio_fields` reads `s.collateral_posted` on every short leg — a field `ShortLeg` does
not have. Measured against the worktree's own sources:

```
ShortLeg  real       : cash_posted, entry_price, id, opened_at, quantity, ticker
ShortLeg  compared   : cash_posted, collateral_posted, entry_price, quantity, ticker
  compared-but-absent: ['collateral_posted']      <-- AttributeError
OptionLeg real       : 14 fields
OptionLeg compared   : avg_premium, collateral_posted, occ_symbol, quantity
  present-but-uncompared: days_to_expiry, expiry, id, multiplier, opened_at, right,
                          strategy_id, strategy_name, strike, underlying
```

Driven, not read — a probe that first asserted its own setup landed (`len(p.shorts) == 1`,
with `sim_short_opened` in the log), then called the guard's own comparator:

```
AttributeError: 'ShortLeg' object has no attribute 'collateral_posted'
```

It has never fired in CI because `_portfolio_fields` has exactly one caller — the D-5 guard
at `:169-171` — and that guard's `_replay` does equity buys/sells only. So:

- the short branch is **dead code**: the guard can never run on a short-carrying book;
- `test_a_short_open_is_unchanged_with_the_flag_off` (`:403`) is the flag-off short guard,
  and it uses narrow hand-written assertions — exactly what the whole-object comparison was
  designed to be better than;
- for options, `multiplier` is **load-bearing in toll arithmetic**
  (`premium_notional` = `Σ |quantity| × multiplier × premium`) and is uncompared.

The docstring's claim — "compared as ONE dict so a leak into a field nobody thought to name
still fails this" — therefore holds for equity-only books and not for the two instrument
classes this slice actually touches.

Not a money-path break: the toll is flag-off in production, no charge can occur, and the
narrow short/option assertions do pass. It is a guard that reads stronger than it is.

#### 2. Rate parity with the game lane — MINOR-2

`training_toll.py:14` states the toll "deliberately matches `games_scoring.FEE_BPS`/`FEE_MIN`
— the two lanes should not disagree about what a round trip costs." The defaults do agree
today (10.0 / 1.00 both sides). **Nothing enforces it.**

The toll reads settings (`training_toll_bps`, `training_toll_min`); `games_scoring` uses
module constants (`FEE_BPS = 10.0`, `FEE_MIN = 1.00`). Two independently-editable copies of
one fact, and the toll's half is env-driven in production:

```
docker-compose.yml:492   TRAINING_TOLL_BPS: ${TRAINING_TOLL_BPS:-10.0}
docker-compose.yml:493   TRAINING_TOLL_MIN: ${TRAINING_TOLL_MIN:-1.0}
```

No test asserts the two agree (`grep FEE_BPS tests/unit/test_cr222_training_toll.py` → empty).
One env var silently produces the divergence the docstring exists to prevent. House rule:
*an entry without an enforcing check is not done.*

#### 3–6. The submission's other four gaps — all resolve in the builder's favour

- **NULL never coerced to 0.0 per row.** `cumulative_toll_for` does `float(value or 0.0)`,
  but that coerces a SQL `SUM()` over *zero matching rows*, not a row's missing toll. Per-row
  NULL is preserved. Migration confirms it structurally: three additive `Numeric(12,2)`
  nullable columns, **no `server_default`**, reversible downgrade; ORM declarations at
  `models.py:622/2443/2581` match exactly. The docstring's reasoning — a `server_default='0'`
  would be "a backfill of amounts wearing a default's clothes" — is right and is enforced,
  not merely stated.
- **§F3 disclosure swap.** Already driven both ways, and better than a server flip would be:
  `test_the_standing_disclosure_stops_saying_nothing_is_charged` (`:672`) asserts the false
  sentence is **gone** and the true one **appears**, against the shipping renderer and the
  shipping validator. The swap is a structural ternary at `portfolio_finding.py:515-520`
  keyed on `isinstance(context.get("toll"), dict)` — a branch, not a prompt instruction
  (CR038). Both tests green. The "not driven live" caveat was unnecessary.
- **Forced-close / game-fill pays nothing.** The carve-out is real, and is the opt-in the
  submission guessed at: `_execute_fill(toll: float | None = None)` (`sim_engine.py:1563`),
  three call sites, and the game site (`:2174`) passes `fee=fee` with **no** `toll=`. The
  game lane's Amendment-D fee therefore cannot reach the toll column. One note: the default
  is `None`, so this is opt-in, not the "every caller obliged to supply one" discipline the
  submission claimed CR194 used — the property holds, the characterisation is loose.
- **Shorts/options not double-charged.** `test_a_short_open_is_not_charged_twice_by_the_two_toll_sites`
  (`:370`) is well-built: it catches the double-charge in the **balance**, the only place it
  is visible (both amounts are equal, so `result.toll_charged` cannot show it), and asserts
  the `-4.00` case is false. Passive-twin symmetry is covered on **both** halves —
  `test_the_twin_deposit_buy_pays_the_toll_when_the_flag_is_on` (`:767`) is the flag-on half
  the submission believed untested.

### Verdict

MINOR-1 and MINOR-2 are both guard-quality findings on a code path that cannot charge anyone
today (flag defaults `False`, and Alpha runs the default). Neither is a defect in the toll
arithmetic, the NULL contract, the disclosure swap, or the lane separation — all four of which
I attacked directly and found sound. The slice does what it says it does.

Both findings should be fixed before `TRAINING_TOLL_ENABLED` is ever flipped on, because
MINOR-1 removes the safety net precisely for shorts and options, and MINOR-2 lets the two
lanes disagree silently about the cost of a round trip.
