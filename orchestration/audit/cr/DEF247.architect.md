# DEF247 — audit submission (architect → auditor)

## The defect, and how it was found

Found by the **post-promotion re-measure of DEF241/DEF243** — the acceptance
those rows said they owed. 3 tickers × 12 agents against live Alpha
(`cr143-postpromo-smoke-20260809`), then the shipped `parse_stance_envelope`
run over the stored `response_text`. **3 of 9 debator turns came back with the
raw machine channel still in the prose AND a null stance:**

```
I'd argue for smaller sizing

[STANCE: against | CONVICTION: medium | HEADLINE: 0.09pt portfolio-drawdown contribution]

- **Size Cap:** Restrict entry to **1.5%** of portfolio …
```

The user reads that bracketed line verbatim inside what CR106 calls a
quotation, and the comb simultaneously draws that agent in the §3.4 "did not
state a view" gutter — while its stated view sits two lines above. That is
precisely the pair DEF147 split this mechanism in two to prevent. The split
worked on the axis it was made on (one regex → FIND/STRIP loose, PARSE strict).
It left a second coupling nobody named: **both jobs still hung off the same two
candidate positions**, `filled[0]` and `filled[-1]`. One conversational opener
ahead of the envelope displaces it off the front while real prose runs past it
off the back; `_STANCE_TAIL_RE` is `\Z`-anchored and does not catch it either;
the function returns the text unchanged.

Not a DEF243 regression. The `Open with:` line DEF243 removed is gone — `grep
-i "open with"` over the three debator prompts returns nothing, and the
deployed bytes hash identical to `main`. The model writes the opener anyway.

## The part to attack first: I reversed a DEF147 test

`test_a_stance_line_mid_argument_is_prose_not_the_machine_channel` asserted the
exact opposite of this fix, on the reasoning *"an agent quoting the format
mid-paragraph is writing prose about it"*. I flipped it, renamed it
`…_is_the_machine_channel_after_all`, and put the measurement above in its
docstring.

I want this challenged, because "the fix required deleting the test that said
not to" is the shape of a bad change. My case: the old assertion was a
**hypothesis with no corpus behind it** — 11,057 turns, zero instances — while
the shape it excluded occurs at a measurable rate. The concern it encoded
(prose must not be eaten) is real, is not dropped, and is now carried by the
fixture that actually exercises it: a bracketed aside **inside a sentence**,
which `_STANCE_LINE_RE`'s `^` anchor excludes at every position. It was always
the anchor doing that work, never the position bound —
`test_only_a_trailing_envelope_is_read` (untouched, predates me) and DEF247's
`test_a_bracketed_aside_inside_a_sentence_is_still_prose` both hold it.

If you can produce a real turn where a whole line opening with `STANCE:` is
prose the user should read, the reversal is wrong and I will restore the bound
and find another way.

## The fix

`backend/app/services/room_runner.py` — the strip stops being positional:

```python
found = [i for i in filled if _STANCE_LINE_RE.match(lines[i])]
```

Front still wins (DEF147's ruling, unchanged). `_STANCE_TAIL_RE` untouched, so
the legacy inline-tail form still parses. Two additions beyond the one-liner,
both deliberate:

1. `re.sub(r"\n{3,}", "\n\n", body)` — removing an interior line puts its two
   flanking blanks back to back, which the user reads as a hole in the argument.
2. `room_stance_envelope_displaced`, its own log key, fired only when the
   envelope is not on the first non-blank line. **This fix makes the failure
   harmless, and a harmless failure that stops being counted is how a ~30%
   instruction-following rate becomes invisible.** DEF147 decoupled these jobs
   so one could absorb a failure while another still counted it; this is the
   counter. It is also live evidence for CR143 Phase 4b's model arm, which is
   the only thing that can actually fix the emission side.

## What I did not do

- **Did not touch the prompts.** `_STANCE_FORMAT` already says *"your VERY
  FIRST line must be this one line… with your prose starting on the line after
  it"*. There is no ambiguity left to remove, and CR038 says another emphatic
  sentence buys ~30%. The emission rate is tagged **model-ceiling**.
- **Did not claim a fixed rate.** 3/9 is an existence proof. A 32-ticker
  baseline batch (`cr143-def247-baseline-20260810`) is running against Alpha
  **on the unfixed code as I write this**, deliberately — promoting the fix
  first would destroy the baseline. The before/after goes on the row when it
  lands.
- **Did not write a prose guard.** Three audit rounds on DEF244/245 established
  that a lexical pattern over generated text is not a control. The regression
  here is nine real turns frozen verbatim in
  `tests/unit/fixtures/def247_debator_turns.json` — the three that leaked and
  the six that did not, because a fix that strips more must not start stripping
  what was already right.

## Where else to attack

- The `\n{3,}` collapse runs on every turn that carries an envelope, including
  ones that were already correct. Is there a turn whose meaning depends on
  three consecutive newlines? I believe not — markdown has no such construct —
  but it is the one thing here that touches output the defect never affected.
- `found[0] != filled[0]` treats "envelope on the last line, nothing before it"
  as displaced. That is the legacy trailing form, which the prompt no longer
  asks for; I think logging it is correct, but it does inflate the counter with
  a shape DEF147 knowingly still accepts.
- The six previously-correct turns are asserted unchanged via a reconstruction
  (`splitlines()[1:]`) rather than a stored expected-output. If that
  reconstruction is wrong, the assertion is vacuous.
