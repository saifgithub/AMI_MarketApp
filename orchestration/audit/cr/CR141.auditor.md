## Acceptance 2 — NULL, never 0 — both paths checked, one real (non-gating) finding

**OpenAI-compatible path** (`_parse_openai_compatible_usage`): `cache_read =
usage.get("prompt_cache_hit_tokens"); if cache_read is None: ...
details.get("cached_tokens")` — no `or 0` anywhere, confirmed by reading the
function directly. Verified DeepSeek's actual field name against their own
API docs: `prompt_cache_hit_tokens` is correct, confirmed live from
`api-docs.deepseek.com`.

**Anthropic path** (`_capture_anthropic_message_start_usage`) — checked the
one thing the submission flagged as unverified. The two extraction lines are
plain `.get()` with no `or 0`, so absence and presence-as-real-zero both
resolve correctly regardless of which the wire actually sends.

**MINOR — the docstring's factual claim about the wire format is not quite
right, though it doesn't affect correctness.** It states Anthropic's API
*"always reports `cache_read_input_tokens` / `cache_creation_input_tokens`
(0 when caching wasn't used, never absent)."* I checked this against
Anthropic's own current streaming docs
(`platform.claude.com/docs/en/build-with-claude/streaming`), which publish
three `message_start` example payloads side by side: the basic text example
and the tool-use example both omit `cache_creation_input_tokens`/
`cache_read_input_tokens` from `usage` entirely; only the web-search-tool
example includes them, as explicit `0`. So the fields are **not always
present** — the assumption in the comment is empirically wrong for at least
two of Anthropic's own three documented shapes.

This does **not** break acceptance 2: `.get()` on a genuinely absent key
already returns `None`, which is the correct NULL outcome either way — the
code is accidentally-but-correctly robust to the comment's own inaccuracy.
What it does mean is that in practice, for this app's actual agent-chat
calls (no `cache_control` blocks, no tool-heavy Anthropic paths currently),
`cache_read_tokens`/`cache_write_tokens` will likely come back NULL far more
often than the comment implies — which is still the honest signal ("no
measurement"), just for a more mundane reason ("the field wasn't in the
frame") than the one written down ("a malformed sub-object"). Worth a
one-line comment correction so the next reader isn't surprised by how often
NULL shows up on Alpha; not gating, since the actual behavior already meets
the acceptance criterion.
