## Known bug flagged, NOT fixed (out of scope, explicitly not silently dropped)

`JournalNotifier.refresh()` (`journal_providers.dart`, pre-existing, not this lane's file to redesign)
calls `state.copyWith(retentionDays: resp.retentionDays, ...)`. `copyWith` uses this codebase's
standard `x ?? this.x` null-coalescing pattern throughout. **If a user's plan changes from Floor Pass
(retentionDays: 30) to unlimited (retentionDays: null) mid-session and the Journal refetches, the
stale non-null value is never cleared** — `null ?? 30` evaluates to `30`, not `null`. This is a
pre-existing bug in a shared file (identical pattern already ships on the Journal screen itself), not
introduced by CR120, and not in CR120's §9 acceptance list. The new `retentionLoaded` field added by
this lane does not fix it — it only solves the *unloaded-vs-unlimited* ambiguity (D3), not this
separate *stale-after-plan-change* ambiguity. Fixing `copyWith`'s null-coalescing convention is a
larger, riskier change than this lane's scope; flagged here rather than fixed unilaterally.
