## But the whitelist fix does not close the general problem — found a second, structurally-related MAJOR

The round-1 fix narrowed the failure mode from "any nearby `$` fires" to "any
`$` reached via level-vocabulary fires" — but the whitelist is *itself* built
out of level-referring nouns (`high`, `low`, `resistance`, `support`, `zone`,
`floor`, `range`, ...) plus the prepositions that relate two of them
(`above`, `below`, `over`, `under`, `near`, `of`). Nothing requires the
captured `$` figure to belong to the **same** level the verb names — a
sentence that states **two different levels**, connected by exactly the
vocabulary the whitelist exists to allow, still fires and attributes the
second level's number to the first level's verb:

```python
>>> _direction_contradictions(
...   "It needs to recover to the prior high, above the recent low of $52.30.", 60.00)
[{'claim': 'recover to the prior high, above the recent low of $52.30',
  'level': 52.3, 'close': 60.0, 'gap_pct': 14.7, 'price_is': 'above'}]
```

The sentence explicitly names **two** levels and explicitly distinguishes
them — "the prior high" (what `recover to` actually targets, no `$` value
given here) is stated to be **above** "the recent low of $52.30" (a
different, lower reference point). The PM never claimed the price needs to
recover to $52.30; it said the opposite structurally — the real target is
higher than that number. Yet the check fires exactly as if `recover to`
named $52.30, and — because $60 is already above $52.30 — appends the same
`[AMI checked this instruction against the price: ...]` note in the same
voice as the genuine SNDK correction, asserting something the sentence did
not say.

**Not a fluke of one phrasing — confirmed the same shape fires with `above`,
`under`, and `below` as the sole connector (no `near`, which is the one
preposition in the whitelist that could plausibly be read as asserting
approximate identity between the two levels):**

```python
>>> _direction_contradictions("Recover to the prior high above the recent low of $52.30.", 60.0)
[{'level': 52.3, ...}]
>>> _direction_contradictions("Break above the resistance line under the 50-day high of $52.30.", 60.0)
[{'level': 52.3, ...}]
>>> _direction_contradictions("Reclaim the key level below the moving average of $52.30.", 60.0)
[{'level': 52.3, ...}]
```

All three explicitly assert the two levels are **different and ordered**
(`above`/`under`/`below` denote relative position, not proximity), and all
three still misattribute the second level's price to the first level's verb.

**This is not a new regression from this round's diff** — the same sentences
would also have false-fired under the round-1 distance cap, since they're
well within 45 characters with no second `$`. It's the same underlying gap
(nothing verifies the captured price is the verb's *own* referent, as
opposed to *a* level mentioned nearby) surfacing in a shape neither round's
test suite exercises: every existing "must fire" test names exactly one
level; every existing "must not fire" test uses a **non**-level object.
Nothing in either round's tests puts two distinct, explicitly-ordered levels
in one sentence — which is ordinary PM prose (comparing the target to a
nearby support/resistance/average as context is a completely normal thing
for a PM to narrate).

**Why I'm not also trying to relitigate the "near" case from my own earlier
exploration:** I did test a `near`-only chain too (*"recover to the 200-day
moving average near the 50-day low of $52.30"*) and it also fires — but
`near` in ordinary English usage genuinely does assert approximate
co-location, so treating that number as a reasonable stand-in for the target
is a defensible reading, not clearly wrong. I'm not filing that one. The
`above`/`under`/`below` cases above have no such defense: those words
explicitly assert the two levels are **not** the same, which is exactly the
grammatical distinction the whitelist fix was supposed to enforce and
doesn't.

**Severity.** Filing this as MAJOR, matching round 1's finding — same
failure class (a false, misleadingly-worded correction appended to
`verdict.reason`, the string CR106 renders as the decision's justification),
same reachability (ordinary PM prose, no synthetic setup, unconditional
insertion point), same cost your own code comment names. Additive-only, not
touching action/size/levels/safety floor, same as before.

**A narrower fix than another rewrite.** The whitelist correctly rejects
non-level vocabulary (round 1's fix). What it needs additionally is to stop
at the **first** level-noun/level-comparison boundary rather than chaining
through a second one — e.g. treat `above`/`below`/`over`/`under`/`near`
followed by an *article + level-noun* as the start of a **second**
level-reference and end the gap there (don't cross into it), rather than
including those same prepositions in the one contiguous vocabulary the verb
can reach through. Concretely: the prepositions that *relate two levels*
(`above`, `below`, `over`, `under`) are doing double duty in the current
whitelist — they're also the verb's own required-direction prepositions
(`recover ... above`, `break ... below`) elsewhere in this file. A same-gap
whitelist can't distinguish "the preposition that starts the verb's own
target phrase" from "the preposition that introduces a second, comparison
level" — which is the actual root cause both rounds share.
