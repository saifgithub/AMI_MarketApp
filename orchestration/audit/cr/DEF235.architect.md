## 0. What to attack hardest

1. **The deliberate behaviour change, which is the one thing here I am least
   sure about.** The old code reported the drawdown of *the size the agent
   narrated*. The new code reports the drawdown of *the mandate's single-name
   cap*, always. Where an agent narrates a size above the cap these differ, and
   the annotation can now sit beside a sentence stating a different number.
   The SCHD fixture is exactly this: the Trader writes *"Size: 10% of
   portfolio"* against a 3.0% cap, and the figure moves 0.96 pt → 0.29 pt.

   My argument: 0.96 pt describes a position the safety floor would never let
   through (`enforce_safety_floor` clamps to the same
   `resolved_single_name_cap_pct`), so the old figure was *also* wrong on that
   turn — just not visibly. And the label now names its own basis
   (*"at the mandate's 3.0% single-name cap"*), so the sentence is not claiming
   to be the agent's number.

   The opposite call is defensible: annotate the narrated size and flag the
   divergence instead, so the user sees the agent overreached. If you think
   that is right, say so — it is a bounded change.

2. **A mandate with a 100.0% cap makes the new figure large and loud.** 6 of 18
   prompts in the epoch carry `Single-name position-size cap: 100.0%`. At a 6%
   stop the annotation would read *"drawdown contribution ≈ 6.00 pt at the
   mandate's 100.0% single-name cap"* — correct arithmetic, correctly
   labelled, and possibly alarming. I did not add a ceiling on the rendered
   figure because a cap on a *reported* number is how you get a second DEF235.
   Push on whether that reads as intended on the Verdict Board.

3. **I removed a pattern rather than tightening it, against this row's own
   filed fix direction.** The row originally proposed requiring a `%` and
   excluding numbers already captured by entry/stop/target. I judged that a
   patched prose parse for a number the run already holds is one unanticipated
   phrasing from the next misfire — the DEF234 shape. If you think the
   narrated size carries information the cap does not, that judgment is the
   thing to break.

4. **The three surviving patterns are untouched and still depend on a format
   `_PROSE_FORMAT` forbids.** entry/stop/target keep the same label-anchored
   shape. I argue they are not the same risk class (a mis-parse cannot silently
   rescale a figure — the triple must form a valid long setup before anything
   renders) but I have not proven that exhaustively. The underlying
   format-vs-parser conflict is DEF236 and stays open.

## 1. The defect

Live Alpha, ANET convene, 2026-08-07 epoch. The Neutral Debator wrote:

> a **MEDIUM** size entry at **$188.62** with a tight **6.0%** stop at **$177.30**

`_LEVEL_PATTERNS["size"]` was `\bsize\b[^\n$0-9]{0,15}\$?\s*(\d+(?:\.\d+)?)\s*%?`
— the label as a whole word, then any number within 15 digit-free characters.
Here the next words are *"entry at $188.62"*, so `size` and `entry` both
returned `188.62`. `drawdown_contribution(188.62, 188.62, 177.30)` = **11.32 pt**,
appended as:

> [AMI verified the trade geometry from the stated levels (entry $188.62 / stop
> $177.30 / target $238.63): R:R 4.4:1; 26.5% upside vs 6.0% downside; drawdown
> contribution ≈ 11.32 pt — the proposal stated no R:R, so AMI rendered it.
> These are the figures of record.]

True figure at the mandate's 3.0% cap: **0.18 pt**. A 63× overstatement against
a 30 pt portfolio cap, under AMI's loudest authority claim.

This is DEF066 reintroduced through the parser rather than the formula. DEF066
was a ~20× drawdown-unit overstatement that made the Room refuse 16 of 64
Street-Buy names; CR046's fix — compute it in Python, hand the agent the result
— is exactly the code that fired here, on a mis-parsed input.

## 2. The fix

- `_LEVEL_PATTERNS["size"]` **deleted**. `_match_level(text, "size")` gone.
- `_verify_and_annotate_geometry(text, *, size_pct: float | None = None)`.
- Call site (`room_runner.py`, in `_compute_agent_text`) passes
  `size_pct=ctx.trader_size_pct`, set once per run by
  `_risk_tier_size_ceiling(mandate)` → `resolved_single_name_cap_pct` — the same
  resolver `enforce_safety_floor` clamps to and the Trader's prompt narrates.
- Omitting `size_pct` renders R:R and asymmetry but **no drawdown figure**.
  Honest degradation: with no cap there is no such number.
- The clause names its provenance:
  `drawdown contribution ≈ 0.18 pt at the mandate's 3.0% single-name cap`.

The `_LEVEL_PATTERNS` comment block was rewritten. It previously carried a
CR144 "what structured field could this have read instead?" note that named
`ctx.trader_size_pct` as the answer and explicitly deferred acting on it to
this defect. That deferral is now cashed in and the comment records it.
