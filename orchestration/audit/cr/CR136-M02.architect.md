## 1. What this is, and why it is in the audit lane at all

M02 is the arithmetic every user-visible number in CR136 is made of: one EWMA
covariance matrix and every second-moment quantity derived from it. Rev 4's
own risk class names M02 and M05 as the two modules wanting independent audit,
and the reason is asymmetric consequence — a wrong renderer produces a visibly
wrong report, while a wrong estimator produces a plausible one.

Scope of the module, all pure and stdlib-only:

| Function | Contract |
|---|---|
| `ewma_covariance(returns, lam=0.97)` | weighted-demeaned, population style, no dof correction; rows = assets, cols = time, newest last; raises on ragged input |
| `t_eff(lam, t)` | `1/Σwⱼ²` of the normalised truncated weights — the direct sum, deliberately not the closed form |
| `portfolio_sigma`, `euler_contributions`, `mcr`, `dr_squared` | `√(wᵀΣw)`, `wᵢ(Σw)ᵢ/σₚ²`, `(Σw)ᵢ/σₚ`, `((Σwᵢσᵢ)/σₚ)²` |
| `beta_r2(w, cov, b_index)` | joint-matrix form; **requires `w[b_index] == 0.0` exactly** |
| `tracking_error(σₚ, σ_b, β)` | `√(σₚ² + σ_b² − 2βσ_b²)`, PSD-dust clamped |
| `hhi_effective_n`, `bad_month`, `se_sigma`, `se_beta`, `append_zero_row`, `annualize_vol`, `scenario_replay` | per Rev 4 §"Estimator API" |

`trading_math/`'s package contract is stdlib-only, pure, copy-portable, no app
imports. **numpy is not a runtime or test dependency**: the known-answer
fixtures were precomputed offline against an independent numpy implementation
and are checked in as literals (`cr136_generate_fixtures.py` regenerates them
but is never imported by tests).

## 2. The load-bearing decisions, and what argues for them

Each of these is a place where the obvious implementation is wrong in a way
that would not be visible in the output.

1. **λ = 0.97 EWMA, not a rectangular window.** A rectangular window produces a
   roll-off echo: measured, the reported figure drops **2.9pp discontinuously**
   on the day an old shock leaves the window — ~50× the median daily change —
   for a reason with nothing to do with the portfolio. EWMA responds at the
   event (half-life 22.8 days; exit-day change 0.03pp). The measured cost is
   disclosed rather than hidden: single-report detection of a newly correlated
   cluster is 82.1% against a rectangular window's 89.0%.
2. **`se_sigma` takes `t_eff`, not `T`, and takes no raw count at all.** Under
   exponential weights the equal-weight formula `σ̂/√(2T)` understates the true
   sampling SE by **~27%** (1.72pp true vs 1.26pp naive at σ=20%). The
   signature makes the wrong formula unreachable by passing the wrong argument.
3. **Weights normalise over the AVAILABLE window**, not against the infinite
   sum `1/(1−λ)`. On a short series the infinite-sum denominator does not sum
   to 1, which silently biases every moment.
4. **`beta_r2` is the joint-matrix form and hard-requires `w[b_index] == 0.0`.**
   The benchmark is an estimation leg, never a holding; a non-zero weight there
   folds the benchmark into the portfolio being compared with it. Rev 4 defines
   β as `Cov_w(p,b)/Var_w(b)` *from the same Σ* precisely so the two sides
   cannot come from different windows.
5. **`t_eff` is the direct sum, not the closed form** `(1+λ)/(1−λ)·(1−λᵗ)/(1+λᵗ)`.
   The closed form is the test's independent check — a formula that checks
   itself checks nothing.
6. **Cash is appended as an exact zero row AFTER estimation** (`append_zero_row`),
   which makes its effect exact rather than approximate: it scales σₚ and β by
   exactly `(1−c)` and leaves risk shares, DR² and R² exactly invariant.
7. **Population style, no dof correction.** There is no single agreed
   `1/(1−Σw²)` form under exponential weights, and the known-answer fixtures
   define exactness.

## 3. Round-1 findings already fixed (`df01c94d`)

Eight, from this repo's own adversarial pass. The three worth the auditor's
attention:

- **Module-wide non-finite screen.** `ewma_covariance` validated its inputs;
  the derived functions did not, so a NaN could enter through `w` and leave as
  a plausible number.
- **`se_beta`'s clamp was unbounded** in one direction, which could publish an
  SE tighter than the estimator supports — the same failure class as #2 above,
  one layer down.
- **The fixture generator was not estimating what the fixtures claimed.** A
  fixture that agrees with the implementation because both compute the same
  wrong thing is worth nothing; the generator now runs the independent path.

## 8. Addendum — findings from the M11 audit, folded in before this lane is delivered

**The cross-check harness in §6 was reading rows the engine excludes.**
`_load_closes()` selected every `price_history_daily` row for a ticker, while
the engine's own read path filters `source != 'mock_walk'` in real mode
(`price_history._load_rows`, and `latest_trading_day` likewise). A table holding
both real and fabricated bars — a state this codebase explicitly anticipates and
has M01 tests for — would have had the harness recomputing from prices the live
engine correctly refused, and reporting a FAIL against an engine that was right.
That is not an independent check; it is a different question asked of different
data.

Fixed: the harness applies the same filter, and prints a loud per-ticker count
of any mock-source rows it skipped — the comparison stays valid, but a book
being priced off a partially-fabricated table is something the operator should
know before trusting a PASS.

**A caveat on the "2238 full-suite green" figure in §4.** The audit found that
`test_cr136_health_gate.py::test_the_daily_cap_applies_in_every_mode` seeded its
fixtures off the live wall clock, so for roughly eleven minutes a day
immediately after UTC midnight those rows landed on *yesterday* and three tests
failed at a SHA where nothing was wrong. The §4 measurement was taken outside
that window and was accurate; the claim was nonetheless conditionally true,
which is not the standard this CR sets. Fixed — the fixtures now clamp to the
start of the UTC day.

## 9. What I would attack if I were the auditor

Offered because a submission that only argues its own case wastes the lane:

1. **The fixtures.** They are literals. Regenerate a subset with your own numpy
   and check the generator is not the same code path as the implementation.
2. **`beta_r2`'s `w[b_index] == 0.0` exact check** — float equality is
   deliberate here (the caller constructs the zero), but it is the kind of
   guard that gets "helpfully" loosened to a tolerance later.
3. **PSD-dust clamps** in `_variance` and `tracking_error`: confirm the
   thresholds cannot swallow a genuinely negative variance from a malformed Σ.
4. **`t_eff` on a very short series** (T = 1, T = 2) — `ewma_covariance`
   documents the all-zero matrix at T = 1 as the formula's own output, and M04
   owns the T ≥ 126 floor. Check the seam holds from both sides.
