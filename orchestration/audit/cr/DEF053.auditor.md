## OUT-OF-SCOPE (recommendations — not blocking DEF053)

Both share one root cause: `_num()` (fundamentals.py:103) returns `float(v)` without a
finiteness check, so a NaN yfinance value passes through as `nan` rather than `None`.

1. **In-scope minor — "nan" can render in the fundamentals block.** yfinance's `info`
   returns `NaN` (not `None`) for some multiples (esp. `pegRatio`/`priceToSales`/
   `enterpriseToEbitda` on unprofitable/pre-revenue tickers). DEF053's new fields then
   format to the literal string `"nan"` (`f"{nan:.1f}"`), and the room_prompts helpers'
   truthiness checks (`if profile.get("price_to_sales")`) pass a non-empty `"nan"` →
   "P/S nanx" reaches the prompt. No crash; a truthfulness fix rendering "nan" as a
   value is mildly self-defeating. Reproduced at the formatting level.
2. **Pre-existing crash (same class as DEF052 F1) — recommend a companion fix/DEF.**
   `fetch_live_fundamentals`'s PRE-EXISTING lines `round(rev_growth*100)`,
   `round(profit_margin*100)`, `round((total_cash-total_debt)/1e6)` use `round()`
   **without** ndigits — `round(nan)` raises `ValueError` (reproduced), outside the
   fetch's try/except, so a NaN `revenueGrowth`/`profitMargins`/`totalCash` would fail
   the Room Convene exactly like DEF052 F1. Not introduced by DEF053, but a single
   `math.isfinite` guard in `_num` closes **both** #1 and #2. Recommend the architect
   fold it into DEF052's round-2 fix or mint a companion DEF.
