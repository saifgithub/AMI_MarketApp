### The requirement: a production build can never skip a tour. Holds, two gates deep.

1. **The flag never reaches a shipping script.** `AMI_QA_SKIP_TOURS` does not appear in
   `build_testflight.sh`, `build_playstore.sh`, `publish_playstore.sh`, `install_iphone.sh` or
   `install_android.sh`. None of them has a generic define passthrough (`--dart-define-from-file`,
   `$EXTRA_*`, `"$@"` into `flutter build`) that could carry it. Only `build_qa_ios_sim.sh`
   forwards it.
2. **Even if forwarded, production refuses it.** `TourQaConfig.resolve` returns `false` for
   `channel == production` (`tour_qa_config.dart:67-79`). The channel is derived only by the two
   store scripts, from `--production` or the shared `RELEASE_CHANNEL=production` (see CR225-226).

The choke point covers every tour. All six `markSeen` call sites across the five screens are
behind `if (await service.hasSeen(...)) return;` on the line before (floor ×2, journal, lessons,
portfolio, you). The QA flag therefore never writes a `tour_*_seen` key, and the CR180 nav-change
precondition stays false (§5 checked, `journal_screen.dart` included). `tourServiceProvider` is the
only production constructor (`tour_providers.dart:12`), with no override (§4).

### MINOR-1 — for tester builds, the only gate is the absence of one line from two scripts, and nothing enforces it (§6)

TestFlight and Play builds for testers are channel `internal`, and `resolve` honours the skip
there by design. So for every build real testers install, gate 2 does not apply. The protection is
gate 1 alone: `AMI_QA_SKIP_TOURS` is not in the store scripts' define list. That is verified by
grep today and asserted by nothing. If someone forwards it to get a UAT run through on a TestFlight
build, every tester would silently lose onboarding tours, and CI would stay green.

The house rule is that a guard entry needs an enforcing check. **Fix:** add a structural test, in
the same shape as `test_config_compose_parity.py`, asserting that neither store script forwards
`AMI_QA_SKIP_TOURS`. Add a `failure_patterns.md` line for "QA-only dart-define reaching a shipping
script".
