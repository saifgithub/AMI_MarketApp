# CR232 — audit lane (persistent shell chrome across every pushed page)

**SCOPE:** cr

**TIER: B.** Mobile-only navigation/chrome refactor. There's no auth, billing, migration or compliance-perimeter change. The trade tickets' submit, destination and preview logic was moved into a page container but not changed (see Attack surface 4). A MAJOR finding raises it to Tier A.

**SHA:** `2f867925` (feature) + `4de818ef` (merge of `main`; conflict resolution below). Both are on `main`. Review with `git diff 4fb4f02f..2f867925 -- mobile/ docs/` for the feature, and `git show 4de818ef` for the merge.

**depends-on:** none. **Promoted:** no (mobile; ships in the next TestFlight/Play build after this verdict).

## What and why
Saiful, 2026-09-24: *"some of the pages are simply using an 'X' to exit the page (top right corner), and the 'X' is (a) obscure (b) is not in line with the rest of the application aesthetics … the bottom menu, the ad, and the ticker tape function should always be on every screen and page, and a more elegant way than the 'X'."*

**Root cause:** the nav and the ticker tape lived in `HomeShell`'s Scaffold, and every `Navigator.push` / `showModalBottomSheet` targeted the root navigator, so pushed pages covered the chrome.

**Rulings (verbatim in the CR doc):**
- Order is nav / ad / tape.
- Trade tickets become full pages with a back chevron and a Cancel action.
- Chrome hides only while the keyboard is open and during onboarding.
- Build now, before the external beta.

**Mid-build additions from the +108 TestFlight screenshots:**
- The ticket header rendered under the iOS status bar.
- The numeric keypad could not be dismissed.

## Changes
- **Tab navigators:** each tab has its own nested `Navigator` (a GlobalKey per `AmiTab`) inside the `IndexedStack`, so all 60 push sites now resolve to the tab navigator.
- **Chrome:** the chrome (`HexBottomNav` / `ShellBannerSlot` / `TickerTape`) is hidden when `viewInsets.bottom > 0`.
- **Back navigation:** `PopScope` makes Android back pop within the active tab. Re-tapping the active tab pops that tab to its root.
- **Ad slot:** `ShellBannerSlot` is a zero-height reservation for CR226.
- **Modal sheets:** 23 `showModalBottomSheet` sites now pass `useRootNavigator: false`.
- **Trade tickets:** both are now pages with `AmiScreenHeader` (back + Cancel), a `SafeArea` body, and tap/drag-to-dismiss for the keyboard.
- **Close buttons:** 3 full-page `Icons.close` exits were converted to back chevrons. 9 inline-dismiss uses were kept.
- **Guard:** structural test `mobile/test/exit_affordance_structural_test.dart` (P36 in failure_patterns.md) fails if a new `Icons.close` appears outside the allowlist.

**Merge `4de818ef`:** DEF415 (`f430764c`, on `main` after this branch's base) added an 11-line close button to each ticket. CR232 supersedes it, so I resolved both conflicts to CR232's side (`--ours`) and regenerated the registers.

## Attack surface (please probe)
1. **Wrong navigator:** any push from a context ABOVE the tab navigator. Examples: a dialog/overlay context, the one `rootNavigator: true` site in `bug_report_sheet.dart`, and deep links or notification taps that land a page on the root navigator and cover the chrome again.
2. **Tab switching:** state preservation across tab switches with a non-root stack, and `activeTabProvider` / DEF190 external tab writes while a tab has pushed pages.
3. **Android back:** at a tab's root it should exit or behave as before, not trap the user.
4. **Trade ticket logic:** the ticket's `_submit` / `_submitAlpacaOnly` / BOTH branch must be byte-identical apart from the container, because DEF419 edits them next. Also check whether the result/confirmation flows (the Room "convene" and "Proceed without" actions) still pop to the right place.
5. **Keyboard:** hiding the chrome while the keyboard is open should not cause layout jumps that hide a submit button.
6. **Guard evasion:** allowlist completeness, and whether an exit built with a different icon or widget evades the guard.

### MAJOR-1 — fixed

**File:line:** `mobile/lib/services/notifications/deep_link_dispatcher.dart:20-55,90-140` (route

`mobile/lib/screens/home_shell.dart:105-119,124,134,163` (`_HomeShellState` publishes/clears its

(`_handleOpenedLink` calls the new `dispatch`, queues on `deferred`, flushes via
`ref.listenManual(homeShellNavKeysProvider, ...)`), `mobile/lib/screens/notifications/notification_centre_screen.dart:149-160`
(same call updated to the new signature).

**Fix:** `dispatch` now switches `activeTabProvider` to the route's owning tab (DEF190's own
mechanism) and pushes on that tab's `GlobalKey<NavigatorState>` — read from
`homeShellNavKeysProvider`, which `_HomeShellState` publishes from its real (previously private)
`_navKeys` map via `addPostFrameCallback` in `initState`, and clears to `null` in `dispose`. A
`null` read (shell not mounted, or a tab's `Navigator` not yet attached this frame) returns
`DeepLinkDispatchResult.deferred` rather than falling back to the root navigator or dropping the
link; `PushNotificationListener` queues a deferred link and flushes it the moment the provider
publishes real keys.

**A caught bug during the fix, worth recording:** the first version of `_HomeShellState.dispose()`
called `ref.read(homeShellNavKeysProvider.notifier).state = null` directly. That throws `Bad
state: Cannot use "ref" after the widget was disposed` — `ConsumerStatefulElement.unmount()`
invalidates `ref` BEFORE calling the underlying `State.dispose()`. The uncaught exception aborted
the rest of that widget-tree unmount, which silently broke an unrelated sibling provider's own
`onDispose` (`telemetryProvider`'s flush-timer cancel), surfacing as 9 unrelated "Timer is still
pending" failures in `home_shell_test.dart` — a full-suite-only flake at first glance, reproduced
in isolation once traced. Fixed by capturing the `StateController` itself in `initState` (while
`ref` is still valid) and using that captured reference in `dispose`, never `ref` there. See the
doc comment on `_HomeShellState._navKeysController` in `home_shell.dart:105-119`.

**Test the auditor asked for — added and mutation-tested:**
`mobile/test/screens/notifications/push_notification_deep_link_chrome_test.dart`. Pumps the real
production shape — `MaterialApp(navigatorKey: appNavigatorKey)` → `PushNotificationListener` →
`BugResolutionToasts` → `HomeShell` — fires a `DeepLink` through a fake
`NotificationService.notificationOpened()` stream, and asserts the pushed `TickerDetailScreen`
lands as a `find.descendant(of: HomeShell, matching: TickerDetailScreen)` — the assertion that
actually distinguishes "pushed inside the tab, below the chrome" from "pushed on the root
navigator, covering it", since `find.byType` alone finds `HexBottomNav`/`TickerTape` either way
(`IndexedStack` never unmounts sibling panes) and a `getTopLeft`-based positional check (tried
first) is equally blind to occlusion — confirmed by mutation below.
