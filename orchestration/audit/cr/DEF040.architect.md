# DEF040 — audit lane (architect)

**Item:** DEF040 — league-standing correctness. Account merge re-keyed `reputation_events` and
summed lifetime `reputation` correctly, but did **not** recompute the adopter's current-week
`league_members.points` — a mid-week claim undercounted current-week league standing. Reopened
**CR004 audit finding F5**. Register: [`docs/defect/def_list.md`](../../../docs/defect/def_list.md) DEF040.

**depends-on:** DEF039 (both touch the reputation/league tables; DEF039 landed first).

**Head SHA:** `7ebc123`

## Root cause

The league-seat re-key (`_rekey_skipping_conflicts` on `LeagueMemberRow`, `conflict_col=week`)
**drops the orphan's `league_members` row outright** whenever both sides already hold a seat for
the current week — the common case (anon user plays, later claims an account that also has
activity). That silently discarded whatever the orphan earned this week, even though its
`reputation_events` rows (re-keyed just above it in the same pass) now belong to the adopter.

## What changed / why

| Piece | Change |
|---|---|
| service | `app/services/merge_service.py` — after the reputation re-key, if the adopter holds a current-week seat, **recompute** its `points` as a full resync: `sum(reputation_events.points)` over the current ISO week's bounds (`league_service.week_end()` − 7d → `week_end()`). A resync (not a delta-add) is correct regardless of which side's seat survived the re-key. New imports: `iso_week`, `week_end`, `_utcnow`. |

## Tests run (self-test)

- `pytest backend/tests/unit/ -q` → **587 passed**.
- New `test_merge_service.py::test_execute_recomputes_adopter_current_week_league_points_on_seat_conflict`:
  both sides hold a week seat; orphan earns 8 (lesson+room), adopter earns 3 (challenge_correct);
  post-merge the single surviving seat = adopter's with **`points == 11`** and the ledger sums to 11.
- **Adversarially confirmed the test is a real regression test**: `git stash` the fix →
  the new test fails at `assert 3 == 11` (adopter frozen at its own pre-merge 3); `stash pop`
  restores → passes. So the test genuinely pins the fix, not tautology.
