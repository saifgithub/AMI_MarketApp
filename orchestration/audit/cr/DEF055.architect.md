## What was done

`journal_context.py::build_journal_context_block()` (introduced in DEF054) is
called from both gate sites with **no Bear-specific code path** — the gate is
`agent_id in (AgentId.BULL_RESEARCHER, AgentId.BEAR_RESEARCHER)` at both
`room_prompts.py::build_room_messages()` and `agent_runner.py`'s 1-on-1 injection.
Bear gets the identical real, ticker-scoped journal history Bull gets — same
function, same formatting, same degradation behavior.

`content/agents/bear_researcher.md` rewritten identically to Bull's: "Historical
context from the Decision Journal" → explicit real, ticker-scoped framing, with
the same "say so, don't invent" instruction for a ticker with no history.

**`bear_size`/`bear_catalyst`/`bear_invalidator` hardcoded literals**: left
untouched, mirroring DEF054's disposition on `bull_size`/`bull_falsifier` —
explicitly deferred as a separate, lower-priority item.

## Why this is safe / minimal

- **Zero duplicated logic**: confirmed by inspection — there is no
  `bear_journal_context.py` or a second `fetch_recent_journal_entries`-shaped
  function anywhere. One shared helper, one set of edge cases handled once.
- **Bear's own gating explicitly tested**, not just inferred from Bull's tests
  passing: `test_bear_researcher_gets_journal_history_when_present` (Room level)
  and `test_journal_block_injected_for_bear_researcher_when_ticker_mentioned`
  (1-on-1 level) both seed real entries and assert they reach *Bear's* prompt
  specifically — proving the shared gate actually includes Bear, not just that
  Bull's path works and Bear was assumed symmetric.
