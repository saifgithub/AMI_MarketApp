## What was done

Additive-only wiring of 4 new BOK tracks across the 3 files coder.api owns for this lane:

1. **`backend/app/schemas/lessons.py`** — introduced `Track(str, Enum)` as the canonical set of valid track ids (7 existing values + 4 new BOK values). `LessonMeta.track` intentionally **stays typed as `str`** — this enum names the tracks, it does not (yet) validate on parse, so no already-authored MDX frontmatter changes its load path.
2. **`backend/app/services/lessons_service.py`** — extended `TRACK_TITLES` (added the 4 new display names: `"Asset Classes"`, `"Economics & Macro"`, `"Quantitative Methods"`, `"Ethics & Integrity"`) and `TRACK_PREFIX` (added the 4 frozen CR044 prefixes: `ASST` / `MACRO` / `QUANT` / `ETHIC`). Existing 7 rows in each map untouched.
3. **`backend/tests/unit/test_lesson_corpus_integrity.py`** — added 6 guards under a new "CR054 Wave 0: BOK track wiring" section:
   - `test_cr054_new_tracks_are_declared_in_the_track_enum` — each of the 4 tracks is present in the `Track` enum.
   - `test_cr054_new_tracks_have_display_names_and_prefixes` — each has BOTH a non-blank display name in `TRACK_TITLES` AND the expected CR044 prefix in `TRACK_PREFIX`.
   - `test_all_cr044_prefixes_are_unique` — whole-map uniqueness sweep so no prefix collides (catches the new 4 against each other and against the 7 existing).
   - `test_track_title_and_prefix_maps_have_matching_keys` — 1:1 key parity between `TRACK_TITLES` and `TRACK_PREFIX` (half-wired track = fail).
   - `test_track_enum_and_maps_cover_the_same_track_set` — `Track` enum ↔ both maps parity; an enum value without maps or a map key without enum both fail.
   - `test_cr054_new_tracks_are_empty_at_wave_0` — no lesson in the corpus already lands in the 4 new tracks (Wave-0 floor; Wave 1 fills them).

**Prefix choices** (frozen from this SHA forward, per CR044 rules): `ASST` (over the shorter `AST` — richer, harder to mishear against `AAPL`), `MACRO` (over `MAC` — the OS name), `QUANT` (unambiguous), `ETHIC` (over `ETH` — the ethereum ticker is common chatter). Documented inline in `TRACK_PREFIX`.

**Glossary category enum:** per spec §"In scope if trivial", checked whether a glossary category enum exists to extend in this file — none does in `schemas/lessons.py` (glossary categories live in `schemas/glossary.py`, out of the "edit ONLY these 3 files" cut for this lane). **Explicitly deferred** to a Wave-1 glossary lane (`noncoder.edu` owns the terms; category-enum wiring rides that lane).

## Why this is safe / minimal

- **Purely additive.** No existing `Track` value, `TRACK_TITLES` row, `TRACK_PREFIX` row, or MDX lesson file was renamed, reordered, or renumbered. `git diff --stat` for source: 3 files changed, 161 insertions, **0 deletions**. Grep-proof below.
- **`LessonMeta.track` stays `str`.** No behaviour change for `parse_mdx`; a lesson with a still-unknown track continues to load and render. The enum is a name-only source of truth today; typing the field is a later lane if we want it.
- **CR044 contiguity holds trivially for the new tracks** — 0 lessons in each, so the existing `test_lesson_codes_are_contiguous_within_each_track` guard has nothing to check for them and doesn't get to fail. Wave 1's first authored lesson in `asset_classes` becomes `ASST 1`, which the existing guards then enforce.
- **CR040 "degrade loudly."** A missing / duplicate / half-wired prefix now fails a build-time test (6 new guards), never a user's screen. Adding a `Track` enum value without wiring both maps fails `test_track_enum_and_maps_cover_the_same_track_set`. Adding a colliding prefix fails `test_all_cr044_prefixes_are_unique`.
- **AMI-by-name intact:** the 4 display names are all human-readable capitalised English, no "LLM" leakage into user-visible strings.
