## Adversarial angles worth probing

- Try constructing a `SectorAllocation` JSON where `max_sector_name` legitimately equals a real
  sector name but `allocation` has only `{"Other": 1.0}` — contradictory input the backend should
  never produce, but confirm the client doesn't crash or paint a false breach on it (currently:
  it would just render whatever string it's given as the legend/breach text — no special-case
  guard against a contradictory wire body; worth a call on whether that's acceptable given the
  backend already guarantees the invariant).
- Confirm `_LotStatusChip`'s three-way switch on `status` degrades sanely for a value outside the
  documented enum (falls into the `default:` "PARTIAL" case today) — a wire value like `"unknown"`
  would silently read as "partially_closed", which is a soft version of the exact defect class
  this CR closes. Flagged here, not fixed — the contract only documents three literal values, so
  this is a defensive-coding judgment call for the auditor/architect, not a contract violation.
