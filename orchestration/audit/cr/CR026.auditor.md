### A genuine test-coverage gap found by extending the architect's own methodology

The architect's adversarial check (FAIL-WITHOUT-FIX) only exercises the **pure**
`check_mandate_compliance`/`sector_cap_breach` functions directly, called with
hand-built `holdings`/`quotes`/`sector_map` arguments. I asked the next question:
does anything catch a regression that silently drops the **wiring** that supplies
those three arguments at each of the four real call sites?

- Mutated `sim_engine.py`'s `submit()` to drop `holdings=`/`quotes=`/`sector_map=`
  from its `check_mandate_compliance(...)` call → **full suite still 1262/1262 green.**
- Mutated `sim_engine.py`'s `preview()` the same way — same call-site pattern, and
  grepping confirms no test anywhere references `sector` for `SimEngine.preview`.
- Mutated **both** `room_runner.py` call sites simultaneously (the scripted
  `_assemble_verdict` path and the live-PM `enforce_safety_floor` path) → **full
  suite still 1262/1262 green.**

Grepped every test file for `_build_room_sector_context`/`sector_holdings`/
`sector_marks`/`ctx.sector_map` outside `test_cr026_sector_allocation.py` — zero
hits. The only test that calls `sim.submit()` at all
(`test_sector_allocation_endpoint_contract_and_ownership`'s `_engine_with_buy`
helper) submits a single-name Tech buy that never approaches the sector cap, so it
cannot detect a dropped wiring either.

**This is worse than a coverage gap alone — the failure direction is unsafe.** Block
6b is deliberately designed to skip enforcement when `sector_map`/`holdings`/`quotes`
are `None` (documented behavior, for backward-compat with legacy callers that don't
pass sector context — confirmed correct via `test_sector_check_is_skipped_without_sector_context`).
That means a future regression that silently drops any of the four wiring points
(e.g. a merge conflict, a refactor of `_RoomContext`, an accidental parameter drop)
would **silently disable the entire sector-concentration cap** for that surface —
not fail loud, not fail safe, just quietly stop enforcing a D-5 locked-decision
compliance rule — and the 1262-test suite would report all green. This is the
opposite failure direction from DEF061's analogous MINOR finding (where the dropped
wiring's `None` default resolved to `UNAVAILABLE`, which blocks) and from CR055's
Finding 1 (a weakened assertion, not a silently-skippable feature).

**Severity: MAJOR** (test-coverage gap, not a functional defect in the delivered
code — the wiring is correct today, verified above by reading every diff and by the
`sector_allocation` endpoint's own test exercising a real breach through the API
layer). Recommend a follow-up: one structural test per call site (mirroring CR055's
"any call site" pattern) asserting a genuinely sector-breaching trade is rejected
through `SimEngine.submit`/`SimEngine.preview` and through a `RoomRunner`-level
integration path, not just through the pure `check_mandate_compliance` function
directly.

All mutations reverted; final suite re-confirmed 1262/1262 clean.
