### The question this lane has to answer

The submission asks it itself: can any surface show a number the user doesn't have? Saiful's
question was "how does a user check how many credits they have left", so the balance each new
surface shows has to track what the user actually has after they spend.

### What holds

- **Unknown stays unknown.** Every new widget renders an explicit unknown state for a null
  balance or cost (DEF437), and the ad signals fail closed.
- **The post-Room line.** It shows a balance only once the post-`done` refresh has succeeded
  (`balanceAfter`), and says "This Room used N credits" until then. The row no longer watches
  `mandateNotifierProvider`, so the gate the architect asked about can't skip the refresh; the
  refresh lives in `room_providers.dart:367`, independent of rendering.
- **`refunded`.** It now comes from DEF432's shared `run_was_refunded`. `RoomStatus` has exactly
  five values (queued / running / completed / failed / cancelled), and cancelled correctly reports
  false.

### MAJOR-1 — the balance is refreshed only after a Room or a purchase, so the new composer line goes stale after the first paid turn

The mandate, which holds `creditBalance`, is refreshed in exactly three places in `mobile/lib`:
after a Room's `done` (`room_providers.dart:367`), after a purchase
(`purchase_providers.dart:100`), and by Settings' manual refresh (`settings_screen.dart:1114`).
A 1-on-1 turn costs `one_on_one_credit_cost` and a Brief turn costs `brief_credit_cost` (both 1
by default, `config.py`). Neither `one_on_one_providers.dart` nor `brief_providers.dart` refreshes
the mandate.

I measured it. The probe drove the real `OneOnOneNotifier.send()` through a completed reply,
with `mandateNotifierProvider` counting `refresh()` calls, starting balance 63:

```
PROBE reply=a paid reply refresh_calls_after_turn=0 balance_shown=63
```

So the line this CR adds to the 1-on-1 composer ("You have 63 credits") keeps saying 63 through
the whole conversation while each turn is billed. The same stale value feeds the Convene sheet's
"you have N" and the Settings row after any 1-on-1 or Brief. I established that by the grep
above, not a separate run. That is the "number the user doesn't have" the submission asks about,
on the surface built to answer Saiful's question.

**Fix direction:** refresh the mandate after each completed 1-on-1 and Brief turn, the same way
`room_providers.dart` does after `done` (and after a refunded failure too, so the refund shows).
Pin it with a notifier test like the probe: one send → one refresh.

### MINOR-1 — "this Room didn't reach a verdict" is wrong for the refunded CIO-outage PASS

`roomResultRefunded` reads "Not charged — this Room didn't reach a verdict". Since DEF432's
follow-up (`27da3d06`), `run_was_refunded` is also true for the DEF059 CIO-outage **PASS**. That
Room shows a PASS verdict and then, under it, "didn't reach a verdict". The line comes straight
from `refunded`, and the copy is fixed. The verdict reason itself already says "This Room wasn't
charged." Either word the refunded line so it holds for both shapes (e.g. "Not charged — AMI
couldn't finish this Room"), or drop the cause. Re-seed ar/ms if so (`retranslate:[ar,ms]`).

### Round-1 MAJOR-1 (balance not refreshed after a 1-on-1 or Brief turn): fixed

`OneOnOneNotifier.send()` and `BriefNotifier.send()` now call
`mandateNotifierProvider.notifier.refresh()`. They do so after a successful stream and again in
the `catch`. Both calls check `mounted` first.

- **A refresh failure can't turn a good turn into an error.** The success-path call sits inside
  the `try`, so if `refresh()` threw, the finished turn would be replaced by an error bubble.
  It can't throw: `refresh()` (`mandate_providers.dart:42-67`) catches everything and records
  it in its own `error` field.
- **The refresh reaches the screen.** The composer's balance line reads
  `ref.watch(mandateNotifierProvider)` at `one_on_one_screen.dart:272`.
- **Refreshing in the `catch` is correct.** `one_on_one.py` and `brief.py` charge before they
  stream, so a failure the client sees can still mean the balance moved.

### Round-1 MINOR-1 (refunded copy wrong for the CIO-outage PASS): fixed

The copy is now "Not charged — AMI couldn't finish this Room". It is true for both a failed run
with no verdict and an outage PASS that shows one. It names AMI, not "the AI". The ar and ms
seeds were refreshed for that one key.
