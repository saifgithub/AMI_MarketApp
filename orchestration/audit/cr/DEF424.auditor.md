# DEF424 — auditor verdicts (LLM-down leaks a raw transport error on Brief + non-Concierge 1-on-1)

## Round 1 — auditor U68

**SHA audited:** fix `18e1c0a3`, merged `b5de455c`, at `main` `16990d51`. Not live: Alpha runs
`685dbdd0`. Scratch worktree `audit-U68-Q` per DEF159.

**Real payloads.** I ran the same throwaway melehost stack as DEF425 (API on the HEAD tree, its
own Postgres and Redis), with `VLLM_BASE_URL` configured and broken two ways: a dead port
(`127.0.0.1:9`, which gives a transport `ConnectError`) and a stub that answers every call
`503`. The test user was on plan `trader` with 150 credits. I used the real routes:
`/v1/brief/start` + `/message` (`market_analyst`), `/v1/agents/one_on_one/start` + `/message`
(`trader`), and `/v1/room/stream`.

### What holds: the defect as filed is fixed, and the refund still holds

```
dead port  BRIEF  200 'event: token  data: AMI's Technical Strategist, currently offline. … AMI is in fallback mode — check back in a moment.'
dead port  1on1   200 'event: token  data: AMI's Execution Desk, currently offline. … AMI is in fallback mode.'
ledger: brief 150->149 then refunded 149->150; one_on_one 150->149 then refunded 149->150      (net 0 on both)
logs:   brief_llm_failed ×1, one_on_one_llm_failed ×1   (backend structured logs only, §5)
```

- **No `All connection attempts failed` anywhere.** The fallback is the per-agent "offline" copy,
  not a fabricated analysis, so it is not the DEF059 shape.
- **The six agents with no canned entry get `_DEFAULT`**, which is branded, *"AMI is in fallback
  mode — …"* (§2).
- **Other LLM surfaces with the model unreachable:**
  - **The Room:** `NO_VERDICT` with the DEF336 outage copy, and 0 hits for any raw transport
    string across the full SSE body.
  - **The portfolio finding:** it catches the exception and renders the deterministic sections.
- **Mutation, mine:** Brief's fallback without the `meta["stream_error"]` signal gives 1 failed
  (`test_brief_connect_error_yields_branded_copy_no_charge`). The refund is guarded. The builder's
  two `except` mutations are recorded.

### MINOR-1 — the other half of the same outage still shows operator text: HTTP 503 says "vllm … Check backend logs"

With the provider reachable but refusing, as vLLM does while restarting or overloaded, both
surfaces show:

```
503 stub  BRIEF  'data: \n\n[AMI error: HTTP 503 from the upstream provider (vllm). Check backend logs.]'
503 stub  1on1   'data: \n\n[AMI error: HTTP 503 from the upstream provider (vllm). Check backend logs.]'
(refunded on both — ledger net 0)
```

The lane leaves this path alone by design (its "scope boundary"). But the coordinator's question
was whether any user-visible path still leaks raw transport text. This one leaks the internal
provider name, an HTTP status and an instruction meant for an operator. It is the same outage
seen from the other side, and it gets different copy from DEF424's branded fallback. The refund
holds and the text is AMI-prefixed, so this is MINOR. **Fix:** route the in-band sentinel through
`canned_agent_fallback` for these two surfaces. `meta["stream_error"]` already marks it, so the
refund is unchanged.

### MINOR-2 — a stream that fails mid-reply ends silently (§3)

When the provider has already yielded chunks, `if not buf:` suppresses the fallback
(`agent_runner.py:263-272`, `brief_engine.py:299-306`). The user sees a reply that simply stops,
with nothing saying it was cut off. The turn is refunded through `stream_error`, but the user is
not told that either. This is degrade-loudly (CR040). **Fix:** when `buf` is non-empty, append one
short branded line, for example *"— AMI lost the connection mid-reply; this turn wasn't charged."*
