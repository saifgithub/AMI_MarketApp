for the same agent. So the lane has to meet two conditions:

2. A guard fails if an old label comes back. This is the second occurrence of the class, which
   is why it's registered as P37.

### MAJOR-1 — the new guard cannot see the possessive "PM's"

I replayed round 1's matrix against the round-2 guard (`test_def423_agent_rename_residue.py` +
`test_def423_round2_rename_residue_extended.py` + `test_cr160_agent_rename.py`, baseline 14
passed) and added mutations for the strings round 2 fixed:

```
M1  room_prompts.py      "Execution Desk's size" -> "Trader's size"          caught
M2  lesson 283           "CIO" -> "PM"                                       caught
M4  ai_meta.json         "CIO" -> "PM"                                       caught
M5  overlay_generator    "Role guidance — Execution Desk" -> "— Trader"      caught
M6  room_runner sentinel "Chief Investment Officer" -> "Portfolio Manager"   caught
M8  website faq.md       "Chief Investment Officer" -> "Portfolio Manager"   caught
M12 room_runner          "not stated by the CIO" -> "not stated by the PM"   caught
M7  brief_engine         "You can shape the CIO's" -> "You can shape PM's"   14 passed  NOT CAUGHT
M9  room_runner          "CIO's own; the reasoning" -> "PM's own; …"          14 passed  NOT CAUGHT
M10 lesson 011           "CIO's" -> "PM's"                                   14 passed  NOT CAUGHT
M11 ai_meta.json         "CIO's" -> "PM's"                                   14 passed  NOT CAUGHT
```

The cause is one character. `_BARE_PM = re.compile(r"(?<![A-Za-z])PM(?![A-Za-z'])")`
(`test_def423_round2_rename_residue_extended.py:76`) has an apostrophe in its negative
lookahead, so "PM" followed by `'s` never matches in any of the areas it scans. No comment
explains the exclusion. The time-of-day and ticker exclusions sit in separate context regexes,
not here.

This matters because the possessive is the form the residue actually took. Two of the round's
own fixes were "PM's": the Brief Your Agent refusal suggestion, and `_PM_TRUNCATED_NO_NARRATION`'s
"the PM's own". Both can be reverted with the guard green. Right now there is no live "PM's"
residue: I grepped backend, EN lessons, content JSON, `app_en.arb` and the FAQ, and got zero hits.
So this is a regression hole, not live copy. But the defect's acceptance is "renamed and kept
renamed", and round 1's MAJOR-1 was precisely a guard that missed what the lane touched.

**Fix direction:** drop `'` from the lookahead (so `(?![A-Za-z])`) and add a "PM's" case to
`test_backend_ast_scan_finds_the_known_positive`. Handle the curly `’` the same way. If a real
allowed "PM's" exists, give it a named allowlist entry like the others.
