## The fix — verified against the actual defaults and the actual route

**`Quote`'s defaults, read directly.** `change_pct: float = 0.0`,
`market_state: str = "CLOSED"` — confirmed exactly as claimed, and the
pre-fix `YfinanceProvider.quote()` really was the one-line
`return Quote(price=..., source=...)`, so both fields fell through
silently on every real quote. `USE_REAL_MARKET_DATA=true` on Alpha
confirmed makes this the production path, not a degraded one.

**The route does not post-process — confirmed, not assumed.**
`GET /v1/sim/quote/{ticker}` calls `sim.current_quote(ticker)`, which is a
direct pass-through to `self._provider.quote(ticker)` with only a
None-fallback chain — no field mutation anywhere between the provider and
the JSON response. The submission's own "where to attack" #2 flagged
uncertainty here and said "I believe it does not [post-process]" — correct,
confirmed by reading `SimEngine.current_quote` directly.

**`is_us_market_open` is pure and thread-safe — confirmed, not assumed.**
No I/O, no shared mutable state, only `datetime` arithmetic against a
converted timezone. "Where to attack" #1 raised the concurrent
`ThreadPoolExecutor` fan-out as unprofiled; profiling wasn't necessary to
settle the correctness question — a pure function with no shared state
cannot have a concurrency bug here, whatever its wall-clock cost turns out
to be under load.

## The third lead — confirmed exactly as risky as disclosed, not more

**The bare `except Exception` in `_previous_close`'s per-key lookup**
would indeed swallow a genuine bug in a key name (a future yfinance
version rename, a typo in a refactor) the same way it swallows the
expected `KeyError` for an absent key — confirmed by reading the loop
directly. Agree this isn't silent in the CR040 sense: a swallowed lookup
still falls through to the "no previous close" branch, which logs
`yfinance_quote_no_previous_close` at WARN. So a future regression here
would show up as a warning-rate change, not true silence — worth knowing,
not worth blocking on.
