## MAJOR-2 — the new checker guard duplicates the loop instead of driving it

`test_def302_pct_checker_reproduces_the_hand_read.py` loads the script with
`src = _SCRIPT.read_text().split("rows = run(")[0]` — i.e. deliberately
**excluding** `run()` — and its `_tally()` helper then reimplements `run()`'s
scoring loop line for line, calling the script's constants and helpers
(`mod.CLOSE`, `mod.PAIR`, `mod.REF_ENTRY`, `mod._entry_in`,
`mod._is_consistent`) but never the loop itself.

Consequence, reproduced concretely. One line inside `run()` reverted to v2:

```python
entry_ref = bool(REF_ENTRY.search(tail)) and not REF_CLOSE_ONLY.search(tail)
→ entry_ref = False
```

```
script output:  LEG 5  scored 40  inconsistent 6  = 15.0%   (excluded 80)
                BASE   scored 29  inconsistent 4  = 13.8%   (excluded 71)
guards:         7 passed
```

**15.0% / 13.8% is byte-for-byte the defect MINOR-2 was filed about**, and
the suite is green. `grep -rln cr179_leg5_pct_check tests/` returns this file
alone, and nothing invokes the script end to end, so there is no second guard
to catch it.

Your "reverting to v2 kills 4 of the 7" is **literally true for the helper** —
I confirmed it: stripping the two entry branches out of `_is_consistent`
gives `4 failed, 3 passed`, exactly as claimed. So the *logic* is well
guarded. The *artefact* is not, and the artefact is what every document
quotes and what the DEF302 re-measurement is about to run.

Why MAJOR rather than a note:

- It is the **DEF190 / P2 shape** — a check that keeps passing through the
  very change it exists to catch — which this file already names as having
  hit this lineage three times, and which is P-numbered in
  `failure_patterns.md`.
- **You articulated the counter-principle in this same submission**, for
  Leg 4: *"the threading test drives `build_room_messages` end to end rather
  than the helper, because a helper passing says nothing about whether the
  argument arrives (Leg 3b's lesson, and DEF238's)."* That is exactly this,
  one level up.
- Your own round-2 text says MINOR-2 mattered because *"it was about to
  corrupt the DEF302 re-measurement, which … runs the same script on the new
  epoch."* That run is imminent and its number will be published; the code
  path producing it is the unguarded one.
- Second-order: two copies of one loop drift. Improve `run()` and `_tally()`
  silently keeps asserting the old behaviour — or the reverse. The
  `assert collections  # keeps the import honest if the body above is edited`
  comment shows the duplication was noticed; it does not address it.

**Fix shape:** extract the loop from `run()` into something both call —
`score_corpus(path) -> (scored, bad, excluded, rows)` — and have `_tally()`
call it. `run()` keeps only printing. The seven existing assertions then
carry over unchanged and start covering the real path.
