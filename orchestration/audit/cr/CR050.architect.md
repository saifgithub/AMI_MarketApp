# CR050 — audit lane (architect)

**Item:** CR050 — tighten login UX: federated Apple/Google button becomes the sign-in hero; the
email 6-digit card collapses behind a "Use email instead" toggle. Also flips Google Sign-In on
(config, not code) and documents the Apple Guideline 4.8 coupling. Register:
[`docs/forward_planning/cr_list.md`](../../../docs/forward_planning/cr_list.md) CR050. Full spec:
[`CR050_tighten_login.md`](../../../docs/forward_planning/CR050_tighten_login/CR050_tighten_login.md),
[`google_signin_enablement.md`](../../../docs/forward_planning/CR050_tighten_login/google_signin_enablement.md).

**depends-on:** none — backend OAuth (Apple + Google JWKS/OIDC verify) already shipped pre-CR050.

**Head SHA:** `44759a9` (CR050's own commits: `28d16e4` UX + `d1a56a6` Google enablement — both
already on `main`, authored directly, ahead of this dispatch round; I picked up the lane, verified,

## What was done

1. `mobile/lib/screens/auth/sign_in_screen.dart` — federated OAuth (Apple on iOS / Google on
   Android) is now the visual hero; `_EmailClaimCard` is hidden by default behind a "Use email
   instead" `TextButton` toggle. Claim controls gate on `!user.isAnonymous` so already-claimed users
   never see them.
2. `mobile/lib/l10n/app_en.arb` (+regenerated) — new key `signInUseEmailInstead`.
3. `mobile/test/widgets/sign_in_email_disclosure_test.dart` — asserts the email card is hidden by
   default and revealed by the toggle tap.
4. `docs/initial_specs/09_compliance/store_compliance.md` — Apple Guideline 4.8 coupling note
   (per-platform OAuth gating keeps iOS compliant; Google-on-iOS would make SIWA mandatory — not
   doing that, D-057).
5. Google Sign-In flipped on: `GOOGLE_AUDIENCES` live on melehost (`ami_api_alpha` loads it, no
   `aud` rejects), web client id baked as the default for `GOOGLE_OAUTH_WEB_CLIENT_ID` in
   `scripts/install_android.sh` + `scripts/build_playstore.sh` (degrade-loudly — never a
   forgotten-export silent disable).

No wire-format / `fromJson` changes — this CR is UX + build-config only; the Apple/Google auth
response shapes (`signInWithApple`/`signInWithGoogle` in `auth_providers.dart` →
`/v1/auth/apple`/`/v1/auth/google`) were already live pre-CR050 and untouched here. Contract check:
N/A (no HOT-FILE / schema touched).

## Why this is safe / minimal

- Pure UX reorder + visibility gating on the sign-in screen; no change to the OAuth mechanism, the
  anonymous-first bootstrap, or the Concierge interview (out of scope, confirmed untouched).
- Email path is retained (not removed) — still the only portable cross-ecosystem recovery path
  (Apple ID iOS-only, Google Android-only) and future Huawei fallback; just demoted.
- Google enablement is additive config (env var + baked default), not a code path change — the
  client-side `_googleOAuthWebClientId.isEmpty` guard (pre-existing) still degrades loudly if the
  define is ever missing.
