## Design

### Backend: `services/ticker_interest.py`

Four query functions, all real-user-filtered via `admin_analytics._real_users_clause()`
(imported, not reimplemented — same CR035 synthetics / seed-burst / CR125 probe-user exclusion
every other admin metric already applies):

- `top_tickers(days, limit)` — `room_runs` grouped by ticker: run count, distinct researcher
  count (`count(distinct user_id)`), credit spend, status breakdown (a second grouped query,
  merged in Python by ticker — chose two queries over one to avoid a
  `(ticker, status)`-keyed result needing reshaping either way).
- `ticker_orders(days, limit)` — `sim_trades` (filled) and `sim_resting_orders` (bucketed by
  `state` into `pending` = working/triggered/filling vs. `not_filled` = cancelled/expired/
  rejected) merged by ticker in Python, ranked by total volume.
- `watchlist_interest(days, limit)` — `sim_watchlists` grouped by ticker.
- `ticker_detail(ticker, days)` — one symbol's full history across all four tables, for the
  admin tab's click-through drilldown.

### Backend: `api/admin_ticker_interest.py`

`/v1/admin/ticker-interest/{top,orders,watchlist,detail/{ticker}}`, `Depends(get_admin)` —
identical gating shape to `admin_verdict_outcomes.py`, the most recently added sibling admin
route. Wired into `main.py` alongside the other CR200 admin routers.

### Frontend: `static/admin/ticker_interest.js`

New `TICKERS` tab, self-registered via `registerView()` — no shell edit needed beyond the one
`<script>` tag added to `admin.html`. Table rendering follows `bugs.js`'s pattern (a generic
`tiTable()` helper with a `render` callback per column) rather than `analytics.js`'s stat-tile
+ SVG-bar-chart pattern, since this is fundamentally a ranked list, not a KPI dashboard — three
ranked tables (most-researched, order fulfilment, watchlist) plus a click-through detail card
that reuses the same table helper for the drilldown's nested lists.

## The load-bearing guarantee: real-user filtering must actually exclude, and the fill-state
## split must actually split

This is the finding I most want attacked. `top_tickers`/`ticker_orders` both join `User` and
apply `_real_users_clause()` — reused, not reimplemented — but the reuse itself only proves
intent, not that the join is wired correctly in each of the four functions independently.
Similarly, `ticker_orders`'s three-way bucket (`filled`/`pending`/`not_filled`) is a manual
Python `if/elif` over `SimRestingOrderRow.state` string literals — the kind of logic that
silently degrades if a state name is mistyped or a bucket is left out.

**Proven by mutation, not just asserted.** Two separate mutations in the verify worktree
(both reverted after, `git status --short` clean each time):

1. Dropped `.join(User, ...)` + `_real_users_clause()` from `top_tickers` and `ticker_orders`
   (regex-replaced the two `.where(_real_users_clause(), ...)` call sites with the bare
   date-range filter). Re-ran `test_cr200_r001_ticker_interest.py`:
   ```
   FAILED test_top_tickers_groups_and_excludes_synthetics — assert 3 == 2
   FAILED test_ticker_orders_excludes_probe_user — assert not True
   2 failed, 4 passed
   ```
   Exactly the two tests naming that guarantee. Reverted; 6/6 again.
2. Dropped `"rejected"` from `_TERMINAL_NOT_FILLED_STATES`. Re-ran
   `test_ticker_orders_splits_filled_pending_not_filled`:
   ```
   FAILED — assert row["not_filled"] == 1, got 0
   ```
   Reverted; 6/6 again.

## Known gap, flagged rather than worked around

No raw ticker-lookup/view telemetry exists anywhere in the codebase — no `research_events`
table, confirmed by grep before design. This CR reports on Room runs, trades, resting orders,
and watchlist adds — the interest signals that already exist in the data — not on passive
symbol lookups (opening a detail screen without transacting). Recorded in the CR doc's own
"Why" section as a known limit, not discovered by the auditor.
