# DEF051 — audit lane (architect)

**Item:** DEF051 — Convene the Room checked mandate compliance against a hardcoded
fake $100,000/0%-drawdown portfolio, always. `RoomStartRequest.portfolio_value`/
`.current_drawdown_pct` (`backend/app/api/room.py`) were client-suppliable request
fields nobody ever overrode — the mobile client's `streamRoom()` had matching dead
defaults, never sent. A user whose real simulated portfolio had already breached
their mandate's `max_drawdown_pct` still saw 0% drawdown on every Room verdict —
this is the deterministic, "sacred" compliance gate's own input, not a
prompt-honesty gap like CR023/CR024. Register:
[`docs/defect/def_list.md`](../../../docs/defect/def_list.md) DEF051. Full spec:
[`DEF051_room_portfolio_defaults.md`](../../../docs/defect/DEF051_room_portfolio_defaults/DEF051_room_portfolio_defaults.md).

**depends-on:** none.

**Head SHA:** `22c84c6`

## What was done

`stream_room` (`backend/app/api/room.py`) now takes `sim: SimEngine =
Depends(get_sim_engine)` and resolves `portfolio_value = sim.total_value(req.user_id)`
/ `current_drawdown_pct = sim.current_drawdown_pct(req.user_id)` immediately before
calling `runner.start_run(...)`, instead of trusting `req.portfolio_value` /
`req.current_drawdown_pct`. Mirrors the identical `Depends(get_sim_engine)` +
`sim.total_value()`/`sim.current_drawdown_pct()` pattern already in production at
`mandate.py::audit_holdings` (lines 214-244) and used internally by
`SimEngine.submit()`/`.preview()`'s own compliance checks (`sim_engine.py:452-459`,
`613-620`).

The two now-dead `portfolio_value`/`current_drawdown_pct` fields were removed from
`RoomStartRequest` entirely (nothing overrides them once the route stops trusting
client input — kept, they'd be misleading dead weight, not a real override).
`mobile/lib/services/api/api_client.dart::streamRoom()`'s matching dead
`portfolioValue`/`currentDrawdownPct` params and JSON body keys were dropped too;
its sole call site (`room_providers.dart:94`) already omitted them, so no mobile
behavior changes.

`RoomRunner.start_run()`/`.run()` (`room_runner.py:848-849, 972-973`) keep their own
independent `100_000.0`/`0.0` defaults untouched — `test_room_runner.py` calls the
runner directly (never through the route) and relies on those defaults in every
test; the bug was specifically that the *route* never computed real values, not
that the runner lacks its own default. No reason to touch a working, well-tested
surface the bug wasn't in.

## Finding not in the original defect doc

`SimEngine.total_value()`/`.current_drawdown_pct()` already handle a brand-new user
gracefully — `ensure_portfolio()` (`sim_engine.py:347`) auto-creates a portfolio at
`starting_capital = current_cash = _STARTING_CAPITAL = 10_000.0`
(`sim_engine.py:184`) if none exists yet. So a fresh user's *real* value is **$10,000
at 0% drawdown**, not the old fake $100k. Drawdown itself is `(starting_capital -
total_value) / starting_capital * 100` (`schemas/trade.py:47-52`, vs starting
capital, not a running peak) — no holdings means `total_value == current_cash`
exactly. **This means the defect doc's proposed "keep 100k/0% as a fallback for
users with no portfolio yet" is unnecessary** — the real computation already covers
that case correctly. No special-cased fallback logic was added; there's nothing to
add.

## Why this is safe / minimal

- **Server is now the sole source of truth** for the compliance-check inputs —
  matches the pattern already used everywhere else a real portfolio value/drawdown
  is needed (`mandate.py`, `sim_engine.py`'s own submit/preview checks). The route
  was the outlier, not the rest of the codebase.
- **No client-side trust removed that was ever real** — the mobile client never sent
  these fields; removing them from the request schema and from `streamRoom()`'s
  signature just deletes dead code, doesn't change any live client behavior.
- **`RoomRunner`'s own defaults untouched** — bounds the blast radius to exactly the
  route handler, the actual locus of the bug; `test_room_runner.py`'s ~30+ tests
  calling the runner directly are unaffected.

## Tests run (self-test)

- New `backend/tests/unit/test_room.py` (2 tests):
  - `test_stream_room_ignores_spoofed_body_uses_real_sim_state` — seeds a
    `SimPortfolioRow` directly (`starting_capital=10_000.0, current_cash=5_000.0`,
    no holdings → deterministic 50% drawdown, no price-provider flakiness), POSTs a
    spoofed body (`portfolio_value: 999999.0, current_drawdown_pct: 0.0`), overrides
    `get_room_runner` with a `_FakeRunner` double that records the kwargs
    `stream_room` actually hands it (no real LLM-backed Room run needed — this
    tests exactly the surface DEF051 broke), asserts the captured kwargs show
    `portfolio_value == 5_000.0` and `current_drawdown_pct == 50.0` — the real
    state, not the client's fake.
  - `test_stream_room_fresh_user_gets_real_starting_capital` — a brand-new user
    with no seeded portfolio gets `portfolio_value == 10_000.0`,
    `current_drawdown_pct == 0.0` from `ensure_portfolio()`'s auto-create, proving
    the "no portfolio yet" path needs no special-cased fallback.

  `test_auth_phase1_5_audit_fixes.py::test_room_stream_rejects_foreign_user_in_body`'s

- `pytest backend/tests/unit/ -q` → **675 passed** (673 → 675, both new tests
  green, `test_room_runner.py` unaffected as expected).
