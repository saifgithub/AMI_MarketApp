## The MAJOR — a real prompt change that ships with an unchanged version

You wrote: *"A template branch that only fires for, say, a halal mandate
or `risk_score <= 2` is invisible to this hash... if you can construct a
prompt change that ships with an unchanged version, that is a MAJOR."*

I constructed it. `_aggressive_block` in `overlay_generator.py` has:

```python
if m.risk_score <= 2:
    parts.append("- For low-risk-score user: ...")
```

The reference mandate is `risk_score: 3`, so this branch never executes
during reference assembly — its text is entirely absent from what gets
hashed. I replaced the string inside that branch with unrelated text and
recomputed `prompt_version(AgentId.AGGRESSIVE_DEBATOR)` before and after:

```
before: 86c3b410b5c0
after:  86c3b410b5c0
```

Identical. A real edit to text that a risk_score-1-or-2 user's Aggressive
Debator actually receives produces **no change** in the stamped version —
the exact failure mode you named. Reverted immediately, `git status
--short` clean.

**Why this matters more than "one known edge case."** CR158 exists
because CR143 silently mis-partitioned measurements across a time
boundary (18.4% vs. the true 0/18, 4.5% vs. the true rate) by reconstructing
epochs by hand. This blind spot reproduces the *same class of silent
mis-partitioning*, but across a **mandate-shape boundary** instead of a
time boundary: a future prompt edit scoped to low-risk-score users (or,
by the same mechanism, halal-only branches, `risk_score >= 4` branches,
or any other mandate-conditional text) would ship, actually change what
some users receive, and the version column would report "nothing
changed" for exactly the population it changed for. Anyone who trusts
the column to partition a future epoch — which is the column's entire
stated purpose — would silently repeat CR143's error for that slice.

**Not prescribing the fix.** Two shapes occur to me, offered as leads:
(1) run the reference assembly multiple times, once per mandate-shape
axis that has conditional branches (risk_score tier, halal on/off, at
minimum), and combine the hashes — costs more compute per version but
covers every branch that currently exists; (2) accept the blind spot but
say so explicitly in the docstring/row rather than only in the "what to
attack" section of a doc that won't ship with the code, so a future
reader of `prompt_version.py` knows the guarantee is narrower than "this
prompt's generation" and is actually "this prompt's generation, for a
risk_score-3, non-halal mandate." Right now the docstring states the
broader claim without the caveat.
