## The fix

Both call sites in `room_runner.run()` now `await asyncio.to_thread(...)`. Neither builder's return
value nor the prompt assembly order changes. `_WAIVED_CALL_CHAIN_NAMES` and
`_DEF120_KNOWN_BLOCKING_PAIRS` are both **empty**.

Those three had to land in one commit: `test_waived_chains_still_pin_the_known_offender_set` asserts
in **both** directions, so a pin that stops blocking while still listed fails it. That coupling is
the check that distinguishes a real fix from a waiver moved around, and it is why the acceptance
insisted on 1–3 together.

## The part worth your attention: my first measurement test was wrong, and it passed under mutation

Acceptance 5 asked for a loop-responsiveness test because *"this has never been measured — all four
DEF120 rounds reasoned statically."* I wrote one, it went green, and both mutations went red. It
looked done.

It wasn't. I ran the mutations with `-x`, so pytest stopped at the first failure and I never saw
that the **responsiveness** test itself was still passing — only the thread-identity test was
catching anything. Re-running without `-x` exposed it.

The metric was heartbeat **ticks counted over the convene**. Measured across all four states, two
runs each:

| State | Ticks | Elapsed |
|---|---|---|
| both wrapped (correct) | **197, 196** | 2.17s |
| `_build_sim_holdings_block` un-wrapped | **171, 171** | 2.17s |
| `_build_room_sector_context` un-wrapped | **169, 169** | 2.16s |
| both un-wrapped | **141, 142** | 2.14s |

The signal is real but it is a **13% dip inside a 2.1s run**. My floor was set from a wrong premise
too — I sized it against `2 × _BLOCK_S = 0.6s` when the convene actually takes ~2.15s, so the
heartbeat runs for the whole run, not just the blocking window. Any floor loose enough to survive a
loaded CI box also sails past a single un-wrapped call site.

**Replaced with the longest gap between consecutive ticks.** A blocked loop cannot run the heartbeat
*at all* for the block's duration, so the gap goes from scheduler jitter (~0.01s) to `_BLOCK_S`
(~0.30s) — a ~10x separation that is indifferent to machine speed and to how long the convene takes.
Threshold at `_BLOCK_S / 2`.

## What I want you to attack

1. **The threshold.** `_BLOCK_S / 2` = 0.15s. It is 15x jitter and half a real stall, but the numbers
   above come from one idle Mac. If you think a loaded box can produce a 0.15s inter-tick gap with
   the loop genuinely free, that is a flake and I want to know.
2. **`_SilentGateway` shortcuts the agents.** The convene still runs its real phase machinery, but
   the LLM is a stub. If the real gateway path reaches either builder again by a route I did not
   exercise, the test would not see it.
3. **Empty is now the correct state of both sets** — but `_DEF120_KNOWN_BLOCKING_PAIRS` being empty
   also means the second assertion has nothing to protect. Worth checking that an empty pin set does
   not make the whole companion test vacuous.
