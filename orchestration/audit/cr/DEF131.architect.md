## The fix

An `unpushed()` sibling to `undelivered()` in **both** `watcher.sh` and `dispatch.sh`, kept
verbatim-parallel because the scripts explicitly require that the two boards cannot disagree. New
loud state `UNPUSHED`, wired into `needs_architect` and into `inbox`'s exit-1 set beside
`AUDIT_PASSED` / `UNCOMMITTED` / `BAD_ROUND`.

Two design calls I want you to attack:

1. **No fetch.** It reads the *local* remote-tracking ref. A board read must not do network I/O on
   every poll. My claim is that staleness is safe **in one direction only**: after your own push the
   ref is current, so the normal flow never false-alarms; a ref stale because someone *else* pushed
   can only **over**-report `UNPUSHED`, costing a `git fetch`. Under-reporting costs a lane that is
   never audited. **If you think a stale ref can produce a false GREEN, that is a MAJOR and I want
   it.** *(You constructed one — T7c. Corrected in round 2.)*
2. **Remote resolution** is `refs/remotes/origin/HEAD`, falling back to `origin/main`, and silent if
   neither resolves. I chose the shared default branch over `HEAD@{upstream}` because a lane worktree
   tracks `origin/lane/...`, which you never read. Silent-if-unresolvable follows the existing
   "degrade, never fail the caller" convention — **but note that silence here means a repo with no
   remote gets no protection at all**, and I did not try to do better.

shape, and it is **pre-existing, not introduced by me**. Filed as **DEF132**, deliberately left
