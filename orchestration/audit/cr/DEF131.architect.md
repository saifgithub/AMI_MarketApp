## The finding underneath it — the protocol already said the words

`undelivered()` exists in both scripts and closes the adjacent gap (uncommitted), with this comment:

> *"This auditor works from its own checkout, so it would find nothing there while this table said
> work was waiting."*

Exactly the failure I hit — one step earlier in the pipeline. And `dispatch.sh` goes further:

- `print_inbox`: *"UNCOMMITTED (verdict **unpushed** — chase, then merge)"*
- `print_verdict`: *"Chase the auditor to commit **and push**."*

**Both name pushing. Neither checks it.** `git diff --quiet HEAD` passes happily for a committed,
unpushed file. This is the project's **"a claim in a comment is not a control"** class (CR038) in the
orchestration layer — the same shape as your own DEF120 round-2 MAJOR, where
`_SIM_ENGINE_SYNC_SAFE_METHODS` membership was asserted only in a comment. I would not have believed
this was a real class if you had not already made me prove it twice on product code.

## The fix

An `unpushed()` sibling to `undelivered()` in **both** `watcher.sh` and `dispatch.sh`, kept
verbatim-parallel because the scripts explicitly require that the two boards cannot disagree. New
loud state `UNPUSHED`, wired into `needs_architect` and into `inbox`'s exit-1 set beside
`AUDIT_PASSED` / `UNCOMMITTED` / `BAD_ROUND`.

Two design calls I want you to attack:

1. **No fetch.** It reads the *local* remote-tracking ref. A board read must not do network I/O on
   every poll. My claim is that staleness is safe **in one direction only**: after your own push the
   ref is current, so the normal flow never false-alarms; a ref stale because someone *else* pushed
   can only **over**-report `UNPUSHED`, costing a `git fetch`. Under-reporting costs a lane that is
   never audited. **If you think a stale ref can produce a false GREEN, that is a MAJOR and I want
   it.**
2. **Remote resolution** is `refs/remotes/origin/HEAD`, falling back to `origin/main`, and silent if
   neither resolves. I chose the shared default branch over `HEAD@{upstream}` because a lane worktree
   tracks `origin/lane/...`, which you never read. Silent-if-unresolvable follows the existing
   "degrade, never fail the caller" convention — **but note that silence here means a repo with no
   remote gets no protection at all**, and I did not try to do better.

## A separate bug I found while measuring, and did NOT fold in — now DEF132

**`watcher.sh state` exits 1 on a successful read.** `print_state` ends with
`[ "$n" -eq 0 ] && echo "(no lanes yet…)"`; with lanes present the test is false, the `&&`
short-circuits, and that becomes the script's exit status. Measured side by side:
`watcher.sh state` → **exit 1**, `dispatch.sh state` → **exit 0**. The header advertises
"0 work found (**or table printed**)", so the code contradicts its own contract.

Nothing gates on it today, so it is not exploited — but it is exactly the silent-wrong-direction
shape, and it is **pre-existing, not introduced by me**. Filed as **DEF132**, deliberately left
unfixed here so this lane stays one auditable thing. Say if you would rather it rode along.
