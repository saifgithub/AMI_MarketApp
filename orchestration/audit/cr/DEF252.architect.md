# DEF252 — audit submission (architect → auditor)

## What was broken

`YfinanceProvider.quote()` was one line:

```python
return Quote(price=float(price), source=self.name)
```

`Quote` is a `NamedTuple` whose `change_pct` defaults to `0.0` and whose
`market_state` defaults to `"CLOSED"`. yfinance is the production provider
(`USE_REAL_MARKET_DATA=true`), so **every quote Alpha has ever served asserted a
flat, closed market** — and `/v1/sim/quote/{ticker}` hands both fields straight
to the app, which renders them as fact. Saiful saw it from his iPhone at 14:37 ET
on Monday 2026-08-10, mid-session on a −2% day: `CLOSED · NFLX $75.51 −0.0% ·
AMD $475.65 −0.0%`.

Still reproducing when I picked it up:

```
GET http://192.168.20.59:8000/v1/sim/quote/AAPL
{"price":308.26,"source":"yfinance","change_pct":0.0,"market_state":"CLOSED"}
```

**The part worth dwelling on: this was already known and routed around.** Both
`price_history.py::_should_fetch` and `trading_math/market_hours.py`'s docstring
say in prose that `Quote.market_state` cannot be trusted because the production
provider never sets it. CR109 needed a real answer and built
`is_us_market_open()` to get one. Nobody fixed the value the **UI** reads, so the
workaround protected the game's fill gate and left the user-facing tape wrong.
That is CR040 inverted — a dataclass default asserting a fact nobody supplied —
and it is the DEF038/DEF063 shape, where absent data reads as a confident
negative rather than as unknown.

## The fix, and why the two halves come from different places

I re-derived the row's two factual claims against the live API instead of
inheriting them, because the whole remedy turns on them:

| claim | verified |
|---|---|
| the previous close is already on `fast_info` | yes — `previousClose` **and** `regularMarketPreviousClose`, and they disagree: 313.25 vs 313.33 on AAPL |
| `market_state` is not on `fast_info` | yes — `KeyError`; it exists only on the heavy `.info` call |

So `change_pct` costs **nothing** — same object, no second round-trip — and
`market_state` is derived from `is_us_market_open()` rather than bought with a
network call CR145 already flags as the uncached hot-path hazard.

`_previous_close` prefers `regular_market_previous_close` **on purpose**: Yahoo's
own `regularMarketChangePercent` divides by it, and this number is rendered
beside a price the user can check against Yahoo in another tab. Matching Yahoo
beats picking the fresher-looking figure.

Live, after the fix: **AAPL −1.62%, NVDA −2.86%, KO −0.21%** — `0.0` for all
three before.

## Two residuals I did not smuggle a fix for

1. **`market_hours` has no NYSE holiday calendar** (a documented CR109 slice-2
   simplification), so a holiday now reads `REGULAR`. Wrong ~9 days a year
   against wrong 100% of the time. It is a narrowing, not a closure, and the
   calendar gap is the thing to fix — not this derivation.
2. **`change_pct` is still not nullable end to end.** When neither key answers,
   the provider logs `yfinance_quote_no_previous_close` at warn and falls back to
   `0.0` — loud in the logs (CR040), still `−0.0%` on the pixel. `float | None`
   through the API and the Flutter `ticker_tape` / `trade_ticket_sheet` render
   path is the honest answer, and it is a client change that does not belong in a
   backend-only promotion.

Both are on the row. Neither is claimed as fixed.

## Revert-proof QA

`tests/unit/test_def252_quote_change_and_market_state.py`, 11 tests. The fake
`_FastInfo` **raises** on an absent key, like the real `FastInfo` — a dict
returning `None` would not have reproduced the behaviour `_previous_close` is
guarded against.

The last test is the **P18** one, and it is the reason the others are not enough:
it drives the real `GET /v1/sim/quote/{ticker}` with only the network faked, and
asserts the response carries the derived values. A provider that is right while
the route still emits a default is exactly DEF238's shape — proven on the
builder, never on the caller.

**Mutation harness, 8 of 8 killed:**

| | mutation | killed by |
|---|---|---|
| M1 | restore the one-line quote (the defect itself) | 5 tests |
| M2 | reverse the two previous-close keys | `…_the_regular_session_close_wins…` |
| M3 | invert the session ternary | `…_the_session_comes_from_the_calendar…` |
| M4b | hardcode the session as always open | same, on the CLOSED branch |
| M5 | drop the loud log for a missing previous close | `…_no_previous_close_says_so_out_loud` |
| M6 | warn on every quote, not just the blind one | `…_a_quote_that_knows_its_change_says_nothing` |
| M7 | hand the calendar a naive `now` | `…_consulted_with_an_aware_utc_now` |
| M8 | treat a zero previous close as usable | `…_a_zero_previous_close_is_not_a_previous_close` |

**Disclosure — M4 as first written produced unparseable Python and I counted the
resulting collection error as a kill.** An unparseable mutant proves nothing
about the tests; it is a false kill, the mirror of the equivalent-mutant false
survivor I recorded on DEF247. Replaced with a valid `market_state="REGULAR"`
before the count above was published.

## Where to attack

- `is_us_market_open` is called once per quote. `SimEngine._marks_with_quotes`
  fans out over a thread pool, so this now runs concurrently — it is pure and
  allocation-light, but I have not profiled it under the fan-out.
- The route test stubs `SimEngine` with a two-line class. If the real engine
  post-processes a `Quote` between provider and response, my caller test would
  not see it. I read `current_quote` and believe it does not; worth a second
  pair of eyes, because that is precisely the gap the test exists to close.
- `_previous_close` catches bare `Exception` around the lookup. That is
  deliberate (FastInfo's failure mode varies by quote type) but it would also
  swallow a genuine bug in the key names — M2 is the only thing standing
  between that and a silent regression to `0.0`.
