# DEF424 — audit lane (LLM-down leaks a raw transport error on Brief + non-Concierge 1-on-1)

**SCOPE:** chunk (backend copy/UX fix — the credit/refund spine underneath it was already correct)

**TIER: A.** Touches the credits path (`meta["stream_error"]` is the same key `brief.py`/`one_on_one.py` read to decide whether to refund) even though this specific defect is scoped as copy/UX, not billing — any edit near the refund-decision key gets Tier A treatment.

**SHA:** `0ab6e8f1` (worktree base, = current `main` merge-base — no divergent commits yet; this round's changes are uncommitted on `worktree-agent-af8d7a4d7aa9cc9e9`, listed below). Diff base: `git diff 0ab6e8f1 -- backend/app/services/agent_runner.py backend/app/services/brief_engine.py backend/app/services/llm_gateway.py`.

**depends-on:** none. **Promoted:** no — needs `/promote-to-alpha` after this verdict.

## What and why

Found running CR004's A3 drill 1 (LLM down) against live Alpha (`alpha-2026-09-25-4`) with `VLLM_BASE_URL` pointed at a dead port: a Brief `POST /v1/brief/message` turn streamed `event: error` / `data: All connection attempts failed` — a raw httpx connection-pool string, not AMI-branded copy.

**Root cause:** `LLMGateway.stream_chat` (`backend/app/services/llm_gateway.py`) picks exactly one provider per call and re-raises any exception uncaught ("there is no runtime fallback in this gateway" — its own docstring). `BriefEngine.stream_chat` (`brief_engine.py:236`, pre-fix) had no try/except around its own `self._llm.stream_chat` call, so the raised exception propagated straight through the generator to `brief.py`'s catch-all `except Exception as e: yield sse_text("error", str(e)[:300])` — the exception's own text, verbatim, on the wire. `AgentRunner.stream_one_on_one_message`'s non-Concierge branch (`agent_runner.py:145-249`, pre-fix) had the identical gap. Only `_stream_concierge` (`agent_runner.py:261`, hardened under RETRO-SECURITY MAJOR-2 round 3) already caught this shape, for the Concierge only.

Credits were correctly refunded on both surfaces even pre-fix (`stream_error`/exception-triggered refund logic already held) — this was a copy/UX defect, not a billing defect. Confirmed the distinction still holds post-fix (see tests).

**The fix:**
- `llm_gateway.py`: new module-level `canned_agent_fallback(agent_id: AgentId | str) -> str` — looks up `MockProvider._CANNED` by `agent_id` directly (not sniffing the system prompt the way `MockProvider.stream_chat` itself does; every caller of this helper already knows exactly which agent it is), falling back to `MockProvider._DEFAULT` for the six agents `_CANNED` has no dedicated entry for (news/social analysts, research manager, the three risk debators).
- `agent_runner.py`: the non-Concierge branch's `async for chunk in self._llm.stream_chat(...)` is now wrapped in `try`/`except Exception as exc`, mirroring `_stream_concierge`'s existing handler exactly — logs, sets `meta["stream_error"]` (same key the caller already reads for the refund decision), and yields `canned_agent_fallback(agent_id)` only if nothing was yielded yet (`if not buf:`).
- `brief_engine.py`: same treatment on `BriefEngine.stream_chat`'s single `self._llm.stream_chat` call.
- **Scope boundary, deliberate:** the pre-existing in-band `[AMI error: HTTP …]` sentinel path (`OpenAICompatibleProvider`/`AnthropicProvider`'s non-200 branch, and the in-band SSE error frame, DEF376) is UNCHANGED. That path never raises — it yields its own sentinel text into the generator and returns cleanly — so this fix's try/except never fires for it, and it keeps refunding via the pre-existing `meta["stream_error"]` write. The DEF424 row itself draws this same line ("not the in-band … sentinel — that sentinel only covers a provider that answered with a non-200"). Confirmed by test (see below) rather than assumed.

## Mutation evidence

1. `agent_runner.py`: changed `except Exception as exc:` → `except NameError as exc:` in the non-Concierge branch (never fires on a `ConnectError`). Result: `test_one_on_one_non_concierge_connect_error_yields_branded_copy_no_charge` failed (`data: {"chars": 0}` — the raw exception escaped the generator entirely, `one_on_one.py`'s own catch-all fired, no fallback text). Reverted; 8/8 green again.
2. `brief_engine.py`: same mutation on `BriefEngine.stream_chat`'s except clause. Result: `test_brief_connect_error_yields_branded_copy_no_charge` failed the same way. Reverted; 8/8 green again.

Both mutations were killed by exactly the test written for that fix — no other test in the 281-test run above moved.

## Attack surface (please probe)

1. **Scope boundary correctness** — verify the in-band HTTP-503 sentinel really is pre-existing, working, unrelated behavior, not something this fix accidentally weakened. `test_one_on_one_non_concierge_http_503_is_refunded_no_raw_text` / `test_brief_http_503_is_refunded_no_raw_text` are the controls; consider re-running with the fix reverted to confirm they were ALREADY green before (they should be — this fix touches only the `except` addition, not the existing in-band branch).
2. **`canned_agent_fallback` correctness for the six agents with no `_CANNED` entry** (news_analyst, social_media_analyst, research_manager, aggressive/conservative/neutral_debator) — confirm `MockProvider._DEFAULT` is genuinely branded AMI copy and not empty/generic. `test_canned_agent_fallback_defaults_for_an_agent_with_no_canned_entry` pins this for `RESEARCH_MANAGER` only; consider extending to the other five.
3. **`buf` semantics on a mid-stream failure** — if the provider yields SOME chunks before raising, `agent_runner.py`'s `if not buf:` guard means the fallback is NOT appended (partial real content is kept, no confusing branded-copy-after-partial-real-copy concatenation). Re-verify this is the right UX call for a stream that dies halfway rather than at the very first byte — live drills only exercised the "zero bytes received" (immediate ConnectError) shape.
4. **Live re-drill**: re-run CR004 A3 drill 1 against Alpha with `VLLM_BASE_URL` pointed at a dead port once promoted — confirm the SSE payload now reads branded AMI copy for both a Brief turn and a non-Concierge 1-on-1 turn (e.g. `agent_id=trader`), and that `/v1/billing/*` (or the ledger) shows net-zero credits for that turn.
5. **The `logger.warn` calls added** (`one_on_one_llm_failed`, `brief_llm_failed`) — confirm they don't leak the raw exception text anywhere a user-facing surface reads logs from (they shouldn't — these are backend structured logs only, same shape as the pre-existing `concierge_llm_failed`).
