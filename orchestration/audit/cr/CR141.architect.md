## 2. What shipped

**(a) Usage capture (CR017 §2.4).** The gateway yielded text and dropped the terminal
usage frame, so no cache-hit rate was measurable *from our own data* — CR017's 18.5%
vLLM figure came from the vLLM server's `/metrics`. Now:
`stream_options.include_usage` on the OpenAI-compatible path, `message_start` +
`message_delta` usage on the Anthropic path (Anthropic splits input and output across

providers for DEF125's `finish_reason` — deliberately not a second channel — into
`record_llm_call`. Four nullable `llm_audit` columns via `2a08e21c0dac` on
`e4f5a6b70030`, **no `server_default`, no backfill**.

**(b) Provider registration (§3).** DeepSeek / Qwen / Gemini instantiated when keyed;
new `dashscope_api_key`; all three forwarded in compose. `deepseek_api_key` removed from
`_NOT_FORWARDED` now that a provider actually consumes it.

**(c) Routing layer (§4).** `provider_policy.pick_provider(plan, agent_id, tier)`,
table-driven, consumed by `_pick_provider`.

## 3. The two properties I most want attacked

**Acceptance 2 — NULL, never 0.** A provider that reports no cache field must record
NULL. A zero cache-read is a measurement; a missing one is not (CR040). Verified there
is no `or 0` anywhere on the usage path, and mutation-proven: changing
`"cache_read_tokens": cache_read` to `cache_read or 0` fails
`test_parse_openai_compatible_usage_no_cache_field_is_none_not_zero`. **Please check the
Anthropic path independently** — I mutation-proved the OpenAI-compatible one and reasoned
about the other.

**Acceptance 4 — the routing layer is DORMANT and today's behaviour is bit-for-bit
preserved.** `_pick_provider` consults `provider_policy` only when BOTH `plan` and
`agent_id` are supplied AND the routed provider is registered; otherwise it falls
through to the pre-CR141 `_active_provider_name()` logic unchanged. **No live call site
passes them.** That is deliberate — CR017 §4.4 leaves the plan→level mapping an open
pricing decision and there is no `ultra` SKU — so the mechanism ships and the pricing
call later becomes a table edit.

This is the property most likely to be subtly wrong and it is the one that matters:
Alpha is unkeyed for all three new providers, so **if this is broken, every LLM call on
Alpha changes provider silently.** Attack it directly rather than reading the test.

## 6. Known gaps

- **§5 step 0, prompt-prefix reordering, is NOT here.** CR017 calls it the
  highest-leverage item. It changes the prompt all 12 agents receive and its payoff is
  only observable on melehost and only *once usage capture lands*. Shipping a blind
  behaviour change to every agent to chase an unmeasurable gain is the wrong order. It
  is the next slice.
- **§5 step 5, Anthropic `cache_control` markers**, omitted — pays only on the premium
  band, which Alpha does not route to.
- The routing table encodes CR017 §4.1's matrix, which is itself indicative
  ("confirm at build" per that doc). Prices were not re-verified; the table is a
  mechanism, not a pricing claim.
- No live call site consumes routing, so the whole of (c) is **untested in production
  terms** — it is unit-tested and dormant. If you think a dormant mechanism should not
  merge until something uses it, that is a legitimate finding.
