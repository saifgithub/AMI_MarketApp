## Stated build-lane decisions (the CR left these open — coder decided, I concur)

- **Latest-vs-history: append-only**, read = latest row by `fetched_at`. Fits the CR's defensibility
  argument + is what makes A4 (frozen-mirror freshness) observable. Retention unbounded for now
  (~1 row/day, like `llm_audit`).
- **Hold-window: 30 days** (new `sharia_hold_window_days`), deliberately longer than the 7-day
  `sharia_staleness_days`. Reasoning: the 7-day window existed when a fetch failure hard-blocked
  (DEF093); with the list persisted an outage no longer blocks, so a recorded row is safer to serve
  stale-ish — 30 days keeps every served list inside one quarterly SPUS rebalance while still pausing
  loudly at a month dead. `sharia_staleness_days` (7) repurposed as the source-lag signal.

## Adversarial-focus notes (where to attack this)

- **(a) Seed is the only outage path to UNAVAILABLE.** The reader reads the row, never the source, so
  an outage has zero effect on the reader. UNAVAILABLE-when-enabled arises only from (i) no row (seed
  — `_snapshot_fetcher` raises → paused) or (ii) a held row aged past the 30-day window (A3). Attack:
  find a third runtime path to UNAVAILABLE under an enabled provider. `test_a6_..._is_the_only_outage_path`
  contrasts empty-table-UNAVAILABLE vs same-outage-with-valid-row-PASS.
- **(b) Outage + held in-window row resolves normally showing the held date** — `test_a2_...` patches
  `httpx.Client` to raise, proving the reader opens no socket, and asserts `as_of == held date`.
- **(c) Aged-out held row still pauses** — `test_a3_...` (40d > 30d window → UNAVAILABLE).
- **(d) `fetched_at` advances while `as_of` holds** — `test_a4_...`: two `run_sharia_refresh_tick(force=True)`
  with a fixed `as_of` → two append-only rows, same `as_of`, `rows[1].fetched_at > rows[0].fetched_at`,
  `latest_snapshot` = the later row. This is the frozen-mirror freshness signal made real.
- **(e) The three-state seam is byte-unchanged.** I confirmed the diff on `sharia_universe.py` touches
  NO `resolve` / `HalalUniverse.__new__` / `_build` / `get` / `ShariaStatus.*` line (grep of the
  `+`/`-` hunks is empty for those); all changes are new module-level functions. The 3 accessor
  signatures (`get_sharia_universe_provider` / `default_halal_universe` / `default_halal_universe_async`)
  are byte-identical → the 4 read-path callers are unaffected → `safety_floor`/`sim_engine`/`room_runner`
  need no change. Attack: prove a caller sees a changed contract.
- **(f) The read path opens no socket** — `test_a1_read_resolves_from_row_without_a_socket` resolves
  through the REAL `default_halal_universe()` accessor with `httpx.Client` patched to raise; the
  idempotency guard proves a restart with a fresh row does zero network fetch.
- **Refresh-failure loud on the refresher, not the reader** — `test_refresh_failure_is_loud_on_the_refresher_not_the_reader`:
  N failing ticks raise the counter + fire `sharia_refresh_failing_repeatedly`, while the reader still
  resolves PASS from the held in-window row (CR040 applied to the refresher, quiet on the reader).
