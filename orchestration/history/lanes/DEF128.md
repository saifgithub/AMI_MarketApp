## The gap

CR104 replaced a 13-name allowlist with a **taint-following, deny-by-default** guard: any
`profile[...]` assignment whose value derives from the per-ticker `rng` fails the build. The polarity
is right and it is already proved against single-hop laundering, a two-hop chain, and laundering into
a field name outside any list.

**The traversal is incomplete.** The round-2 auditor reproduced four shapes that still pass **GREEN**:

1. **Tuple unpacking** — `a, b = rng.uniform(...), rng.uniform(...)` then `profile["pe"] = a`
2. **Augmented assignment** — `_v = 0` then `_v += rng.uniform(...)`
3. **A nested helper function** closing over `rng` and returning a fabricated value
4. **A read of the taint-excluded `profile` local** — laundering a value back out of the dict it was
   excluded from

Each recreates DEF123's shape: a fabricated numeric reaching `_format_profile` under a
`(LIVE)`-labelled header. **Nothing is fabricated in production today** — `_profile_for_ticker` uses
none of these shapes — so this is a completeness limit in a guard, not a live defect.

## What I did

Extended the taint-tracking helpers inside
`backend/tests/unit/test_cr104_no_fabricated_numeric_reaches_room_prompt.py` (the ONLY file
touched — `git diff --name-only main` confirms one file, plus the two registry files for the
DEF128 row + regen, committed separately in scope but listed here for completeness):

1. **`_local_name_assignments`** now also yields: each element of a tuple/list-unpacking target
   paired with its source element (or the whole RHS if the source isn't itself a literal
   tuple/list — e.g. unpacking a call), and `AugAssign` targets (`_v += rng.uniform(...)`).
2. **`_nested_function_defs`** (new) collects nested `FunctionDef`/`AsyncFunctionDef` nodes.
   **`_rng_tainted_locals`**'s fixed point now also adds a nested function's name to the tainted
   set if its body references `rng` or an already-tainted name. A call to that function then
   taints the assignment for free — `_expr_is_tainted`'s existing `ast.walk` already visits the
   `Call.func` `Name` node, so no separate Call-handling was needed.
3. **`_expr_is_tainted`** now also treats `profile[<key>]` as tainted when `<key>` is in
   `_EXCLUDED_NARRATIVE_FIELDS` — closing shape 4 (D3): narrative fields are the only place an
   rng-tainted value is legitimately allowed to sit, so reading one back out is the only read of
   `profile` that needs to propagate taint. Reads of any other key (including live protected
   fields like `"pe"`) stay untainted, so `float(profile["pe"])`-style reads elsewhere don't
   false-positive-flood — verified by the fact all 3 original tests still pass.
