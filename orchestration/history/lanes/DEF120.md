## The bug

`backend/app` runs **one uvicorn process, no `--workers`** (`backend/Dockerfile` CMD). `SimEngine`'s
valuation and trade-execution methods call `self.current_quote` **synchronously and internally**, so
the blocking call never appears at the route — which is why DEF116's re-derived call-site table
missed the entire class. Found by emptying DEF116's guard waiver and re-running.

Root shape, `sim_engine.py:271`:

```python
def _marks_with_quotes(self, tickers: list[str]) -> dict[str, Quote]:
    return {t.upper(): self.current_quote(t) for t in tickers}
```

**One sync network fetch per ticker, serially, on the event loop.**

Nine handlers reach it: `sim.py:get_portfolio` / `submit_trade` / `preview_trade` / `reset_portfolio` /
`close_trade` / `evaluate_trades`, `mandate.py:audit_holdings`, `portfolio.py:sector_allocation`,
`room.py:stream_room`. **A larger stall than any site DEF116 fixed, on routes users hit far more often.**

### `get_portfolio` is worse than one pass — it is FOUR

Measured, in-source:

| Line | Call | Reaches |
|---|---|---|
| `sim.py:126` | `sim.current_marks(tickers)` | N × `current_quote` |
| `sim.py:147` | `sim.total_value(user_id)` | `sim_engine.py:386` → N more |
| `sim.py:148` | `sim.current_drawdown_pct(user_id)` | `sim_engine.py:391` → N more |
| `sim.py:149` | `sim.aggregate_source(tickers)` | `_marks_with_quotes` → N more |

Plus three redundant `ensure_portfolio` DB round-trips.

**State this honestly and do not inflate it:** the 60-second `CachingProvider`
(`market_data.py:384-412`) collapses passes 2–4 to cache hits once pass 1 warms it, so the *network*
cost in the common case is ~N, not 4N. The **redundancy is unconditional**, the **blocking is real**,
and on a cold cache the first pass is N × a real fetch with nothing overlapped. Report what you
measure, not the scary number.

## Architect decisions — settled, do not re-open

**D1 — Fix at the `SimEngine` boundary, not at nine call sites.** The route handlers `await
asyncio.to_thread(<sync SimEngine method>, …)`. Nine mostly one-line route changes; no engine
rewrite, no async-ifying `SimEngine`. The engine stays sync — that is what makes it thread-safe to
call this way, and it keeps `market_data.py`'s sync provider stack unchanged.

**D2 — `_marks_with_quotes` must fan out with a PLAIN `concurrent.futures.ThreadPoolExecutor`, NOT
`loop.run_in_executor`.** This is the composition rule and getting it wrong is the trap in this lane.
`sim.py:509`'s `quotes_batch` fan-out is **asyncio-bound** — it needs a running event loop, so it
breaks the moment it is called from inside a `to_thread` worker. Copying that pattern here produces
code that works in a test calling it directly and explodes under D1. Use a sync pool with `.map()`,
no `asyncio` import in `sim_engine.py`'s fetch path at all. It then composes: sync fan-out inside,
one `to_thread` outside.

**D3 — Collapse `get_portfolio`'s four passes into one.** Fetch the marks once, pass them down.
`total_value` / `current_drawdown_pct` / `aggregate_source` need mark-accepting variants (or one
snapshot call) so the route does a single fetch. Leaving four passes "because the cache makes it
cheap" is depending on a cache for correctness of a latency property — and the cold-cache path is
exactly when the user is waiting.

**D4 — Measure the stall, before and after, and report both cold and warm cache.** This defect is
graded as half an MVP show-stopper on the strength of a latency claim. Prove it. A test that times
`get_portfolio` against a provider stubbed with a deliberate sleep, cold and warm, is enough —
you cannot hit live Yahoo from the Mac and should not try.
