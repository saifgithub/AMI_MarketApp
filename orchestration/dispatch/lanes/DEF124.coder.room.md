## Design notes for the audit

- `relative_day_phrase` lives in `app/core/time.py`, not `room_runner.py` — `fundamentals.py`
  already imports `fetch_live_fundamentals` *from* `room_runner`'s dependency graph in reverse
  (`room_runner` imports `fetch_live_fundamentals` from `fundamentals`), so a
  `fundamentals → room_runner` import would cycle. `app/core/time.py` has no service-layer
  imports, so it's a safe shared home; both callers now compute "how many days" identically.
- The Room's earnings-line render condition gained a third clause
  (`profile.get("next_earnings_interval")`) alongside the existing date-presence and
  `field_state` checks — this is the acceptance-6 guarantee made structural. Two existing tests
  (`test_format_profile_includes_forward_eps_estimate_when_present`,
  `test_format_profile_includes_earnings_when_present`) needed `next_earnings_interval` added to
  their hand-built profiles to keep rendering the line at all — both updated, both still assert
  the same substrings.
- Did not touch `_forward_catalyst_text`'s signature or the FOMC line — it already had the
  correct pattern (that's *why* DEF124 says "copy it"); the shared `today` computed once in
  `_profile_for_ticker` is now threaded into it (`_forward_catalyst_text(today)` instead of
  `_forward_catalyst_text()`), so the FOMC countdown and the earnings interval can never
  disagree about what day it is, mid-render.
- Did not touch `docs/defect/DEF124_room_prompts_have_no_date_anchor/` (spec doc) — it's already
  accurate to what shipped; only the registry row needed a status flip.
