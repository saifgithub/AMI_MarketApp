## Round 2 (coder.api) — D9, one MAJOR closed

**Branch:** continued on `lane/DEF120.coder.api` in the existing worktree, off round 1's audited
`cec80c9`. One commit: `93c6b84`.

**Read first:** `orchestration/audit/cr/DEF120.auditor.md`. Round 1's fix itself was not re-opened —
the auditor could not fault the fan-out, the thread hop, the four-pass collapse, or D2/D5/D7. The one
MAJOR: `_marks_with_quotes` hands `current_quote` to `pool.map` **by reference**, so the route-level
walker (which only follows `ast.Call` nodes) goes blind past that hop. Round 1's own remedy for this —
naming `portfolio_marks_snapshot`/`valuation_snapshot` in `_BLOCKING_LEAF_METHOD_NAMES` — closed the
two names that broke, not the mechanism. The auditor reproduced a third: a fresh `SimEngine` method
(`audit_probe_snapshot`) reaching the network via `_marks_with_quotes`, called directly from
`sector_allocation` with no `to_thread` → **7 passed, green.**

**D9 — single-file, deny-by-default assertion over `SimEngine` itself.** Added
`test_every_network_reaching_simengine_method_is_declared` to
`backend/tests/unit/test_no_blocking_io_in_async_routes.py` (same file, no new file). It does not walk
*into* the engine from routes — it walks `SimEngine`'s own methods against each other, using attribute
**references** as edges (not just calls), so a leaf handed to `pool.map` by reference is exactly as
visible as one called directly. Every method that transitively touches
`self._provider.<quote|history|news|earnings>` is "network-reaching" and must be declared in one of
two sets:
- `_BLOCKING_LEAF_METHOD_NAMES` (existing set) — an async route may call it directly, every call site
  must be `to_thread`-wrapped.
- `_SIM_ENGINE_SYNC_SAFE_METHODS` (new) — never called directly from an async route; only reached from
  inside an already-`to_thread`-wrapped method. Populated with the 11 methods this is currently true
  for (`current_price`, `current_marks`, `current_marks_with_source`, `_marks_with_quotes`,
  `aggregate_source`, `total_value`, `current_drawdown_pct`, `submit`, `preview`,
  `evaluate_outcomes`, `manual_close`), verified by grep over `backend/app/api/*.py` — none of the
  first seven appear after `sim.` in a route file at all; the last four do, always behind
  `to_thread`.

A method in neither set is **undeclared**, and undeclared fails red — no allowlist to extend, the new
method just isn't in either set until a human puts it there.
