## Why this lane exists as its own lane

Chunks carry a short evidence list; they do not render the DoD. Most DoD rows are honestly
unanswerable at chunk scope — a chunk cannot update a register row or close a defect — so if chunks
rendered the table, every submission would arrive with a column of `N/A`s, an auditor would learn to
wave `N/A`s through, and the rule that *a false `N/A` is a MAJOR* would be dead by the time it
reached the only gate where it matters. The DoD belongs here.

## The DoD is filled in by a FRESH agent — never by a chunk author

`coder.api` and `coder.mobile` are disqualified from filling this in for their own work. A worker
grading itself inherits its own blind spot; that is how a defect ships with two guards that only
catch the exact phrasing their author had already thought of. The Architect spawns a fresh agent,
hands it `orchestration/DEFINITION_OF_DONE.md` and the CR document, and **does not tell it what it
thinks the answers are**.

**Never economy tier.** A cheap grader returns a confident, unearned pass — worse than no grader,
because it manufactures false confidence instead of leaving a visible gap.

## What the terminal audit must check that no chunk audit can

1. **Decomposition completeness.** Diff the delivered chunks against the CR document. Five chunks
   were written down before any was dispatched (`CR069-BE`, `-MOBILE`, `-DIVERGE`, `-MY`, `-VENDOR`);
   a sixth that should have existed and does not is precisely the hole this gate can catch and a
   chunk gate structurally cannot.
2. **The claim matches the mechanism, end to end.** DEF084's unbuilt guard, generalized: the ARB
   copy, the API verdict, the safety-floor enforcement and the agent narration must all name the
   same standard, the same source and the same as-of date. **Three surfaces contradicted each other
   in DEF084** — deterministic path, mobile copy, and agent narration (DEF084-BE / -MOBILE / -ROOM
   were one defect across three surfaces). Check all three, including
   `overlay_generator.py`, which no CR069 chunk touches and which asserted a Sharia screen at three
   sites last time.
3. **The third state survived integration.** Constraint 2 is the one most likely to be quietly lost
   between a backend that returns `unknown` and a UI that renders it as a rejection. Exercise it.
4. **Nothing silently fell back.** Constraint 3, fourth occurrence of the degrade-loudly class. Kill
   the source and confirm the flag pauses **visibly** on both surfaces rather than answering from a
   stale set or the old 7-ticker list.
5. **`sharia_screen()` is still dormant.** Constraint 4. If any chunk wired the three-ratio math to
   guessed inputs, that is a BLOCKER regardless of test results.
