## What and why

Saiful, twice — bug report `583602ee` on `+57`, and again 2026-07-29 after `+58` shipped:
*"when the room is running, we are still getting the full text displayed to the user. we are
supposed to only show the status of what is running."*

**CR106 fixed the destination and left the journey.** It restructured the *finished* run — Verdict
Board, collapsed transcript, both surfaces — and never touched the live stream. So during the ~40s
convene the user is still fed the same 3,500–6,000 chars over 12 turns that CR106 was filed to stop
presenting all at once. That is why the complaint survived the fix.

**The site is exact.** `room_screen.dart:191-202`: when `settled` is false the screen renders
`_AgentLine(agentId:, text: state.transcript[agentId] ?? '', active:)` per agent — the growing
prose. When `settled` is true it already renders `RoomTranscriptRows` (CR106's collapsed rows).
Only the `else` branch changes.

## Scope — both halves

Ruled by Saiful at the 0900 check-in as *"Status + the agent's headline as it lands"*. The headline
half depends on the CR106 B2 stance envelope being reliable. **That gate is now cleared, measured on
live traffic — you do not have to take anyone's word or the row's number for it.**

The REL58 auditor parsed 308 live prose-agent room turns from `llm_audit` over 7 days, using the
**shipped** parser:

- **Post-DEF147 (2026-07-29, 88 turns): 2 null, 2.3%.** Both `research_manager`, and in both the
  envelope is simply **absent** — not truncated, not malformed — which is the case
  null-is-not-neutral was designed to handle.
- Pre-fix under that same parser: **132/132 no-parse**, with only 17% of turns even attempting an
  envelope. The old "27%" was an artefact of the previous end-anchored ruler, so the real pre-fix
  rate was far worse than the row claimed and the front-of-turn fix is measured working.

**So the headline is IN this lane.** ~2% of turns will have no stance; that is a case to render
honestly, not a reason to withhold the feature. **A null stance must render as an explicit
not-recorded state — never as neutral, never as an empty gap that reads as "no opinion".** That
inversion is DEF059's shape and it is the one thing here that must not be got wrong.

## What to build

1. **Per-agent status, not prose.** Each roster entry moves `waiting → thinking → responded`. The
   agent's text does not stream. `state.transcript[agentId]` is still populated — you are changing
   what is *rendered*, not what is received.
2. **Auto-scroll goes.** `_scrollToBottom()` (`room_screen.dart:70`, wired at `:87` off
   `transcript.length`) exists to pin the user to growing text. A fixed roster has nowhere to
   scroll to. Remove the behaviour, not just the call — a listener that fires on every token and
   does nothing is worse than none.
3. **Nothing is lost, and say so if the UI needs to.** The full text is reachable the moment the run
   ends via TRANSCRIPT and the per-agent peek sheet CR106 already built. This stops the prose being
   *pushed*, not being *available*.
4. **The headline lands with the status, and the data is already in state — this is render-only.**
   I traced it so you do not have to: `room_providers.dart:222-244` already parses `agent_done` into
   `state.agentStances[agentId]` as an `AgentStance(stance, conviction, headline, recorded)`. So when
   an agent flips to `responded`, its one-line headline is available in the same frame. **Do not add
   a backend field, a new event, or a second parse** — if you find yourself editing
   `room_providers.dart`'s SSE handling, stop and disclose, because that is CR106's and it means I
   have mis-scoped this.

   **`recorded` is the field that keeps this honest, and it is already correct.** It is
   `ev.containsKey('stance')` — the *presence of the key*, not the truthiness of the value. Three
   states, and they must render as three:
   - `recorded == false` → this run does not carry stances at all (pre-B2 run). Show status only.
   - `recorded == true`, `headline == null` → the agent finished and stated none. This is the ~2%.
     It must read as **stated nothing**, not as neutral and not as a blank that looks like a
     rendering bug.
   - `recorded == true`, `headline` present → show it.

### Two behaviours to specify, not inherit

- **A withheld or errored agent must reach a terminal state that is visibly NOT "responded".**
  `state.withheldAgents[agentId]` already carries CR098 D1's disclosure and the existing
  `_WithheldAgentChair` already renders it in both branches — keep that. What needs deciding is the
  **errored** case: an agent whose turn fails must not sit on `thinking` forever, and must not
  silently read as `responded`.
- **A truncated turn must not read as a clean completion.** DEF125 marks a length-stopped turn
  `[AMI: ...incomplete]`. In prose that marker is visible; a bare `responded` chip hides it. Decide
  and state what the row shows for that case.

## Acceptance

   `transcript` entries — the test must prove the text is present in state and absent from the tree.
2. Each roster entry renders `waiting`, `thinking` and `responded` for the correct agent at the
   correct time, driven off `state.activeAgent` and `state.transcript`.
3. The settled branch is unchanged — `RoomTranscriptRows` still renders after the run, with the
   full text reachable.
4. A withheld agent still shows its CR098 disclosure during the live run.
5. An errored agent reaches a terminal state that is not `responded`, and the test names it.
6. A DEF125-truncated turn does not read as a clean completion.
7. No scroll listener fires on transcript growth. Assert the absence of the behaviour, not just the
   deletion of one call.
8. **The headline renders on `responded`, read from `state.agentStances`, with no new stream
   parsing.**
9. **All three `recorded`/`headline` states render distinguishably, and the test asserts they differ
   from each other** — not merely that each one renders something. A test that only checks "no
   crash" passes when *stated nothing* and *neutral* look identical, which is the exact failure this
   acceptance exists to prevent (DEF059's inversion). This is the criterion I most expect to be
   satisfied vacuously, so it is the one I will read first.
10. **Zero diff in `mobile/lib/state/room_providers.dart`.** If the headline needed a change there,

## Architect's ruling on the round-1 disclosures (2026-07-29, post-build, pre-verdict)

The lane asked for two things to be ruled rather than assumed. Recorded here rather than in
`CR112.architect.md`, which is the coder's bridge under DISPATCH_PROTOCOL §6 — the auditor should
have both files.

**1. Withheld-chair seating moved from arrival order (`state.order`) to canonical roster order
(`kAllAgents`). ACCEPTED, and it was the right call.** Arrival-order seating means a seat *moves*
when some other agent finishes — which is the same churn this CR exists to remove, one level down.
A roster that reorders itself is a growing list wearing a roster's clothes, and the acceptance
"a fixed roster has nowhere to scroll to" is not satisfiable while rows reshuffle. The lane was
right to flag it as a real behavioural change and right on the merits; **auditor, please still
verify it independently rather than take my agreement as clearance** — it changes where a withheld
chair sits relative to a real agent's row, and CR098 D4's disclosure guarantee rides on that.

**2. `roomAgentThinking` is an orphaned ARB key — minted in all three locales, rendered nowhere.**
Do not fix it in this lane; it is minted as **DEF174**. The orphan is the visible residue of a real
gap: the `thinking` state is a pulsing dot with no text and no semantics label, so a screen reader
is told nothing during a convene — CR112 removes the prose that was previously the only thing a
screen reader *could* read. That is broader than this branch (it is the pre-existing `_RosterRow`
convention) and is scoped to DEF174 accordingly. **The key stays in the ARBs for now** so the
translation flag and the fix land together rather than the key being deleted and re-minted.
