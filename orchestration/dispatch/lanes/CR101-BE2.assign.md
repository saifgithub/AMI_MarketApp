## What and why

CR101, and Saiful directly: *"we had a CR related to 4 additional risk parameter to be set for the
customer."* These are those four. **Measured on `main` at `73a25c7f`: none of them exist in any
form** — no schema field, no enforcement, no overlay reference, nothing to reconcile. Unlike
CR101-BE1's two caps, there is no legacy behaviour to preserve here; there is only the invariant to
satisfy from scratch.

The four:

1. **Post-loss cooldown** — after a stop-out, a self-imposed pause before the next entry.
2. **Max open positions** — a ceiling on concurrent holdings.
3. **Max trades per day / per week** — an over-trading brake.
4. **Total open risk cap** — the sum of (position size x stop distance) across open positions.

These are not invented: ~6 lessons (DEF102) and ~26 daily challenges (DEF117) already **teach** them
as if the Mandate enforces them. That is the "phantom mandate" cohort. Saiful ruled **build, not
strip** (2026-07-27), which is why the lesson-strip of that cohort was halted.

## The invariant — every one of the four, no exceptions

A Mandate field feeding an enforced limit is **(a) enforced deterministically, (b) disclosed to the
user in its own units, (c) disclosed in the agent overlay, (d) settable** — or it is **deleted**.
No third state. A field that is settable but unenforced is **DEF129's failure with better UX**: a
promise the system does not keep. A field that is enforced but not settable is what CR101 was
amended to abolish.

## What to build

- **Schema**: four fields on `Mandate` (`backend/app/schemas/mandate.py`), each with an explicit
  unit in its name or type, each defaulting to a value that is **off / non-binding** so no existing
  user's behaviour changes on deploy.
- **Enforcement**: deterministic, in the PM compliance check — **same rigor as the halal floor, not
  prompt-level**. CR038 measured that agents ignore even emphatic prompt instructions ~70% of the
  time; if it must hold, it is structural. `agents/safety_floor.py` is the site.
- **Overlay**: thread all four through `agents/overlay_generator.py` in their own units, so the PM
  reasons from the user's actual numbers. **Interpolate the constants — no numeric literals in agent
  prose** (`safety_floor.py:30-35` explains why; shared constraint with **CR105** item 2).
- **Retro-tightening is DEFINED and is not a free choice:** when a user tightens a limit below what
  their current portfolio already satisfies, **flag the affected holdings and block new buys —
  never force-sell.** Reuse the BL12 holdings-audit path that already exists for mandate PATCH.
- **Reuse, do not rebuild:** PATCH already bumps `version`, writes a `MANDATE_EDIT` journal entry,
  and `POST /rollback/{v}` restores it (BL5). Only the plain-English diff needs extending to
  describe the new fields.

## Fences

- **Do NOT touch `mobile/`.** UI is CR101-MOBILE.
- **Do NOT re-do CR101-BE1's two caps** (sector, single-name). They land before you.
- **Do NOT introduce a ceiling on what the user may set.** L3 is decided: no ceiling, loud
  disclosure. In a simulation-only trainer the blow-up IS the lesson; hiding the dial is the
  opacity CR040 exists to stop. A looser-than-preset value must show its consequence at set-time.
- **Cooldown hard-block vs soft-warn was an OPEN design question in CR089 and it is now decided:**
  hard-block the entry, and say plainly what is blocked and when it lifts. A soft warning on a
  self-imposed discipline rule is the "prompt instructions are not controls" mistake in UI form.
- **Registers:** row file and regenerated table in the SAME commit (**DEF159**).

## Acceptance

1. Each of the four is enforced by a deterministic check that a test can drive to **block** —
   four separate tests, each naming the limit it exercises.
2. Each of the four is disclosed in the agent overlay in its own units, with **no numeric literal**
   in the prose. A test greps the generated overlay for the interpolated value.
3. Each of the four is settable via PATCH and survives a round-trip.
4. **Defaults are non-binding**: a test proves that a mandate created without these fields produces
   byte-identical enforcement to pre-change behaviour. No user gets silently constrained on deploy.
5. The four-leg guard test from **CR101-BE1** now enumerates these four as well and passes. If BE1's
   guard does not automatically pick them up, that is a defect in the guard — fix it and say so.
6. Retro-tightening: a test tightens a limit that the current portfolio violates and proves the
   result is **flag + block new buys**, and specifically **not** a forced sell.
7. Over-trading limits are evaluated against a **clock the test controls** — no reliance on real
   wall-clock time, and the day/week boundary is pinned by a test that names the timezone basis.
8. Mutations: for each of the four, revert its enforcement and show its acceptance-1 test go RED.
   Report all four, honestly, **including any that come back GREEN**.
9. Full backend suite green — `"./backend/.venv/bin/python" -m pytest backend/tests/unit/ -q` from
   repo root, ~250s. `python` is not on PATH. Never `pytest -x`. Baseline is BE1's post-merge count,
   not 1589 — state the number you started from.
