## The gap

CR104 replaced a 13-name allowlist with a **taint-following, deny-by-default** guard: any
`profile[...]` assignment whose value derives from the per-ticker `rng` fails the build. The polarity
is right and it is already proved against single-hop laundering, a two-hop chain, and laundering into
a field name outside any list.

**The traversal is incomplete.** The round-2 auditor reproduced four shapes that still pass **GREEN**:

1. **Tuple unpacking** — `a, b = rng.uniform(...), rng.uniform(...)` then `profile["pe"] = a`
2. **Augmented assignment** — `_v = 0` then `_v += rng.uniform(...)`
3. **A nested helper function** closing over `rng` and returning a fabricated value
4. **A read of the taint-excluded `profile` local** — laundering a value back out of the dict it was
   excluded from

Each recreates DEF123's shape: a fabricated numeric reaching `_format_profile` under a
`(LIVE)`-labelled header. **Nothing is fabricated in production today** — `_profile_for_ticker` uses
none of these shapes — so this is a completeness limit in a guard, not a live defect.
