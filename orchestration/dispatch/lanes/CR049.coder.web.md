## Round 2 — fixed the audit's MAJOR + MINOR (AT:R65)

Round 1 tip `1830e2a` + two new commits: `49ba614` (MAJOR fix + guard), `d2c648c` (MINOR fix).

**MAJOR — blocking synchronous HTTP in async routes.** `turnstile.py::verify_turnstile` and all of
`email_service.py`'s send functions made **synchronous** `httpx.post()` calls, invoked directly (no
threadpool) from `async def` route handlers on a no-`--workers` uvicorn process — every call parked
the single event loop for the whole network round-trip, so one slow Turnstile/Resend request stalled
*every* concurrent request. Same class as CR036's backend show-stopper — second occurrence, so this
earns a guard per CLAUDE.md.

**Chose `httpx.AsyncClient`** over making the routes sync `def`: the routes are already `async def`
and the concierge route in particular needs to interleave with SSE streaming for other concurrent
users — a threadpool caps concurrency at pool size instead of actually removing the block, and mirrors
`llm_client.py`'s already-correct `AsyncClient` pattern in the same codebase (an inconsistency, not
unfamiliarity). All 4 call sites (`turnstile.py`, `email_service.py`'s `send_email` + its 4 wrapper
fns) converted; all 3 route handlers (`concierge_message`, `submit_contact`, `submit_data_request`)
and the `contact.py`/`data_request.py` callers updated to `await`.

**Guard added:** `website_api/tests/test_no_blocking_io_in_async_routes.py` — walks the static AST
call graph from every `async def` route handler in `app/routes/` and fails the build if it can reach
a direct `httpx.<verb>()` call (not through `AsyncClient`). **Demonstrated failing**: temporarily
reverted `turnstile.py` to the sync-call pattern → guard correctly flagged all 3 routes
(`data_request.py:submit_data_request`, `concierge.py:concierge_message`, `contact.py:submit_contact`,
each `-> httpx.post (via verify_turnstile in .../turnstile.py)`) → reverted the demo, re-ran clean.

**Checked for other blocking I/O**: `grep -rn "requests\.|urllib\.|socket\.|time\.sleep|smtplib"
app/` across all of `website_api/app` → zero hits. No other blocking network/sleep calls in the
website stack.

**MINOR — "the AI" in visitor-facing copy.** `sad-to-see-you-go/index.html:71` "the AI
trading-education app" → "the AMI trading-education app". Re-ran `\bthe AI\b` across **all 9** HTML
files under `website/` (the entire visitor-facing surface, confirmed by `find . -name "*.html" | wc
-l`) — this was the only genuine hit; the 4 "the AI Coach corpus" hits in `terms/*/index.html` are
the legitimate proper noun already cleared by round-1 audit.
