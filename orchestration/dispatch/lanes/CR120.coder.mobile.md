## A real bug this measurement forced, not a pre-existing thing I chose to ignore

Acceptance 1's *measured, not asserted* requirement caught a genuine overflow risk in `_ValueCard`'s P&L row: `Row([Icon, Text(pnlText), Spacer(), Text(CASH), Text(cashValue)])` — a bare `Text` next to a `Spacer` has no width bound (`Spacer` only claims leftover space, it does not shrink siblings), so a long enough P&L string threw a `RenderFlex overflowed` error under the test's font metrics. This card is pinned on every tab, so it's directly in scope for acceptance 9 ("nothing clips at 1.15"). Fixed with `Flexible` + ellipsis on both the P&L text and the cash value. I did not independently verify this was reachable in production with the real bundled font (test-environment font substitution may exaggerate string width vs. the shipped font) — but a `RenderFlex` overflow is a hard error either way, and `Flexible`+ellipsis is strictly safer than the previous unbounded `Text`, so I fixed it rather than treating it as a test artifact.
