## Rules checked

- No `?? default` on a required field — required fields use `as Type` (throws on
  missing/renamed key); nullable fields use `as Type?`. See
  `test/models/sim_cr100_contract_test.dart`'s "missing required key throws" cases for
  all three contracts.
- Nullable-means-absent: `unrealisedPnl` null on a closed lot renders "—", not 0.00;
  `maxSectorName` null stays null (tested); both dividend fields null hides the chip (tested).
- `max_allowed` read from the response (tested with a non-default 0.60 mandate value).
- "Other" never a breach — structural: the breach line only ever reads
  `compliance.maxSectorName`, which the backend contract guarantees excludes "Other"; a
  dedicated test asserts the model doesn't invent "Other" as a breach name either.
- AMI-by-name: no new user-visible string says "the AI".
- i18n: all new strings in `app_en.arb` with `@key` translator-context descriptions; AR/MS
  untouched (`l10n.yaml` falls back to English for missing keys — confirmed via `flutter gen-l10n`
  output, "14 untranslated" on ar/ms, zero errors).

## What I did NOT verify — explicit, for the auditor

- **No widget-level pump test** for `_DividendChip`, `_LotsSection`/`_LotCard`, or
  `_SectorAllocationCard`/`_DonutPainter`. `ApiClient` has no seam to inject a fake `Dio`
  response in this codebase's existing test setup (checked: `sharia_verdict_test.dart` only
  widget-tests a banner given a hand-built model, never a provider chain hitting
  `ApiClient`/`Dio`). Coverage here is: (a) model-layer contract tests (real-shaped JSON →
  model, including the null/nullable/hidden-chip cases), (b) `flutter analyze` clean on every
  touched file, (c) manual code read of the three new widget trees against the acceptance
  bullets. I did not run the app on a device or simulator (Mac is a pure editor per CLAUDE.md;
  this lane's assign also says not to build to a device).
- **No live capture from Alpha.** All three fixtures were transcribed by reading the backend
  source files directly (paths/line numbers cited in the test file's docstring), not by curling
  `https://api-alpha.agenticmarketintel.ai`. I did not independently confirm those source files
  match what's actually deployed on Alpha right now — worth a spot-check
  (`curl -s https://api-alpha.agenticmarketintel.ai/v1/sim/earnings/AAPL` etc., with a real
  bearer token) if the auditor wants belt-and-suspenders on drift between `main` and the running
  container.
- **Donut color-blind legibility** not checked — 8-color hash-based palette (`_sectorColor`) could
  in principle collide two similarly-colored sectors adjacent in the ring for an unlucky hash; low
  stakes (legend carries the text label regardless) but not verified visually.
- **`_LotCard` date parse fallback** (`entryDate` string shown raw if `DateTime.parse` throws) —
  exercised in the "missing required field throws" test only for the whole-response case, not for
  a syntactically-invalid-but-present `entry_date` string specifically.
