## The bug

The model is asked to do date arithmetic **without one of the operands.**

Measured on run `1906ccf2` (2026-07-27, BBAI, 12/12 agents, zero errors): the fact sheet's last line
read `Next earnings (LIVE): 2026-07-30 (Q3)` — **3 days away**. The News Analyst wrote *"leaving a
13-month void of reported data"*; the Research Manager wrote *"no earnings data for 13 months"* and
*"no clear catalyst until mid-2026"*. Because the RM synthesis is what EXECUTION, RISK and VERDICT
reason from, the invention became the Room's premise, and **the PM's recorded verdict reason** cites
*"the absence of earnings data until 2026-07-30 leaves the trade reliant on speculative sentiment."*

**0 of 12 prompts in that run contain `2026-07-27`.** Across 30 days, **2 of 9,789** `flow='room'`
prompts contain any date outside the earnings line. The grounding directive forbids the model
recalling a date, so it guesses — and a 2026 date reads as distant future against a training cutoff.

**This is not a model failure.** Like DEF123 it is upstream: we handed it an absolute date and no
"today". CR038 is the governing rule — *hand it the computed value, don't ask it to compute*.

## The fix already exists in the same file — copy it

`_forward_catalyst_text()` renders the FOMC date **relatively** (`FOMC decision in 2 days`) and
**four agents quoted it correctly** in the same run that got earnings wrong. Half the Room's dates
are anchored, half are not. Make the other half match.

## Architect decisions — settled

**D1 — Render the interval, and keep the absolute date.** `Next earnings (LIVE): 2026-07-30 (Q3) —
in 3 days`. Not one or the other: the absolute date is what a user cross-checks, the interval is what
stops the model guessing. Compute the interval in Python; never ask the model for it.

**D2 — State the run date ONCE, in the fact-sheet header.** One anchor for every other absolute date
in the prompt, so this class cannot recur field-by-field. **Coordinate with CR104** — it is making
that header true by construction; the run date is a fact with a real provenance (the clock), so it
belongs in the same per-field scheme rather than bolted beside it.

**D3 — Sweep the renderers that share the profile.** The defect row names the 1-on-1 and Brief Your
Agent paths. Same profile, same missing anchor. Fix them or state explicitly why one does not apply.

**D4 — Timezone must be explicit and stated.** "In 3 days" computed in UTC against a market date is
off by one for part of the day. Pick the basis, state it in the rendered string or in-source, and
test the boundary. An off-by-one interval is the same class of bug with a smaller number.

**D5 — Assert on the RENDERED PROMPT STRING.** Not on a helper's return value. DEF123's whole lesson
is that the rendered artifact is the product; a green helper test next to a wrong prompt is what got
us here.
