## The finding (measured, in the spec — do not re-derive)

narrated was wrong, and nothing in the Room caught it. One-step arithmetic (a % difference between
two given prices) was fine. SCHD: narrated `R:R 2.5:1`, actual **0.2:1** (12.5× overstated) on a
2.3%-up / 9.6%-down setup — **and the PM APPROVED it**. VGK: narrated `R:R >2:1`, actual 1.4:1;
drawdown `~2.5%`, actual 0.078 pt (32× overstated). Full table in the spec.

## Why nothing caught it — three fix sites, all coder.room

1. **The coherence check inspects only the PM.**
   [`_pm_rr_coherence_signal`](../../../backend/app/services/room_runner.py#L587) (room_runner.py:587-604;
   the spec's working title `_rr_incoherence_flag` — the real name is this) is called at
   [room_runner.py:1477](../../../backend/app/services/room_runner.py#L1477) on the **PM APPROVE path only**.
   Line 601: `if stated is None or rr_is_coherent(...): return None`. SCHD's PM narrated no ratio → `stated
   is None` → silent pass. Meanwhile the **Trader's** `R:R: 2.5:1` — the number that actually drove the
   debate — is free prose in EXECUTION, inspected by nothing.
2. **Even when it fires, it's telemetry.** Its docstring: *"Flag only — the safety floor owns vetoes."*
   It emits a `room_pm_rr_incoherent` log warning (room_runner.py:1481) and nothing reaches the user or
   the transcript. A user reads `R:R: 2.5:1` on a 0.2:1 trade with no annotation.
3. **The Trader is structurally starved of its own derived figure.**
   [room_prompts.py:214-216](../../../backend/app/services/room_prompts.py#L214) —
   `proposal = trade_proposal if phase in ("RISK","VERDICT") else None` (DEF066) — so the Trader
   (EXECUTION) is the one agent that proposes levels and never receives the computed
   `drawdown_contribution()`. It was required to invent one, and did.

**Contagion vector:** the Trader speaks in EXECUTION; the three Risk debators and the PM read its output
as `Transcript so far:`, so a wrong ratio becomes the premise the whole Room reasons from (the Neutral
Debator already quotes it back). A fix that only annotates for the user but still feeds RISK/VERDICT the
narrated number leaves the debate poisoned — fix the transcript the downstream agents consume, not just
the display.

## Build (you decide the exact shape; these are the required properties)

Per **CR038** the robust fix is structural — *remove the opportunity to miscalculate*, don't instruct
the model not to. An emphatic "compute R:R correctly" is not a control.

1. **The system computes every derived ratio from the Trader's own levels, and that computed figure is
   what the Room and the user see.** After the Trader emits entry/stop/target, parse them, compute
   `risk_reward()` + `drawdown_contribution()` (+ `trade_asymmetry()` if useful), and surface the
   **computed** value into the transcript that RISK/VERDICT read — the same way
   [`_drawdown_snapshot_line`](../../../backend/app/services/room_prompts.py#L117) already injects the
   derived contribution for RISK/VERDICT. The Trader may state levels; it must not be the source of
   record for the ratio.
2. **Generalise the coherence check beyond the PM to any agent that proposed levels**, and make
   `stated is None` on an agent that *proposed levels* a **flagged** condition (the system should have
   rendered a ratio and didn't), not a silent pass. Keep it flag-only for the safety floor's authority
   (it must not start vetoing — DEF059), but its output must now reach a surface, not just a log.
3. **Surface in the transcript, not telemetry.** An incoherent narrated ratio is annotated in the
   transcript (or the narrated figure is replaced by the computed one) so both the user and the
   downstream agents see the truth. Telemetry nobody reads is not a control (CR040 degrade-loudly — the
   machinery exists and returns `None` on the path that matters).

The narrowest, most robust end state (CR038): the Trader emits levels only; the system renders R:R,
drawdown, and upside/downside for every proposal. If you keep the Trader stating a ratio, it MUST be
checked and, when incoherent, corrected before it enters the transcript.

## Guard (mandatory — the deliverable's spine, §Guard)

1. Feed a **known-incoherent** Trader proposal (SCHD's numbers: entry 32.75 / stop 29.60 / target 33.50,
   narrated `R:R 2.5:1`) through the Room and assert the R:R figure a **downstream agent receives** is the
   computed `0.2:1`, not the narrated `2.5:1`. Prove it **red first** (today it's the narrated one).
2. Assert no agent output carrying an `R:R:` line reaches the transcript without having been checked
   against `rr_is_coherent()` — i.e. an incoherent ratio cannot survive unannotated.

Both are the DEF084 shape: a number that looks authoritative and is wrong, that every existing test
passes over.
