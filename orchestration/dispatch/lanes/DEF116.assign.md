## The bug

One uvicorn process, one event loop. Several `async def` handlers call **synchronous**, network-bound
functions inline (yfinance, `httpx.Client`) with no thread offload. Each 1–3s+ call freezes the whole
loop — every other user's SSE stream, LLM token relay and unrelated API call queues behind it. Fires
on **every Room convene** and **every 1-on-1 turn mentioning a ticker**.

Saiful graded it an **MVP show-stopper**: near-harmless at Stealth Alpha (10–20 invite testers rarely
overlap), total at public launch where concurrency is the point.

## Architect decisions — settled

**D1 — `asyncio.to_thread` at the CALL SITE. Not a new `ThreadPoolExecutor`, not `async def` leaves.**
This is already the codebase's pattern (`sharia_universe.py:512-521`,
`classification_universe.py:508-513`, `main.py:100,117`, each justified in-source with "the one
uvicorn process serves every concurrent request"). Follow it.

**D2 — Every leaf function stays plain synchronous and untouched.**
`_profile_for_ticker`, `build_live_data_block`, `build_news_context_block`,
`build_social_context_block`, `build_technicals_context_block`, `SimEngine.current_*`. This is what
keeps ~15 existing `monkeypatch.setattr` tests working — patching still works from inside a
`to_thread` worker because it is the same process memory. **Making a leaf `async def` breaks those
tests and is explicitly out of scope** (the intake calls this out as a separate latency optimisation,
not this correctness fix).

**D3 — Do NOT parallelise the 5 sequential fetches inside `_profile_for_ticker`.**
Tempting (~5-10s → ~1-2s) but it requires making it `async def` (see D2) and it is a *single-user
latency* optimisation, not the *cross-user concurrency* fix this defect is about. Different problem,
different decision, not yours.

**D4 — Do NOT fold in the Alpaca snapshot.**
`alpaca_service.py:77,113` (via `alpaca_snapshot_text`, called from `room_runner.py:1557` and
`agent_runner.py:145`) has the **identical** pattern. It was found incidentally, outside scope, and
needs its own decision. **Flag it in your hand-off** — if your guard catches it (it should), say so
explicitly and leave it failing-but-excluded or mark it with a documented, narrowly-scoped waiver.
Do not silently widen scope, and do not silently suppress the guard.

**D5 — Do NOT propose multi-worker uvicorn.**
Single process is deliberate: `BriefEngine._sessions` (`brief_engine.py:182`) and
`AgentRunner._sessions` (`agent_runner.py:66`) are process-local in-memory stores that multi-worker
would break. Out of scope.
