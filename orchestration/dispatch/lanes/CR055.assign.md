## Context (diagnosis already verified by the Architect — build on it, re-confirm before leaning)

A brand-new user convened the Room for SCHD; the Trader refused to buy, asserting the user "already
holds a 10–15% allocation" — the user held **nothing**. Root cause: the only holdings block
(`alpaca_snap`) is injected **only if `urow.alpaca_access_token` is set**; a new user has none →
`alpaca_snap = None` → **zero holdings data in any prompt** → the model fabricated a holding from the
only number on the table (the researchers' *proposed* 10–15% size). The real portfolio is already
computed (`sim.total_value`) but only the aggregate is passed down — `sim.list_trades` / the holdings
list is **never rendered into any prompt** (confirmed: no such call in `room_runner.py` today).

**Caveat to re-confirm:** the CR quotes a base role-prompt promise *"You know: the user's current
portfolio"*. That exact string no longer greps in the prompt files (may have been reworded since the
CR was filed 2026-07-21). The fix does not depend on it — agents are blind on holdings regardless —
but locate the current wording before relying on the "promise-vs-silence" framing in any comment.

## Build

1. **Sim-sourced holdings block (the fix), injected UNCONDITIONALLY.** Add a builder (mirror the
   contract of `alpaca_service.snapshot_text` — a pre-formatted text block) that reads the user's
   **open** positions via `sim.list_trades(user_id, status=OPEN)` + cash / `sim.total_value(user_id)`
   and renders a compact block, e.g.:
   ```
   --- YOUR SIMULATED PORTFOLIO ---
   Cash: $100,000.00 | Portfolio value: $100,000.00
   Open positions: none — you hold nothing yet. Any BUY here opens a NEW position.
   ---
   ```
   For a user WITH holdings, list them (`SYMBOL ×qty (weight% of portfolio, unrealised ±$)`) and —
   critically — state the weight of **the ticker under discussion explicitly** (`0%` when not held),
   so no agent has to infer "do we own this?". Inject it for **every** Room agent through the existing
   `build_agent_prompt` snapshot slot, **unconditionally** — a new user gets the explicit "none"
   block, never silence. AMI by name in any user-facing string; this is a system block, so no "AI".
2. **Degrade loudly (CLAUDE.md / CR040 — this is the exact bug that silence caused).** If the sim
   holdings fetch raises, render a loud `Portfolio unavailable this run.` line in the block — **never**
   fall back to silence or omit the block. A unit test must prove the failure path renders the loud
   line, not nothing.
3. **Precedence over the Alpaca overlay.** The Alpaca snapshot stays as an optional overlay for the
   minority who linked a paper account; the **sim block is the always-present source of truth and is
   authoritative for Room reasoning**. Decide precedence explicitly in code — do NOT emit two
   conflicting portfolio blocks. (Simplest: sim block always; Alpaca overlay only when linked, clearly
   labelled as the external paper account, sim labelled as the app's portfolio of record.)
4. **Researcher size cap (M03 coherence — removes the specific bad number).** Give the Bull / Bear /
   Research-Manager prompts the same `risk_tier_cap(risk_score)` ceiling the Trader & PM already see
   (consume the existing `_risk_tier_size_ceiling` / `risk_tier_cap` — **no coder.math sub-lane, no
   edit to `trading_math`**), phrased as the ceiling their sizing suggestion must respect. This kills
   the 10–15%-vs-3.0% incoherence that fed the hallucination.
5. **Tighten `long_only` wording (one sentence, prevents the downstream misfire).** Wherever
   `long_only` is described to Room agents, state it plainly: *"long-only = no short/negative
   positions. It does NOT forbid buying, adding to, or holding a name."*
