## OUT-OF-SCOPE

- **O1 (non-blocking, informational — zero exposure today):** `risk_tier_cap(score, caps)`
  is total only for **contiguous-key** tables. It clamps `score` into `[min(keys), max(keys)]`
  then indexes; a *sparse* custom `caps` (e.g. `{1:x, 5:y}`) with an intermediate score
  would `KeyError`. No exposure in-tree — every app call site uses the contiguous default
  `{1..5}`, and the only custom-table test passes a contiguous `{1,2}`. The docstring says
  "clamps to the nearest tier"; it clamps to the key *range*, not the nearest *existing* key.
  Informational only; no DEF recommended (architect mints if sparse tables ever ship).
