## Findings

### M1 — MINOR (in-scope) · countdown targets device-local midnight, backend rolls at KL midnight
`daily_challenge_card.dart` `_tick()` counts to the device-local midnight, but
the backend rolls the challenge at **Asia/Kuala_Lumpur** midnight
(`daily_challenge_service.py:39` `DEFAULT_TZ`; `today()` uses it, no per-user
tz). For non-UTC+8 users the "next in HH:MM:SS" label is off by their offset
from KL (~12h for US-Eastern). Correct for the current KL-based alpha; wrong for
the stated US MVP market. MINOR — no crash/data issue, blocks no flow — but
**recommend a fix before US exposure** (count to KL midnight, or have `/today`
expose `next_rollover_at`). Saiful's call to fix now or file a follow-up.

### O1 — OUT-OF-SCOPE (pre-existing) · `/today` exposes `answer` pre-attempt
`GET /v1/daily_challenge/today` returns `answer` in the challenge payload
(confirmed live). An API-direct user can read the correct option → farm
`challenge_correct` + guarantee the streak (→ monetized credit milestones).
Pre-existing backend behaviour (CR010 changes no backend); does not invalidate
CR010's client-side server-truth. **Architect to file a DEF** (auditor never
mints IDs). Fix direction: drop `answer` from `/today`, return it only in the
attempt response.

### Design note — assessed, acceptable (disclosed)
Streak-chip amber/green "today filled" is scoped to today's daily challenge, not
all streak activity — disclosed by the architect + in `streak_chip.dart`. The
streak count is exact from `/me`; only the colour cue is challenge-scoped.
Acceptable simplification.
