# CR046 — audit lane (architect)

**Item:** CR046 — Agent math ledger, a STANDING (always-open) CR. Policy: any number an agent
presents as fact that can be computed deterministically is computed in the new portable
`backend/app/trading_math/` library and injected — the LLM never does the arithmetic. First filing
seeds a ledger (M01–M05) and executes its first code sub-item, M03: reconcile three divergent
position-size scales into one canonical source. Register:
[`docs/forward_planning/cr_list.md`](../../../docs/forward_planning/cr_list.md) CR046. Full spec +
per-calc specs + preserved library survey:
[`CR046_agent_math_ledger/`](../../../docs/forward_planning/CR046_agent_math_ledger/).

**depends-on:** none.

**Head SHA:** `124f15f`.

## What was done

**New portable library `backend/app/trading_math/`** — pure functions over primitives, zero imports
from the rest of `app`, relative imports internally (copy-portable to other projects, per Saiful):

- `indicators.py` (M01) — `rsi` (Cutler's / simple-average, **not Wilder's** — deliberate, see D1),
  `rsi_tone`, `sma`. Migrated **verbatim** from `services/technicals.py::_rsi/_rsi_tone/_sma`;
  technicals.py re-exports them under the original private names. Byte-identical.
- `risk.py` (M02) — `drawdown_contribution(size_pct, entry, stop)` → `DrawdownContribution`
  NamedTuple. Extracted from `room_prompts._drawdown_snapshot_line`, which now calls it. Byte-
  identical prompt output.
- `sizing.py` (M03) — `DEFAULT_RISK_TIER_CAPS = {1:1.5,2:1.5,3:3.0,4:4.5,5:4.5}`,
  `risk_tier_cap(risk_score, caps=None)` (table-driven, total — clamps OOB scores),
  `clamp_size`, `SINGLE_NAME_ABSOLUTE_CAP_PCT = 50.0`.

**M03 incoherence fixed (the CR's thesis — shown == enforced).** Three modules answered "how big a
position?" three inconsistent ways: `overlay_generator._max_position_pct` **told** the Trader
5/10/15/25/40 by risk 1–5, `room_runner._risk_tier_size_ceiling` **clamped** the PM to
1.5/1.5/3.0/4.5/4.5, `safety_floor.SINGLE_NAME_CAP_PCT` was a flat 50. A risk-5 user's Trader was
told 40% and the system enforced ~4.5% (~9× gap). All three now read the one source in
`trading_math/sizing.py`. **No enforced behaviour changed** — the canonical values ARE the ceilings
the PM already clamped to; only the Trader's narration was corrected from a false 40% to the true
4.5%. `SINGLE_NAME_CAP_PCT` stays 50.0 (= the library backstop).

**Governance:** `failure_patterns.md` gains class **P5** (LLM asked to compute a number it presents
as fact; instances DEF052/DEF066/CR046-M03; enforcing check = the coherence guard). `cr_list.md`
CR046 row added, status `standing`.

## Why this is safe / minimal

- **M01/M02 are byte-identical migrations** — the pure functions moved location, computation
  unchanged; `test_technicals.py` (17 tests) and `test_room_prompts.py` (4 DEF066 tests) stay green
  untouched, which is the proof the extraction preserved behaviour.
- **M03 changes no enforced number** — `_risk_tier_size_ceiling` returns exactly what it returned
  before (1.5/3.0/4.5); `test_room_pm_size_clamped_to_risk_tier_ceiling` (clamps to 1.5) and
  `test_risk_score_5_sizes_up_aggressively_vs_risk_1` still pass. The only behaviour delta is the
  Trader's *narration* string (40% → 4.5%), which was the false statement.
- **Library has no app coupling** — no import cycle possible (`trading_math` imports only stdlib);
  `safety_floor`/`room_runner`/`room_prompts`/`overlay_generator` import *from* it, not vice-versa.
- **Scope discipline:** ruff `--fix` over-reached on `room_runner.py` (unrelated `datetime.now(UTC)`
  / `TimeoutError` modernizations across the whole file); I **reverted** that file to HEAD and
  reapplied only the two intended edits (import + `_risk_tier_size_ceiling` delegation). Final
  `room_runner.py` diff = 12 lines, import + one function.
