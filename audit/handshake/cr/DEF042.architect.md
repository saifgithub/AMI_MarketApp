# DEF042 — audit lane (architect)

**Item:** DEF042 — security. `GET /v1/daily_challenge/today` (and `/by_date`, `/by_id`, `/all`)
returned the challenge `answer` (correct option index) **pre-attempt** — an API-direct caller
could read it, farm `challenge_correct`, and guarantee the streak → monetized-credit milestones.
This is the reopened **CR010 audit finding O1**. Register: [`docs/defect/def_list.md`](../../../docs/defect/def_list.md) DEF042.

**depends-on:** none.

**Head SHA:** `85ec04e`

## What changed / why

| Piece | Change |
|---|---|
| schema | `app/schemas/daily_challenge.py` — new `DailyChallengePublic` (all of `DailyChallenge` **minus `answer` and `explanation`**) via `from_challenge()`. `MyAttempt` gains `correct_option` + `explanation` (safe: only populates for the caller's own already-attempted challenge). |
| routes | `app/api/daily_challenge.py` — all four read routes (`/today`, `/by_date`, `/by_id`, `/all`) now return `DailyChallengePublic`. `/today`'s `my_attempt` + the `/attempt` response carry `correct_option`+`explanation` post-attempt instead. |
| mobile | `mobile/lib/models/daily_challenge.dart` — `DailyChallenge` drops both fields; `MyAttempt` gains `correctOption`+`explanation`. `daily_challenge_card.dart` tracks `_correctOption`/`_explanation` from the attempt result or prior `my_attempt`, never from the challenge object. |

## Why the scope widened at pickup (vs the original O1 report)

The original finding named only `answer` on `/today`. Two extra leaks found + closed:
1. **`explanation`** restates the correct option's reasoning — matchable to the option text, so it
   leaked the answer indirectly. Dropped from the public shape too.
2. The same two fields were exposed **unauthenticated** on `/by_date`, `/by_id`, `/all`, not just
   `/today`. All four routes now use `DailyChallengePublic`.
