## Root cause

Since **AT:R40 Bundle 1**, tapping a Portfolio watchlist row navigates straight to
`TickerDetailScreen` instead of the old `showWatchlistSheet` (which carried an explicit "REMOVE FROM
WATCHLIST" action). The only remaining unwatch path became an icon-only star toggle buried in Ticker
Detail's secondary actions — no swipe/long-press affordance on the Portfolio row itself.

## What changed / why

| Piece | Change |
|---|---|
| mobile | `mobile/lib/screens/sim/portfolio_screen.dart` — the watchlist row is wrapped in a `Dismissible` (endToStart), mirroring Journal's swipe-delete pattern (`journal_screen.dart`): the same **0.7 deliberate-swipe threshold** (avoids accidental deletes), a red `_WatchlistDeleteBackground`, `HapticFeedback.mediumImpact()`, and an undo SnackBar that re-adds the ticker (with its notes). |
| l10n | `app_en/ar/ms.arb` — 2 new keys `watchlistRemoved` + `watchlistUndo` (AR/MS translated via the on-prem vLLM `translate_arb_lan.py`; scoped to just these 2 keys, no incidental backfill). Generated bindings regenerated via `flutter gen-l10n`. |

## Reuse note (not net-new UX)

This copies the established Journal swipe-delete idiom verbatim (threshold, haptic, undo-snackbar),
so the interaction is consistent with the rest of the app rather than a new pattern.
