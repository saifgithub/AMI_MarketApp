# CR034 — audit lane (architect)

**Item:** CR034 — the Room's `forward_catalyst` profile field said
`"FOMC decision in 11 days, sector earnings in 3 weeks"` as a hardcoded
literal, unconditionally, for every ticker, every run, forever — only ever
true on the calendar day it was written. Unlike the sibling synthetic/
illustrative fields it sits next to (`macro_tone`, `fed_tone`, sentiment
fields), this was a specific, falsifiable factual claim presented with no
caveat. Found by Saiful verifying a live HPQ Room convene right after
DEF051-055 shipped. Register:
[`docs/forward_planning/cr_list.md`](../../../docs/forward_planning/cr_list.md)
CR034. Full spec:
[`CR034_room_forward_catalyst_fabricated_fomc_date.md`](../../../docs/forward_planning/CR034_room_forward_catalyst_fabricated_fomc_date/CR034_room_forward_catalyst_fabricated_fomc_date.md).

**depends-on:** none.

**Head SHA:** `e19bf56`.

## What was done

`backend/app/services/room_runner.py`:

- New `_FOMC_DECISION_DATES` — a hardcoded list of the Fed's published 2026
  meeting decision dates (the 2nd day of each 2-day meeting), sourced from
  the official FOMC calendar. Same maintenance shape as any other
  reference-data table in this codebase (e.g. DEF052/053's yfinance-backed
  fields don't need this, but truly-static calendar data does) — needs a
  manual refresh once the Fed publishes next year's schedule; recorded as a
  known, deliberate maintenance point, not silently deferred.
- New `_forward_catalyst_text(today: date | None = None)` — computes real
  days-to-next-FOMC-decision from that table (`today` param exists only for
  deterministic test injection; production calls use
  `datetime.now(timezone.utc).date()`). Degrades to
  `"next FOMC decision date not yet published"` past the last hardcoded date
  rather than silently going stale or crashing.
- Sector-earnings-season timing still has no real feed (same disclosed gap
  CR023 already carries for News) — kept, but now baked directly into the
  value string as `"(illustrative, not date-verified)"`, matching the
  convention already used by `sentiment_score`/`mention_trend` (bake the
  caveat into the value itself so it survives into the agent's final prose
  regardless of what the LLM does with the rest of the prompt — this is the
  exact convention gap DEF052/053/CR023/CR024 already established and this
  CR extends to the one remaining field that lacked it).
- `profile["forward_catalyst"]` now calls `_forward_catalyst_text()` instead
  of returning the frozen literal.

`macro_tone`/`fed_tone`/`fed_impact` unchanged — genuinely unmeasurable
qualitative framing, already disclosed via `room_prompts.py`'s separate
"(synthetic, illustrative)" header line; out of scope here by design.

## Why this is safe / minimal

- **Narrowest possible fix** — one field, one function, no schema change, no
  new external dependency. The frozen-literal bug was specifically the FOMC
  half of the string; the sector-earnings half already had no real feed and
  stays exactly as illustrative as it was, just with the caveat relocated
  into the value itself.
- **Spot-checked against the real calendar**: the array's `date(2026, 7, 29)`
  entry matches the defect doc's claim of "next meeting after 2026-07-13 is
  July 28-29" (a 2-day meeting, decision on the 29th) — consistent with the
  cited federalreserve.gov calendar reference.
- **Degradation path has no silent-failure mode**: past the last hardcoded
  date, the function returns an explicit "not yet published" string rather
  than reusing a stale date or raising — verified directly by
  `test_forward_catalyst_text_after_years_last_published_meeting`.
- **No cross-cutting risk**: purely a value-computation change inside
  `_profile_for_ticker()`; doesn't touch prompt composition, agent gating,
  or any of the DEF051-056 machinery landed the same session.
