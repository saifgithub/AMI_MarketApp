# DEF054 — audit lane (architect)

**Item:** DEF054 — Bull Researcher's prompt claimed "Historical context from the
Decision Journal" as an input, but `journal_store` was write-only from the Room's
perspective — `build_journal_entry_for_run()` writes a run's outcome *after* it
completes; nothing ever read past entries back into a *future* run's prompt. Split
out of CR033 (docs-only, AT:R57) into its own Defect at Saiful's request. Register:
[`docs/defect/def_list.md`](../../../docs/defect/def_list.md) DEF054. Full spec:
[`DEF054_bull_researcher_fabricated_journal_claim.md`](../../../docs/defect/DEF054_bull_researcher_fabricated_journal_claim/DEF054_bull_researcher_fabricated_journal_claim.md).

**depends-on:** none. (DEF055 depends on this lane's wiring, not the reverse.)

**Head SHA:** `5a7ad48` (shared commit with DEF055 — both researchers wired
together; see that lane for Bear-specific detail.)

## What was done

New `backend/app/services/journal_context.py` mirrors Concierge's existing real
pattern (`concierge_prompts.py::load_concierge_context()` →
`journal_store.list_for_user()`) rather than inventing a new one:

- `fetch_recent_journal_entries(user_id, ticker, plan)` — never raises, returns
  `[]` on any failure (anonymous user, store error) or when there's simply no
  history for this ticker. **Genuinely ticker-scoped**: `list_for_user()` already
  supports a `ticker=` filter — no schema change needed, so this isn't the
  general-recent fallback the original defect doc treated as the likely-necessary
  compromise.
- `format_journal_entry()` — one line per entry (`YYYY-MM-DD: title (outcome)`),
  synthesized, not verbatim journal text echoed.
- `build_journal_context_block()` — the system-prompt-ready block, `None` when no
  real history exists.

Wired into the **Room path** (`room_prompts.py::build_room_messages()`) via a new
`journal_note`, gated on `agent_id in (BULL_RESEARCHER, BEAR_RESEARCHER)` and
appended into the per-agent `room_addition` text — mirroring the exact pattern
already established for the Portfolio-Manager-only `pm_note` in the same function.
A `plan` param was threaded through (both `room_runner.py` call sites already
compute `effective_plan_for_user()` for tier-picking; reused rather than
recomputed) so the journal lookback respects the same plan-based retention window
`journal_store` applies everywhere else.

Wired into the **1-on-1 path** (`agent_runner.py`), gated identically, mirroring
CR023/CR024/DEF052's Analyst-only gating pattern. The `plan` computation
(`effective_plan_for_user`) was moved earlier in the function (it already existed,
just further down) so the journal block can reuse it instead of a second DB call.

`content/agents/bull_researcher.md` rewritten: "Historical context from the
Decision Journal" → explicit real, ticker-scoped framing, with an instruction to
say so rather than invent a decision when none exists.

**`bull_size`/`bull_falsifier` hardcoded literals**: left untouched, matching the
original doc's framing that the narrative-reasoning fix (the actual fabricated
claim) was the higher-value target and the sizing figures a separate, lower
priority item.

## Why this is safe / minimal

- **Reuses an established real pattern rather than inventing one**: Concierge
  already does exactly this (real journal read via `list_for_user`), so this isn't
  new architecture — it's extending a proven pattern to two more callers.
- **Ticker isolation tested directly**: a fixture seeds entries for both AAPL and
  MSFT for the same user; the AAPL fetch returns only the 2 AAPL entries, proving
  the `ticker=` filter actually isolates rather than returning everything.
- **Never-raises verified with a genuine failure injection**: a fake store that
  raises `RuntimeError` on `list_for_user()` is used to prove
  `fetch_recent_journal_entries()` returns `[]` rather than propagating.
- **Shared, not duplicated**: DEF055 (Bear) uses the identical
  `build_journal_context_block()` — one code path, one set of edge cases to get
  right, not two.

- New `backend/tests/unit/test_journal_context.py` (9 tests): real entries
  fetched and ticker-isolated (seeded AAPL + MSFT rows, AAPL fetch returns only
  AAPL); empty for a ticker with no history; empty for an anonymous (`None`)
  user; never raises on a store error (`RuntimeError` injection); formatting
  includes date/title/outcome, omits outcome cleanly when absent; block `None`
  when no history, present with real content when it exists; the 5-entry cap is
  actually passed through to the store call (`limit=5` captured and asserted).
- Extended `test_room_runner.py` (+5): Bull gets journal history via
  `build_room_messages()` when it exists; Bear gets it too (proving the shared

  Market Analyst (the Bull/Bear-only gate, unlike the shared fundamentals/
  technicals block); absent for an anonymous (`None`) user.
- New `test_one_on_one_journal_injection.py` (+5, shared with DEF055): injected
  for Bull when a ticker is mentioned with real history; injected for Bear too;
  not injected for Market Analyst; absent when no history; absent for an
  anonymous session.
