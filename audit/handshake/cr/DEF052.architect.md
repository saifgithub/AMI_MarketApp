## What was done

New `backend/app/services/technicals.py` — `compute_technicals(ticker)` (never raises,
same contract as `fetch_live_fundamentals`/`fetch_live_news`/`fetch_live_sentiment`).
Pulls `MarketDataProvider.history(ticker, "3m")` (~65 daily candles, already cached —
the same feed powering the mobile Ticker Detail chart, no new external API) and
computes:

- **RSI(14)** — standard gain/loss average over the last 14 daily deltas.
- **Trend** — `"trading"` when price + 20-day SMA + 50-day SMA are directionally
  aligned (real momentum), `"consolidating"` otherwise. Kept the same two-value
  vocabulary the scripted-fallback template's grammar depends on, now backed by real
  computation instead of `rng.random() > 0.5`.
- **Volume tone** — last-5-day average vs. last-20-day average (three buckets:
  above/below/in-line), real, replacing another coin flip.
- **Support/breakout** — real min/max of the last 50 candles' low/high, replacing
  `base_price × 0.9` / `× 1.03`.

Wired into `room_runner.py::_profile_for_ticker()` (overlay inside the existing
`if settings.use_real_market_data:` block, same pattern as fundamentals/news/social —
each independently overlayable, none coupled) and `agent_runner.py`'s 1-on-1 path
(Market-Analyst-gated `build_technicals_context_block()`, mirroring CR023/CR024's
News/Social-only gating). `room_prompts.py::_format_profile()`'s disclosure header
gained an independent technicals live/synthetic category.

**MACD/Bollinger Bands — explicit scope decision:** dropped from the prompt rather than
half-implemented. `content/agents/market_analyst.md` rewritten to describe only RSI,
the real moving-average trend read, real volume, and real recent-range
support/breakout — and explicitly states MACD/moving-average-crossover/Bollinger Bands
are not computed anywhere in the app.

**Also fixed in passing:** the scripted (non-LLM) fallback template
(`_TEMPLATES[AgentId.MARKET_ANALYST]`, rendered verbatim to real users whenever
`gateway.has_real_provider()` is False or an agent call times out) claimed `support`
came from "the 200-day [MA]" — a claim the real computation never backs (it's a 50-day
recent-range low, not a 200-day moving average). Reworded to "recent support" — same
class of fix as CR024's scripted-fallback platform-naming correction.

## Why this is safe / minimal

- **Never-raises contract preserved**: `compute_technicals` wraps the provider call in
  `try/except Exception`, returns `None` on any failure (missing history, insufficient
  candles, provider error) — callers (`room_runner.py`, `agent_runner.py`) check before
  overlaying, so a yfinance outage falls straight back to the pre-existing synthetic
  block, never surfaces as a Room/1-on-1 error.
- **No key/config gate needed beyond `use_real_market_data`**: unlike CR023/CR024, this
  needs no new API key — the underlying `MarketDataProvider.history()` is already
  configured and already cached (60s TTL) from AT:R41's chart work.
- **Window discipline is tested, not assumed**: the support/breakout test deliberately
  plants absurd extreme values *outside* the 50-candle lookback (10.0 low / 500.0 high
  in the first 15 of 65 candles) and asserts they do NOT leak into the result — proving
  the function actually respects its stated window rather than scanning the full
  history.
- **Independent of fundamentals**: a profile can have live fundamentals + synthetic
  technicals or vice versa — tested explicitly, not assumed from the fundamentals
  precedent.

## Tests run (self-test)

- New `backend/tests/unit/test_technicals.py` (13 tests): RSI hand-verified against a
  deterministic alternating-delta series (avg_gain=1.0, avg_loss=0.5, RS=2.0,
  RSI=66.66→67, hand-computed not just asserted-equal-to-itself); a pure-uptrend case
  (RSI=100, `rsi_tone="overbought"`); trend "trading" (strictly increasing closes) vs.
  "consolidating" (flat oscillation); volume above/below/in-line from real volume
  ratios; support/breakout proven windowed (see above); `None` on missing history,
  short history (<50 candles), and a raising provider.
- Extended `test_room_runner.py` (+5): live overlay populates all five fields +
  `technicals_source`; graceful fallback when `compute_technicals` returns `None`;
  independence from the fundamentals overlay (each combination tested); disclosure
  header labels technicals live/synthetic independently of fundamentals.
- New `test_one_on_one_market_injection.py` (+4): Market-Analyst-only gating (mirrors
  CR023's News-only test) — injected when the agent is Market Analyst and a ticker is
  mentioned; absent for other agents, when disabled, and when compute fails.
