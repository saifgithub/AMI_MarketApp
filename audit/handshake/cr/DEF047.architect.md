# DEF047 — audit lane (architect)

**Item:** DEF047 — onboarding hardcoded `locale: 'en'` on both the initial `start()` call and the
error-retry `start()` call (`onboarding_screen.dart:36,101`) instead of the user's actual active
locale, so an AR/MS user still got an English-hinted Concierge interview. CR004 Plan-A audit
finding #2. Register: [`docs/defect/def_list.md`](../../../docs/defect/def_list.md) DEF047.

**depends-on:** none. (Shares commit `fd0ab6f` with DEF048; the two are independent concerns
audited separately.)

**Head SHA:** `fd0ab6f`

## What changed / why

| Piece | Change |
|---|---|
| mobile | `mobile/lib/screens/onboarding/onboarding_screen.dart` — both `start()` call sites now pass `Localizations.localeOf(context).languageCode` instead of the literal `'en'`. This is the same locale MaterialApp resolves (system locale or the Settings → Language override via `localeNotifierProvider`), so the Concierge greeting hint matches the UI language. |

## Why this is safe / minimal

`Localizations.localeOf(context)` is already the source of truth for every localized string on the
screen; the onboarding start payload was the one place still hardcoding `en`. `supportedLocales`
is `{en, ar, ms}`, so `.languageCode` is always one the backend already accepts.
