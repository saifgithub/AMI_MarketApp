# DEF056 — audit lane (architect)

**Item:** DEF056 — Convene the Room's structured `Verdict` (action/size/entry/
stop/target — the data the "Open Trade Ticket" flow and journal actually use)
was computed from `base_price` + a fixed `mandate.risk_score` tier **before any
of the 12 agents spoke**, then never touched again. `check_mandate_compliance()`
only checks structural mandate rules (drawdown cap, halal/locale universe,
concentration cap) — never the agents' own business-judgment conclusions. On a
real RXT run, Trader/Conservative Debator/PM all independently concluded
WAIT/REJECT using real data, yet the stored verdict was `APPROVE/3%/$4.52`
regardless — and the PM's own LLM narration ("REJECT... FAIL") directly
contradicted the deterministic verdict text it was explicitly instructed not to
contradict. Found verifying a live Room convene right after DEF051-055 shipped.
Register: [`docs/defect/def_list.md`](../../../docs/defect/def_list.md) DEF056.
Full spec:
[`DEF056_room_verdict_ignores_agent_debate.md`](../../../docs/defect/DEF056_room_verdict_ignores_agent_debate/DEF056_room_verdict_ignores_agent_debate.md).

**depends-on:** none. Touches the same `enforce_safety_floor`/
`check_mandate_compliance` machinery DEF051 feeds real portfolio state into,
but is otherwise independent.

**Head SHA:** `e939e46` (filed at `c87b0ce`, resolved at `7561635`).

## What was done

Flipped the PM phase from "narrate around a precomputed action" to "decide,
then the deterministic floor vetoes." The PM already reads the entire
transcript (all 11 prior agents) in its prompt — its own decision now *is* the
verdict, instead of an independently-precomputed verdict the PM was told to
agree with and sometimes didn't.

- `room_prompts.py::build_room_messages()` — dropped the `pm_note`
  ("DETERMINISTIC SAFETY-FLOOR RESULT: APPROVE... Do NOT contradict") the LLM
  had been disregarding. The PM now gets `_PM_VERDICT_FORMAT`: respond with
  only a JSON object — `action: APPROVE | PASS`, `size_pct`/`entry`/`stop`/
  `target`/`horizon_days` if APPROVE, `narration` for the user-visible text.
  Non-PM agents unaffected (`_PROSE_FORMAT`, unchanged).
- `room_runner.py` — new `_parse_pm_verdict()` extracts the PM's JSON via
  `llm_json.extract_json_object()` (new shared module, factored out of
  `brief_engine.py`'s pre-existing `_parse_proposal_json` — same tolerant
  fence/prose-stripping logic, now shared instead of duplicated). A parsed
  APPROVE goes through `enforce_safety_floor()`
  (`backend/app/agents/safety_floor.py:253-287`) — **previously dead code,
  grepped and confirmed zero call sites before this commit** — which re-runs
  `check_mandate_compliance()` and overrides to REJECT on failure, exactly
  matching the old deterministic-first flow's behavior. A parsed PASS (the
  `VerdictAction` schema already had this member, never used before) passes
  straight through — no compliance check needed, since PASS proposes no trade.
  `size_pct` is clamped to `_risk_tier_size_ceiling(mandate.risk_score)`
  regardless of what the LLM asked for (1.5/3.0/4.5% tiers, same values the
  old pre-debate cosmetic sizing used). Unparseable/empty PM responses fail
  safe to `PASS` (`overridden_from_llm=True`) rather than fabricating a trade
  the debate never reached. A total LLM failure (timeout/exception, no
  `raw_text` at all) still falls back to the old deterministic
  `_assemble_verdict()` scripted path — same fallback shape every other
  agent's timeout already used, now explicitly commented as "NOT the live
  path's decision-maker" in `_assemble_verdict()`'s own docstring.
- `safety_floor.py` — `SAFETY_FLOOR_BLOCK`'s embedded JSON example (shown to
  the LLM as a formatting hint) updated from a `{"verdict": "REJECT", ...}`
  shape that was never actually parsed anywhere to the real
  `{"action": "PASS", "narration": ...}` shape — closes a latent
  prompt/parser mismatch that predates this fix.
- Mobile (`room.dart`, `room_screen.dart`, `journal_detail_screen.dart`,
  `share_service.dart`) — `PASS` previously rendered identical to `REJECT`
  (amber + cancel icon) everywhere a verdict is shown; given its own neutral
  treatment (slate + neutral icon) so "debate didn't support a trade" doesn't
  visually read as "your mandate rejected this."
- Trader / Risk Debator phases untouched — still pure narration. The PM
  already sees their conclusions in the transcript; making the PM's own
  decision authoritative was enough to make the debate matter, without
  parsing every agent's prose individually.

**Explicitly out of scope** (recorded in the defect doc, not silently
dropped): SELL/short verdicts (`ProposedTrade.side` stays hardcoded `BUY`),
`MODIFY` (stays unused), and a regenerate-on-self-contradiction loop for the
PM's own prose disagreeing with its own JSON action (much smaller residual
risk now that both come from one generation) — deferred, no incidence data
yet to justify the added LLM cost per run.

## Why this is safe / minimal

- **The deterministic floor's actual guarantee is unchanged and still the
  final word.** `enforce_safety_floor()` calls the exact same
  `check_mandate_compliance()` the old flow called — same structural checks
  (drawdown cap, halal universe, locale universe, single-name concentration),
  same override-to-REJECT behavior on failure. What changed is *what* gets
  fed into it (the PM's real decision vs. a precomputed one) and *when*
  (after the debate, not before it) — the floor itself is untouched code.
- **`PASS` was already a first-class schema member, just dead.** No new
  verdict state was invented; `VerdictAction.PASS` existed
  ("Research Manager: nothing fits mandate today") and was simply never
  reachable before this fix.
- **Fail-safe direction is conservative.** Every failure mode (unparseable
  JSON, missing size, total LLM outage) resolves to PASS or the old scripted
  path — never to fabricating an APPROVE the debate didn't support. Verified
  by `test_room_pm_unparseable_reply_fails_safe_to_pass`.
- **Shared JSON-extraction helper, not a second implementation** —
  `llm_json.extract_json_object()` is the same tolerant logic
  `brief_engine.py` already used for `BriefProposal` parsing, factored out
  rather than reimplemented, so there's one fence/prose-stripping edge case
  to get right, not two.

## Tests run (self-test)

- **+3 new** (`test_room_runner.py`):
  `test_room_pm_pass_verdict_matches_debate` — Trader WAIT + PM PASS JSON →
  stored verdict is PASS, `overridden_from_llm is False` (a genuine PM
  decision, not a failure fallback). `test_room_pm_size_clamped_to_risk_tier_ceiling`

  `overridden_from_llm=True`.

  `test_room_uses_gateway_for_every_agent_when_live`'s fake gateway matched

  word "trader" appearing inside the running transcript text embedded in a
  later agent's own prompt — harmless before DEF056 (the verdict never
  depended on which reply text the PM received), load-bearing now that it
  does. Fixed to match on the turn's actual "Speak as the X" instruction
  instead of a bare substring-anywhere check; the docstring comment
  explaining why is preserved in the test file itself.
